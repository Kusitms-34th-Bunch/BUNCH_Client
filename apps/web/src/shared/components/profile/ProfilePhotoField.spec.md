## 목적과 범위

### 제공하는 동작

- 프로필 사진(없으면 기본 프로필 이미지, 번치 타입과 무관)과 카메라 버튼. 누르면 「프로필 사진 설정」 선택지(`ActionDialog`): 앨범에서 사진 선택하기 / 기본 이미지 적용하기 / 취소. 이미 기본 이미지면 두 번째 선택지는 없다(2-1번).
- 앨범에서 고른 사진은 조정 화면으로 연다. 사진은 화면 폭에 맞춰 통째로 보인다(아주 긴 세로 사진은 영역 높이에 맞춤, Figma 가로 `5878:90300`, 세로 `6501:138753`). 그 위의 칸은 비율이 자유이고, 원은 칸 안에 꽉 차게(지름 = 칸의 짧은 쪽, 칸 가운데) 함께 커지고 줄어든다. 처음 칸은 사진 폭 × 짧은 쪽이라 가로 사진은 사진 전체, 세로 사진은 가운데 정사각형이다(Figma와 같음). 칸 안을 끌거나 방향키(10px)로 옮기고, 모서리 꺾쇠를 끌면 반대 모서리를 고정한 채 좌우로 끌면 폭만, 위아래로 끌면 높이만, 대각선이면 둘 다 바뀐다. `+`·`-` 키는 비율을 유지한 채 1.1배씩 바꾸고, 사진 끝이나 최소 크기에 닿으면 멈춘다. 가운데는 유지하되 사진 끝에 닿으면 안쪽으로 밀린다. 한 변은 화면 80px보다 작아지지 않고 칸은 사진 밖으로 나가지 않는다. 「완료」는 원이 덮는 정사각 영역을 512px JPEG로 만든다(투명 영역은 흰 바탕). 칸은 원본 사진 px로 저장해 화면 크기가 바뀌어도 같은 부분을 가리킨다. 가볍게 움직이도록 다음을 지킨다(2026-11-11 사용자 결정, 끊김 개선). 끄는 동안은 React 상태를 바꾸지 않고 화면 갱신(requestAnimationFrame)마다 한 번 칸·원·그림자 요소의 위치와 크기를 DOM에 직접 쓰고, 손을 뗄 때만 상태를 바꾼다. 원 밖 어두운 막은 원 모양 요소의 큰 그림자로 그려 매 프레임 mask를 다시 계산하지 않는다. 조정 영역은 `contain: layout paint`로 바깥을 다시 계산하지 않게 가둔다. 사진 밖으로 끌면 넘친 거리의 25%만 따라가다가(고무줄) 놓으면 150ms ease-out으로 끝에 맞춰 돌아온다(동작 줄이기에서는 바로). 사진을 디코딩하지 못하거나 자르기용 canvas를 만들지 못하면 조정 화면을 닫고 기획 문구 「이 사진은 사용할 수 없어요.」 토스트를 띄운다.
- 웹 파일 읽기가 300ms를 넘으면 「사진을 불러오는 중」 화면(6번), 작은 사진은 바로 조정 화면.
- 형식·크기: JPEG·PNG·HEIC·WebP, 10MB 이하(`PROFILE_IMAGE_RULES`). 바이트가 작아도 5천만 픽셀을 넘으면 거절한다(디코딩·자르기 메모리 보호). 어긋나거나 브라우저가 읽지 못하면 「JPEG・PNG・HEIC・WebP, 10MB 이하만 가능해요.」 토스트.
- 결과는 미리보기만 하고 `onChange`로 넘긴다. 저장은 화면이 프로필 저장 API를 연결할 때 한다.

### 제공하지 않는 동작

- 서버 업로드와 실패 토스트 「업로드에 실패했어요.」(편집(9)): 이미지 업로드 API 연결 때.
- 확대(핀치): MY Figma·화면 설계서에 이동만 정의. 가입 기능 명세(`docs/specs/login-signup.md`)의 "확대·이동"과 다르다.
- 사진 접근 권한 안내 Dialog(3번)와 OS 권한 창(4번): 아래 결정 참고.

## 결정 (2026-11-05, 사용자 확인)

1. 조정 화면은 브라우저와 앱 모두 이 웹 화면을 쓴다. 앱은 `pickGalleryImage({ edit: false })`로 시스템 정사각형 편집을 끄고, 쉘이 `expo-image-manipulator`로 긴 변 2048px 이하 JPEG를 넘긴다. 다른 사진 선택(온보딩 번치 사진, 번치 프로필 편집)은 기본값(시스템 편집)을 그대로 쓴다.
2. 권한 안내 Dialog는 만들지 않았다. 시스템 사진 선택기(앱)와 파일 선택(브라우저)은 사진 접근 권한이 필요 없어 띄울 경우가 없다. 권한이 필요한 흐름(카메라 촬영 등)이 생기면 기존 `ConfirmDialog`로 문구(「사진 접근 권한이 필요해요」 / 「앨범에서 사진을 고르려면 설정에서 사진 접근을 허용해 주세요.」 / 취소·설정으로 이동)를 연결한다. 설정 이동 bridge는 아직 없다.
3. 형식·크기는 MY Figma 기준으로 가입까지 통일했다(이전 가입 기준 JPEG·PNG·WebP 3MB와 「이 사진은 사용할 수 없어요.」를 대체).

## 접근성

- 카메라 버튼 이름 「프로필 사진 변경」, 사진은 장식.
- 조정 화면은 body에 그리는 `role="dialog"`(`aria-modal`, 이름 「프로필 사진 조정」)다. 열린 동안 뒤 화면은 `inert`이고, Esc·뒤로 가기로 취소한다.
- 열리면 초점이 이동 영역(불러오는 중이면 뒤로 가기)으로 가고, 닫히면 카메라 버튼으로 돌아온다.
- 조정 영역은 이름 「자를 영역 조정」인 버튼이고, 안내 문구와 사용법(끌거나 방향키로 옮기고 모서리나 +·- 키로 크기 조절)을 설명으로 연결한다. 손을 떼거나 키로 바꾸면 칸 크기와 원 가운데 위치를 비율로 읽어 준다(끄는 동안에는 읽지 않음). 모서리 꺾쇠는 20px로 보이고 잡는 영역은 44px다.
- 「완료」는 사진을 불러오기 전에는 비활성. 불러오는 중은 `role="status"`로 알린다. 불러오는 중에 취소하면 읽기가 끝나도 조정 화면이나 오류 토스트를 띄우지 않는다.
- 조정을 마치거나 「기본 이미지 적용하기」를 고르면 미리보기만 바뀌므로 항상 그려 둔 sr-only status로 「사진을 바꿨어요」·「기본 이미지로 바꿨어요」를 읽어 준다(가입·MY·번치 프로필 공통). 새 변경을 시작할 때 문구를 비워 연달아 바꿔도 매번 읽힌다. 고르자마자 서버에 저장하는 번치 만들기 완료 화면은 `announceChange={false}`로 끄고 자기 저장 안내를 쓴다.
- 고른 사진을 읽거나 조정하는 동안(`onPendingChange`)을 부모에 알린다. 끝나기 전에는 부모의 사진 값이 이전 값이라, 따로 저장하는 화면이 그동안 저장을 막는다.

## 확인할 항목

- 조정 화면 배경 토큰: Figma `Surface/surface-inversed-strong`이 내보낸 토큰에 없어 primitive를 썼다. 토큰 export에 추가되면 바꾼다.
- 뒤로 가기 아이콘 대비 (해결): 디자이너가 `icon-tertiary`(약 2.6:1)를 `icon-inversed`(흰색)로 바꿨다.
- 스크린 리더: 열린 동안 뒤 화면이 inert라 그 사이의 토스트가 읽히는지, 방향키·+/- 뒤 위치 안내가 한 번씩(누르고 있으면 뗄 때 한 번) 읽히는지, 데스크톱에서 클릭 뒤 Esc가 동작하는지 VoiceOver·브라우저로 확인한다.
- 앱 쉘 원본 디코딩 메모리: `expo-image-manipulator`는 줄이기 전에 원본 전체를 디코딩한다. 48MP급 사진을 메모리가 적은 기기에서 고를 때 실패하는지 실기기에서 확인하고, 문제가 되면 디코딩 단계에서 줄이는 방법을 찾는다.
- 앱 쉘 전송 크기: 2048px JPEG(0.8)가 4MiB 전송 상한을 넘거나 원본 크기를 모르면 실패 토스트만 보인다. 실기기에서 확인한다.
- 확대(핀치) 지원 여부: 가입 명세와 MY Figma가 다르다. 기획 확인 뒤 정한다.
- 앱 쉘 실기기: `edit: false` 경로(원본 줄이기·전송 크기)와 이전 앱(옵션 무시) 동작은 시뮬레이터·실기기에서 확인하지 않았다.
