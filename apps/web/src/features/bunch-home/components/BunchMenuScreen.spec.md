# 페이지: 번치 더보기 메뉴

- Route: `/bunch/menu`(`apps/web/src/app/(app)/bunch/menu/page.tsx`)
- Status: 역할별 메뉴와 나가기 확인 창 UI 구현. 데이터는 fixture다. 이슈 #169.
- 디자인 출처: 화면설계서 `화면 설계서 - 번치 (메인/상세)`(`1892:37780`), Figma `번치 - 상세` 섹션의 `더보기 메뉴 - 관리자`(`1873:34212`), `더보기 메뉴 - 공동 관리자 및 일반 멤버`(`1873:34609`), `더보기 메뉴 - 일반 멤버`(`2198:44761`, 나가기 확인 창).
- 기능 spec: 기능명세서 5.4, `docs/specs/bunch-home.md`.

## 목적과 범위

### 포함

- 뒤로 가기 헤더와 메뉴 두 묶음, 그 사이 구분선.
- 메인 관리자: 프로필 편집, 멤버 관리, 멤버 초대, 차단 목록 / 번치 나가기, 번치 삭제.
- 공동 관리자와 일반 멤버: 멤버 관리, 멤버 초대, 차단 목록 / 번치 나가기. Figma 두 화면의 항목이 같다.
- 메인 관리자가 아닌 멤버의 「번치 나가기」: 「{번치 이름} 번치를 나갈까요?」 확인 창(「취소」/「나가기」). 나가면 남은 첫 번치의 번치 탭으로 되돌아가고 토스트(#180).
- 메인 관리자의 「번치 나가기」: 새 관리자 지정 화면(`/bunch/menu/leave`). 나만 남은 번치는 역할과 상관없이 「혼자 있는 번치는 나갈 수 없어요」 안내와 「삭제하기」(`BunchLeaveScreen.spec.md`).

### 범위 외(후속 이슈)

- 번치 삭제 화면. 지금은 메뉴 항목이 동작이 없다. 프로필 편집(#172), 멤버 관리·멤버 초대(#175), 차단 목록(#178)은 링크, 나가기(#180)는 역할별로 연결했다. 각 이슈가 route를 만들 때 연결한다.
- 나가기 서버 요청: API 연결 때.

## Route와 접근

- Path: `/bunch/menu`. params·search 없음. 탭 경로 밖이라 iOS 앱에서는 시스템 탭 바가 숨는다(결정 기록 012).
- 접근 권한·guard: 아직 없다(로그인·번치 API 미연결). 이름·역할은 번치 홈에서 고른 fixture 번치(`useCurrentBunchId`)를 따른다. 퇴근런클럽(비공개) 메인 관리자, 여행가조 공동 관리자, 큐시즘 기프 일반 멤버다. 프로필 편집의 공개 전환 안내를 보려면 비공개인 번치가 메인 관리자여야 해서 이렇게 둔다. 서버가 요청 시점의 역할로 다시 판단해야 한다.
- 진입: 번치 홈 헤더 「더보기」 링크(`Link`, 새 탭 열기·가운데 클릭 지원). 화면설계서(`1892:37780`)대로 메뉴가 번치 홈 위를 덮으며 들어오고(Move in / ← / Ease out / 150ms), 뒤로 가면 위에서 빠진다(Move out / →). 전환 경계는 page의 `data-ssgoi-transition`, 규칙은 `AppTransitions`다(`docs/architecture/motion.md`).
- 뒤로 가기: 기록이 있으면 `router.back()`, 직접 진입이라 없으면 번치 홈으로 `replace`. 기록 유무는 `window.history.length > 1`로만 판단한다(사진 상세와 같은 방식).
- Layout: `(app)` layout 안에서 `PageShell` 한 번. `robots: noindex`.

## 상태와 흐름

- 로딩·오류·빈 상태: 데이터가 fixture라 없다. 역할·번치 API를 연결할 때 추가한다.
- 나가기 확인 창: 「취소」·Esc는 닫기만 한다. 바깥 누름은 `ConfirmDialog` 규칙대로 무시한다.

## UI와 접근성

- Component mapping: 헤더는 `Header` + `HeaderIconButton`(subtle), 항목은 DS `MenuLabel`(Figma `Menu Label` `1873:34286`), 구분선은 `MenuDivider`, 확인 창은 `ConfirmDialog`.
- 간격: 헤더 아래 12(`pt-padding-p6`), 좌우 16(`px-padding-p8`), 항목 사이 4(`gap-s2`), 묶음과 구분선 사이 12(`gap-s6`). Figma `1873:34575` 값과 같다.
- 구조: 묶음마다 `ul`/`li`, 항목은 `button`. 헤더에 제목이 없어 화면 제목은 `sr-only` `h1`(「{번치 이름} 번치 더보기」)로 둔다.
- 확인 창 첫 초점은 「취소」(`ConfirmDialog`).

## 확인할 항목

- 권한 차이(디자인): Figma에서는 일반 멤버도 「차단 목록」을 본다. `docs/specs/bunch-home.md` 권한 표에서 다른 번치 차단·해제는 일반 멤버 불가다. 목록 보기만 허용하는지 확인한다. 지금은 Figma를 따른다.
- 새로고침·직접 진입: 서버 렌더와 첫 hydration은 저장된 번치를 몰라(`useCurrentBunchId`가 null) 메뉴 목록을 그리지 않고, 마운트 직후 역할에 맞는 메뉴를 그린다. 다른 역할의 메뉴가 잠깐 보이지는 않지만 목록이 한 프레임 늦게 나타난다. 번치·역할 API 연결 때 서버 데이터로 바꾼다.
- 나가기 뒤 기록: 들어온 길을 되돌아가 번치 탭으로 간다. 앞으로 가기 기록에는 남는다(#180, `BunchLeaveScreen.spec.md`).
