# 페이지: 번치 삭제

## 메타데이터

- Route: `/bunch/menu/delete`(안내, `apps/web/src/app/(app)/bunch/menu/delete/page.tsx`), `/bunch/menu/delete/confirm?bunch={번치 ID}`(확인 문구 입력, `.../delete/confirm/page.tsx`)
- Status: 안내, 확인 문구 입력, 삭제 뒤 이동·토스트 구현. 번치 이름·멤버와 처리는 서버(`memberships`, `deletion`). 이슈 #184, #336.
- 디자인 출처: 화면설계서 `번치 삭제하기`(`2236:41816`, 1~2-3번), Figma `번치 삭제 - 4`(`2255:43337`, 안내), `번치 삭제 - 5`(`2255:43428`, 입력 전), `번치 삭제 - 6`(`2255:43857`, 입력 뒤), 삭제 뒤(`3086:67903`).
- 기능 spec: 기능명세서 5.9, `docs/specs/bunch-home.md`.

## 목적과 범위

### 포함

- 메인 관리자만: 더보기 「번치 삭제」 또는 나만 남은 번치 안내의 「삭제하기」 → 안내(「{번치}을/를 삭제할까요?」, 삭제되는 항목, 복구 불가 경고) → 「다음」.
- 확인 문구 입력: 「삭제하기」를 정확히 입력해야 「삭제하기」 버튼이 켜진다(화면설계서 2·2-1번). 삭제할 번치 정보(번치명, 소속 멤버. 나는 맨 앞에 「(나)」).
- 삭제 뒤: 번치 탭(서버가 정한 새 기본 번치)으로 이동하고 「{번치} 번치를 삭제했어요.」 토스트(2-3번). 남은 번치가 없으면 번치 없음 화면.

### 범위 외(후속)

- 다른 멤버에게 보이는 결과(접근 불가 안내, 5.2.3)와 알림(3번): 서버 연결과 알림 목록 단위.

## 흐름과 결정

- 삭제 대상은 안내 화면에서 정해 확인 화면 주소(`?bunch=`)로 넘긴다. 확인 화면은 그 번치가 지금 기본 번치와 다르면(그사이 전환, 삭제 뒤 앞으로 가기, 주소 직접 입력) 삭제하지 않고 안내로 `replace`해 입력을 비운다.
- 안내와 확인 문구 입력은 route 두 개로 나눴다. 확인 화면의 뒤로 가기(헤더·시스템)가 안내로 돌아가고, 각 단계가 메뉴 하위 화면과 같은 slide로 들어간다.
- 삭제 뒤에는 들어온 길(번치 탭 → 메뉴 → 안내 → 확인)을 세 칸 되돌아가 삭제한 번치의 화면을 뒤로 가기 대상에서 뺀다. 기록이 모자라면(직접 진입) 번치 탭으로 `replace`한다. 확인 화면 → 번치 탭은 메뉴와 같은 `drill` 되돌아가기.
- 메인 관리자가 아니면 두 화면 모두 더보기 메뉴로 `replace`한다(접근 제어는 서버 몫). 삭제 중에는 삭제한 번치를 고정해 다음 번치의 역할로 다시 판정하지 않는다.
- 확인 문구는 화면 문구 「삭제하기」를 `confirmation`으로 보낸다(실서버 값 확인 필요).
- 실패: 「번치를 삭제하지 못했어요」 토스트 뒤 멤버 관리 목록을 다시 받는다. 처리 중 다시 제출해도 한 번만 보낸다(2-2번).
- 처음부터 목록을 못 받으면 뒤로 가기가 있는 다시 시도 화면, 번치가 없으면 번치 탭으로 간다.
- 제목의 조사는 번치 이름의 마지막 글자 받침으로 「을」·「를」을 고른다(한글이 아니면 「를」).
- 확인 문구 입력은 form이라 Enter로도 삭제한다(문구가 맞을 때만). 화면이 빠지는 동안 다시 제출(Enter 반복·연타)해도 한 번만 삭제하고, 빠지는 화면은 다음 번치가 아니라 삭제한 번치를 그대로 그린다.

## UI와 접근성

- Component mapping: `Header`(뒤로 가기), `PageHeader`, `LabeledTextField`(「확인 문구 입력」), `Button`(하단, `PageShell` bottom, 확인 화면은 form 제출 버튼).
- 확인 문구 안내(「`*‘삭제하기’를 정확히 입력하면…`」)는 오류가 아니라 늘 보이는 안내라 `errorMessage`가 아니라 `aria-describedby`로 입력창에 연결한다(`aria-invalid` 없음). 앞의 「`*`」와 번치 정보의 「`:`」는 낭독에서 빼려고 장식(`aria-hidden`, CSS)으로 붙인다.
- 삭제할 번치 정보는 `dl`(번치명, 소속 멤버), 삭제되는 항목은 `ul`.
- 간격: 안내(`2255:43337`) 제목 아래 20(Figma 21, 토큰 없음), 항목 상자 p16·r10, 상자 사이 12, 경고 상자 테두리 r8(Figma 7, 토큰 없음)·py10(Figma 11). 확인(`2255:43857`) 제목 영역 아래 32, 입력 묶음과 번치 정보 사이 36, 번치 정보 pt12·pb16·px16·r10.

## 확인할 항목

- 나만 남은 번치 안내의 「삭제하기」 → 안내 화면 이동은 화면으로 확인하지 못했다. 테스트는 메뉴 화면이 콜백을 부르는 데까지다.
- 돌아갈 기록은 `history.length`로만 판단한다. 확인 화면에 바로 들어온 뒤 이전 방문 기록이 셋보다 많으면 `go(-3)`이 번치 탭이 아닌 곳으로 갈 수 있다(나가기의 `go(-2)`와 같은 한계).
- `PageHeader`의 제목·설명 사이가 4로, Figma 확인 화면(6)과 다르다. 디자인 시스템 컴포넌트 기준이라 이 화면에서 바꾸지 않았다.
- 확인 화면 URL로 바로 들어오면 안내를 거치지 않는다. 대상 번치가 지금 번치와 같을 때만 문구 입력과 메인 관리자 가드를 거쳐 삭제한다.
- 한글 입력 조합 중 Enter가 바로 제출되는지는 실기기에서 확인하지 않았다.
- 제목 조사는 영문·숫자로 끝나는 이름에 늘 「를」을 쓴다.
- 확인 화면의 소속 멤버 순서: Figma는 나 다음 임의 순서, 지금은 나 다음 멤버 목록 순서.
