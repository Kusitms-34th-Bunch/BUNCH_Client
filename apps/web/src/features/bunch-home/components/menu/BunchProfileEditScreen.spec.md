# 페이지: 번치 프로필 편집

## 메타데이터

- Route: `/bunch/menu/profile`(`apps/web/src/app/(app)/bunch/menu/profile/page.tsx`)
- Status: 사진·이름·한 줄 소개·공개 범위 편집과 저장 UI(#172). 서버 프로필·저장·이름 중복 확인 연결(#327).
- 디자인 출처: Figma `번치 - 상세` 섹션의 `번치 프로필 편집 (기본)`(`1873:33493`), `(수정사항 예시)-1`(`1873:33513`, 공개 전환 안내), `(수정사항 예시)-2`(`1873:33533`, 저장 토스트). 화면설계서 `프로필 편집`(`2145:39607`, 1~6번).
- 기능 spec: 기능명세서 5.5(1110판, 2026-11-10 기준), `docs/specs/bunch-home.md`.

## 목적과 범위

### 포함

- 메인 관리자가 번치 대표 사진, 이름(1자 이상 12자 이하), 한 줄 소개(1자 이상 50자 이하), 공개 범위를 바꾸고 「저장하기」로 한 번에 저장한다.
- 비공개였던 번치를 공개로 바꾸면 공개 카드 아래에 「*팔로워에게만 공개되던 번들을 누구나 볼 수 있게 되며, 대기 중인 팔로우 요청은 모두 승인돼요.」를 보여 준다.
- 저장하면 바로 바뀐 값이 반영된 번치 메인탭으로 돌아가고(6-2, `replace`), 메인탭에서 「번치 프로필을 수정했어요.」 토스트를 띄운다. 설계서 6-1은 편집 화면 위 토스트지만 메인탭에서 띄우기로 했다(사용자 결정). 1110판 5.5.5 상세 동작 3도 번치 메인으로 돌아가 토스트를 띄운다.
- 빈 영역이나 「저장하기」를 누르면 키보드를 닫고, 다른 입력을 누르면 키보드를 유지한 채 포커스만 옮긴다(4번, `shared/lib/keyboard.ts`).

### 범위 외(후속)

- 더보기 메뉴의 「프로필 편집」 링크는 아직 fixture 역할로 보인다(메뉴 API 연결 때 서버 권한으로 바꿈). 편집 화면 자체는 서버 권한으로 막는다.
- 사진 접근 권한 거부 창(1110판 5.5.2)은 아직 없다.

## Route와 접근

- Path: `/bunch/menu/profile`. params·search 없음. 탭 경로 밖이라 iOS 앱에서는 시스템 탭 바가 숨는다(결정 기록 012).
- 진입: 더보기 메뉴의 「프로필 편집」 링크(`MenuLabel`의 `renderLink`, 메인 관리자에게만 보임). 메뉴 ↔ 편집은 미는 slide 300ms ease-out(새 화면은 오른쪽에서, 메뉴는 왼쪽으로 밀림). 화면설계서에 정의가 없어 한 단계 들어가는 이동으로 보고 정함(2026-11-01, 시간은 디자이너 요청).
- 접근: 내 기본 번치(`members/me`)의 번치 홈(`GET /bunches/{id}/home`)을 받아 `permissions.canEditProfile`이 아니면 더보기 메뉴로, 기본 번치가 없으면 번치 탭으로 `replace`한다. 화면 가드일 뿐이고 서버가 저장 시점의 권한으로 다시 판단한다.
- 뒤로 가기: 기록이 있으면 `router.back()`, 없으면 더보기 메뉴로 `replace`.
- 번치 홈은 저장해 둔 값(앱 다시 열기)이 있어도 서버에서 다시 받은 뒤에 폼을 연다(`staleTime: 0`). 받는 동안과 다른 화면으로 보내는 동안은 로딩(`PageLoading`, sr-only 「번치 프로필을 불러오는 중이에요」)을 보인다. 그래서 메뉴에서 들어올 때마다 한 번 왕복하는 동안 로딩이 보인다. 다시 받기가 실패하면(오프라인) 저장해 둔 값과 그 버전으로 열리고, 다른 곳에서 바뀌었으면 저장할 때 충돌 경로로 최신 값으로 다시 연다.
- 받은 값이 하나도 없을 때만 번치 홈과 같은 오류 화면과 「다시 시도」를 보인다. 응답에 프로필 버전이 없으면 저장할 수 없으므로 폼 대신 같은 오류 화면을 보인다. 열린 폼은 다시 받기가 실패해도 바꾸지 않는다(입력 유지).
- 폼은 연 순간의 값과 버전으로 고정한다. 그 뒤 다시 받은 값이 바뀌어도 입력·변경 판단·저장 버전은 그대로다.

## 상태와 흐름

| 입력·상태      | 규칙                                                                                                                                                                                                                                                                             |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 번치 이름      | 최대 12자(카운터), 영문·숫자·완성형 한글만. 조합 중에는 자모 허용. 위반 시 「특수문자를 제외한 영문, 한글만 사용할 수 있어요.」                                                                                                                                                  |
| 한 줄 소개     | 최대 50자(카운터), 공백만이면 저장 불가                                                                                                                                                                                                                                          |
| 대표 사진      | `ProfilePhotoField`(번치 만들기 완료와 같음): 고르기 → 원형 조정(정사각 JPEG 512px) → 미리보기. 사진이 있으면 「기본 이미지 적용하기」도 고른다. 서버 저장은 「저장하기」에서 함께 한다                                                                                          |
| 번치 이름 중복 | 지금 이름과 다르고 규칙에 맞으면 입력을 멈추고 0.5초 뒤 `GET /bunches/name-availability?excludeBunchId=`로 확인한다. 확인 중에는 「사용 가능한 이름인지 확인 중이에요.」, 사용 중이면 「이미 사용 중인 번치 이름이에요」. 확인에 실패하면 막지 않고 저장 때 서버가 다시 확인한다 |
| 저장하기 활성  | 저장된 값과 하나라도 다르고, 이름이 1자 이상·규칙에 맞고·사용 중이 아니고·확인 중이 아니며, 소개가 비어 있지 않고, 한글 조합 중이 아니고, 저장 중이 아니고, 고른 사진을 읽거나 조정하는 중이 아닐 때                                                                             |

- 이름 규칙·글자 수·중복 문구는 번치 만들기와 같아 `shared/lib/bunchProfile.ts`에, 중복 확인 호출은 `shared/api/bunchNameAvailability.ts`에 둔다.
- 저장(#327): `PUT /bunches/{id}/profile` 한 번으로 이름·소개·공개 범위·대표 사진을 함께 저장한다(multipart `profile` JSON + 새 사진이면 `photo`, `imageAction` KEEP·REPLACE·RESET, `Idempotency-Key`). 이미지 전용 API(`PUT·DELETE …/profile-image`)는 쓰지 않는다. 버전 확인과 한 번에 묶기 위해서다. `expectedProfileVersion`은 받은 번치 홈의 `profileVersion`이다.
- 저장 성공: 번치 홈(프로필·번들)·내 프로필·전환 목록을 무효화하고 번치 홈을 다시 받은 뒤 메인탭으로 이동한다. 이동한 화면에 새 값이 바로 보인다.
- 저장 실패: 이름 중복(409 `BUNCH_001`)이면 그 이름을 입력란에 사용 중으로 보이고 머문다(이름을 바꾸면 다시 확인). 그 밖의 실패는 번치 홈을 다시 받아 판단한다. 다시 받은 버전이 폼을 연 때와 다르면(다른 곳에서 저장) 폼을 최신 값으로 다시 열고 「다른 곳에서 프로필이 바뀌어 최신 내용으로 다시 불러왔어요.」를 띄운다. 모르고 덮어쓰지 않도록 저장은 항상 폼을 연 때의 버전으로 보낸다. 버전이 같으면 「번치 프로필을 저장하지 못했어요. 잠시 후 다시 시도해 주세요.」를 띄우고 입력을 유지한다. 권한을 잃었으면 다시 받은 값으로 메뉴로 돌아간다.
- 저장 토스트는 성공 체크 아이콘과 함께 번치 탭에서 뜬다(`icon: 'success'`). 저장하면 번치 탭으로 이동하므로 `toastAfterNavigation()`으로 예약해 도착 화면의 전환·로딩이 끝난 뒤 탭 막대 위 16px에 띄운다(`Toast.spec.md`).

## UI와 접근성

- Component mapping: 헤더 `Header` + `HeaderIconButton`(subtle), 사진 `ProfileImage`(L 90) + `CameraButton`, 입력 `LabeledTextField`, 공개 범위 `fieldset`/`legend` + `DescriptionRadioCard`, 하단 `Button`(`PageShell` bottom, `form` 속성으로 폼 제출).
- 간격(Figma `1873:33494`): 헤더 아래 32, 사진과 입력 사이 32, 입력 사이 16, 「공개 범위」 아래 12, 카드 사이 10, 안내는 공개 카드 아래 4.
- 헤더에 제목이 없어 `sr-only` `h1`(「번치 프로필 편집」)을 둔다.
- 공개 전환 안내는 화면설계서 5-1(On Click / Smart Animate / Ease out, 설계서 300ms를 디자이너 요청으로 150ms)대로 높이·투명도가 150ms CSS ease-out으로 펼쳐지고 아래 「비공개」 카드도 함께 내려간다. 닫힐 때는 반대로 접힌다. 동작 줄이기에서는 즉시 바뀐다. 화면용 문구는 항상 DOM에 있어(`aria-hidden`) 낭독용 sr-only `role="status"`에 공개를 고르는 순간 문구를 넣어 읽힌다. 사진 선택 결과(`usePhotoPicker`의 `message`)도 sr-only status로 알린다.

## 확인할 항목

- 버전 충돌 오류 코드: Swagger에 없어 `BUNCH_001` 밖의 실패를 하나로 다룬다. 서버가 코드를 정하면 「다른 곳에서 수정됐어요」처럼 따로 안내할지 정한다.
- 저장 실패·충돌 문구: 기획 원문이 없어 정했다(`BUNCH_HOME_MESSAGES.profileSaveFailed`·`profileChangedElsewhere`).
- 저장 토스트 위치: 저장하면 바로 메인탭으로 이동해 번치 전환 토스트와 같은 자리(「+」와 같은 높이)에 띄운다. 이동 뒤 위치는 화면으로 재지 않았고(미검증), iOS 쉘에서는 웹 탭 막대 기준 고정값이라 더 높이 뜬다.
- 저장하지 않고 나가기: 변경 중 뒤로 가기·새로고침에도 확인 없이 나간다. 화면설계서에 확인 창 정의가 없어 두지 않았다.
- 메뉴 ↔ 편집 전환: 화면설계서에 정의가 없어 미는 slide로 정했고 시간은 디자이너 요청대로 300ms다. 규칙은 메뉴 ↔ 편집 한 쌍이라, 번치 홈과 편집 사이를 바로 오가면(새로고침 뒤 뒤로 가기 등) 전환이 없다.
- 저장 뒤 초점: 메인탭으로 이동하면 초점이 문서 처음으로 돌아간다. 화면 이동 때 초점을 어디에 둘지는 앱 전체에 정해진 규칙이 없어 이 화면에서만 따로 처리하지 않았다.
- 저장 뒤 기록: `replace`라 기록이 번치 홈 → 메뉴 → 번치 홈이 되어, 메인탭에서 뒤로 가면 메뉴가 나온다.
- 저장하기 비활성 이유: 이름·소개가 비었을 때는 오류 문구 없이 버튼만 비활성이다(디자인에 문구 없음).
- 사진 실패 안내: 실패하면 토스트(「이 사진은 사용할 수 없어요.」)와 status 문구(`usePhotoPicker`의 형식·용량 안내)가 함께 나와 두 번 읽힐 수 있다.
- 1110판 5.5.2: 「기본 이미지 적용」은 번치를 만들 때 고른 분위기(2.2.9)의 기본 이미지로 바꾼다. 지금 기본 이미지면 이 항목을 숨긴다. 저장하면 번치 메인 프로필 이미지(5.1.3)와 이미지를 쓰는 모든 곳에 보인다.
- 1110판 5.5.2: 사진 접근 권한을 거부했으면 「사진 접근 권한이 필요해요」 / 「앨범에서 사진을 고르려면 설정에서 사진 접근을 허용해 주세요.」, 「취소」/「설정으로 이동」 창을 띄운다. 구현은 아직 권한 거부 창이 없다(`usePhotoPicker` 안내 문구만).
- 1110판 5.5.4: 번들 공개 범위 이름이 「공개 / 멤버 공개」다(이전 「비공개」). 공개 전환 안내 문구에는 영향이 없다.
- 1110판은 관리자 권한을 잃은 뒤 저장할 때의 예외(5.5.1·5.5.5)를 뺐다. 지금은 실패 토스트를 띄우고 번치 홈을 다시 받아, 권한이 없으면 메뉴로 돌아간다.
