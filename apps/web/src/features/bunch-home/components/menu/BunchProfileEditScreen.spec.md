# 페이지: 번치 프로필 편집

## 메타데이터

- Route: `/bunch/menu/profile`(`apps/web/src/app/(app)/bunch/menu/profile/page.tsx`)
- Status: 사진·이름·한 줄 소개·공개 범위 편집과 저장 UI 구현. 데이터와 저장은 fixture다. 이슈 #172.
- 디자인 출처: Figma `번치 - 상세` 섹션의 `번치 프로필 편집 (기본)`(`1873:33493`), `(수정사항 예시)-1`(`1873:33513`, 공개 전환 안내), `(수정사항 예시)-2`(`1873:33533`, 저장 토스트). 화면설계서 `프로필 편집`(`2145:39607`, 1~6번).
- 기능 spec: 기능명세서 5.5, `docs/specs/bunch-home.md`.

## 목적과 범위

### 포함

- 메인 관리자가 번치 대표 사진, 이름(1자 이상 12자 이하), 한 줄 소개(1자 이상 50자 이하), 공개 범위를 바꾸고 「저장하기」로 한 번에 저장한다.
- 비공개였던 번치를 공개로 바꾸면 공개 카드 아래에 「*팔로워에게만 공개되던 번들을 누구나 볼 수 있게 되며, 대기 중인 팔로우 요청은 모두 승인돼요.」를 보여 준다.
- 저장하면 바로 바뀐 값이 반영된 번치 메인탭으로 돌아가고(6-2, `replace`), 메인탭에서 「번치 프로필을 수정했어요.」 토스트를 띄운다. 설계서 6-1은 편집 화면 위 토스트지만 메인탭에서 띄우기로 했다(사용자 결정).
- 빈 영역이나 「저장하기」를 누르면 키보드를 닫고, 다른 입력을 누르면 키보드를 유지한 채 포커스만 옮긴다(4번, `shared/lib/keyboard.ts`).

### 범위 외(후속)

- 서버 저장, 번치 이름 중복 확인, 사진 업로드: 번치 API 연결 때 한다. 지금 저장 값은 메모리 저장소(`useBunchProfileEdits`)에 두어 번치 홈·전환 목록에 반영하고, 새로고침하면 사라진다.
- 저장 실패 토스트와 재시도: API 연결 때 한다.

## Route와 접근

- Path: `/bunch/menu/profile`. params·search 없음. 탭 경로 밖이라 iOS 앱에서는 시스템 탭 바가 숨는다(결정 기록 012).
- 진입: 더보기 메뉴의 「프로필 편집」 링크(`MenuLabel`의 `renderLink`, 메인 관리자에게만 보임). 메뉴 ↔ 편집은 미는 slide 300ms ease-out(새 화면은 오른쪽에서, 메뉴는 왼쪽으로 밀림). 화면설계서에 정의가 없어 한 단계 들어가는 이동으로 보고 정함(2026-11-01, 시간은 디자이너 요청).
- 접근: 번치 홈에서 고른 fixture 번치(`useCurrentBunchId`)의 역할이 메인 관리자가 아니면 더보기 메뉴로 `replace`한다. 접근 제어가 아니라 API 연결 전의 임시 UX 가드다. 서버가 요청 시점의 역할로 다시 판단해야 한다.
- 뒤로 가기: 기록이 있으면 `router.back()`, 없으면 더보기 메뉴로 `replace`.
- 첫 hydration은 저장된 번치를 몰라 폼을 그리지 않고, 마운트 직후 그 번치 값으로 채운다.

## 상태와 흐름

| 입력·상태     | 규칙                                                                                                                            |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 번치 이름     | 최대 12자(카운터), 영문·숫자·완성형 한글만. 조합 중에는 자모 허용. 위반 시 「특수문자를 제외한 영문, 한글만 사용할 수 있어요.」 |
| 한 줄 소개    | 최대 50자(카운터), 공백만이면 저장 불가                                                                                         |
| 대표 사진     | `usePhotoPicker`(네이티브 갤러리 또는 웹 파일). 쓸 수 없는 사진은 「이 사진은 사용할 수 없어요.」 토스트                        |
| 저장하기 활성 | 저장된 값과 하나라도 다르고, 이름이 1자 이상·규칙에 맞고, 소개가 비어 있지 않고, 한글 조합 중이 아닐 때                         |

- 이름 규칙과 글자 수는 번치 만들기와 같아 `shared/lib/bunchProfile.ts`에 둔다.
- 저장 토스트는 성공 체크 아이콘과 함께 메인탭의 「+」 옆 높이에 뜬다(`icon: 'success'`, `fullWidth`, 번치 전환 토스트와 같은 `BUNCH_HOME_TOAST_OFFSET`).

## UI와 접근성

- Component mapping: 헤더 `Header` + `HeaderIconButton`(subtle), 사진 `ProfileImage`(L 90) + `CameraButton`, 입력 `LabeledTextField`, 공개 범위 `fieldset`/`legend` + `DescriptionRadioCard`, 하단 `Button`(`PageShell` bottom, `form` 속성으로 폼 제출).
- 간격(Figma `1873:33494`): 헤더 아래 32, 사진과 입력 사이 32, 입력 사이 16, 「공개 범위」 아래 12, 카드 사이 10, 안내는 공개 카드 아래 4.
- 헤더에 제목이 없어 `sr-only` `h1`(「번치 프로필 편집」)을 둔다.
- 공개 전환 안내는 화면설계서 5-1(On Click / Smart Animate / Ease out, 설계서 300ms를 디자이너 요청으로 150ms)대로 높이·투명도가 150ms CSS ease-out으로 펼쳐지고 아래 「비공개」 카드도 함께 내려간다. 닫힐 때는 반대로 접힌다. 동작 줄이기에서는 즉시 바뀐다. 화면용 문구는 항상 DOM에 있어(`aria-hidden`) 낭독용 sr-only `role="status"`에 공개를 고르는 순간 문구를 넣어 읽힌다. 사진 선택 결과(`usePhotoPicker`의 `message`)도 sr-only status로 알린다.

## 확인할 항목

- 저장 토스트 위치: 저장하면 바로 메인탭으로 이동해 번치 전환 토스트와 같은 자리(「+」와 같은 높이)에 띄운다. 이동 뒤 위치는 화면으로 재지 않았고(미검증), iOS 쉘에서는 웹 탭 막대 기준 고정값이라 더 높이 뜬다.
- 저장하지 않고 나가기: 변경 중 뒤로 가기·새로고침에도 확인 없이 나간다. 화면설계서에 확인 창 정의가 없어 두지 않았다.
- 메뉴 ↔ 편집 전환: 화면설계서에 정의가 없어 미는 slide로 정했고 시간은 디자이너 요청대로 300ms다. 규칙은 메뉴 ↔ 편집 한 쌍이라, 번치 홈과 편집 사이를 바로 오가면(새로고침 뒤 뒤로 가기 등) 전환이 없다.
- 저장 뒤 초점: 메인탭으로 이동하면 초점이 문서 처음으로 돌아간다. 화면 이동 때 초점을 어디에 둘지는 앱 전체에 정해진 규칙이 없어 이 화면에서만 따로 처리하지 않았다.
- 저장 뒤 기록: `replace`라 기록이 번치 홈 → 메뉴 → 번치 홈이 되어, 메인탭에서 뒤로 가면 메뉴가 나온다.
- 저장하기 비활성 이유: 이름·소개가 비었을 때는 오류 문구 없이 버튼만 비활성이다(디자인에 문구 없음).
- 사진 실패 안내: 실패하면 토스트(「이 사진은 사용할 수 없어요.」)와 status 문구(`usePhotoPicker`의 형식·용량 안내)가 함께 나와 두 번 읽힐 수 있다.
