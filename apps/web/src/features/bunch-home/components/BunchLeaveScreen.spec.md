## 목적과 범위

### 포함

- 일반 멤버·공동 관리자: 더보기 「번치 나가기」 → 확인 창 → 남은 첫 번치의 번치 탭으로 이동, 「{번치} 번치를 나왔어요.」 토스트(4·4-1번).
- 메인 관리자: 「번치 나가기」 → `/bunch/menu/leave`에서 나를 뺀 멤버 한 명을 고름(처음엔 「관리자로 지정하기」 비활성) → 확인 시트 「지정하고 나가기」 → 번치 탭, 「{이름}님을 관리자로 지정하고 나갔어요.」 토스트(1~2-4번).
- 나만 남은 번치: 「혼자 있는 번치는 나갈 수 없어요」 / 「더 이상 사용하지 않는 번치는 삭제할 수 있어요.」(4-2번). 「삭제하기」는 번치 삭제 안내(`/bunch/menu/delete`, #184)로 간다.
- 나간 뒤 남은 번치가 없으면 번치 탭에 번치 없음 화면(「참여 중인 번치가 없어요」, 「새 번치 만들기」 → `/onboarding/create`, 「초대 링크 참여하기」 → `/onboarding/join`, 2-5번, 사용자 결정으로 이번에 포함).

### 범위 외(후속)

- 서버 처리와 실패: 나가기 API 연결 때 한다. 지금은 나간 번치를 메모리 저장소(`useLeftBunches`)에 두어 번치 탭·전환 목록에서 빼고, 새로고침하면 fixture로 돌아간다.
- 고른 멤버가 그사이 나간 경우의 오류 토스트와 목록 갱신(3~3-2번): 서버 응답이 있어야 해서 API 연결 때 한다.
- 안내 그림(확인 시트·번치 없음): 최종본 전달 전 회색 자리표시.

## 흐름과 결정

- 나간 뒤 이동할 번치는 전환 목록의 접근 가능 번치 중 첫 번째다. 보고 있던 번치를 나가면 저장된 현재 번치도 그 번치로 바꾼다.
- 지정 화면의 멤버는 Figma처럼 이름순이다(멤버 관리의 역할순과 다름).
- 확인 시트 안내 상자는 디자인 시스템 컴포넌트(Figma Bottom Sheet 05) 문구 「함께 남긴 사진과 발행된 번들은 번치에 그대로 남아요.」를 쓴다. 화면설계서 2-3번은 「올린 사진은 사진함에서만 삭제돼요.」라 다르다(확인할 항목).
- 나간 뒤 토스트는 Figma(`3086:68263`)처럼 아이콘 없이 메인탭의 「+」 높이(`BUNCH_HOME_TOAST_OFFSET`)에 띄운다.
- 더보기 메뉴는 멤버를 알기 전에는 항목을 그리지 않는다(나만 남은 번치 판정이 늦어 다른 나가기 흐름으로 가지 않게).
- 지정 화면은 메인 관리자가 아니거나 나만 남았으면 더보기 메뉴로 `replace`한다(API 전 임시 가드). 나가는 중에는 다음 번치의 역할로 다시 판정돼 메뉴로 덮어쓰지 않게 가드를 멈춘다.

## Route와 접근

- 진입: 더보기 메뉴 「번치 나가기」(메인 관리자). 메뉴 ↔ 지정 화면은 메뉴 하위 화면과 같은 미는 slide 300ms. 탭 경로 밖이라 iOS 앱에서는 시스템 탭 바가 숨는다.
- 뒤로 가기: 기록이 있으면 `router.back()`, 없으면 더보기 메뉴로 `replace`.
- 나간 뒤 기록: 들어온 길을 되돌아가 나간 번치의 화면을 뒤로 가기 대상에서 뺀다(앞으로 가기 기록에는 남는다). 일반 멤버·공동 관리자는 메뉴에서 한 칸(`router.back()`), 메인 관리자는 지정 화면에서 두 칸(`history.go(-2)`) 뒤로 번치 탭에 간다. 돌아갈 기록이 모자라면(직접 진입) 번치 탭으로 `replace`한다. 뒤로 가는 이동이라 메뉴가 빠지는 Move out 전환이 재생된다.
- 나간 번치: 현재 번치 저장소(`useCurrentBunchId`)가 나간 번치를 가리키면 남은 첫 번치를, 없으면 `null`을 돌려준다. 메뉴·프로필 편집·멤버 관리·차단 목록도 나간 번치를 다시 그리지 않는다.
- 번치 없음은 탭 화면(`/bunch`)이라 탭 바가 보이고, 헤더·「+」는 없다(기능명세 5.1.7).

## 확인할 항목

- 확인 시트 안내 문구: 디자인 시스템(Bottom Sheet 05)과 화면설계서 2-3번 중 어느 쪽이 최종인지.
- 화면설계서의 번치 없음(`2236:41002`)에는 헤더 「번치 선택」이 있고, Figma `1892:36523`과 기능명세 5.1.7은 헤더가 없다. 지금은 헤더 없음.
- 모두 나간 뒤 앞으로 가기로 메뉴·하위 화면에 가면 빈 화면이 남는다. 현재 번치 `null`이 「hydration 대기」와 「번치 없음」을 함께 뜻하기 때문이다(뒤로 가기는 된다). 임시 저장소라 API 연결 때 서버 목록으로 바꾸며 구분한다.
- 돌아갈 기록은 `history.length`로만 판단한다. 다른 사이트에서 같은 탭으로 메뉴에 바로 들어와 나가면 뒤로 가기가 앱 밖으로 나가 토스트가 보이지 않는다(다른 뒤로 가기와 같은 한계).
- 나간 직후 이동이 끝나기 전 메뉴·지정 화면이 다음 번치 기준으로 한 번 다시 그려질 수 있다(화면 미확인).
- 나간 뒤 남은 번치가 없을 때의 토스트 위치: 번치 없음 화면에는 「+」가 없지만 같은 높이에 띄운다.
- 나간 뒤 초점: 번치 탭으로 돌아가면 초점이 문서 처음(body)으로 간다. 앱의 다른 화면 이동과 같아 이 흐름만 따로 옮기지 않았다. 「화면 이동 뒤 새 화면의 `h1`으로 초점」 공통 규칙을 별도 이슈로 정하면 함께 적용된다. 결과는 토스트(알림 영역)로 읽힌다(스크린 리더 미검증).
