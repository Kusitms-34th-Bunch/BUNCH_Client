# 페이지: 다른 번치 프로필과 팔로우

## 메타데이터

- Route: `/bunches/[bunchId]`(프로필, `apps/web/src/app/(app)/bunches/[bunchId]/page.tsx`), `/bunches/[bunchId]/members`(멤버 목록)
- Status: 공개·비공개 프로필, 팔로우·팔로우 요청·팔로우 취소·요청 취소 시트, 멤버 목록 구현. 데이터와 팔로우 처리는 fixture·메모리다. 이슈 #189.
- 디자인 출처: 화면설계서 `번치 팔로우`(`2500:68583` 1~4번, `2500:71333` 4번 멤버 리스트), Figma 공개 `3086:68423`(팔로우)·`3086:68534`(팔로잉), 비공개 `3086:68654`(팔로우)·`3086:68758`(요청됨), 시트 `3086:70741`(팔로우 취소)·`3213:76818`(요청 취소).
- 기능 spec: 기능명세서 5.10, `docs/specs/bunch-home.md`.

## 목적과 범위

### 포함

- 공개 번치: 팔로우 전에도 번들을 보여 준다. 「팔로우」 → 바로 「팔로잉」, 팔로워 수 +1(1번).
- 비공개 번치: 팔로우 중이 아니면 번들 대신 「비공개 번치예요 / 번들을 보려면 이 번치를 팔로우하세요.」. 「팔로우」 → 「팔로우 요청됨」(승인 전이라 계속 가림, 2번).
- 「팔로잉」 → 팔로우 취소 시트(상대 번치 이미지·이름·「공개 번치」/「비공개 번치」, 3번), 「팔로우 요청됨」 → 요청 취소 시트(「요청 대기 중인 비공개 번치」, 4번). 「취소」는 상태 유지.
- 멤버 수 → 그 번치의 멤버 목록(확인용, 관리 동작 없음, 역할은 이미지 배지). 팔로워·팔로잉 수 → 그 번치의 팔로워·팔로잉 목록(#192, `BunchFollowsScreen.spec.md`).
- 입구: 피드 탭의 임시 링크(공개 캠핑러버, 비공개 책방산책).

### 범위 외(후속)

- 더보기(차단·신고)와 차단된 번치 화면: 9번 단위.
- 서버 처리, 실패, 연타 방지, 상대가 요청을 승인했을 때의 갱신: 팔로우 API 연결 때. 지금은 팔로우 상태를 메모리 저장소(`useBunchFollow`)에 둔다.
- 피드의 번치 이름 입구: 피드 화면이 생기면 임시 링크를 대체한다.

## 흐름과 결정

- 팔로우 명의는 지금 번치(번치 전환 기준)다. 다만 지금의 메모리 저장소는 상대 번치 id만 구분해, 번치를 바꿔도 팔로우 상태가 그대로 보인다(API 연결 때 반영). 팔로워 수는 처음 상태와 비교해 내 번치 한 명만큼만 더하거나 뺀다.
- 시트 문구는 시트를 연 순간의 상태로 고정한다(취소한 뒤 닫히는 동안 바뀌지 않게).
- 팔로우·요청·취소 결과는 버튼 이름 변화와 함께 늘 마운트된 상태 영역(`role="status"`)이 「{번치} 번치를 팔로우했어요.」 등으로 알린다.
- 시트 제목은 보이는 번치 이름 뒤에 숨은 질문(「팔로우를 취소할까요?」·「팔로우 요청을 취소할까요?」)을 붙여, 「취소」와 실행 버튼만으로 확인 내용을 알 수 없는 문제를 막는다.
- 시트는 Figma Bottom Sheet 05 모양이지만 디자인 시스템 `AdminTransferSheet`는 관리자 지정 문구가 고정이라, 같은 `BottomSheet` 부품으로 화면 쪽(`FollowCancelSheet`)에서 조립했다.
- 프로필 영역은 번치 홈의 `BunchProfile`을 재사용하고 「가볼 곳」은 숨긴다(Figma `3086:68423`에 없음). 버튼이 없어도 수치 줄 높이 32를 지켜 Figma와 위치를 맞췄다.
- 없는 번치 id는 404(`notFound`). 루트 `app/not-found.tsx`가 앱 틀 안에서 안내와 「번치 탭으로 가기」를 보여 준다(없는 주소의 404도 같이 씀).
- 전환: 피드 → 프로필 → 멤버 목록, 프로필 헤더 알림 → 알림 목록은 `drill`(`docs/architecture/motion.md`). 뒤로 가기는 기록이 없으면 프로필은 피드, 멤버 목록은 프로필로 `replace`.

## UI와 접근성

- Component mapping: `Header`(뒤로 가기, 알림 링크), `BunchProfile`(h1 번치 이름, 비공개 자물쇠 숨은 글자), `FollowButton`(`follow`·`following`·`requested`, 시트를 여는 상태는 `aria-haspopup="dialog"`), `CompletedBundleGrid`(「번들」 영역), `FollowCancelSheet`(`BottomSheet`), 멤버 목록 `ProfileListItem`.
- 비공개 안내 상자는 제목(h2)을 이름으로 하는 영역이다. 멤버 수 링크는 터치 영역을 사방 8px 넓혔다.
- 비공개 안내 상자(`3086:68654`): 회색 r12, 위아래 40·좌우 16, 자물쇠 원 40(`surface-tertiary`)과 글자 사이 20, 제목 body-1-medium, 설명 body-4-regular.
- 멤버 목록은 보이는 제목이 없어 sr-only `h1`(「{번치} 멤버」).

## 확인할 항목

- Figma의 다른 번치 화면에는 하단 탭 막대와 「+」가 있다. spec 기준(1~9번 단위는 탭 경로 밖)에 따라 탭 막대 없이 두었고, 「+」(번들 만들기)는 다른 번치에서 쓸 수 없어 뺐다.
- 헤더 알림은 내 번치의 알림 목록으로 간다. 더보기(⋯)는 차단·신고 단위에서 붙인다.
- 시트 그림 자리는 Figma가 회색 원이지만 화면설계서(3·4번)대로 상대 번치 대표 이미지를 넣었다(92px).
- 멤버 수 링크는 다른 수치와 겉모습이 같아 링크라는 시각 단서가 없다(Figma 기준이라 그대로, 디자이너 확인).
- 시트를 닫은 뒤 초점이 팔로우 버튼으로 돌아오는지, 멤버 역할 배지가 낭독되는지는 스크린 리더로 확인하지 않았다.
- 시트 두 프레임(`3086:70741`, `3213:76818`)의 배경은 내 번치 화면이 섞인 것으로 보여 시트 모양만 따랐다.
