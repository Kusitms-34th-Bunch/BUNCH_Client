# 페이지: 번치 알림 목록

## 메타데이터

- Route: `/bunch/notifications`(`apps/web/src/app/(app)/bunch/notifications/page.tsx`)
- Status: 목록, 읽지 않음 표시, 누르면 읽음, 「모두 읽음」, 알림 받기 설정 안내 줄 구현(#186). 목록·열기·모두 읽음을 서버에 연결(#352).
- 디자인 출처: Figma `알림`(`1892:36947`), 화면설계서 `번치 삭제하기`(`2236:41816`) 3·3-1번(알림 아이콘, 알림 헤더), 알림 카드는 디자인 시스템 `NotificationCard`(`Alert_Label`).
- 기능 spec: 기능명세서 5.12(1110판, 2026-11-10 기준), `docs/specs/bunch-home.md`.

## 목적과 범위

### 포함

- 번치 탭 헤더 「알림」(링크) → 지금 번치의 알림 목록(최신순). 읽지 않은 알림은 시각 뒤 빨간 점과 숨은 글자 「읽지 않음」.
- 지금 번치는 `members/me` 기본 번치다. 목록은 첫 쪽 50개(`GET /bunches/{id}/notifications`), 제목·내용은 서버 `title`·`body`, 시각은 피드와 같은 경과 시간 글자다.
- 알림을 누르면 열기(`POST …/{notificationId}/open`)로 읽음이 되고 응답의 `target.kind`에 맞는 화면으로 간다. 갈 화면이 사라졌으면(`available=false`) 이동하지 않고 「더 이상 볼 수 없는 알림이에요.」(명세에 없어 제안). 연달아 눌러도 한 번만 연다.
- 「모두 읽음」(`POST …/read-all`)은 지금 번치의 알림만 읽음으로 바꾼다(화면설계서 3-1번). 읽을 알림이 없으면 요청하지 않는다. 실패하면 「알림을 읽음으로 바꾸지 못했어요.」 토스트이고 결과 낭독은 하지 않는다.
- 읽음이 바뀌면 목록과 번치 홈·전환 목록(「알림 N개」)을 다시 받는다.
- 맨 위 「알림 받기를 설정하고 유용한 알림을 받아보세요.」 안내 줄.

### 범위 외(후속)

- 이동 화면 중 「작성 중인 번들」 탭(`DRAFT_LIST`)·추천 번들 시트(`CANDIDATES`)·접근 불가 안내(`ACCESS_NOTICE`)는 바로 여는 주소가 없어 번치 홈·번들 만들기 시작으로 보낸다.
- 더 불러오기(51번째 알림부터).
- 안내 줄 → 알림 설정 화면(MY): 화면이 생기면 연결. 지금은 누를 수 없는 안내 문장이다(화살표는 장식).
- 헤더 알림 아이콘의 안 읽은 점(화면설계서 3번): 번치 메인 GUI 프레임에 디자인이 없어 「번치 메인 API 연결, 알림 점」 단위에서 정한다.
- 오래된 알림 정리, 빈 목록 화면(디자인 없음).

## 흐름과 결정

- 전환은 더보기 메뉴와 같은 SSGOI `drill` 프리셋이다. 방향은 화면설계서(Move in ←, Ease out, 150ms)와 같고, 시간은 250ms(사용자 결정)이며 뒤 화면이 20% 함께 밀린다(`docs/architecture/motion.md`).
- 「모두 읽음」은 읽을 알림이 없어도 비활성으로 바꾸지 않는다(누른 버튼이 비활성이 되면 초점이 문서 처음으로 빠짐). 그때 누르면 바뀌는 것이 없다. 결과는 늘 마운트된 `role="status"` 영역이 「모든 알림을 읽음으로 바꿨어요.」 또는 「읽지 않은 알림이 없어요.」로 알린다(초점은 버튼에 남고 카드 이름만 바뀌어 스크린 리더가 알 수 없어서).
- 알림이 없으면 빈 목록(`ul`)을 그리지 않고 상태 영역이 「아직 알림이 없어요.」를 알린다(제안). 빈 목록 화면은 디자인이 정해지면 추가한다.
- 알림을 여는 동안 로딩 덮개를 씌우고 상태 영역이 「알림을 여는 중이에요」를 알린다. 「모두 읽음」은 서버의 읽지 않은 수로 판단하고(첫 쪽 밖 포함), 요청 중 다시 눌러도 한 번만 보낸다.
- 배경과 헤더는 회색(`surface-secondary`)이고, `data-app-background="secondary"`로 상단 Safe Area도 같은 색이다.

## 확인할 항목

- 안내 줄이 누를 수 있는 모양(화살표)인데 지금은 동작이 없다. 알림 설정 화면을 언제 만드는지.
- 빈 목록과 오래된 알림의 표시 기준(Figma·명세 없음).
- 뒤로 가기는 `history.length`로만 돌아갈 기록을 판단한다. 다른 사이트에서 같은 탭으로 바로 들어오면 앱 밖으로 나간다(다른 화면의 뒤로 가기와 같은 한계).
- 1110판 5.12.1: 피드 헤더 알림 아이콘(6.1.2)도 이 목록으로 들어오고, 뒤로가기는 들어온 화면(번치 메인 또는 피드)으로 간다. 기록이 있으면 `router.back()`이라 맞지만, 기록이 없을 때의 대체 이동은 아직 번치 메인 기준이다.
- 1110판 5.12.3 알림 표: 9번(뭉치 성장)은 삭제하고 번호만 남긴다. 22번(내 댓글에 답글, 원댓글 작성자에게, 원댓글의 번치에 쌓임)을 더했다. 20번 제목은 「{번치 이름} 번치 {닉네임}님이 '{번들 제목}' 번들에 댓글을 남겼어요」다. 이동 화면은 11~13번이 역할별 권한 안내(5.6.2), 4번이 번치 메인 「작성 중인 번들」 탭이다. 16번은 종류별 토글로 끌 수 없다.
- 1110판 5.12.3 로직: 3번 리마인드는 멤버마다 참여 멤버가 된 시점부터 24·72시간에 센다. 8번은 추천 번들이 새로 생길 때만 보낸다. 콕한 장소에서 장소가 자동으로 빠지는 일은 알림을 만들지 않는다. 서버 발송 규칙이라 API 연결 때 확인한다.
