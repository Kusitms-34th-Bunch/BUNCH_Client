# 페이지: 번치 홈(하단 탭 `/bunch`)

## 메타데이터

- Route: `/bunch`(`apps/web/src/app/(app)/(main)/bunch/page.tsx`)
- Status: 프로필·번들 두 탭·빈 상태·작성 중인 번들 삭제·번치 전환 시트·접근 불가 번치 안내 UI 구현됨. 데이터는 fixture와 목 동작이다. 개발 서버 Chrome(앱 폭 430px)에서 Figma와 위치를 대조했고 실기기는 확인하지 않았다.
- 화면설계서: Figma `1892:37781`(번치 메인 탭 > 계정 전환 / 번치 만들기).
- 디자인 출처: Figma `번치 - 메인`(node `1873:29989`) 섹션의 `번치 - 메인`(`3086:66283`), `번치 - 계정 전환(1)·(2)`(`3086:67437`·`3086:67555`), `번치 - 작성 중인 번들`(`3213:75914`·`3213:77085`), 빈 상태(`3213:76983`), `번치 계정 전환 Modal`(`1873:30725`), 안내 Dialog(`2321:44039`·`2321:44066`). 이슈 #162.
- 기능 spec: 기능명세서 5장 번치(메인/상세) 5.1~5.3. 번들 영역은 명세서(「우리의 번들」)와 최신 Figma(아이콘 탭)가 달라 Figma를 따른다(사용자 결정, 아래 확인할 항목).

## 목적과 범위

### 포함

- 헤더: 번치 이미지·이름·전환 화살표(`AccountSwitcher`), 알림, 더보기. 배경은 캐릭터 영역과 같은 `surface-brand-subtle-1`이다.
- 캐릭터 영역: 헤더 아래 118px. 캐릭터 에셋이 아직 없어 120px 회색 자리표시를 오른쪽에 두고 흰 시트에 32px 걸친다.
- 프로필: 번치 이름(페이지 `h1`), 비공개면 자물쇠(「비공개 번치」), 소개, 팔로워·팔로잉·멤버 수, 「가볼 곳」 버튼.
- 번들 탭(`MenuTabs.IconTab` 두 개, 반씩 차지): 완성된 번들(사진 아이콘), 작성 중인 번들(연필 아이콘). 탭을 바꾸면 탭 아이콘과 내용이 Dissolve / Ease out / 75ms로 바뀐다(화면설계서 3번, 첫 진입·되돌아올 때는 재생 안 함). 선택 밑줄은 200ms ease-out으로 미끄러진다(사용자 결정, `docs/architecture/motion.md`).
  - 완성된 번들: 대표 사진 3열 그리드(123:163 비율, 사이 1px, 좌우 2px). 없으면 「추억은 많은데, 번들은 아직!」 + 「첫 번들 만들기」.
  - 작성 중인 번들: `BundleCard` 목록(사이 10px). 휴지통을 누르면 「작성 중인 번들을 삭제할까요?」(「취소」/「삭제하기」) 뒤 카드를 지운다. 없으면 「아직 작성 중인 번들이 없어요」.
- 오른쪽 아래 「+」(번들 만들기)는 스크롤과 상관없이 탭 막대 위 10px에 고정한다.
- 번치 전환 시트(5.2.1): 「번치 전환하기」, 소속 번치 목록(디자인 시스템 `BunchSwitchSheet`). 지금 번치는 맨 위에 흐리게(`current`, 누를 수 없음), 삭제·내보내진 번치는 흐림 + 「접근 불가」(`unavailable`), 알림이 있으면 「알림 N개」 칩. 다른 번치를 고르면 시트를 닫고 완성된 번들 탭으로 돌아가며 새 번치 내용을 Dissolve / Ease out / 150ms로 표시하고(화면설계서 7, 첫 진입 제외) 「{번치 이름} 번치로 전환했어요.」 토스트를 「+」와 같은 높이(세로 가운데, Figma `3086:67555`)에 띄운다. 화면설계서 1-2-1 문구는 「+」 16px 위라 서로 달라 Figma를 따랐다(사용자 결정). 「새로운 번치 추가하기」는 시트가 다 내려간 뒤 번치 시작 선택(`/onboarding?from=bunch`, 닫기(X)가 번치 홈으로 돌아옴)으로 Dissolve / Ease out / 150ms로 이동한다(5.2.4, 화면설계서 7·8).
- 접근 불가 번치 안내(5.2.3): 전환 시트에서 「접근 불가」 번치를 누르면 전환하지 않고 시트 위에 안내를 띄운다. 삭제됐으면 「{이름} 번치가 삭제됐어요」, 내보내졌으면 「{이름} 번치에서 내보내졌어요」. 「번치 목록에서 삭제」를 누르면 그 번치를 전환 목록에서 지우고 지금 화면은 그대로다. Esc는 안내만 닫고 목록에 남긴다. 바깥 누름은 `ConfirmDialog`(AlertDialog)라 닫히지 않는다. 삭제 뒤 초점은 시트의 「닫기」로 간다(개발 서버에서 확인).

### 범위 외(추후 작업 예정)

- 서버 연동, 로딩·오류 상태: 번치·번들 API 계약이 없다. 연결하면 `useBunchHome`만 TanStack Query로 바꾸고 로딩·오류 화면을 추가한다.
- 「첫 번들 만들기」·「+」·작성 중인 번들 열기: 번들 작성 이슈에서 연결한다(호출 지점 `onCreateBundle`·`onOpenDraft`만 있음).
- 알림·「가볼 곳」: 화면이 없어 버튼만 있다. 더보기는 `/bunch/menu`로 가는 링크다(#169, `BunchMenuScreen.spec.md`).
- 완성된 번들 그리드 칸: 번들 상세가 없어 누를 수 없는 사진이다.
- 마지막 번치 복원, 번치 전환 시 캐시 키, 보고 있던 번치가 삭제·내보내진 경우의 안내와 이동(5.2.3 상세 동작 4), 전환·목록 삭제 실패 토스트, 최대 10개 토스트(5.2.4): API 연결 때 함께 한다.
- 번치 없음 화면(5.1.7), 멤버 이동(5.1.4), 알림 빨간 점(5.1.2): 각 화면·API가 생길 때 한다. 팔로워·팔로잉 수는 목록으로 연결했다(#192).

## Route와 접근

- Path: `/bunch`. params·search는 없다. 제거 조건: 번치 API를 연결하는 PR에서 `fixtures/`와 `useBunchHome`의 목 동작을 함께 삭제한다. 그 전까지는 운영에서도 `/bunch`가 fixture(가짜 번치 데이터)를 보여 주므로 로그인·API 연결 전에는 일반 사용자에게 열리지 않아야 한다.
- 접근 권한·guard: 아직 없다(로그인 미구현). 번치 멤버만 볼 수 있어야 하며 서버가 판단한다.
- Layout: `(app)/(main)` 하단 탭 layout 안에서 `PageShell`을 한 번 쓴다. `robots: noindex`.

## 상태와 흐름

- `useBunchHome`이 호출 지점이고 지금은 fixture와 목 동작(`switchBunch`·`deleteDraftBundle`·`removeBunch`)을 돌려준다. fixture 번치마다 내 역할이 달라(퇴근런클럽 메인 관리자, 여행가조 공동 관리자, 큐시즘 기프 일반 멤버) 번치를 전환하면 더보기 메뉴가 역할에 맞게 바뀐다.
- 탭·전환 시트·삭제 대상·접근 불가 안내 대상은 화면 안 상태다.

## 접근성

- 페이지 제목은 번치 이름 `h1`이다. 헤더의 번치 버튼은 이름이 접근성 이름이고 `aria-haspopup="dialog"`·`aria-expanded`로 시트 열림을 알린다.
- 번들 탭은 `tablist`(「번들」)와 `tab`(「완성된 번들」·「작성 중인 번들」)이고 아이콘은 장식이다.
- 그리드 사진은 번들 제목을 `alt`로 쓴다.
- 전환 목록의 지금 번치는 `aria-current`·`aria-disabled`라 초점은 받지만 고를 수 없다. 접근 불가 번치는 누를 수 있는 버튼이고 상태는 「접근 불가」 글자로 전달한다.

## 확인할 항목

- 「가볼 곳」의 깃발 아이콘이 디자인 시스템 아이콘에 없어 글자만 표시했다(아이콘 세 크기 추가 필요).
- 작성 중인 번들 탭의 선택 아이콘(채운 연필)이 디자인 시스템에 없어 선 아이콘을 색만 바꿔 쓴다.
- 「+」의 동작(번들 만들기로 해석), 알림·「가볼 곳」·그리드 칸을 눌렀을 때의 이동.
- Figma 안내 제목의 「홍대먹짱」과 목록의 「홍대 먹짱」 띄어쓰기 차이.
- 전환 토스트는 Figma대로 「+」와 같은 높이라 떠 있는 3초 동안 「+」를 덮는다(의도). 덮인 동안 「+」를 누를 수 있는지는 확인하지 않았다.
- 지금 번치 ID는 `useCurrentBunchId`가 sessionStorage에 둔다. 더보기 메뉴·시작 선택에서 돌아오거나 새로고침해도 고른 번치가 유지되고, 탭(세션)을 닫으면 첫 번치(여행가조)로 돌아간다. API 연결 때 서버의 마지막 사용 번치로 바꾼다.
- 보고 있던 번치가 접근 불가가 되면 지금은 `unavailable`로 표시되어 `aria-current`가 빠진다. API 연결 때 5.2.3 상세 동작 4와 함께 정한다.
- 기능명세서(5.1.5·5.3)와 Figma 차이(Figma를 따름, 기획 확인 필요): 명세는 「우리의 번들 N」 제목 + 작성 중 안내 줄 → 별도 작성 중 목록 화면, 발행 번들 2열 그리드다. 작성 중 카드(폭 가득 사진·닉네임 칩·날짜·장소)와 삭제 확인(일러스트 바텀시트, 「번들에 작성한 모든 내용이 삭제돼요.」, 삭제 후 토스트)도 다르다.
- 「가볼 곳」은 기능명세서에 없다.
- 접근 불가 안내: 명세(5.2.3)는 바깥 누름으로도 닫히는데 디자인 시스템 `ConfirmDialog`는 바깥 누름을 막는다. 버튼이 하나라 첫 초점이 「번치 목록에서 삭제」에 있어 Enter 한 번으로 지워진다(지워지는 것은 이미 접근 불가인 번치).
- 접근 불가 행은 이제 누를 수 있는데 Figma처럼 흐림(40%)과 `text-disabled`가 겹쳐 대비가 낮다. 디자이너 확인이 필요하다.
- 화면설계서(`1892:37781`)와 다른 점: 4번 설명은 「2 Grid」지만 같은 설계서 3-1 화면과 Figma는 3열이라 3열을 따른다. 7번은 접근 불가 번치를 「Disabled, Interaction 미적용」으로 두지만 기능명세 5.2.3(누르면 안내)을 따른다(사용자 결정).
- 번치 시작 선택 화면의 X 닫기는 진입 경로에 따라 다르다. 번치 홈에서 들어온 경우(`/onboarding?from=bunch`)는 이전 화면으로 돌아가고, 기록이 없으면 `/bunch`로 대체 이동한다. 첫 진입의 X(확인 모달 → 피드, 화면설계서 8-1)는 아직 동작이 없다(onboarding feature).
- 캐릭터 이미지 에셋과 번치별 상태.
- 작성 중인 번들 삭제 확인 창에 번들 이름이 없다(Figma 문구 그대로).
- 연결 전 버튼(알림·「가볼 곳」·「+」·「첫 번들 만들기」)은 눌러도 반응이 없다. 오래 남으면 비활성 처리를 검토한다.
