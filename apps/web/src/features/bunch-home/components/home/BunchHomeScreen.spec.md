# 페이지: 번치 홈(하단 탭 `/bunch`)

## 메타데이터

- Route: `/bunch`(`apps/web/src/app/(app)/(main)/bunch/page.tsx`)
- Status: 프로필·번들 두 탭·빈 상태·작성 중인 번들 삭제·번치 전환 시트·접근 불가 번치 안내 UI 구현됨. 화면은 서버 데이터(`useServerBunchHome`)로만 그린다. API 연결 전에는 fixture(가짜 번치·멤버 데이터, `fixtures/bunchHome.fixture.ts`·`bunchMembers.fixture.ts`)와 메모리 저장소로 화면과 전환·삭제 동작을 먼저 만들었고, 서버 연결 뒤 테스트용 샘플 모드로만 남아 있던 것을 #413에서 지웠다. fixture 파일은 기록용으로 남겨 두었고 쓰는 곳은 없다. 개발 서버 Chrome(앱 폭 430px)에서 Figma와 위치를 대조했고 실기기는 확인하지 않았다.
- 화면설계서: Figma `1892:37781`(번치 메인 탭 > 계정 전환 / 번치 만들기).
- 디자인 출처: Figma `번치 - 메인`(`5402:112707`)·계정 전환 모달(`5402:112815`), `번치 - 계정 전환(1)·(2)`(`5402:113083`·`5402:113196`), `번치 - 작성 중인 번들(1)·(2)`(`5402:113555`·`5402:113781`)과 빈 상태(`5402:114263`), 안내 Dialog(`5402:105298`·`5402:105299`). 이슈 #162(최초 구현), #300(2026-11 디자인 개편 반영, 이전 노드 `3086:66283`·`3086:67437`·`3086:67555`·`3213:75914`·`3213:77085`·`3213:76983`·`1873:30725`).
- 기능 spec: 기능명세서 5장 번치(메인/상세) 5.1~5.3, 1110판(2026-11-10) 기준. 번들 영역은 이전 판(「우리의 번들」)과 달라 Figma(아이콘 탭)를 따랐고(사용자 결정), 1110판이 같은 구조로 바뀌었다.

## 목적과 범위

### 포함

- 헤더: 번치 이름·전환 화살표(`AccountSwitcher`), 알림, 더보기. 배경은 프로필 이미지 영역과 같은 번치 성격 색이다.
- 성격 색(Figma `1873:29989`): 서버 `characterType`이 `TYPE_1`이면 bunch-50(`surface-brand-subtle-1`), `TYPE_2` orange-50, `TYPE_3` pink-50, `TYPE_4` green-50. 헤더, 프로필 이미지 영역, 위쪽 Safe Area(`data-app-background`)가 같은 색이다. 대표 이미지가 없으면 성격별 기본 이미지(`public/images/default-bunch/type-1~4.svg`)를 쓴다. 성격별 배경(`lib/bunchTheme.ts`)과 프로필 이미지(`BunchProfileImage`)는 번치 홈과 다른 번치 화면이 같이 쓴다.
- 프로필 이미지 영역: 헤더 아래 82px(시트 시작 192px). 오른쪽 위에 번치 프로필 이미지(디자인 시스템 `ProfileImage` L 90px 원형, 1px `border-tertiary` 테두리)를 영역 위에서 24px 아래, 오른쪽 16px에 놓고 흰 시트에 32px 걸친다. 이전의 성장 단계(`stage`)별 캐릭터 그래픽은 2026-11 Figma 개편으로 없앴고, 서버 `stage` 값은 화면이 쓰지 않는다. 홈 두 프레임(`5402:112707`·`5402:112815`)만 시트·이미지가 3px 아래(195·137)인데 나머지 5개 프레임(192·134)을 따랐다(사용자 결정).
- 프로필: 번치 이름(페이지 `h1`), 비공개면 자물쇠(「비공개 번치」), 소개, 팔로워·팔로잉·멤버 수, 「콕한 장소」 버튼(깃발 아이콘 `FillFlagSmallIcon`). 멤버 수는 멤버 목록(`/bunch/members`, 5.1.4 상세 5) 링크다.
- 번들 탭(`MenuTabs.IconTab` 두 개, 반씩 차지): 완성된 번들(사진 아이콘), 작성 중인 번들(연필 아이콘, 선택하면 채운 연필 `FillPencilMediumIcon`). 탭을 바꾸면 탭 아이콘과 내용이 Dissolve / Ease out / 75ms로 바뀐다(화면설계서 3번, 첫 진입·되돌아올 때는 재생 안 함). 선택 밑줄은 250ms ease-out으로 미끄러진다(사용자 결정, `docs/architecture/motion.md`).
  - 완성된 번들: 대표 사진 3열 그리드(123:163 비율, 탭 아래 2px, 사이 1px, 좌우 2px). 칸은 번들 상세(`/bunches/{bunchId}/bundles/{bundleId}`) 링크이고 이름은 번들 제목이다. 누르면 상세를 먼저 받아(최대 400ms) 404면 이동하지 않고 「삭제된 번들이에요.」 토스트 뒤 그리드를 다시 받는다(5.1.5). 400ms 안에 답이 없거나 그 밖의 실패면 그대로 이동하고 상세 화면이 볼 수 없음을 안내한다. 그리드 끝이 보이면 다음 쪽을 이어서 받고, 실패하면 받은 칸은 두고 「목록을 더 불러오지 못했어요.」와 「다시 시도」. 멤버 공개 번들은 사진 오른쪽 위 6px에 24px 원(`overlay-pressed`)과 멤버 아이콘(`Image` `Show Icon`, `3086:66539`)을 얹고 대체 텍스트로도 알린다. 서버 `published-bundles`의 `visibility`는 명세에 아직 없어 값이 없으면 숨긴다(백엔드 확인 필요, 2026-11-16 확인). 없으면 「추억은 많은데, 번들은 아직!」 + 「첫 번들 만들기」.
  - 작성 중인 번들: `BundleCard` 목록(탭 아래 12px, 사이 10px; 두 값은 사용자 결정, Figma 프레임마다 값이 달라 12px·10px로 정함). 휴지통은 삭제 권한이 있는 카드에만 보이고(서버 `permissions.canDelete`: 초안 생성자, 참여 중인 관리자, 기능명세 5.3.2), 누르면 「작성 중인 번들을 삭제할까요?」(「취소」/「삭제하기」) 뒤 카드를 지우고 「작성 중인 번들을 삭제했어요.」를 띄운다. 제목이 빈 초안은 「제목 미정」을 흐리게 보인다(5.3.1). 없으면 「아직 작성 중인 번들이 없어요」.
- 오른쪽 아래 「+」(번들 만들기)는 스크롤과 상관없이 탭 막대 위 10px에 고정한다.
- iOS 26 이상 앱에서는 「+」를 앱이 Liquid Glass 버튼으로 그리고 웹 버튼은 그리지 않는다(결정 기록 026). 시트·대화상자가 열린 동안은 숨긴다. 브라우저·iOS 26 미만은 웹 버튼이다.
- 번치 전환 시트(5.2.1): 「번치 전환하기」, 소속 번치 목록(디자인 시스템 `BunchSwitchSheet`). 지금 번치는 맨 위에 흐리게(`current`, 누를 수 없음), 삭제·내보내진 번치는 흐림 + 「접근 불가」(`unavailable`), 알림이 있으면 「알림 N개」 칩. 다른 번치를 고르면 시트를 닫고 완성된 번들 탭으로 돌아가며 새 번치 내용을 Dissolve / Ease out / 150ms로 표시하고(화면설계서 7, 첫 진입 제외) 「{번치 이름} 번치로 전환했어요.」 토스트를 「+」와 같은 높이(세로 가운데, Figma `3086:67555`)에 띄운다. 화면설계서 1-2-1 문구는 「+」 16px 위라 서로 달라 Figma를 따랐다(사용자 결정). 「새로운 번치 추가하기」는 시트가 다 내려간 뒤 번치 시작 선택(`/onboarding?from=bunch`, 닫기(X)가 번치 홈으로 돌아옴)으로 Dissolve / Ease out / 150ms로 이동한다(5.2.4, 화면설계서 7·8).
- 접근 불가 번치 안내(5.2.3): 전환 시트에서 「접근 불가」 번치를 누르면 전환하지 않고 시트 위에 안내를 띄운다. 삭제됐으면 「{이름} 번치가 삭제됐어요」, 내보내졌으면 「{이름} 번치에서 내보내졌어요」. 「번치 목록에서 삭제」를 누르면 그 번치를 전환 목록에서 지우고 지금 화면은 그대로다. Esc는 안내만 닫고 목록에 남긴다. 바깥 누름은 `ConfirmDialog`(AlertDialog)라 닫히지 않는다. 삭제 뒤 초점은 시트의 「닫기」로 간다(개발 서버에서 확인). 안내 창은 `hooks/useAccessNoticeDialog`로 아래 두 경우와 함께 쓴다.
- 보던 번치가 삭제·내보내짐(5.2.3 상세 동작 4, #414): 받아 둔 기본 번치로 홈을 다시 받다 `409 BUNCH_008`이 오면(받아 둔 홈이 있어도) 로딩 화면 위에 같은 안내를 띄운다. 안내 내용은 오류 `detail.noticeId`로 `GET /members/me/bunch-access-notices/{noticeId}`(명세 078)에서 받는다. 「번치 목록에서 삭제」면 안내를 지우고, Esc면 전환 목록의 접근 불가 줄로 남긴다. 어느 쪽이든 닫히면 `members/me`·전환 목록을 다시 받아 서버가 고른 최근 번치(없으면 번치 없음 화면)로 바뀐다. 안내를 받지 못하면(이미 확인했거나 30일 지남) 안내 없이 바로 바뀐다. 다시 받은 기본 번치가 같아 여전히 같은 안내면 「다시 시도」 오류 화면이다(서버는 소속이 끝난 번치를 기본 번치로 고르지 않으므로 정상 흐름에서는 생기지 않음).

### 범위 외(추후 작업 예정)

- 서버 연동: 번치 프로필·권한·개수(`GET /bunches/{id}/home`)와 완성된 번들(`GET /bunches/{id}/published-bundles`)은 `useServerBunchHome`이 내 기본 번치 기준으로 받는다(`/home` 응답은 Swagger 생성 타입과 묶음, #408). 로딩은 `PageLoading`, 오류는 「다시 시도」가 있는 `BunchHomeError`, 소속 번치가 없으면 번치 없음 화면이다. 번들 발행 뒤에는 번치 홈 key 전체(`sharedKeys.bunchHomeScope`)를 무효화해 새 번들이 맨 앞에 쌓인다. 팔로우·알림·멤버 관리는 각 화면이 서버에서 받고, 연동 현황은 `docs/workflows/mock-server-status.md`에 모아 두었다.
- 작성 중인 번들: 서버 모드에서는 초안 목록(`GET /bunches/{id}/bundles?status=DRAFT`, 최근 수정순 첫 쪽 50개)으로 카드를 만들고(대표 사진은 첫 사진, 참여 멤버는 번치 멤버 정보로 채움, 제목이 비면 흐린 「제목 미정」). 카드를 누르면 초안 상세를 새로 받아 확인한 뒤 `/bunch/drafts/{id}`로 이동한다. 이미 삭제됐으면(404) 「삭제된 번들이에요.」, 이미 발행됐으면 「발행된 번들이에요.」를 띄우고 이동 대신 목록을 다시 받는다(5.3.1 예외 처리, 400ms 안에 답이 없으면 확인 없이 이동). 삭제는 직전에 상세를 새로 받아 이미 발행됐으면 지우지 않고 「이미 발행된 번들이에요.」를 띄운다(삭제 API가 발행본도 지울 수 있어서). 그다음 `DELETE`로 보낸다. 404는 「이미 삭제된 번들이에요.」, 409 `BUNDLE_002`는 「이미 발행된 번들이에요.」, 403은 「번들은 초안을 만든 멤버나 참여 중인 관리자만 삭제할 수 있어요.」를 띄우고 창을 닫는다(목록은 다시 받음). 그 밖의 실패는 공통 실패 토스트를 띄우고 창을 유지한다(5.3.2 예외 처리). 초안을 만들거나 나가거나 삭제하거나 발행하면 번치 홈 key 전체가 무효화되어 목록이 갱신된다. 「첫 번들 만들기」·「+」는 `/bunch/bundles/new/members`(번들 만들기 멤버 선택)로 이동한다. 작성 중인 번들이 이미 10개면(홈 응답 `draftCount`) 이동하지 않고 「번들 초안은 최대 10개까지 만들 수 있어요.」를 띄운다(4.1.1 상세 동작 1). 번치 멤버가 2명 미만이면 이동하지 않고 「함께할 멤버가 없어요」 창(「취소」·「초대하기」, Figma `5618:81971`)을 띄우며 「초대하기」는 멤버 초대 화면(`/bunch/members/invite`)으로 간다.
- 「콕한 장소」: 누르면 `/bunch/places`(`bunch-places` feature, `BunchPlaces.spec.md`)로 이동한다(#257). 알림은 화면이 없어 버튼만 있다. 더보기는 `/bunch/menu`로 가는 링크다(#169, `BunchMenuScreen.spec.md`).
- 번치 전환(#313): 전환 목록은 `GET /members/me/bunches`로 받는다. 지금 번치를 맨 위, 나머지 소속 번치를 최근 사용순, 접근 불가 번치(안내)를 맨 아래에 둔다. 목록을 못 받으면 지금 번치 하나로 보이고 홈은 막지 않는다. 다른 번치를 고르면 `PUT /bunches/{id}/last-used`로 마지막 사용 번치를 저장하고 `members/me`·전환 목록을 다시 읽은 뒤 새 번치 홈과 전환 토스트를 보인다. 앱 전체가 `members/me`의 기본 번치를 보므로 사진함·번들 만들기도 새 번치 기준이 되고, 앱을 다시 열어도 그 번치로 들어온다. 저장에 실패하면 지금 번치에 머물고 「일시적인 오류가 발생했어요. 다시 시도해 주세요」(기획 원문 없음). 「번치 목록에서 삭제」는 `DELETE /members/me/bunch-access-notices/{noticeId}` 뒤 그 줄만 목록에서 빼고, 실패하면 토스트와 함께 목록을 다시 읽는다. 소속 번치가 최대 개수(`activeCount >= maxActiveCount`)면 「새로운 번치 추가하기」는 이동하지 않고 「참여할 수 있는 번치는 최대 10개예요.」.
- 보고 있던 번치가 삭제·내보내진 경우의 안내와 이동(5.2.3 상세 동작 4): 서버가 기본 번치를 어떻게 바꾸는지 확인한 뒤 한다.
- 번치 없음 화면(5.1.7), 알림 빨간 점(5.1.2): 각 화면·API가 생길 때 한다. 팔로워·팔로잉 수는 목록으로 연결했다(#192).

## Route와 접근

- Path: `/bunch`. params는 없고 search `tab=drafts`면 「작성 중인 번들」 탭으로 연다(알림에서 바로 가기, 5.12.2). 다른 값은 완성된 번들 탭이고, 번치를 전환하면 주소와 상관없이 완성된 번들 탭이다. 화면은 서버 데이터(`useServerBunchHome`)로 그린다.
- 접근 권한·guard: `(app)` layout의 `AuthGate`가 서버의 가입 상태로 막는다(`features/auth/lib/accessPolicy.ts`, 결정 기록 019). 가입을 마친 사용자만 들어오고, 비로그인은 로그인(처음이면 인트로)으로, 가입 중이면 약관·프로필로 보낸다. 번치 멤버인지는 서버가 판단한다.
- Layout: `(app)/(main)` 하단 탭 layout 안에서 `PageShell`을 한 번 쓴다. `robots: noindex`.

## 상태와 흐름

- 화면 데이터는 `BunchHome`이 `useServerBunchHome`으로 받는다. 동작(`switchBunch`·`deleteDraftBundle`·`removeBunch`)은 서버 mutation(`useSwitchBunchMutation`·`useDeleteBundleMutation`·`useDeleteBunchNoticeMutation`)이다. 더보기 메뉴의 역할은 서버 멤버 목록(`useMyBunchMemberships`)으로 정한다.
- 테스트는 가짜 서버(MSW)의 시작 데이터(기본 번치 여행쥬아)로 그린다(`BunchHome.test.tsx`·`BunchHome.server.test.tsx`·`BunchHome.needMembers.test.tsx`).
- 탭·전환 시트·삭제 대상·접근 불가 안내 대상은 화면 안 상태다. 탭의 처음 값만 주소(`?tab=drafts`)로 정한다.
- 그리드 → 번들 상세의 삭제 확인은 feed feature의 상세 query(`usePrefetchBundleDetail`)를 route(`BunchHomeRoute`)가 넘겨 쓴다. 상세 → 번치 홈과 같은 drill 전환이다.

## 접근성

- 페이지 제목은 번치 이름 `h1`이다. 헤더의 번치 버튼은 이름이 접근성 이름이고 `aria-haspopup="dialog"`·`aria-expanded`로 시트 열림을 알린다.
- 번들 탭은 `tablist`(「번들」)와 `tab`(「완성된 번들」·「작성 중인 번들」)이고 아이콘은 장식이다.
- 그리드 사진은 번들 제목을 `alt`로 쓴다.
- 전환 목록의 지금 번치는 `aria-current`·`aria-disabled`라 초점은 받지만 고를 수 없다. 접근 불가 번치는 누를 수 있는 버튼이고 상태는 「접근 불가」 글자로 전달한다.

## 서버 연동의 후속과 알려진 차이

번치 홈 조회(`/home`)는 Swagger 생성 타입과 스키마를 묶었다(#408). 발행 번들 목록은 화면에 필요한 필드만 받아 아직 묶지 않았다. 아래를 운영 응답으로 확인한다.

- 기본 번치와 서버 현재 번치: 화면은 `members/me`의 기본 번치로 `/home`을 부른다. 서버의 `currentBunchId`와 다르면 EXTERNAL 응답(소속·개수 null)이 와서 지금은 오류 화면이 된다. 두 값이 항상 같은지 서버 담당자 확인이 필요하다.
- 다른 번치 열람(EXTERNAL): 비소속 번치의 `/home`은 오류가 아니라 EXTERNAL 응답(공개 범위·팔로우에 따라 `canView*`)이고, `/published-bundles`는 PUBLIC 발행본만 돌려준다. 다른 번치 프로필(#341, `OtherBunchScreen.spec.md`)이 쓰며 가짜 서버도 같은 응답을 준다.
- 쪽 크기: 발행 번들은 50개씩 `useInfiniteQuery`로 이어서 받는다(`bunchHomeKeys.publishedPages`, `hasNext`가 false면 끝). 쪽 번호 방식이라 받는 사이 새 번들이 앞에 생기면 다음 쪽이 겹치고, 같은 번들은 처음 것만 남긴다. 기기 저장(`persistedQuery`)은 유지해 받은 쪽 모두를 저장하고, 복원 뒤 오래됐으면 받은 쪽을 처음부터 다시 받는다. 작성 중인 번들은 아직 첫 쪽 50개만 받는다.
- 표지 주소: 안전하지 않은 이미지 주소는 해당 항목만 기본 이미지로 대체한다(파싱 실패로 홈 전체를 막지 않음). 서버가 어떤 주소를 내려주는지 정해지면 기준을 다시 본다.
- Stage: 가짜 서버는 명세 값(발행본 0~~1=1, 2~~5=2, 6~9=3, 10개 이상=4)으로 내려준다. 기능명세 1110판(5.1.3)은 단계를 없앴으므로 서버 응답에서 빠지는지 확인한다.

## 확인할 항목

- 「+」의 동작(번들 만들기로 해석).
- 그리드 칸에서 삭제를 알아내는 기준은 상세 404다. 400ms 뒤에 오는 404는 상세 화면의 「볼 수 없음」 안내로 간다(그리드는 다시 받지 않음).
- Figma 안내 제목의 「홍대먹짱」과 목록의 「홍대 먹짱」 띄어쓰기 차이.
- 전환 토스트는 Figma대로 「+」와 같은 높이라 떠 있는 3초 동안 「+」를 덮는다(의도). 덮인 동안 「+」를 누를 수 있는지는 확인하지 않았다.
- 지금 번치는 `members/me`의 기본 번치다. `PUT /bunches/{id}/last-used` 뒤 기본 번치가 그 번치로 바뀐다고 보고 연결했다(가짜 서버도 그렇게 동작). 실서버가 같은지 확인한다.
- 홈 말고 다른 화면(콕한 장소·피드 상세 등)이 `BUNCH_008`을 받는 경우는 이 안내로 연결하지 않았다. 콕한 장소는 서버가 지금 번치를 고르는 API라 해당하지 않는다.
- 기능명세서(5.1.5·5.3)와 Figma 차이: 1110판이 아이콘 탭·3열 그리드·탭 안 작성 중 목록·삭제 확인 모달로 바뀌어 구조는 같아졌다. 삭제 확인 문구도 구현과 같다. 남은 차이는 작성 중 카드 모양이다. 1110판은 왼쪽 사진, 오른쪽 제목, 참여 멤버 프로필 최대 3개 + 「외 N명」(6.1.3과 같은 방식)이다. 구현 `BundleCard`가 Figma와 같은지 확인한다(명세와 다름, 확인 필요).
- 탭 이름: 1110판은 「번들」·「작성 중인 번들」 탭이다. 구현의 접근성 이름은 「완성된 번들」·「작성 중인 번들」이라 맞출지 확인한다.
- 1110판 5.1.3(확인 필요): 뭉치 캐릭터가 서비스에서 빠지고, 배경 띠 오른쪽에 번치 프로필 이미지(원형, 아래쪽이 프로필 영역과 겹침)를 둔다. 발행 번들 수로 바뀌는 단계는 없다. 구현은 #300에서 이 구조로 바뀌었다(위 「프로필 이미지 영역」). 명세는 이미지 로딩에 실패해도 분위기 기본 이미지를 보이라고 하는데, 구현은 주소가 없을 때만 기본 이미지를 쓴다(확인 필요).
- 1110판 5.1.3: 배경 띠 색은 분위기(2.2.9)의 연한 색이다. 지금 `characterType` 기준 성격 색과 같은 값인지 확인한다.
- 1110판 5.1.4: 멤버 수를 누르면 「멤버 리스트 화면」으로 간다(이전 판은 멤버 관리). 구현은 멤버 관리 화면(`/bunch/members`, 5.6.1)으로 연결했다. 두 화면이 같은지 기획 확인이 필요하다.
- 「콕한 장소」(이전 이름 「가볼 곳」, 2026-11-06 Figma에서 변경)는 기능명세서 「콕」 8.1로 들어왔고 화면은 `bunch-places`가 소유한다.
- 접근 불가 안내: 명세(5.2.3)는 바깥 누름으로도 닫히는데 디자인 시스템 `ConfirmDialog`는 바깥 누름을 막는다. 버튼이 하나라 첫 초점이 「번치 목록에서 삭제」에 있어 Enter 한 번으로 지워진다(지워지는 것은 이미 접근 불가인 번치).
- 접근 불가 행은 이제 누를 수 있는데 Figma처럼 흐림(40%)과 `text-disabled`가 겹쳐 대비가 낮다. 디자이너 확인이 필요하다.
- 화면설계서(`1892:37781`)와 다른 점: 4번 설명은 「2 Grid」지만 같은 설계서 3-1 화면과 Figma는 3열이라 3열을 따른다. 7번은 접근 불가 번치를 「Disabled, Interaction 미적용」으로 두지만 기능명세 5.2.3(누르면 안내)을 따른다(사용자 결정).
- 번치 시작 선택 화면의 X 닫기는 진입 경로에 따라 다르다. 번치 홈에서 들어온 경우(`/onboarding?from=bunch`)는 이전 화면으로 돌아가고, 기록이 없으면 `/bunch`로 대체 이동한다. 첫 진입의 X(확인 모달 → 피드, 화면설계서 8-1)는 아직 동작이 없다(onboarding feature).
- 작성 중인 번들 삭제 확인 창에 번들 이름이 없다(Figma 문구 그대로).
- 연결 전 버튼(알림)은 눌러도 반응이 없다. 오래 남으면 비활성 처리를 검토한다.
