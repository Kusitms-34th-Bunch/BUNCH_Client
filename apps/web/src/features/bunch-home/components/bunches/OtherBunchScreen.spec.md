# 페이지: 다른 번치 프로필과 팔로우

## 메타데이터

- Route: `/bunches/[bunchId]`(프로필, `apps/web/src/app/(app)/bunches/[bunchId]/page.tsx`), `/bunches/[bunchId]/members`(멤버 목록)
- Status: 공개·비공개 프로필, 팔로우·팔로우 요청·팔로우 취소·요청 취소 시트, 멤버 목록 구현. 프로필·공개 번들·팔로우는 서버(`home`의 `EXTERNAL` 응답, `published-bundles`, `following`), 멤버 목록·차단·신고는 아직 샘플이다. 이슈 #189, #341.
- 디자인 출처: 화면설계서 `번치 팔로우`(`2500:68583` 1~4번, `2500:71333` 4번 멤버 리스트), Figma 공개 `3086:68423`(팔로우)·`3086:68534`(팔로잉), 비공개 `3086:68654`(팔로우)·`3086:68758`(요청됨), 시트 `3086:70741`(팔로우 취소)·`3213:76818`(요청 취소).
- 기능 spec: 기능명세서 5.10(1110판, 2026-11-10 기준), `docs/specs/bunch-home.md`.

## 목적과 범위

### 포함

- 공개 번치: 팔로우 전에도 번들을 보여 준다. 「팔로우」 → 바로 「팔로잉」, 팔로워 수 +1(1번). 번들을 볼 수 있는지는 서버의 `canViewBundles`를 따르고, 볼 수 없으면 공개 번들을 요청하지 않는다.
- 비공개 번치: 팔로우 중이 아니면 번들 대신 「비공개 번치예요 / 번들을 보려면 이 번치를 팔로우하세요.」. 「팔로우」 → 「팔로우 요청됨」(승인 전이라 계속 가림, 2번). 팔로워·팔로잉·멤버 수는 목록의 서버 연결 전까지 공개·비공개 모두 글자로만 보이고, 멤버 목록 주소로 직접 들어와도 명단 대신 「목록을 보려면 이 번치를 팔로우하세요.」(기능명세 5.10, #192).
- 「팔로잉」 → 팔로우 취소 시트(상대 번치 이미지·이름·「공개 번치」/「비공개 번치」, 3번), 「팔로우 요청됨」 → 요청 취소 시트(「요청 대기 중인 비공개 번치」, 4번). 「취소」는 상태 유지.
- 멤버 목록(확인용, 관리 동작 없음, 역할은 이미지 배지)과 팔로워·팔로잉 목록(#192, `BunchFollowsScreen.spec.md`)은 주소로 들어갈 수 있고 아직 샘플이다. 프로필의 수 링크는 목록을 서버에 연결할 때 다시 건다.
- 내가 속한 번치(`accessScope: INTERNAL`)의 주소로 들어오면 지금 번치는 그대로, 다른 소속 번치는 그 번치로 전환한 뒤 번치 탭으로 `replace`하고 전환 토스트(실패해도 번치 탭으로, 실패 토스트).
- 입구: 피드 탭의 임시 링크(공개 캠핑러버, 비공개 책방산책).

### 범위 외(후속)

- 상대가 요청을 승인했을 때의 즉시 갱신: 다시 들어오거나 다시 받을 때 반영된다(알림 연결 때).
- 팔로워·팔로잉 목록의 팔로우 버튼(샘플 저장소)과 프로필(서버)의 팔로우 상태는 목록을 서버에 연결할 때 맞춘다.
- 피드의 번치 이름 입구: 피드 카드의 번치를 누르면 들어온다(지금 번치면 번치 탭).

## 흐름과 결정

- 팔로우 명의는 지금 번치(`members/me`의 기본 번치)다. 같은 번치라도 명의마다 팔로우 상태·열람 범위가 달라 query key에 명의 번치를 넣었다. 처리하면 응답의 상태를 바로 반영한 뒤 그 번치 홈(팔로워 수·열람 범위)과 내 번치 홈(팔로잉 수)을 다시 받는다.
- 실패하면 「팔로우를 처리하지 못했어요」 토스트 뒤 홈을 다시 받고 버튼 상태는 그대로다. 처리 중에는 버튼이 흐려지고(`opacity-60`) `aria-busy`이며 다시 눌러도 보내지 않는다. 결과 낭독은 서버 반영 뒤이고, 같은 문구가 이어져도 다시 읽히게 시작할 때 비운다. 취소가 404면 다시 받아 관계가 없을 때만 성공으로 보고(이미 해제됨), 남아 있으면(오래된 ID) 실패로 안내한다. 홈 응답에 관계 ID가 없으면 팔로우 요청(이미 있으면 같은 관계)으로 ID를 얻은 뒤 해제한다.
- 홈 응답의 `currentBunchId`(서버가 본 명의)가 캐시의 기본 번치와 다르면 `members/me`를 다시 받고, 그동안 팔로우를 막는다. 다시 받아도 다르거나 다시 받기가 실패하면 다시 시도 화면을 보인다.
- 팔로우를 보내는 중에 차단하면 그 요청이 끝나기를 기다린 뒤 최신 상태로 해제한다(요청 중이라 상태가 아직 「팔로우 안 함」이어도 관계가 남지 않게). 번치가 없는 회원은 팔로우 버튼이 없다.
- 불러오는 동안은 헤더와 숨은 상태 문구(「번치를 불러오는 중이에요」)만, 내 정보·홈을 못 받거나 `accessScope`가 없는 응답이면 뒤로 가기가 있는 다시 시도 화면.
- 사용자 결정으로 다른 소속 번치의 주소는 열기만 해도 전환한다. 같은 번치 멤버가 보낸 링크로도 기본 번치(사진함·번들 만들기 기준)가 바뀔 수 있고, 내 소속 번치로만 바뀌며 전환 토스트로 알린다.
- 다른 소속 번치로 전환하는 동안 뒤로 가면 전환은 서버에서 끝나지만 토스트는 뜨지 않는다(알려진 한계).
- 공개 번들을 받지 못하면 빈 그리드로 보인다(재시도 안내는 후속).
- 시트 문구는 시트를 연 순간의 상태로 고정한다(취소한 뒤 닫히는 동안 바뀌지 않게).
- 팔로우·요청·취소 결과는 버튼 이름 변화와 함께 늘 마운트된 상태 영역(`role="status"`)이 「{번치} 번치를 팔로우했어요.」 등으로 알린다.
- 시트 제목은 보이는 번치 이름 뒤에 숨은 질문(「팔로우를 취소할까요?」·「팔로우 요청을 취소할까요?」)을 붙여, 「취소」와 실행 버튼만으로 확인 내용을 알 수 없는 문제를 막는다.
- 시트는 Figma Bottom Sheet 05 모양이지만 디자인 시스템 `AdminTransferSheet`는 관리자 지정 문구가 고정이라, 같은 `BottomSheet` 부품으로 화면 쪽(`FollowCancelSheet`)에서 조립했다.
- 프로필 영역은 번치 홈의 `BunchProfile`을 재사용하고 「콕한 장소」는 숨긴다(Figma `3086:68423`에 없음). 버튼이 없어도 수치 줄 높이 32를 지켜 Figma와 위치를 맞췄다.
- 없는 번치 id(서버 404)와 잘못된 주소(400)는 404(`notFound`). 그 밖의 실패는 뒤로 가기가 있는 다시 시도 화면. 루트 `app/not-found.tsx`가 앱 틀 안에서 안내와 「번치 탭으로 가기」를 보여 준다(없는 주소의 404도 같이 씀).
- 전환: 피드 → 프로필 → 멤버 목록은 `drill`(`docs/architecture/motion.md`). 뒤로 가기는 기록이 없으면 프로필은 피드, 멤버 목록은 프로필로 `replace`.

## 차단·신고 (#196)

- 디자인 출처: 화면설계서 `번치 차단하기`(`2500:67470` 1~~3번), `번치 신고하기`(`2500:69551` 1~~3-2번), Figma `3086:68983`·`3086:69394`, 접근 제한 `2500:69518`.
- 헤더 더보기(⋯, `OtherBunchMoreMenu`) → 메뉴 시트(`MoreMenuSheet`, Bottom Sheet 06): 「차단하기」·「신고하기」·「취소하기」. 차단은 멤버 누구나 할 수 있다(기능명세 5.10.4, 2026-11-04 변경 전에는 공동·메인 관리자만이었다). 차단 해제는 차단 목록에서 메인·공동 관리자만 한다. 메뉴가 다 닫힌 뒤 다음 시트를 연다.
- 차단: 확인 시트(`ConfirmSheet`, Bottom Sheet 05) 「{번치} 번치를 차단할까요?」와 안내 상자, 「취소」·「차단하기」. 차단하면 내 번치가 한 팔로우(요청 포함)를 해제하고(2번, 상대가 나를 팔로우한 관계의 해제는 팔로워 목록이 서버 데이터가 되는 API 연결 때) 내 번치 차단 목록 맨 위에 더하며, 「{번치} 번치를 차단했어요.」 토스트와 함께 프로필이 접근 제한 화면으로 바뀌고 초점은 그 제목으로 간다. 완료 토스트 문구는 화면설계서에 없어 임시로 정했다.
- 접근 제한(`BlockedBunchScreen`, 3번): 프로필·팔로워·팔로잉·멤버 목록 모두 대신 「볼 수 없는 번치예요 / 해당 번치의 프로필 정보를 불러올 수 없어요.」와 뒤로 가기. 차단 목록에서 해제하면 다시 보인다.
- 신고: 사유 시트(`ReportSheet`, Bottom Sheet 07) 「{번치} 번치를 신고할까요?」, 부제 「{내 번치} 계정으로 신고해요」(2026-11-04 Figma 변경), 사유 단일 선택(스팸·음란 · 부적절한 내용·괴롭힘 · 욕설·개인정보 노출·기타), 기타는 상세 사유 필수(최대 200자), 사유 전에는 「신고하기」 비활성. 신고하면 시트를 닫고 「신고가 접수됐어요.」 토스트(기능명세 5.10.7).
- 명의는 지금 내 번치다. 서버 렌더·첫 hydration에는 저장된 내 번치를 몰라 차단 여부를 알 수 없으므로, 프로필·목록 대신 헤더만 그린 뒤 확인되면 그린다(차단한 번치 내용이 잠깐 보이지 않게). 내 번치를 모르는 동안 더보기도 숨긴다. API를 연결하면 접근 제한은 서버가 막아야 한다(차단한 번치의 내용이 응답에 실리지 않게).
- 범위 외: 서버 처리·실패, 상대가 나를 차단한 경우의 접근 제한(지금은 내가 차단한 경우만), 신고 횟수 제한.
- 1110판 5.10.7: 같은 번치(현재 번치 명의)는 같은 대상을 첫 신고부터 24시간 동안 최대 2번 신고한다(같은 번치 다른 멤버 신고 포함). 3번째는 서버가 접수하지 않고, 시트를 닫은 뒤 「이미 신고가 접수되어 검토 중이에요.」 토스트를 띄운다. 구현은 아직 이전 기준(늘 접수 토스트)이다.

## 확인할 항목

- Figma의 다른 번치 화면에는 하단 탭 막대와 「+」가 있다. spec 기준(1~9번 단위는 탭 경로 밖)에 따라 탭 막대 없이 두었고, 「+」(번들 만들기)는 다른 번치에서 쓸 수 없어 뺐다.
- 헤더에 알림은 없다(Figma `5402:122344`, 다른 번치에서는 숨김).
- 시트 그림 자리는 Figma가 회색 원이지만 화면설계서(3·4번)대로 상대 번치 대표 이미지를 넣었다(92px).
- 멤버 수 링크는 다른 수치와 겉모습이 같아 링크라는 시각 단서가 없다(Figma 기준이라 그대로, 디자이너 확인).
