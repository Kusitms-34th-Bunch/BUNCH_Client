# 페이지: 번치 멤버 관리와 역할별 권한 안내

## 메타데이터

- Route: `/bunch/members`(`apps/web/src/app/(app)/bunch/members/page.tsx`), `/bunch/members/roles`(`.../members/roles/page.tsx`)
- Status: 멤버 목록, 역할별 관리 메뉴·확인 창·토스트, 권한 안내 표 구현. 이슈 #175. 서버 목록과 지정·해제·넘기기·내보내기 연결(#330).
- 디자인 출처: Figma `관리자 뷰`(`2500:65206`), `관리자 권한주기(1)`(`2198:47143`), `내보내기 (2)`(`2236:38618`), `관리자 권한 해제(1)`(`2236:38658`), `멤버 뷰`(`2637:49761`·`2643:33078`·`2643:33525`), `권한`(`2500:54066`, 화면설계서 안 사본 `3289:79956`은 「번들 업로드」 문구만 다름). 화면설계서 `멤버 관리`(`2198:42965`, 1~4-1번).
- 기능 spec: 기능명세서 5.6(1110판, 2026-11-10 기준), `docs/specs/bunch-home.md`.

## 목적과 범위

### 포함

- 「멤버 N/8명」과 멤버 목록. 메인 관리자 → 공동 관리자 → 일반 멤버 순, 같은 역할은 이름 오름차순(화면설계서 1번). 나는 이름 뒤 「(나)」.
- 관리 메뉴(`ActionDialog`, Figma Dialog `Profile (Stack)`): 프로필 사진·이름·역할, 동작 버튼, 「취소」.
- 동작마다 확인 창과 토스트(체크 아이콘). 처리하면 목록이 바로 바뀌고 다시 정렬된다.
- 「역할별 권한보기」: 기호 안내와 번치·번들 권한 표(보기만, 화면설계서 1-1).

### 범위 외(후속)

- 더보기 메뉴·나가기 화면 등 다른 화면은 아직 fixture 멤버(`useBunchMembers`)를 쓴다. 나가기·삭제 연결(#330 뒤 4번 이슈) 때 바꾼다.

### 서버 연결(#330)

- 목록: 내 기본 번치(`members/me`)의 `GET /bunches/{id}/memberships`. 번치를 전환하면 서버의 마지막 사용 번치가 바뀌어 기본 번치가 되므로(#313) 지금 보고 있는 번치와 같다. 들어올 때마다 새로 받는다(`staleTime: 0`). 번치 이름은 번치 홈(`/home`)에서 받는다. 받는 동안은 로딩(sr-only 「멤버를 불러오는 중이에요」), 받은 값이 없을 때만 오류 화면과 「다시 시도」, 기본 번치가 없으면 번치 탭으로 보낸다.
- 관리 메뉴: 서버가 멤버마다 준 동작(`actions`: `canGrantCoOwner`·`canRevokeCoOwner`·`canTransferOwner`·`canRemove`)만 보이고, 하나도 없으면 「⋯」를 숨긴다. 서버가 요청 시점의 권한으로 다시 판단한다.
- 처리: 지정·해제 `PUT …/memberships/{id}/role`(CO_OWNER·MEMBER), 내보내기 `POST …/memberships/{id}/remove`, 넘기기 `POST /bunches/{id}/owner-transfer`(`Idempotency-Key`). 모두 요청자 소속 ID(`actorMembershipId`)와 목록을 받을 때의 버전(`expectedMembershipVersion`)을 보낸다.
- 처리 중: 창을 닫은 뒤 응답까지 「⋯」를 숨기고(같은 요청이 두 번 가지 않게) sr-only status로 「처리하는 중이에요」를 알린다.
- 성공: 번치 홈 전체(개수·내 역할·권한·이 목록), 멤버 목록(`sharedKeys.bunchMembers`, 번치 홈·사진함·번들), 전환 목록(`myBunches`)을 다시 받은 뒤 토스트를 띄운다. 관리 처리를 한 뒤 초점을 잃었으면 「멤버 N/8명」 줄로 옮긴다. 주로 창이 닫힐 때 옮기고, 창이 닫힌 뒤 응답이 와 행이 사라지면 화면에 반영된 뒤 한 번 더 확인한다(들어올 때·다시 받을 때는 옮기지 않음). 실패 뒤 목록을 다시 받는 동안도 처리 중으로 둔다. 번치 이름을 받지 못하면 내보내기 확인 창은 「번치」로 쓴다.
- 닉네임이 없는 멤버는 「알 수 없는 멤버」로 보인다.
- 실패: 목록을 다시 받아 버전이 요청한 버전과 다르면(그 사이 다른 곳에서 바뀜) 「멤버 정보가 바뀌어 최신 목록으로 다시 불러왔어요.」, 같으면 「처리하지 못했어요. 잠시 후 다시 시도해 주세요.」를 띄운다. 다시 받기도 실패하면 목록·버전이 오래됐으므로 관리하지 않고 오류 화면과 「다시 시도」를 보인다(받으면 목록으로 돌아옴). 충돌 오류 코드는 Swagger에 없어 버전으로 판단한다.
- 번치 홈 프로필의 멤버 수를 눌러 들어오는 진입(5.1.4). 1110판은 이 진입을 「멤버 리스트 화면」으로 바꿨다. 멤버 관리와 같은 화면인지 확인한다.
- 1110판 5.6.2: 역할별 권한 안내는 역할 변경 알림(5.12.3의 11~13번, 앱 안 알림·푸시)으로도 들어온다. 뒤로가기는 들어온 경로에 따라 다르다. 멤버 관리·알림 목록에서 왔으면 그 화면, 앱 사용 중 푸시면 푸시 전 화면(번치가 바뀌었으면 그 번치 메인), 꺼진 앱에서 푸시면 그 번치 메인이다. 구현은 아직 이전 기준(기록이 없으면 멤버 관리)이다.

## 역할별 관리

| 나 \ 대상   | 메인 관리자 | 공동 관리자                            | 일반 멤버                                |
| ----------- | ----------- | -------------------------------------- | ---------------------------------------- |
| 메인 관리자 | (나)        | 공동 관리자 해제하기, 넘기기, 내보내기 | 공동 관리자로 지정하기, 넘기기, 내보내기 |
| 공동 관리자 | 없음        | 내보내기(나 제외)                      | 내보내기                                 |
| 일반 멤버   | 없음        | 없음                                   | 없음                                     |

- 관리할 수 없는 행에는 「⋯」 버튼이 없다.
- 일반 멤버에게도 「관리자 권한 넘기기」를 둔다. 화면설계서 4번은 공동 관리자 메뉴에서 넘긴다고 적었지만 Figma 화면(`2198:47143`)을 따랐다(사용자 결정).
- 공동 관리자의 내보내기 범위는 Figma 권한 표(멤버 내보내기: 공동 관리자 허용, 메인 관리자는 내보낼 수 없음)를 따랐다(사용자 결정). 1110판 5.6.2 표도 같다.
- 넘기면 대상이 메인 관리자가 되고 나는 일반 멤버로 남는다. 내 역할이 바뀌므로 목록의 「⋯」가 사라지고, 더보기 메뉴·프로필 편집도 같은 저장소의 역할을 쓴다.

| 동작     | 확인 창 제목·설명                                                                                               | 버튼     | 토스트                                        |
| -------- | --------------------------------------------------------------------------------------------------------------- | -------- | --------------------------------------------- |
| 지정     | 「{이름}님을 공동 관리자로 지정할까요?」 / 「번치를 함께 관리할 수 있어요.」                                    | 완료     | 「{이름}님이 공동 관리자가 되었어요.」        |
| 해제     | 「{이름}님의 공동 관리자 권한을 해제할까요?」 / 「해제 시 일반 멤버로 바뀌어요.」                               | 해제하기 | 「{이름}님의 공동 관리자 권한을 해제했어요.」 |
| 넘기기   | 「{이름}님에게 관리자 권한을 넘길까요?」 / 「넘긴 뒤에는 일반 멤버로 번치에 남아요.」                           | 완료     | 「{이름}님이 관리자가 되었어요.」             |
| 내보내기 | 「{이름}님을 {번치}에서 내보낼까요?」 / 「{이름}님이 올린 사진은 사진함에서 삭제되고, 발행된 번들에만 남아요.」 | 내보내기 | 「{이름}님을 번치에서 내보냈어요.」           |

- 관리 메뉴가 다 닫힌 뒤 확인 창을 연다(모달 → 모달). 확인 창의 「취소」는 아무것도 바꾸지 않는다.
- 토스트는 확인 창이 다 닫힌 뒤 띄운다(열린 창 뒤에서 낭독이 묻히지 않게).
- 내보내기·넘기기로 돌아갈 「⋯」가 사라지면 초점을 「멤버 N/8명」 줄로 옮긴다. 지정·해제는 같은 행이 다시 정렬될 뿐이라 「⋯」로 돌아간다.
- 지정 확인 창의 버튼 이름은 화면설계서 2-1-1의 「완료」다(Figma 화면을 받지 못함).

## Route와 접근

- 진입: 더보기 메뉴 「멤버 관리」 링크(모든 역할). 헤더 「+ 멤버 초대」는 `/bunch/members/invite`(`features/bunch-invite`의 초대 화면)로 `push`한다. 메뉴 ↔ 멤버 관리, 멤버 관리 ↔ 권한 안내는 메뉴 하위 화면과 같은 미는 slide 300ms(화면설계서에 정의 없음). 탭 경로 밖이라 iOS 앱에서는 시스템 탭 바가 숨는다.
- 경로를 `/bunch/menu/` 아래에 두지 않은 이유: 번치 홈 프로필의 멤버 수에서도 들어올 예정이다(5.1.4).
- 뒤로 가기: 기록이 있으면 `router.back()`, 없으면 멤버 관리는 더보기 메뉴로, 권한 안내는 멤버 관리로 `replace`.
- 첫 hydration은 저장된 번치를 몰라 목록을 그리지 않는다. 역할 확인은 화면 표시용이고 서버가 요청 시점의 역할로 다시 판단해야 한다.

## UI와 접근성

- Component mapping: `Header`(뒤로 가기, 번치 이름 제목, `TextButton` sm 「+ 멤버 초대」), `ProfileListItem`(역할 배지, 「⋯」), `ActionDialog`(관리 메뉴·확인 창), `ProfileImage` 56px(대화상자 이미지), `RoleBadge`(권한 표 열 머리).
- 간격(Figma `2500:65206`): 헤더 아래 16, 요약 줄과 목록 사이 12, 행 사이 8.
- 권한 표(Figma `2500:54066`): 헤더 아래 12, 기호 안내와 표 사이 36, 표 묶음 사이 28, 표 제목과 표 사이 14, 행 높이 37. 표 제목 radius는 Figma 9px라 가장 가까운 `r5`(10)를 썼다.
- 원·세모 기호는 디자인 시스템 아이콘이 없어 Figma 벡터를 화면 안에 옮겼다. 닫기는 `LineCloseSmallIcon`.
- 목록은 `ul`/`li`. 「⋯」 이름은 「{이름} 관리」. 역할 배지는 「메인 관리자」·「공동 관리자」로 읽힌다.
- 권한 표는 `table`(caption 「번치 역할별 권한」 등), 열 머리는 역할 배지 이미지 이름, 행 머리는 권한 이름, 칸은 「모두 허용」·「일부 허용」·「권한 없음」 이미지 이름으로 읽힌다. 「*」는 장식이라 읽히지 않는다. 대신 각주가 붙은 행 이름 뒤에 각주 문장을 sr-only로 붙이고, 「일부 허용」 칸은 「일부 허용, 해당 번들에 참여한 경우만」으로 읽힌다.
- 헤더에 화면 이름이 없어 `sr-only` `h1`(「{번치} 멤버 관리」, 「역할별 권한」)을 둔다.

## 확인할 항목

- 관리 메뉴의 역할 설명: Figma는 일반 멤버만 「일반 멤버」를 쓰고 공동 관리자 화면(`2637:49761`)에는 설명이 없다. 지금은 두 역할 모두 역할 이름을 보여 준다.
- 관리 메뉴의 첫 초점은 디자인 시스템 정책대로 「취소」이고, 제목이 이름뿐이라 목적(관리)이 드러나지 않는다. 「⋯」에 `aria-haspopup`이 없고 역할 배지가 이름 앞에서 읽힌다. 셋 다 `ActionDialog`·`ProfileListItem`을 바꿔야 해 디자인 시스템 후속으로 둔다.
- 권한 표의 내용은 `docs/specs/bunch-home.md` 권한 표와 함께 Figma 기준으로 맞췄다. 서버 권한 규칙은 백엔드와 확인한다.
- 1110판 5.6.2 번치 권한 표의 마지막 행은 「다른 번치 차단 해제」다(차단은 멤버 누구나). 구현(`BunchRoleGuide`)은 아직 「다른 번치 차단」이다. 번들 표의 「작성 중인 번들 업로드」는 구현과 같다.
- 1110판 5.6.1: 공동 관리자가 일반 멤버를 열 때 버튼은 「내보내기」다. 구현은 아직 「번치에서 내보내기」다.
- 1110판 5.6.5: 내보낸 멤버의 기존 번들 코멘트는 작성자 「작성자」, 내용 「삭제된 코멘트입니다」로 보인다(6.2.5). 같은 계정이 다시 들어오면 참여 멤버·픽·코멘트를 복구하고 사진함에서 지운 사진은 복구하지 않는다. 다시 들어오면 일반 멤버다. 서버 처리라 API 연결 때 확인한다.
