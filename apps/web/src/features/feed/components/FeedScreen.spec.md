# 페이지: 피드 탭

## 메타데이터

- Route: `/feed`(`apps/web/src/app/(app)/(main)/feed/page.tsx`, #263). 하단 탭 화면(`MainTabPage`)
- 소유: `features/feed`. 번치 홈 쪽 주소(알림·번치 탭·다른 번치 프로필)는 route-local `FeedRoute`가 `BUNCH_HOME_PATHS`로 조합해 넘긴다(feature끼리 import하지 않음)
- Status: 목록은 서버(`GET /feed`, #364)이고 끝에 닿으면 다음 쪽을 이어 받는다. UI는 개발 서버 Chrome 375폭 렌더로 Figma와 대조(샘플 데이터 때). 실기기 전
- 기능명세: 피드 6.1(`docs/specs/feed.md` 구현 단위 1). 기능명세서 1110판(2026-11-10) 대조
- 디자인 출처: Figma 피드 `4940:99466`(섹션 「피드」 `4940:100716`), 헤더 `4940:99533`, 구간 안내 `4940:101293`, 끝 안내 `4940:101966`

## 목적과 범위

### 포함

- 헤더: 로고(누르면 맨 위로), 알림(번치 알림 목록), 지금 번치 이미지(번치 탭). 지금 번치는 내 정보의 기본 번치(`myProfileQueryOptions`, 번치 홈과 같은 기준)
- 번들 카드(`FeedBundleCard`) 목록: 서버 응답 `items` 순서대로 팔로우한 번치 구간 → 구간 안내(축하 로티와 양옆 선, 서버의 `FOLLOWING_CAUGHT_UP` 자리) → 공개 구간 → 끝 안내(체크 로티). 두 목록은 카드의 `segment`로 나누고, 구간 안내는 그 항목이 온 뒤에 보인다. 모르는 항목 type은 건너뛴다
- 카드 글자: 장소는 「{첫 장소} 외 N곳」, 날짜는 올해도 「YYYY년 M월 D일」. 피드 응답에는 콕 여부가 없어 콕하기 시트의 장소는 모두 「콕하기」로 시작한다(API 연동 8번에서 연결)
- 이어 받기: 목록 끝 표시가 화면에 보이면 다음 쪽(`hasNext`이고 `nextCursor`가 있을 때). 더 받을 쪽이 없을 때만 끝 안내를 보인다. 같은 커서가 다시 오면 멈춘다
- 피드는 지금 번치(내 정보의 기본 번치)를 안 뒤에 받는다. query key에 명의를 넣어 번치를 바꾸면 처음부터 다시 받는다
- 차단·팔로우·소속 변경이 바로 보이게 피드 화면에 들어올 때마다 받은 쪽을 다시 받는다. 당겨서 새로고침도 받은 쪽 전부를 다시 받는다
- 경과 시간(`lib/elapsedTime.ts`): 「방금 전」·「N분 전」·「N시간 전」·7일까지 「N일 전」·8일부터 「YYYY년 M월 D일」. 브라우저에서만 계산한다(`useClientNow`, 서버 렌더·첫 hydration은 빈 글자). 서버와 브라우저의 시계·시간대가 달라 글자가 어긋나지 않게 하기 위함이며, 기준 시각은 화면에 들어온 시각이다. 피드에 다시 들어오거나 탭·앱으로 돌아와 다시 보일 때(`visibilitychange`) 갱신되고, 보고 있는 동안에는 갱신되지 않는다
- 카드에서 누르는 곳: 번치 → 지금 번치면 번치 탭, 아니면 다른 번치 프로필 / 사진 → 번들 상세 / 말풍선 → 번들 상세 댓글 영역 / 하트 → 좋아요(화면에서만 바꿈) / 위치 → 콕하기 시트 / 참여 멤버 → 참여 멤버 시트(시트는 `BundleDetailScreen.spec.md`)
- 광고 카드(`FeedAdCard`, `AdPhotoCard`, 6.1.5~6.1.6): 서버가 정한 자리(누적 번들 6개마다)에 둔다. 광고 이름은 카드 제목, 소개는 홍보 문구, 위치는 주소(없으면 장소 이름). 「콕하기」는 바로 담고, 「콕 했어요」는 콕 취소 확인 창을 띄운다. 연타는 첫 탭만 받는다
- 광고 숨기기: 더보기 → 확인 시트(`ConfirmSheet`, Figma `5991:164178`, 일러스트·「이 장소를 숨길까요?」·설명) → 그 자리에 「장소를 숨김 처리 했어요」(Figma `5367:127753`)를 4초 보인 뒤, 카드가 0.4초 동안 접히며 사라지고 아래 내용이 올라온다(요청 값, Figma에 없음). 동작 줄이기면 접힘 없이 바로 뺀다. 피드에 다시 들어와도 없다. 지금은 메모리 보관이라 새로고침하면 다시 보인다. 소속 번치가 없어도 숨길 수 있다
- 소속 번치가 없으면 헤더에 로고만, 공개 구간만, 좋아요는 「번치에 참여하면 할 수 있어요.」 토스트(6.1.7)

### 범위 외

- 다른 탭에 갔다 와도 스크롤 위치 유지(뒤로 오면 복원은 하고, 탭을 눌러 새로 들어오면 맨 위. 스크롤 값은 그 피드의 history 항목에 저장)
- 안 읽은 알림 점: 번치 홈 헤더처럼 Figma가 정해지면 추가
- 좋아요 서버 반영·실패 되돌리기(API 연동 3번), 장소 콕 상태(API 연동 8번), 광고 콕·숨김 서버 반영(API 연동 10번), 광고 사진을 눌러 외부로 나가는 동작(bridge 결정 후)
- 번들 상세는 아직 샘플이라 서버 카드에서 상세로 가면 「삭제되었거나 볼 수 없는 내용이에요」가 보인다(API 연동 2번에서 연결)

## 상태

- 지금 번치를 받는 중: 헤더 오른쪽은 알림과 번치 이미지 자리의 회색 원(응답 뒤 알림이 밀려 잘못 누르지 않게, 움직이지 않는 자리표시). 내 정보 요청이 실패하면 알림만(번치 이미지 없음). 번치 유무를 모르는 동안은 피드를 요청하지 않는다(명의에 따라 구간이 달라서). 내 정보 요청이 실패하면 아래 처음 받기 실패와 같은 안내를 보이고, 「다시 시도」는 내 정보부터 다시 받는다
- 피드를 처음 받는 중: 늘 있는 상태 영역에 「피드를 불러오는 중이에요」(화면에는 보이지 않음). 처음 받기에 실패하면 「일시적인 오류가 발생했어요. 다시 시도해 주세요」와 「다시 시도」
- 다음 쪽 받는 중: 같은 상태 영역에 「피드를 더 불러오는 중이에요」. 다음 쪽이 `FEED_001`(번치·팔로우가 그사이 바뀜)이면 받은 쪽을 버리고 처음부터 다시 받는다. 저절로는 연달아 한 번만 하고, 또 `FEED_001`이면 아래 실패 안내로 넘긴다(이때 「다시 시도」는 처음부터 다시 받음). 그 밖의 실패(400 포함)는 받은 카드를 두고 목록 끝에 「피드를 더 불러오지 못했어요」와 「다시 시도」
- 「다시 시도」는 누른 뒤 응답이 올 때까지 남아 있고 다시 누를 수 없다(`aria-disabled`)
- 소속 번치 없음: 위 「포함」 마지막 항목
- 번들이 하나도 없으면 끝 안내만

## 접근성

- 화면 제목 `h1`(「피드」, 화면에서는 숨김), 카드 제목은 `h2`, 목록은 구간마다 `ul`
- 로고 버튼 이름은 「BUNCH, 맨 위로」, 지금 번치 링크는 「{번치 이름} 번치 홈」
- 로티는 장식(`aria-hidden`), 안내 글자는 일반 문단. 동작 줄이기면 재생하지 않고 축하는 첫 장면, 체크는 마지막 장면(체크가 보이는 상태)
- 광고를 숨기면 더보기 버튼이 사라지므로 초점을 숨김 카드로 옮기고, 같은 알림 영역에서 안내를 읽어 준다. 카드가 사라질 때 초점이 그 안에 있으면 다음 카드의 첫 버튼으로 옮기고, 다음 카드가 없으면 이어 받기 자리나 끝 안내로 옮긴다
- 「다시 시도」가 성공해 버튼이 사라지면 초점은 새로 받은 첫 카드로 간다. 이어 받기 자리는 「다음 피드」라는 이름의 group이다
- 실패 안내는 `role="alert"`로 읽어 준다. 받는 중 문구는 늘 있는 `role="status"` 영역 하나에서 글자만 바꾼다
- 로고로 맨 위로 갈 때 동작 줄이기면 바로 이동. 초점은 고정 헤더의 로고 버튼에 남는다
- 헤더 누르는 영역: 로고 43px 높이, 알림 40px·번치 이미지 44px(사이 16px라 겹치지 않음)

## Styling과 의존성

- 카드 목록 좌우 16, 카드 사이 32(`gap-s14`), 위 16. 구간 안내 위아래 32, 선과 글자 사이 9(`gap-2.25`, 토큰 없음), 선은 `border-tertiary`. 끝 안내 위아래 40
- 로고는 Figma에서 받은 `shared/assets/images/logo/wordmark-dark.svg`(76×19, Figma `4940:99533`)
- 로티는 안내가 처음 화면에 보일 때(`useInView`, IntersectionObserver) `LazyLottie`(`loop={false}`, 동작 줄이기 장면 `stillFrame`)로 `feedCaughtUp*.json`을 받아 한 번 재생. 스크롤해 다시 보일 때는 재생하지 않고, 피드에 다시 들어오면 다시 재생. 안내 글자(구간 안내는 양옆 선 포함)도 그때 0.233초 동안 투명 → 선명으로 나타난다(체크 모션의 투명도 구간과 같음, Figma에는 없지만 디자이너 확인). 글자는 처음부터 DOM에 있어 화면 낭독은 모션과 무관하고, 동작 줄이기면 모션 없이 보인다

## 확인할 항목

- 구간·끝 안내 글자 `text-quinary`(#BCBEC2)는 흰 바탕에서 약 1.9:1이다(Figma 값). 상태를 알리는 글자라 진한 회색(`text-quaternary`·`text-tertiary`)으로 바꿀지 디자이너 확인
- 동작 줄이기에서 체크 로티가 마지막 장면으로 그려지는지는 실제 렌더로 확인하지 않았다(테스트는 로티를 대체함)
- 피드를 받는 중과 다음 쪽을 받는 중의 화면 모양(스켈레톤·스피너)은 Figma에 없어 지금은 화면 낭독 문구만 있다. 디자이너 확인
- 실패 안내와 「다시 시도」 버튼의 모양도 Figma에 없어 `tertiary` 버튼으로 두었다. 디자이너 확인
- 응답의 `currentBunchId`가 화면이 아는 지금 번치와 다를 때(번치 전환 직후 등)는 비교하지 않는다. 실서버에서 어긋나는지 확인

- 「N일 전」은 24시간 단위로 셌다(어제 밤 글이 오늘 아침에 「N시간 전」). 달력 날짜 기준인지 기획 확인
- 광고 숨김 자리: 1110판 6.1.6 상세 3은 회색 카드와 체크 아이콘이다. 구현은 Figma `State=Hidden`대로 체크 모션과 안내 글자다(보이는 모양은 Figma 우선, 디자이너 확인)
- 광고 장소 정보: 1110판 6.1.5 상세 3은 소개와 위치(핀 아이콘)를 줄을 나눠 쓴다. 구현은 한 줄에 이어 쓰고 넘치면 줄바꿈한다(Figma 기준 확인)

## 검증

- 단위 테스트: 경과 시간 경계값, 구간 순서·안내 위치, 두 구간이 모두 빈 경우, 헤더 링크, 카드 누름 이동, 위치·참여 멤버 시트 열기, 좋아요 수, 소속 번치 없음(로고만·공개 구간만·토스트)
- 서버 연동 단위 테스트: 모르는 type 건너뛰기, 이어 받기, `FEED_001` 재시작과 연달아 한 번 제한, 400은 재시작 없이 다시 시도, 다시 시도 중 버튼·초점 유지, 다음 쪽·처음 받기·내 정보 실패의 다시 시도
- 광고 단위 테스트: 숨김 안내·접힘 시간과 목록 제거, 초점 이동(끝 카드는 끝 안내, 중간 카드는 다음 카드), 닫히는 중 재오픈 취소, 소속 번치 없음, 콕하기 연타·재탭, 콕 취소
- 광고 확인 시트는 Chrome 폭 430 측정 뒤 간격을 고쳤고, 고친 화면은 사용자 확인(Figma `5991:164178`)이다. 동작 줄이기와 실기기는 확인 전이다
- 개발 서버(Chrome, 폭 375) 측정: 헤더 48, 카드 343×463(사진 429 + 간격 10 + 반응 줄 24), 카드 사이 32, 구간 안내 높이 121, 끝 안내 높이 137로 Figma와 같음
