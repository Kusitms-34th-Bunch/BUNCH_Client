## 목적과 범위

### 포함

- 헤더: 로고(누르면 맨 위로), 알림(번치 알림 목록), 지금 번치 이미지(번치 탭). 지금 번치는 내 정보의 기본 번치(`myProfileQueryOptions`, 번치 홈과 같은 기준)
- 카드 → 번들 상세 전환: 카드 사진이 상세 첫 사진 자리로 옮겨 가는 hero(Figma `6892:46500`, `docs/architecture/motion.md` 「페이지 전환」). 뒤로 가면 같은 hero로 카드 자리로 돌아온다. 사진에 손가락이 닿으면 상세·번치 정보를 미리 받고, 사진·말풍선을 누르면 받기가 끝나거나 400ms가 지난 뒤 이동한다(기다리는 동안 다시 누르면 무시, 동작 줄이기면 바로 이동)
- 헤더 스크롤 숨김: 아래로 스크롤하면 헤더가 위로 숨고, 위로 올리면 다시 나온다. 맨 위 근처는 항상 보인다(A안, 2026-11-15 사용자 결정, `docs/architecture/motion.md` 「스크롤로 헤더 숨김」). 헤더의 흰 배경은 상태 표시줄 자리까지 덮고 함께 오르내려, 헤더가 숨으면 본문이 상태 표시줄 뒤까지 올라간다(Facebook 방식, 상태 표시줄 자리에는 흐림 없음)
- 번들 카드(`FeedBundleCard`) 목록: 서버 응답 `items` 순서대로 팔로우한 번치 구간 → 구간 안내(축하 로티와 양옆 선, 서버의 `FOLLOWING_CAUGHT_UP` 자리) → 공개 구간 → 끝 안내(체크 로티). 두 목록은 카드의 `segment`로 나누고, 구간 안내는 그 항목이 온 뒤에 보인다. 안내가 오기 전에는 마지막 팔로우 카드 뒤의 광고도 팔로우 목록에 둬 다음 쪽이 와도 광고가 다시 그려지지 않는다. 모르는 항목 type은 건너뛴다
- 카드 글자: 장소는 「{첫 장소} 외 N곳」, 날짜는 올해도 「YYYY년 M월 D일」. 피드 응답에는 콕 여부가 없어 콕하기 시트를 열 때 따로 받는다(명세 021, 시트 동작은 `BundleDetailScreen.spec.md`)
- 이어 받기: 목록 끝 표시가 화면에 보이면 다음 쪽(`hasNext`이고 `nextCursor`가 있을 때). 더 받을 쪽이 없을 때만 끝 안내를 보인다. 같은 커서가 다시 오면 멈춘다
- 피드는 지금 번치(내 정보의 기본 번치)를 안 뒤에 받는다. query key에 명의를 넣어 번치를 바꾸면 처음부터 다시 받는다
- 차단·팔로우·소속 변경이 바로 보이게 피드 화면에 들어올 때마다 받은 쪽을 다시 받는다. 당겨서 새로고침도 받은 쪽 전부를 다시 받는다
- 경과 시간(`lib/elapsedTime.ts`): 「방금 전」·「N분 전」·「N시간 전」·7일까지 「N일 전」·8일부터 「YYYY년 M월 D일」. 브라우저에서만 계산한다(`useClientNow`, 서버 렌더·첫 hydration은 빈 글자). 서버와 브라우저의 시계·시간대가 달라 글자가 어긋나지 않게 하기 위함이며, 기준 시각은 화면에 들어온 시각이다. 피드에 다시 들어오거나 탭·앱으로 돌아와 다시 보일 때(`visibilitychange`) 갱신되고, 보고 있는 동안에는 갱신되지 않는다
- 카드에서 누르는 곳: 번치 → 지금 번치면 번치 탭, 아니면 다른 번치 프로필 / 사진 → 번들 상세 / 말풍선 → 번들 상세 댓글 영역 / 하트 → 좋아요(아래 「좋아요」) / 위치 → 콕하기 시트 / 참여 멤버 → 참여 멤버 시트(시트는 `BundleDetailScreen.spec.md`)
- 광고 카드(`FeedAdCard`, `AdPhotoCard`, 6.1.5~6.1.6): 서버가 정한 자리(누적 번들 6개마다)에 둔다. 광고 이름은 카드 제목, 소개는 홍보 문구, 위치는 주소(없으면 장소 이름). 「콕하기」는 바로 담고, 「콕 했어요」는 콕 취소 확인 창을 띄운다. 연타는 첫 탭만 받는다. 콕은 명세 022, 취소는 번들 장소와 같은 명세 009로 보내고 콕 상태는 피드 캐시의 그 광고(같은 광고의 모든 자리)에 둔다. 실패하면 되돌리고 「일시적인 오류가 발생했어요. 다시 시도해 주세요」, 다른 멤버가 이미 뺀 콕의 취소는 알리지 않고 「콕하기」로 둔다. 콕 응답 전(콕 ID 없음)에는 취소를 받지 않는다
- 광고 숨기기: 더보기 → 확인 시트(`ConfirmSheet`, Figma `5991:164178`, 일러스트·「이 장소를 숨길까요?」·설명) → 그 자리에 「장소를 숨김 처리 했어요」(Figma `5367:127753`)를 4초 보인 뒤, 카드가 0.4초 동안 접히며 사라지고 아래 내용이 올라온다(요청 값, Figma에 없음). 동작 줄이기면 접힘 없이 바로 뺀다. 숨기기는 확인하면 명세 023으로 보내고, 시트가 닫힌 뒤 성공하면 안내를 보인다(응답을 기다리는 사이 초점을 다른 곳으로 옮겼으면 초점은 그대로). 받는 동안 카드는 `aria-busy`와 「장소를 숨기는 중이에요」를 알리고 더보기는 무시한다. 실패하면 카드를 그대로 두고 공통 오류 토스트다. 숨긴 광고는 서버가 피드에서 빼서 새로고침 뒤에도 없고, 앱이 켜져 있는 동안은 받아 둔 목록에서도 뺀다. 안내를 보이는 4초 사이 피드를 다시 받으면 카드가 바로 빠진다(제약). 소속 번치가 없어도 숨길 수 있다
- 좋아요(`PUT·DELETE /bundles/{bundleId}/like`, 명세 011·012, #369): 지금 번치 명의다. 누르면 응답 전에 하트와 수를 바꾸고(피드 카드와 상세 캐시 함께), 실패하면 그 카드의 좋아요만 누르기 전 값(연달아 눌렀으면 마지막으로 확정된 값)으로 되돌리고 「좋아요를 반영하지 못했어요. 다시 시도해 주세요」 토스트. 403·404·409 실패면 내 정보와 피드를 다시 받는다. 연타는 첫 탭만 받고(0.4초), 요청은 순서대로 보내 마지막 누른 값이 남는다. 응답의 지금 번치가 화면 명의와 다르면 내 정보와 피드를 다시 받는다
- 소속 번치가 없으면 헤더에 로고만, 공개 구간만, 좋아요는 「번치에 참여하면 할 수 있어요.」 토스트(6.1.7)

### 범위 외

- 다른 탭에 갔다 와도 스크롤 위치 유지(뒤로 오면 목록이 그려진 뒤 복원하고, 탭을 눌러 새로 들어오면 맨 위. 스크롤 값은 그 피드의 history 항목에 저장)
- 안 읽은 알림 점: 번치 홈 헤더처럼 Figma가 정해지면 추가
- 광고 사진을 눌러 외부로 나가는 동작(bridge 결정 후)

## 상태

- 지금 번치를 받는 중: 헤더 오른쪽은 알림과 번치 이미지 자리의 회색 원(응답 뒤 알림이 밀려 잘못 누르지 않게, 움직이지 않는 자리표시). 내 정보 요청이 실패하면 알림만(번치 이미지 없음). 번치 유무를 모르는 동안은 피드를 요청하지 않는다(명의에 따라 구간이 달라서). 내 정보 요청이 실패하면 아래 처음 받기 실패와 같은 안내를 보이고, 「다시 시도」는 내 정보부터 다시 받는다
- 피드를 처음 받는 중: 늘 있는 상태 영역에 「피드를 불러오는 중이에요」(화면에는 보이지 않음). 처음 받기에 실패하면 「일시적인 오류가 발생했어요. 다시 시도해 주세요」와 「다시 시도」
- 다음 쪽 받는 중: 같은 상태 영역에 「피드를 더 불러오는 중이에요」. 다음 쪽이 `FEED_001`(번치·팔로우가 그사이 바뀜)이거나 400(커서 오류, size는 고정)이면 받은 쪽을 버리고 처음부터 다시 받는다. 저절로는 연달아 한 번만 하고, 또 같은 실패면 아래 실패 안내로 넘긴다(이때 「다시 시도」는 처음부터 다시 받음). 그 밖의 실패는 받은 카드를 두고 목록 끝에 「피드를 더 불러오지 못했어요」와 「다시 시도」
- 「다시 시도」는 누른 뒤 응답이 올 때까지 남아 있고 다시 누를 수 없다(`aria-disabled`)
- 소속 번치 없음: 위 「포함」 마지막 항목
- 번들이 하나도 없으면 끝 안내만

## 접근성

- 화면 제목 `h1`(「피드」, 화면에서는 숨김), 카드 제목은 `h2`, 목록은 구간마다 `ul`
- 로고 버튼 이름은 「BUNCH, 맨 위로」, 지금 번치 링크는 「{번치 이름} 번치 홈」
- 로티는 장식(`aria-hidden`), 안내 글자는 일반 문단. 동작 줄이기면 재생하지 않고 축하는 첫 장면, 체크는 마지막 장면(체크가 보이는 상태)
- 광고를 숨기면 더보기 버튼이 사라지므로 초점을 숨김 카드로 옮기고, 같은 알림 영역에서 안내를 읽어 준다. 카드가 사라질 때 초점이 그 안에 있으면 다음 카드의 첫 버튼으로 옮기고, 다음 카드가 없으면 이어 받기 자리나 끝 안내로 옮긴다
- 「다시 시도」가 성공해 버튼이 사라지면 초점은 새로 받은 첫 카드로 간다. 처음부터 다시 받은 경우는 새 목록의 첫 카드로 간다. 내 정보 다시 시도는 이어지는 피드 요청이 끝난 뒤 옮긴다. 카드가 없으면 다시 나타난 「다시 시도」, 이어 받기 자리, 끝 안내, 화면 제목(`h1`) 순으로 간다. 이어 받기 자리는 「다음 피드」라는 이름의 group이다
- 실패 안내는 `role="alert"`로 읽어 준다. 받는 중 문구는 늘 있는 `role="status"` 영역 하나에서 글자만 바꾼다
- 로고로 맨 위로 갈 때 동작 줄이기면 바로 이동. 초점은 헤더의 로고 버튼에 남는다(위로 올라가므로 헤더가 다시 보임)
- 헤더 누르는 영역: 로고 43px 높이, 알림 40px·번치 이미지 44px(사이 16px라 겹치지 않음)

## Styling과 의존성

- 카드 목록 좌우 16, 카드 사이 32(`gap-s14`), 위 16. 구간 안내 위아래 32, 선과 글자 사이 9(`gap-2.25`, 토큰 없음), 선은 `border-tertiary`. 끝 안내 위아래 40
- 로고는 Figma에서 받은 `shared/assets/images/logo/wordmark-dark.svg`(76×19, Figma `4940:99533`)
- 로티는 안내가 처음 화면에 보일 때(`useInView`, IntersectionObserver) `LazyLottie`(`loop={false}`, 동작 줄이기 장면 `stillFrame`)로 `feedCaughtUp*.json`을 받아 한 번 재생. 스크롤해 다시 보일 때는 재생하지 않고, 피드에 다시 들어오면 다시 재생. 안내 글자(구간 안내는 양옆 선 포함)도 그때 0.233초 동안 투명 → 선명으로 나타난다(체크 모션의 투명도 구간과 같음, Figma에는 없지만 디자이너 확인). 글자는 처음부터 DOM에 있어 화면 낭독은 모션과 무관하고, 동작 줄이기면 모션 없이 보인다

## 확인할 항목

- 구간·끝 안내 글자 `text-quinary`(#BCBEC2)는 흰 바탕에서 약 1.9:1이다(Figma 값). 상태를 알리는 글자라 진한 회색(`text-quaternary`·`text-tertiary`)으로 바꿀지 디자이너 확인
- 동작 줄이기에서 체크 로티가 마지막 장면으로 그려지는지는 실제 렌더로 확인하지 않았다(테스트는 로티를 대체함)
- 피드를 받는 중과 다음 쪽을 받는 중의 화면 모양(스켈레톤·스피너)은 Figma에 없어 지금은 화면 낭독 문구만 있다. 디자이너 확인
- 실패 안내와 「다시 시도」 버튼의 모양도 Figma에 없어 `tertiary` 버튼으로 두었다. 디자이너 확인
- 응답의 `currentBunchId`가 화면이 아는 지금 번치와 다를 때(번치 전환 직후 등)는 비교하지 않는다. 실서버에서 어긋나는지 확인

- 「N일 전」은 24시간 단위로 셌다(어제 밤 글이 오늘 아침에 「N시간 전」). 달력 날짜 기준인지 기획 확인
- 광고 숨김 자리: 1110판 6.1.6 상세 3은 회색 카드와 체크 아이콘이다. 구현은 Figma `State=Hidden`대로 체크 모션과 안내 글자다(보이는 모양은 Figma 우선, 디자이너 확인)
- 광고 장소 정보: 1110판 6.1.5 상세 3은 소개와 위치(핀 아이콘)를 줄을 나눠 쓴다. 구현은 한 줄에 이어 쓰고 넘치면 줄바꿈한다(Figma 기준 확인)
