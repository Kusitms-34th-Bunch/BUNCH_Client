# 페이지: 번들 상세

## 메타데이터

- Route: `/bunches/[bunchId]/bundles/[bundleId]`(`apps/web/src/app/(app)/bunches/[bunchId]/bundles/[bundleId]/page.tsx`, #266, #367에서 번치 ID를 주소에 넣음). 하단 탭 없음(`(main)` 밖). 말풍선에서는 `?focus=comments`
- 소유: `features/feed`. 번치 쪽 주소와 번치 이름·이미지(상세 응답에 없어 번치 홈 응답의 `bunch`)는 route-local `BundleDetailRoute`가 조합해 넘긴다
- Status: 내용은 서버(`GET /bunches/{bunchId}/published-bundles/{bundleId}`, 명세 084, #367). 좋아요·댓글·신고·삭제·공개 범위·콕은 아직 화면에서만 바뀐다. UI는 fixture 때 개발 서버 Chrome 렌더로 Figma와 대조. 실기기 전
- 기능명세: 피드 6.2(`docs/specs/feed.md` 구현 단위 2). 기능명세서 1110판(2026-11-10) 대조
- 디자인 출처: Figma `번들_전체` `5367:103510`, `번들_Empty` `5367:103541`, 콕 시트 `5367:112139`, 콕 취소 `5367:112361`, 참여 멤버 시트 `5367:112596`(섹션 「피드」 `4940:100716`)

## 목적과 범위

### 포함

- 헤더(뒤로 가기)와 아래 고정 입력란(`CommentComposer`), 그 사이만 스크롤
- 번치 정보·참여 멤버(`BundleAuthorInfo`): 번치를 누르면 지금 번치면 번치 탭, 아니면 다른 번치 프로필
- 제목·위치(「{첫 장소} 외 N곳」)·날짜(「YYYY년 M월 D일」)(`BundleInfo`), 멤버 공개면 제목 옆 뱃지. 상세 응답에는 콕 여부가 없어 콕하기 시트의 장소는 모두 「콕하기」로 시작한다(API 연동 8번)
- 사진(`BundlePhoto` `detail`): 둥근 카드를 넘기고 옆 사진이 살짝 보임, 사진마다 순번. 그 사진을 pick한 멤버가 있으면 얼굴을 겹쳐 보임(5초 안에 멈추는 떠다니는 모션). 2명 이상이면 `pick` 버튼이고 누르면 세로로 펼침
- 멤버별 코멘트(`MemberComments`, 응답의 `comments`): 칩 가로 스크롤, 처음엔 첫 멤버. 나간·탈퇴한 멤버는 기본 프로필 이미지(`DELETED_USER_IMAGE`, 사진 없는 사용자와 같은 `default-profile.svg`)와 「작성자」, 내용 대신 「삭제된 코멘트입니다」
- 좋아요·댓글 수(서버 값, 좋아요는 화면에서만 바뀜), 댓글 목록과 빈 상태. 소셜 댓글 목록은 댓글 API(API 연동 4번) 전이라 처음에 비어 있고, 댓글 수는 서버 값이라 둘이 다를 수 있다(일러스트 72×72와 「아직 작성된 댓글이 없어요」 13/18, 간격 12, Figma 5367:103541)
- 입력 안내: 「{번치 이름}으로 댓글 달기」(받침에 따라 으로/로, `lib/josa.ts`). 번치를 모르거나 없으면 「댓글 달기」
- 답글 누르면 답글 작성 상태(대상 줄·닫기, 「{번치 이름}으로 답글 달기」)
- 댓글 등록(6.2.8~6.2.9): 보내면 원댓글은 맨 위, 답글은 그 댓글의 답글 끝에 넣고 댓글 수와 「답글 N」을 올린다. 앞뒤 공백을 지우고 줄바꿈은 둔다. 입력란을 비우고 답글 상태를 풀며 새 댓글로 초점을 옮긴다. 작성자는 내 닉네임과 프로필 이미지, 배지는 현재 번치 이름과 성격 색이다
- 남의 댓글 더보기(6.2.10, Figma `5367:110378`·`5367:121909`): 「신고」/「취소」 시트 → 시트가 닫힌 뒤 「이 댓글을 신고할까요?」 신고 시트(번치 신고와 같은 사유, 「{현재 번치} 계정으로 신고해요」) → 접수되면 그 댓글을 바로 숨기고(원댓글이면 답글도, 답글이면 원댓글의 「답글 N」에서도) 댓글 수에서도 빼며 「신고가 접수됐어요.」. 초점은 그 자리의 다음 댓글로 간다
- 메인 관리자 헤더 더보기(6.2.11·6.2.13, Figma `5367:123992`): 서버 권한에 따라 항목을 고른다. `canEdit`면 「수정하기」/「공개 범위 설정」, `canDelete`면 「삭제하기」(빨강), 마지막은 「취소」. 공개 범위 설정은 `/bunches/[bunchId]/bundles/[bundleId]/visibility`(`BundleVisibilityScreen`)로 간다. 삭제는 「게시글을 삭제할까요?」 → 창이 닫힌 뒤 화면에서 지우고(`bundleEdits`) 이전 화면으로 가서 「번들을 삭제했어요」. 지운 번들에 다시 들어오면 볼 수 없다는 안내다(들어올 때 기준이라 지운 직후 떠나는 동안에는 바뀌지 않는다). 공개 범위 화면은 상세 응답의 공개 범위와 `canEdit`을 읽고, 권한이 없거나 없는·지운 번들이면 같은 안내, 일시 오류면 「다시 시도」다. 피드는 원래 공개였다가 「멤버 공개」로 바꾼 번들만 뺀다. 「수정하기」는 수정 화면이 없어 지금은 시트만 닫고, 수정 화면이 생기면 이동을 붙인다
- 헤더 더보기(6.2.11·6.2.14, Figma `5367:122444`): 서버 권한 `canReport`가 있으면 「신고」/「취소」 → 「이 게시글을 신고할까요?」 → 접수되면 이전 화면으로 가서 「신고가 접수됐어요.」. 소속 번치가 없으면 신고 시트를 열지 않고 안내한다. 두 권한이 모두 없으면 더보기 버튼이 없다
- 내 댓글 더보기(6.2.10, Figma `5367:121393`·`5367:121647`): 「삭제」/「취소」 시트 → 시트가 닫힌 뒤 「댓글을 삭제할까요?」 → 「삭제」면 창이 닫힌 뒤 「삭제된 댓글입니다」로 바꾸고 「댓글을 삭제했어요」(기능명세서 문구, Figma는 「댓글을 삭제했어요」). 삭제된 댓글에는 답글 버튼이 없다
- `?focus=comments`: 댓글 영역으로 스크롤하고 입력란에 초점. 다른 값은 무시
- 없는·볼 수 없는 번들과 잘못된 주소(서버 404·403·400, 화면에서 지운 번들): 헤더와 「삭제되었거나 볼 수 없는 내용이에요」
- 시트(`useBundleSheets`, 6.3.1·6.3.2, 피드 카드도 같이 씀): 바깥 터치·아래로 끌기·「취소」로 닫는다
  - 위치 → 콕하기 시트. 「콕하기」는 시트를 닫지 않고 「콕 했어요」로 바꾼다(토스트 없음)
  - 「콕 했어요」 → 시트를 닫고 확인 창. 「삭제하기」면 콕을 빼고, 「아니요」면 그대로 둔다. 어느 쪽이든 창이 닫힌 뒤 시트를 다시 올린다(화면설계서 피드 2번). 명세와 다름(확인 필요): 1110판 6.3.1 상세 5는 「아니요」면 시트를 다시 열지 않는다
  - 참여 멤버 → 참여 멤버 시트. 멤버를 누르면 시트가 닫힌 뒤 멤버 프로필로 간다. 나간·탈퇴한 멤버는 기본 이미지와 「작성자」이고 배지 없이 누를 수 없다. 역할 배지는 Figma 기준이고 1110판 6.3.2도 같다(메인 관리자 노란 왕관, 공동 관리자 회색 왕관)
  - 카드와 상세 헤더의 얼굴 묶음도 나간·탈퇴한 멤버는 기본 이미지다

### 범위 외

- 멤버 공개(PRIVATE) 번들: 외부 상세(084)에서 빠져 볼 수 없다는 안내가 나온다. 알림으로 들어오는 우리 번치 번들도 대부분 이 안내다. 서버에 멤버 공개로 저장되면 공개 범위 화면에도 다시 들어오지 못한다. 우리 번치 멤버·관리자용 조회는 API 연동 6번에서 정한다
- 남의 댓글 신고 흐름은 코드는 있지만 소셜 댓글을 받기 전이라 닿지 않는다(API 연동 4·5번에서 다시 확인)
- 좋아요 서버 반영(API 연동 3번). 화면 표시는 피드와 상세가 같은 값이다(`likeStore`)
- 댓글 목록·서버 반영과 이어 불러오기(API 연동 4번): 등록·삭제는 화면 안에서만 바뀌고 다시 들어오면 처음 값이다. 피드 카드의 댓글 수도 그대로다
- 번들 수정 화면과 「수정하기」 이동(API 연동 7번): 공동 편집 화면 재사용을 정한 뒤
- 번들 삭제·공개 범위의 서버 반영(API 연동 6번): 지금은 화면에서만 바뀌고 새로고침하면 처음 값이다
- 신고 서버 반영과 같은 대상 24시간 2회 제한(API 연동 5번): 지금은 화면에서만 숨긴다. 다시 들어오면 처음 목록이다
- 콕 서버 반영(API 연동 8번): 지금은 화면에서만 바뀌고 다시 들어오면 처음 값이다. 피드와 상세도 공유하지 않는다
- 사진 캡션: 기획 변경으로 상세에서 빠졌다(Figma에 없음, 1110판 6.2.4도 캡션 대신 픽)

## 상태

- 받는 중: 페이지 로딩(`PageLoading`)이 헤더까지 덮어 뒤로 가기도 막는다(앱 공통 덮개). 상태 영역에 「번들을 불러오는 중이에요」. 번치 이름·이미지도 기다리고, 받지 못하면 「번치」와 기본 이미지로 보인다
- 받기 실패(400·403·404 외): 「일시적인 오류가 발생했어요. 다시 시도해 주세요」(`role="alert"`)와 「다시 시도」. 내 정보를 받지 못해도 같은 안내이고 「다시 시도」는 내 정보부터 다시 받는다. 성공하면 초점을 번들 제목(`h1`)으로 옮긴다
- 지금 번치를 받는 중: 입력 안내는 「댓글 달기」, 번치 명의 행동은 무시. 실패하면 오류 토스트. 소속 번치 없음이면 「번치에 참여하면 할 수 있어요.」 토스트(`useFeedViewer`). 토스트는 하단 입력란 영역(`PageShell` bottom 슬롯, `wrapper` 앵커) 바로 위 4px에 좌우 16씩 띄운 폭으로 띄운다. Figma `6079:178315`는 입력란 위 12px였으나 2026-11-10에 하단 영역 위 4px 규칙으로 통일했다(`Toast.spec.md`). 입력란 높이가 바뀌어도 띄우는 순간 앵커를 재서 따라간다.
- 시트에서 소속 번치가 없으면 모든 장소가 「콕하기」이고 눌러도 바뀌지 않으며 토스트를 헤더 아래에 띄운다(피드도 같음, 시트가 하단을 덮기 때문)
- 말풍선: 댓글 영역으로 스크롤하고 입력란에 초점을 둔다(`?focus=comments`와 같음)
- 키보드가 올라오면 하단 Safe Area를 덮으므로 입력란 아래 여백을 없앤다(`useKeyboardOpen`, `data-keyboard-open`). iOS가 페이지를 위로 밀어 헤더가 가려지는 것은 그대로 둔다

## 접근성

- 번들 제목이 `h1`, 멤버별 코멘트·댓글은 이름 있는 `section`, 댓글은 목록(`ul`)
- 칩 묶음은 「참여 멤버」 그룹이다. 칩을 고르면 코멘트 문단(`aria-live="polite"`)을 「{이름}의 코멘트:」와 함께 읽어 준다
- 댓글을 등록하면 새 댓글(목록 항목)로 초점을 옮겨 키보드를 내리고 「댓글을 등록했어요」(답글이면 「답글을 등록했어요」)를 상태 영역으로 읽어 준다. 삭제하면 더보기가 사라지므로 그 댓글로 초점을 옮기고, 결과는 토스트(자체 알림 영역)로만 알려 두 번 읽히지 않게 한다
- 더보기 버튼 이름: 내 댓글은 「내 댓글 더보기」, 남의 댓글은 「{이름} 댓글 더보기: {내용 앞 20자}」(같은 작성자의 댓글이 여럿이어도 구분). 헤더는 「번들 더보기」이고 서버 권한이 없으면 그리지 않는다
- 답글을 누르거나 닫으면 초점이 입력란으로 간다. `?focus=comments`는 입력이 목적이라 모바일에서 키보드가 올라오는 것을 의도한다
- 시트 제목은 `h2`이고 콕 버튼은 장소 이름을 설명으로 읽는다. 참여 멤버 행은 링크다. 확인 창이 닫히면 초점은 시트를 연 버튼으로 돌아간다
- 뱃지는 「멤버 공개」로 읽힌다. `pick` 버튼은 「pick {멤버 이름들}」로 읽히고 펼침 상태(`aria-expanded`)를 알린다. 1명이면 같은 이름의 이미지(`role="img"`)다

## Styling과 의존성

- 위에서부터: 번치 줄 좌우 16·위아래 8, 제목 영역 위 16·아래 10·좌우 16, 코멘트 영역 위 24·칩과 카드 사이 8, 반응 줄 위 24·아래 16·좌우 16, 구분선 8(`surface-secondary`), 댓글 영역 위 16·좌우 16, 빈 상태 높이 256
- 코멘트 카드는 `surface-secondary`, 모서리 10, 안쪽 16, `body-3-regular`

## 확인할 항목

- 칩은 `aria-pressed` 토글이라 「하나를 고름」 맥락이 약하다. 라디오 그룹(방향키 이동)은 `ChipButton` 변경이 필요해 두었다
- 나간 멤버가 둘 이상이면 칩 이름이 같은 「작성자」로 겹친다
- 사진마다 순번이 읽히고 화면 밖 사진까지 낭독된다. 사진 `alt`는 데이터가 생기면 넘긴다
- 입구가 늘면(번치 메인·프로필·알림) 직접 진입 때 돌아갈 곳(`useBackOr`, 지금은 피드)과 전환 규칙을 입구별로 정한다
- 화면설계서(`5367:114452`)는 이미 콕한 장소를 「Disabled」로 적었지만 Figma 콕 취소 창과 기능명세서 6.3.1은 눌러서 취소한다. 뒤의 둘을 따랐고 설계서 수정은 디자이너 확인 필요
- 빈 상태·안내 글자 `text-quinary`(#BCBEC2)는 흰 바탕에서 약 1.9:1이다(계산값, Figma 값). 디자인 협의 대상
- 1110판: 펼친 픽 프로필은 다른 사진으로 넘기면 접힌다(6.2.4 상세 4). 구현은 사진마다 펼침 상태를 따로 두어 넘겨도 유지되는 것으로 보인다(코드로 추론). 구현은 아직 이전 기준
