- Route: `/signup/profile`(`apps/web/src/app/(app)/signup/profile/page.tsx`)

## 목적과 범위

### 포함

- 가입 마지막 단계에서 닉네임(필수)과 프로필 사진·출생연도·성별(선택)을 입력해 가입을 완료하는 화면. 출생연도·성별은 선택 약관에 동의한 경우에만 입력란이 나오고, 동의하지 않으면 닉네임만 보인다(Figma `5374:97164` 미동의, `977:6300` 동의).
- 구성: 헤더(뒤로 가기, `SignupFrame`), 제목·설명(`PageHeader`), 프로필 이미지와 사진 변경 버튼(누르면 사진 선택, 아래 항목), 닉네임·출생연도(`LabeledTextField`), 성별(여성·남성 선택), 공개 안내 문구, 하단 고정 「BUNCH 시작하기」 버튼.
- 프로필 사진: MY 프로필 수정과 같은 `shared/components/profile/ProfilePhotoField`를 쓴다(#217). 카메라 버튼 → 「프로필 사진 설정」 선택지(앨범에서 사진 선택하기 / 기본 이미지 적용하기 / 취소, 기본 이미지면 두 번째 없음) → 원형 조정 화면 → 미리보기. 형식은 JPEG·PNG·HEIC·WebP 10MB 이하이고 어긋나면 「JPEG・PNG・HEIC・WebP, 10MB 이하만 가능해요.」 토스트(MY Figma 기준으로 통일, 이전 가입 기준 3MB·「이 사진은 사용할 수 없어요.」를 대체). 고른 사진은 저장하지 않고 미리보기만 한다.
- 닉네임: 한글·영문·숫자와 사이 공백만 허용하고 특수문자·이모지는 오류(「특수문자를 제외한 영문, 한글만 사용할 수 있어요.」)이며, 최대 12자와 글자 수(`n/12`)를 보인다. 앞뒤 공백은 지운 길이로 판단하고(저장 전에 NFC 정규화), 공백만 입력하면 빈 값으로 본다. 한글 조합 중인 자모는 오류로 보지 않지만 시작하기와 중복 확인은 조합이 끝난 완성된 값에서만 켠다. 규칙은 `src/shared/lib/nickname.ts`가 가진다(MY 프로필 수정과 공유).
- 닉네임 중복 확인: 입력을 멈추고 0.5초 뒤 확인하고(`useNicknameAvailability`), 확인 중이거나 사용 중(「이미 사용 중인 닉네임이에요.」)이거나 확인에 실패하면 시작하기가 비활성이다. 확인 함수(`checkNickname`)를 넘길 때만 동작하고, 지금은 넘기지 않아 확인하지 않는다.
- 출생연도: 숫자 키보드로 4자리를 직접 입력한다(숫자만, 최대 4자리). 범위는 1950년부터 올해 − 14년까지다(서버 기준, 기획 명세의 1930년은 1950년으로 확정). 4자리를 다 쓴 뒤 범위를 벗어났거나 4자리를 채우지 않고 포커스를 벗어나면 오류 문구를 보인다. 비워 두면 값 없음이다. 선택 약관에 동의한 경우에만 보인다.
- 성별: 여성·남성 중 하나이고 다시 누르면 해제된다. 선택한 버튼은 Figma 눌림 모양(10% 어두운 오버레이, 진한 글자)을 유지하고 비선택은 흰 바탕에 연한 글자다.
- 시작하기: 닉네임이 규칙에 맞고(중복 확인을 쓸 때는 사용 가능일 때) 출생연도가 유효하면 활성화되고, 누르면 프로필을 저장한다. 저장 뒤 이동은 가드가 한다(아래 「Success·완료 후 이동」).
- 키보드: 포커스하거나 키보드로 화면 높이가 바뀌면 입력창이 보이게 스크롤(`nearest`라 이미 보이면 스크롤하지 않음)하고, 입력창·라벨·버튼이 아닌 빈 영역을 누르면 키보드를 닫고(버튼은 누르는 중이 아니라 클릭이 끝난 뒤 닫는다), 시작하기·성별·사진 변경을 누르면 클릭 뒤에 닫으며 다른 입력창을 누르면 키보드를 유지한다.

### 범위 외

- 프로필 사진의 권한 거부 안내 모달(시스템 사진 선택기는 권한이 필요 없어 띄울 경우가 없음, `ProfilePhotoField.spec.md`)과 서버 저장.
- 접근 제어(가입 중이며 약관 동의를 마친 사용자만 진입)는 `AuthGate`가 맡는다. 초대 정보에 따른 이동(초대 참여)은 초대 정보 보관을 만들 때 붙인다.
- 입력값의 임시 보관. 뒤로 가기 후 다시 들어오면 입력이 비어 있다.
- iPhone 상태 바·홈 인디케이터(기기 요소, Safe Area는 `AppFrame`이 처리한다).

## Route와 접근

- Path·params·search: `/signup/profile`. params와 search는 없다.
- 접근 권한·guard: `AuthGate`가 판단한다(`lib/accessPolicy.ts`). 비로그인은 로그인으로, 약관 미동의 가입 중 사용자는 약관으로, 가입 완료 사용자는 도착 화면으로 보낸다. 약관에 동의하고 프로필에 직접 들어오면(새로고침·재로그인) 약관 화면의 메모리에 있던 선택 약관 동의가 사라져, 출생연도·성별 입력은 나오지 않고 동의 없이 가입이 끝난다(알려진 한계, 서버의 가입 상태 응답에 선택 약관 동의가 없어 복원할 수 없다. 백엔드 확인 항목).
- Layout·redirect·navigation: `(app)/signup/layout.tsx` 안에서 `SignupFrame`(`PageShell`)을 쓴다. 가입 완료 뒤 도착 화면은 `AuthGate`가 정하고(`app/(app)/layout.tsx`가 다른 feature의 경로를 조합해 전달) 이 화면은 이동 경로를 받지 않는다. 뒤로 가기는 `router.back()`이다(약관 화면과 달리 로그아웃하지 않는다, 기획에 프로필 뒤로가기 정의가 없어 확인 항목).

## 상태와 흐름

- 초기 진입: 모든 입력이 비어 있고 기본 프로필 이미지이며 시작하기는 비활성이다.
- Loading: 닉네임 중복 확인 중(시작하기 비활성, 별도 표시 없음), 가입 저장 중(`PageLoading`으로 화면 전체를 덮음, 시작하기 `aria-busy`, 화면에 보이지 않는 `role="status"` 「프로필을 저장하는 중이에요」, 다시 눌러도 한 번만 저장).
- Empty: 출생연도·성별은 비워 둘 수 있다. 프로필 사진이 없으면 기본 이미지다.
- Error·retry: 닉네임 문자 오류, 중복, 출생연도 범위 오류는 해당 항목 아래에 문구로 보인다. 저장할 때 서버가 닉네임 중복(409 `USER_002`)이라고 하면 입력란 아래에 「이미 사용 중인 닉네임이에요」를 보이고 시작하기를 비활성화하며 포커스를 닉네임 입력으로 돌려준다(닉네임을 바꾸면 다시 시작할 수 있다). 이미 가입을 마친 계정(409 `USER_003`)이거나 약관 버전이 바뀐 경우(409 `AUTH_016`)는 토스트와 함께 가입 상태를 다시 읽어 가드가 알맞은 화면으로 보낸다. 그 밖의 저장 실패는 토스트 「일시적인 오류가 발생했어요. 잠시 후 다시 시도해 주세요」를 보이고 입력을 유지한 채 다시 시도할 수 있다. 사진 저장만 실패하면 서버가 기본 이미지로 가입을 완료한다.
- Disabled·invalid: 시작하기 버튼. 닉네임이 비었거나 규칙 위반·중복·확인 중·확인 실패, 또는 출생연도가 4자리·범위를 만족하지 않을 때 비활성이다.
- Success·완료 후 이동: 시작하기를 누르면 ① 키보드를 닫고 ② `POST /members/me/registration`(multipart: `profile` JSON과 선택 `photo` JPEG)으로 저장하고 ③ 가입 상태(`sharedKeys.session()`)를 다시 읽어 기다린다. 이 화면은 직접 이동하지 않는다: 가입 상태가 가입 완료로 바뀌면 `AuthGate`가 가입 화면(`/signup/*`)에 있는 가입 완료 사용자를 도착 화면(기본 번치가 있으면 번치 홈, 없으면 번치 시작 선택)으로 `replace`한다. 이동 주체를 가드 하나로 두어 초대 정보에 따른 이동(기획 1.4.7, 초대 정보 보관을 만들 때)도 한 곳에서 붙인다. 가입 상태를 다시 읽지 못하면 저장 실패와 같은 토스트이고, 같은 프로필의 재시도는 서버가 기존 결과를 돌려준다.

## 데이터 의존성

- Query와 enabled 조건: 닉네임 중복 확인은 `GET /members/nickname-availability`(`features/auth/api/registration.ts`)를 입력을 멈추고 0.5초 뒤 한 번 호출한다(query 캐시 없음). 서버는 앞뒤 공백 제거와 유니코드 정규화 뒤 판단하며 이름을 예약하지 않는다.
- Mutation·cache 영향: 가입 저장은 `useRegisterMutation`(`queries/signup.ts`)이고 성공하면 `sharedKeys.session()`을 무효화하고 기다린다(`AuthGate`가 옛 상태로 이동을 되돌리지 않도록). 선택 약관 동의가 있으면 현재 동의 버전(`GET /auth/terms`의 `DEMOGRAPHICS`)을 `demographicsConsentVersion`으로 함께 보내며(서버는 동의 없이 출생연도·성별을 받으면 400), 서버가 버전을 주지 않으면 출생연도·성별은 보내지 않는다.
- API 계약 확인 항목: 닉네임 형식이 틀린 입력에 닉네임 확인 API가 무엇을 돌려주는지(명세에 없음, 지금은 입력 단계에서 형식을 막는다). 사진은 JPEG만 보내며(JPEG 외 형식은 요청 없이 실패) 정사각형·1024px 이하·5MiB 이하이고 앱의 512px JPEG 출력이 맞는다. 사진 EXIF는 조정 화면의 canvas 재인코딩으로 제거되고 서버 재인코딩은 확인하지 못했다. 가입 저장 때 선택 약관 동의 버전은 그 시점의 서버 현재 버전이라 약관 화면에서 동의한 버전과 다를 수 있다(서버가 버전을 올리면 AUTH_016).

## UI와 접근성

- Component mapping: `web`의 `PageHeader`·`ProfileImage`·`CameraButton`·`LabeledTextField`·`Option`, `core`의 `Button`·`Header`(`SignupFrame`). 입력 칸 묶음은 `src/shared/components/profile/ProfileFields`(값·검증은 `useProfileFields`)이고 MY 프로필 수정과 함께 쓴다. 성별(`GenderField`)은 `Button`(tertiary·md)에 `aria-pressed`를 붙인 UI다.
- Keyboard·focus·accessible name: 닉네임·출생연도는 `LabeledTextField`의 제목이 입력창 이름이고 필수는 `aria-required`, 오류는 `role="alert"`와 `aria-invalid`로 알린다. 성별은 `role="group"`(이름 「성별」)이고 두 버튼은 `aria-pressed`로 선택 상태를 전달한다. 사진 변경 버튼 이름은 「프로필 사진 변경」이고 프로필 이미지는 장식이다(선택한 사진도 마찬가지). 선택 중에도 버튼을 비활성으로 바꾸지 않아 포커스를 잃지 않으며, 중복 선택은 hook이 막는다. `PageHeader` 제목이 `h1`, `main`은 `PageShell`이 하나만 만든다. 공개 안내 문구는 출생연도 입력과 성별 그룹의 `aria-describedby`로 연결하고, 출생연도에는 「숫자 4자리로 입력해 주세요.」(화면에는 보이지 않음)도 함께 연결한다.
- Responsive·긴 텍스트·overflow: 좌우 16px이고 375px에서 가로 넘침이 없다. 본문은 `main`에서 스크롤되고 시작하기는 아래에 고정된다.

## 확인할 항목

- 닉네임 공백 (제안): 설계서가 앞뒤 공백은 지우고 중간 공백은 1자로 센다고 해서 사이 공백을 허용했다. 같은 설계서의 오류 문구는 「영문, 한글」만 말해 숫자·공백 허용과 어긋난다(`login-signup.md` 확인할 항목 기획 3번). 글자 수 표시와 입력 제한(`maxLength` 12)은 입력 그대로의 길이를 센다. 앞뒤 공백도 12자에 포함된다.
- 닉네임 입력 제한 (제안): 설계서는 허용되지 않은 문자의 입력을 제한한다고 하지만, 한글 조합 입력 중에는 막기 어려워 번치 이름 입력과 같이 입력은 받고 오류 문구와 시작하기 비활성으로 처리했다.
- 출생연도 오류 문구 (임시, 디자인 확인): Figma에 출생연도 범위 오류 문구가 없어 「1950년부터 (현재 연도 − 14)년 사이로 입력해 주세요.」를 임시로 썼다. 4자리가 아닐 때는 포커스를 벗어난 뒤에만 안내한다.
- 선택 표시·안내 문구 줄바꿈 (확정, Figma 5878:77365): 출생연도·성별 제목 옆에는 「선택」 표시를 두지 않는다(공용 `ProfileFields`에서 제거). 안내 문구는 Figma가 두 문단이라 「…활용되며,」 뒤에서 줄이 바뀐다(줄바꿈 문자 `\n`과 `whitespace-pre-line`).
- 출생연도 입력 방식 (확정, 사용자 결정): 숫자 키보드 직접 입력이다. 설계서의 「선택 안함이 항상 상단」은 목록 방식 문구라 해당하지 않는다.
- 중복 확인 실패 문구 (확인): 실패 토스트 문구는 약관·로그인과 같은 「일시적인 오류가 발생했어요. 다시 시도해 주세요」로 임시 적용했다. 확인 중에는 별도 표시가 없다.
- 입력값 보관 (제안): `login-signup.md`는 가입 완료 전까지 임시 유지하라고 하지만 이 화면은 화면 안 상태만 가진다. 뒤로 갔다 오면 비워진다.
- 키보드 처리 (미검증): 자동 스크롤은 `visualViewport` 크기 변화와 `focusin`에서 `scrollIntoView({ block: 'nearest' })`를 부르는 방식이다. iOS WebView에서 키보드가 입력창을 가릴 때 실제로 보이게 되는지는 실기기로 확인해야 한다. 빈 영역 탭으로 키보드를 닫는 것은 `pointerdown`에서 포커스를 해제하는 방식이라 터치로 스크롤을 시작하는 순간에도 포커스가 풀릴 수 있다(실기기 확인). 버튼은 누르는 중에 키보드를 닫으면 화면이 밀려 탭이 사라지는 문제가 있어 클릭이 끝난 뒤에 닫는다(iOS 실기기 확인 전). 핀치 줌으로 확대한 동안에는 자동 스크롤하지 않는다.
- 프로필 사진 (범위 외): 기본 이미지는 번치 타입과 관계없는 기본 프로필 이미지(`/images/default-profile.svg`, Figma `5931:166793`)를 쓴다.
- 성별 비선택 글자색 (확정): Figma 성별 버튼은 `text-tertiary`(`#535a61`)이고 `Button`의 tertiary 기본(진한 글자)과 달라 이 화면에서 덮어썼다. 선택은 Tertiary Pressed(10% 어두운 오버레이)로 표현했다.
- 접근 조건 (구현됨): `AuthGate`가 비로그인은 로그인으로, 약관 미동의 가입 중 사용자는 약관으로, 가입 완료 사용자는 도착 화면으로 보낸다.
- 가입 뒤 도착지 (제안): 도착지는 지금 번치 시작 선택(`/onboarding`)으로 고정이다. 기능 spec의 도착지 규칙(1.2.8: 보관한 초대 정보 → 마지막 번치 홈 → 가장 최근 번치 홈 → 번치 시작 선택)의 초대 맥락·마지막 번치 판단은 인증·번치 연동 때 연결한다. 함수 prop인 `checkNickname`도 서버 컴포넌트인 page가 넘길 수 없어, 연결할 때는 client 쪽(query hook 등)에서 주입한다.
- 프로필 사진 (부분 연결): 선택지·기본 이미지 되돌리기·원형 조정 화면·JPEG·PNG·HEIC·WebP 형식은 공용 `ProfilePhotoField`로 연결했다(#217). 확대(핀치)는 지원하지 않고 이동만 된다. 권한 모달은 띄울 경우가 없어 만들지 않았고(`ProfilePhotoField.spec.md` 결정 2), 서버 저장은 이미지 API 연결 때 붙인다.
- 성별 선택 표시 (디자인 확인): 선택은 10% 어두운 오버레이와 진한 글자로만 구분되어 대비가 낮다(스크린 리더에는 `aria-pressed`로 전달). Figma 모양을 따랐다.
- 출생연도 자동 완성 (확인): 입력 목적 식별(`bday-year`) 대신 `autoComplete="off"`를 썼다. 저장된 값이 채워지는 것을 막으려는 선택이다.
- 중복 확인 중 표시 (제안): 확인 중에는 시작하기가 비활성이라는 것 외에 표시가 없다.
- 시작하기 동작 (연결됨): 가입 저장 뒤 이동한다. 선택 약관 동의 여부는 약관 화면의 메모리에만 있어 프로필에서 새로고침하면 사라지고, 그러면 출생연도·성별 입력은 나오지 않는다(결정: 저장되지 않은 입력은 유지하지 않는다).
