# 페이지: 사진함 목록(하단 탭 `/photos`)

## 메타데이터

- Route: `/photos`(`apps/web/src/app/(app)/(main)/photos/page.tsx`)
- Status: 목록·멤버 필터·날짜 미확인 아코디언·빈 상태·번치 없음·로딩·오류 UI 구현됨(fixture와 목 동작, 개발 서버 headless Chrome 375×812 실측. 실기기 전). 선택 모드(#126: 고르기·「⋯」 메뉴·저장·번들 만들기·삭제)도 같은 화면에 구현했고 삭제는 API 연동, 저장은 쉘 연동이다. 사진 올리기 시트·선택 모드 날짜 바꾸기 시트·끌어서 날짜 변경(#127)도 구현했고 날짜 변경은 서버 API에 연결했다(#316). 번치 전환과 앨범·카메라 연동은 호출 지점만 있음.
- 디자인 출처: Figma `사진함`(node `1782:30110`)의 `사진함_01~05`, 선택 모드 `사진함_07·08·10~12`, `번치 Empty Space`(`1861:36971`)와 화면 설계서(`1861:30963`). 이슈 #125.
- 기능 spec: `docs/specs/photo-box.md`의 3.1 사진함 탭.

## 목적과 범위

### 포함

- 헤더(번치 대표 이미지·이름·전환 화살표, 「선택」)는 상단에 고정하고, 멤버 필터 칩과 날짜 미확인 아코디언·날짜별 사진 목록은 함께 스크롤한다. 오른쪽 아래 「+」는 고정한다. 하단 탭 막대는 본문 위에 떠 있고(사진이 뒤로 비친다), 목록 끝 여백은 `PageShell`이 막대 + 36px(Figma 사진함_02)로 확보하며 「+」는 막대 위 10px에 둔다.
- 사진을 누르면 썸네일이 상세 사진 자리로 커지는 hero로 들어가고, 뒤로 오면 보던 스크롤 위치로 복원된 뒤 사진이 그 칸으로 돌아온다(`docs/architecture/motion.md` 「사진함 → 사진 상세」).
- 멤버 필터: 「전체」와 멤버(프로필 이미지·닉네임) 칩, 하나만 선택(radio 그룹), 가로 스크롤, 사진이 없는 멤버도 칩을 보인다. 고른 필터는 이 화면의 history 항목에 번치 id와 함께 둬, 사진 상세에서 뒤로 돌아오면 그 필터로 다시 그린다(#500, 2026-11-21 팀 QA). 새로 들어오거나 번치를 바꿨거나 그 멤버가 목록에 없으면 「전체」다.
- 사진은 촬영 날짜 섹션으로 나누고 최신 날짜가 위, 섹션 안은 최근 촬영이 앞, 같은 시각이면 업로드 순이다. 한 줄 3장 정사각형, 사이 1px.
- 섹션 날짜: 올해는 「9월 27일 일요일」, 올해가 아니면 요일 없이 「2025년 12월 24일」.
- 「촬영 날짜를 확인할 사진 N장」 아코디언: 기본 접힘, 펼치면 업로드 최신순 3열, 0장이면 숨김. N은 선택한 멤버 기준.
- 빈 상태: 번치에 사진이 없으면 「첫 번째 사진을 공유해 보세요」, 선택한 멤버의 사진이 없으면 「첫 사진을 기다리고 있어요!」.
- 번치 없음: 「참여 중인 번치가 없어요」와 「새 번치 만들기」(`/onboarding/create`)·「초대 링크로 참여하기」(`/onboarding/join`). 헤더·필터·「+」는 없다.
- 로딩(회색 자리표시, 헤더도 같은 높이의 자리로 그려 다 받은 뒤 내용이 밀리지 않음)·오류(기획 문서의 기본 문구 「일시적인 오류가 발생했어요. 다시 시도해 주세요」와 「다시 시도」), 처리 중이거나 불러오지 못한 사진의 회색 자리표시(Figma에 없는 상태).

- 선택 모드(#126): 「선택」→「취소」, 사진마다 선택 원과 누른 순서 번호(최대 50장, 51번째는 「사진은 한 번에 50장까지 고를 수 있어요.」), 필터 칩에 「전체 (N)」·멤버별 장수(0장이면 숫자 없음, 함께 올린 사진은 올린 멤버 모두에게), 「+」→「⋯」(0장이면 비활성), 하단 탭 막대 숨김.
- 「⋯」 메뉴: 저장·번들 만들기·날짜 바꾸기, 구분선 아래 빨간 삭제. 열면 첫 항목에 포커스, Esc·바깥 누름·항목 선택으로 닫는다.
- 저장: 확인 없이 호출하고 화면 전체 dim 위 점 3개 로딩, 완료하면 선택 모드를 끝내고 「이미지 저장이 완료되었어요.」. 일부 실패는 저장된 사진을 선택에서 빼고 「N장은 저장하지 못했어요. 다시 시도해 주세요.」, 전부 실패는 「일시적인 오류가 발생했어요. 다시 시도해 주세요」(선택 유지).
- 번들 만들기: 1~20장이면 확인 창 없이 `onCreateBundle`(고른 순서)을 부르고(기능 spec 3.3.4), `/photos` 화면(`PhotoBox`)이 이를 받아 고른 사진을 넘기고(`startFromPhotoBox`) 선택을 기억한 뒤(`lib/selectionResume.ts`) 참여 멤버 고르기(`/bunch/bundles/new/members`)로 `push`한다. 멤버를 고르고 「다음」을 누르면 그 화면이 사진 선택 없이 초안 생성 API를 불러 작성 화면으로 `replace`하고 기억한 선택을 비운다. 멤버 고르기에서 뒤로 오면 기억한 사진과 번호로 선택 모드가 이어진다(2분 안, 같은 번치일 때만, 목록이 준비되면 사라진 사진은 빼고 하나도 안 남으면 선택 모드를 켜지 않으며, 한 번 확인하면 기억을 비움). 21장 이상이면 넘어가지 않고 「번들에는 사진을 20장까지 담을 수 있어요.」를 띄우고 선택을 유지한다. 사진함 → 멤버 고르기 전환 모션은 정의가 없어 기본 동작이다.
- 삭제: 일반 멤버가 다른 멤버 사진을 섞으면 「내가 올린 사진만 삭제할 수 있어요.」, 아니면 「선택한 사진을 삭제할까요?」 확인 창(「삭제하기」/「취소」, 처음 포커스는 「취소」) 뒤 삭제하고 「사진함에서 사진 N장이 삭제되었어요.」(0장이면 토스트 없음). 함께 올린 사진은 내 이름만 빠진다. 지운 뒤에는 눌렀던 메뉴·선택 칸이 사라지므로 확인 창이 닫힌 뒤 초점을 화면 제목 `h1`(「사진함」, `tabIndex={-1}`)으로 옮긴다(`web-interface-guidelines.md`의 「같은 화면에서 항목이 사라지면」).
- 날짜 바꾸기: 일반 멤버가 다른 멤버 사진을 섞으면 「내가 올린 사진만 날짜를 바꿀 수 있어요.」, 아니면 바텀시트(오늘이 속한 달을 아무것도 고르지 않고 열며 고르기 전에는 「저장」 비활성)를 연다. 「저장」은 고른 사진 전부의 날짜를 한 번에 바꾸고(시각 유지, 전부 성공 또는 전부 실패) 선택 모드를 끝내며 「사진 날짜가 변경되었어요.」(되돌리기 없음)를 띄운다. 실패하면 오류 토스트와 함께 시트를 유지한다. 관리자가 다른 멤버 사진이나 함께 올린 사진을 포함하면 저장 전에 확인 창(문구는 원문이 없어 임시, 「바꾸기」/「취소」)을 거치고, 확인 창은 시트 위에 겹쳐 뜨고(포커스는 창 안에 머묾), 취소하거나 Esc를 누르면 확인 창만 닫혀 고른 날짜가 그대로 남는다.
- 쓸어서 고르기(#284): 선택 모드에서 사진 위를 쓸면 시작한 사진부터 손가락이 있는 사진까지가 하나의 범위가 되어(화면 순서, 줄을 넘어가도 이어짐) 한꺼번에 고르거나 푼다. 시작한 사진이 선택 전이면 범위를 모두 고르고, 선택돼 있으면 모두 푼다. 같은 방향으로 가면 범위가 늘고 되돌아오면 줄며, 벗어난 사진은 쓸기 전 상태로 돌아간다. 시작 사진을 지나 반대편으로 가면 그쪽으로 범위가 뒤집힌다. 손가락은 가로로 먼저 8px 움직일 때만 쓸기이고 세로로 먼저 움직이면 스크롤이다(마우스는 방향 무관). 쓸기가 시작되면 화면은 같이 스크롤되지 않는다. 길게 눌러 끌 수 있는 사진을 약 280ms(끌기 시작 300ms보다 20ms 일찍, 두 판정 시계가 어긋나도 겹치지 않게 함) 넘게 누르고 있다가 움직이면 아래 길게 눌러 날짜 변경으로 넘기고, 끌 수 없는 사진은 오래 눌러도 쓸기로 본다.
- 쓸기 중 가장자리 자동 스크롤(#284): 손가락이 목록 보이는 영역의 위·아래 80px 안으로 들어오면 그쪽으로 스크롤하고, 깊이 들어갈수록 빨라져 끝에서 프레임당 12px이다. 손가락이 멈춰 있어도 계속 가며 스크롤로 밀린 사진까지 범위가 이어진다. 손가락을 떼면 멈춘다. 손가락으로 직접 조작하는 동안만 도는 스크롤이라 동작 줄이기 설정으로 끄지 않는다. 최대 장수에 닿으면 안내 토스트를 한 번 띄우고 그 쓸기는 거기서 멈춘다. 번들 만들기·사진 추가 선택 화면도 같은 영역(`PhotoDragSelect`)을 쓴다. 키보드·스크린 리더는 기존 칸별 버튼(Enter·Space)을 쓴다.
- 탭 처리와 첫 터치 씹힘 수정(#284): 브라우저는 클릭을 손가락을 뗀 위치의 요소로 보내, 칸 사이 간격이 1px뿐인 격자에서 경계 근처를 누르다 조금만 미끄러져도 옆 사진이 토글되던 것이 씹힘의 원인이었다(실기기 이벤트 로그로 확인). 거의 움직이지 않고(8px 미만) 뗀 터치·마우스는 클릭이 아니라 처음 닿은 사진을 토글하고, 뒤따르는 클릭은 400ms 동안 막는다. 누른 순간 100ms 안에 목록이 스크롤됐으면(관성 스크롤을 멈추려는 터치) 선택하지 않고 뒤따르는 클릭도 막는다. 길게 눌러 끌 수 있는 사진을 약 280ms 이상 누르고 뗀 탭은 끌기 쪽이 처리하고, 끌기가 시작되지 않은 280~300ms 구간은 뒤따르는 클릭이 토글을 맡는다. 끌기 라이브러리는 끌기가 시작되면 뒤따르는 클릭을 막으므로, 8px 안에서 놓은 끌기는 탭으로 보고 선택·해제한다. 한 장을 눌러도 그 사진 칸만 다시 그려지도록 선택 목록을 사진별로 구독한다.
- 끌어서 날짜 변경(#127): 선택 모드에서만, 권한 있는(내가 올렸거나 관리자) 처리 끝난 사진을 300ms 길게 누르면 끌 수 있다(짧게 누르면 선택·해제, 이동 8px 안에서 유지). 끄는 사진은 한 장이고 선택 여부와 무관하다. 원래 자리는 흐려지고 반투명 복사본이 따라가며 다른 섹션 위에서는 주변 사진이 비켜 자리를 보여 준다(, 기록 016). 놓으면 그 섹션 날짜로 바꾸고(시각 유지라 같은 날짜 안 자리는 촬영 시각 순) 「사진 날짜가 변경되었어요.」 + 「되돌리기」(5초, 원래 날짜로 한 번 더 바꿈)를 띄운다. 원래 섹션이나 섹션 밖에 놓으면 변경 없고, 실패하면 원래 자리로 돌려 오류 토스트를 띄운다. 날짜 미확인 사진도 영역을 펼쳐 같은 방식으로 끌어 날짜 섹션으로 옮길 수 있고(권한·확인 창 기준이 같음, `PhotoDragArea`가 영역을 함께 품음), 이 영역으로 다시 놓을 수는 없다(위로 지나가면 처음 자리로 돌아감). 날짜 미확인이던 사진의 「되돌리기」는 `clearDate: true`로 날짜 없음으로 되돌린다(`changePhotoDates(ids, null)`). 키보드·스크린 리더의 대체 경로는 날짜를 고르는 시트다. 관리자가 다른 멤버 사진이나 함께 올린 사진을 놓으면 날짜 바꾸기와 같은 확인 창을 거친다.
- 토스트 위치: 선택 모드는 하단 탭 막대를 숨겨 토스트가 「⋯」 버튼 위 16px에 뜬다(`FloatingButtonToastAnchor`, 웹·iOS 26 네이티브 버튼 모두, #503). 선택 모드가 아니면 탭 막대 위 16px이다. iOS 26 네이티브 버튼이 떠 있으면 토스트를 쉘이 네이티브로 띄우고, 선택 모드도 토스트가 「⋯」와 겹치는 모양이 탭 막대 화면과 같다(결정 기록 030, 실기기 확인 전).
- 사진 올리기: 「+」는 시트(「{번치 이름}에 사진 올리기」, 「앨범에서 선택」·「카메라로 찍기」)를 열고, 사진함이 1,000장이면 시트 대신 「사진함이 가득 찼어요.」 토스트를 띄운다. 방식을 고르면 시트를 닫고 `onUpload('album' | 'camera')`만 부른다.
- 실행 직전(확인 창의 확정 포함) 고른 사진이 목록에서 사라졌으면 실행하지 않고 선택에서 빼며 「선택한 사진 중 N장이 사진함에서 사라져 선택이 해제됐어요.」를 띄운다(선택 모드 유지).

### 범위 외(추후 작업 예정)

- 번치 전환: 헤더의 번치 이름을 누르면 번치 탭과 같은 번치 전환 시트가 열린다(`useBunchSwitchSheet`, `PhotosRoute`가 `useBunchSwitcher`를 조합해 `bunchSwitcher`로 넘김). 시트 자체의 설계는 번치 홈 spec을 따른다. 번치 탭의 화면 전환 모션(#492)은 쓰지 않고 목록만 새 번치로 바뀐다.
- 번들 만들기 진입 확인: 선택 모드 「번들 만들기」는 들어가기 직전에 멤버 목록과 작성 중인 번들 수를 새로 받아, 나 혼자면 「함께할 멤버가 없어요」 창, 초안이 10개면 「번들 초안은 최대 10개까지 만들 수 있어요.」를 띄우고 선택을 유지한다(기능명세 3.3.4 상세 동작 1, #453). 확인은 번들 만들기 feature의 `useBundleEntryCheck`이고 `PhotosRoute`가 조합해 `checkBundleEntry`로 넘긴다. 확인 중 화면을 떠나거나 번치가 바뀌면 이동하지 않는다.
- 앨범·카메라 연동, 업로드 결과 토스트·「다시 시도」, 카메라 권한 모달은 `usePhotoUpload`가 맡는다(#317): 시트에서 고른 방식으로 쉘의 선택·촬영을 열고, 고른 사진을 한 장씩 가공해 받아 동시에 3장까지 올린다(`POST /bunches/{bunchId}/photos`, 사진 1장당 요청 1건). 대상 번치는 올리기를 시작한 시점의 번치로 고정하고, 끝나면 결과 문구 하나(「N장의 사진을 사진함에 추가했어요.」·「N장을 추가했어요. M장은 올리지 못했어요.」·「사진을 올리지 못했어요.」)를 아래 업로드 상태 줄에 보이며 새로 들어간 사진이 있으면 목록을 다시 받는다. 네트워크 실패와 일시 장애(`PHOTO_007`, BFF가 백엔드에 닿지 못한 `BFF_UPSTREAM_UNAVAILABLE`, 코드 없는 502·504)로 못 올린 사진이 있으면 같은 결과 문구에 「다시 시도」(5초)를 붙인 토스트를 띄우고(상태 줄에 버튼 자리가 없어 우선 이렇게 함, #511), 누르면 같은 묶음 ID로 처음 가공한 파일을 그대로 다시 보낸다. 형식·용량·한도 오류는 다시 시도 대상이 아니고 「올리지 못한 사진」으로만 센다. 하루 한도(`PHOTO_002`)나 한 번에 올릴 수 있는 수(`PHOTO_003`) 오류를 받으면 남은 사진은 읽지도 보내지도 않고 같은 방식으로 센다(다시 시도에서도 같고, 사진함 1,000장 `PHOTO_001`은 같은 사진 합치기가 허용될 수 있어 계속 보낸다). 쉘이 준 이미지는 웹이 보내기 전에 한 번 더 확인해(비어 있거나 JPEG 시작 바이트가 아니거나 4.4MB를 넘으면) 보내지 않고 올리지 못한 사진으로 센다. 올리는 도중에도 새로 올라간 사진은 3초 간격으로 목록에 반영한다(`UPLOAD_LIST_REFRESH_MS`, 사진마다 받으면 최대 1,000장 목록을 자주 다시 받으므로 묶어서 반영). 올리는 동안 화면을 막는 로딩은 두지 않아 올리는 중에도 사진함을 보거나 다른 화면으로 갈 수 있으며 다시 올릴 수도 있다. 다시 시도 결과는 다시 시도한 사진만 센다(기획 확인 완료). 쉘이 없는 브라우저와 새 bridge 메서드가 없는 이전 쉘에서는 안내 토스트만 띄운다(문구는 기획 원문이 없어 임시). 내가 이미 올린 같은 사진(`ALREADY_UPLOADED`)은 서버가 변경 없이 제외하는 중복이다. 실패가 없으면 중복 장수를 알리고(일부 중복 「중복된 M장을 제외하고, 사진 N장을 추가했어요.」, 전부 중복 「이미 사진함에 업로드된 사진이에요.」), 실패가 있으면 중복도 「올리지 못한 M장」에 함께 센다(기획 확정). 다른 멤버가 올린 같은 사진(`MERGED`)은 내 배지가 붙어 사진함에 추가되므로 추가(N)에 센다.
- 업로드 상태 줄(#511, Figma 사진함_02 `7682:83959`, 애니메이션 스펙 `7724:48227`): 멤버 칩 아래·아코디언 위에 높이 54px(위 여백 18px)로 놓는다. 올리는 중에는 썸네일(고른 사진 중 처음 읽은 사진, 34px) + 「{번치 이름}에 N장 업로드 중..」 + 진행 바(사진마다 두 칸: 쉘에서 받으면 한 칸, 결과가 나오면 한 칸. 받지 못한 사진은 결과 때 두 칸. 첫 사진을 받는 순간부터 움직이게 하려는 것이고, 결과는 성공·실패·중복 모두 셈. 다시 시도는 받아 둔 파일을 보내 결과 때 두 칸)를 보인다. 마지막 사진이 끝나면 진행 바가 다 찬 뒤 250ms 쉬고 문구와 진행 바가 위로 10px 올라가며 흐려지고(320ms), 결과 문구가 아래 10px에서 올라오며 나타난다(420ms). 결과 문구는 결과 토스트 문구를 한 줄로 그대로 쓰고(사용자 결정), 한 장이라도 추가됐으면 실패·중복이 섞여도 둘째 줄 「번들을 업로드해보세요.」를 붙인다(시안 문구 그대로, 사용자 결정). 결과는 사진함이 실제로 보이는 순간부터 5초 유지하고 높이와 투명도가 함께 접히며(380ms) 아래 목록이 올라온다. 앱은 탭마다 WebView가 따로라 다른 탭(번치 홈 등)에 가 있는 동안 끝나면 결과를 들고 기다렸다가, 사진함 탭이 다시 보일 때(`visibilitychange`) 5초를 세기 시작한다. 결과 토스트(「다시 시도」·보는 화면 없음)도 페이지가 숨어 있으면 다시 보일 때 띄우고, 보는 화면이 있는지도 그때 판단한다(숨은 사이 다른 탭에서 번치를 바꾼 경우). 결과가 끝내 보이지 않으면 그 번치의 항목과 썸네일 주소가 다음 업로드나 새로고침 때까지 남는다(번치당 하나). 숨은 탭 판단은 숨은 탭 WebView의 `visibilityState`가 `hidden`이라는 전제라 iOS 실기기 확인이 필요하다. 썸네일은 그대로 두고 글자 영역만 바뀐다. 스펙의 채움 전 대기 450ms는 프로토타입이 50%에서 시작하는 시연용이라 넣지 않았다. 나타날 때는 스펙에 모션이 없어 바로 자리를 잡는다. 진행 상태는 화면 밖 저장소(`uploadStatusStore`)에 번치별로 둬 올리는 중에 다른 탭에 다녀와도 남고, 다른 번치의 사진함에서는 보이지 않으며, 결과가 처음 보인 시각 기준으로 지워져, 보인 뒤에 잠깐 떠났다 오면 남은 시간만 보인다. 올리는 중에 같은 번치에 또 올리면 한 줄로 합쳐 장수를 더하고(진행 바는 뒤로 가지 않고 실제 진행이 따라잡을 때까지 멈춘다) 모든 묶음이 끝나면 합친 결과를 보인다(먼저 끝난 묶음에 「다시 시도」 토스트가 뜨면 그 토스트는 그 묶음만 센 문구라 나중의 상태 줄 문구와 다를 수 있다). 결과 문구가 떠 있는 동안 새로 올리면 새 줄로 다시 시작한다(진행 바도 처음부터). 이 번치의 상태 줄을 보는 화면이 없을 때(사진 상세, 다른 번치로 바꾼 사진함, 로딩·오류 화면) 끝나면 결과를 토스트로 알린다(화면 전환 모션이 도는 수백 ms 사이에 끝나면 토스트가 빠질 수 있다). 번치 이름이 길면 이름만 줄여 「N장 업로드 중..」은 남긴다. 글자가 넘치면 말줄임 처리한다(320px 폭에서 긴 중복 문구). 스크린 리더에게는 시작 때 「사진을 올리는 중이에요.」(문구는 기획 원문이 없어 임시), 끝나면 결과 문구를 화면 밖 live region으로 알린다(화면이 inert여도 들리게). 동작 줄이기에서는 이동·높이·진행 바 전환과 교체 대기 없이 투명도만 바뀌고, 접힐 때는 높이를 둔 채 흐려진 뒤 자리를 비운다. 접히기 시작하면 보조기기에서도 숨긴다. 번들 작성의 「내 갤러리에서 가져오기」는 상태 줄을 쓰지 않고 지금처럼 실패가 있을 때만 토스트를 띄운다.
- 사진 상세(#128)는 보통 모드에서 사진을 누르면 `/photos/[photoId]`로 이동한다(`PhotoCell`이 링크, 처리 중·실패 사진은 이동하지 않음, 화면 spec은 `PhotoDetail.spec.md`). 번들 만들기 확정은 `onCreateBundle`로 넘기고 `PhotoBox`가 초안 작성 화면 이동을 맡는다.
- 확인 항목: 날짜 바꾸기·끌기 확인 창의 문구와 시안(임시 문구 사용 중), 끌기 시각 값(반투명 정도·그림자·자동 스크롤 영역), 섹션 안 순서 저장 여부(Nice to have).
- 이어서 불러오기는 구현했다(#315): 첫 쪽(100장)이 오면 먼저 보이고 나머지는 이어서 받는다. 앱을 다시 열면 지난번 첫 쪽(날짜 있는 사진·날짜 모르는 사진 각각, 저장본 24시간)을 먼저 보이고 다시 받는다(#494). 받는 동안 목록 아래에 회색 자리표시 한 줄(Figma에 없는 상태), 실패하면 표시를 숨기고 오류 토스트(「일시적인 오류가 발생했어요. 다시 시도해 주세요」, 명세 3.1.1의 목록 로딩 실패 문구)를 띄우며, 아래로 다시 스크롤하면 그 쪽부터 다시 받는다(키보드·스크린 리더는 포커스 때만 보이는 「사진 더 불러오기」 버튼). 당겨서 새로고침은 피드·번치 홈과 공통이라 `PageShell`의 `onRefresh`로 구현했다(#340): 프로필·멤버·사진 목록을 다시 받고, 선택 모드·저장·삭제 중에는 당김을 끈다. 상세에서 만난 삭제된 사진(404)은 사진 상세가 처리하고, 삭제 요청 중 사라진 사진(`PHOTO_004`)은 #316에서 처리한다.
- iPhone 상태 바·홈 인디케이터(기기 요소. Safe Area는 `AppFrame`이 처리한다)와 하단 탭(`MainTabBar`).

## Route와 접근

- Path·params·search: `/photos`. params는 없다. 임시 `preview` search(`loading`·`error`·`no-bunch`·`empty`)로 상태를 눈으로 확인할 수 있고, route 경계(`lib/preview.ts`의 `parsePreview`)에서 허용 값만 통과시킨다. 알 수 없는 값은 무시하고 운영(`NODE_ENV=production`)에서는 아예 열지 않는다. 제거 조건: 번들 화면 테스트의 샘플 사진(`photoBox.fixture`)이 필요 없어지면 `preview.ts`·`fixtures/`·page의 `searchParams` 읽기를 함께 삭제한다. 사진함 화면·사진 크게 보기·번들 만들기 화면은 이미 사진함 API(개발·시연에서는 가짜 서버)를 쓴다.
- 렌더링: `searchParams`를 읽어 `/photos`가 정적 prerender 대신 요청마다 렌더되는 동적 route다. 정적 정보뿐인 화면이라 비용은 작고, `preview`를 없애면 함께 사라진다.
- 사진을 누르면 사진 상세 `/photos/[photoId]`로 이동한다(`PhotoCell`, `PHOTO_BOX_PATHS.detail`).
- 접근 권한·guard: `(app)` layout의 `AuthGate`가 서버의 가입 상태로 막는다(`features/auth/lib/accessPolicy.ts`, 결정 기록 019). 가입을 마친 사용자만 들어오고, 비로그인은 로그인(처음이면 인트로)으로, 가입 중이면 약관·프로필로 보낸다. 번치 멤버인지는 서버가 판단한다(`docs/specs/photo-box.md`).
- Layout·redirect·navigation: `(app)/(main)` group의 하단 탭 layout 안에서 `PageShell`을 한 번 쓴다. `robots: noindex`.

## 상태와 흐름

- 화면 상태는 `PhotoBoxState`(`loading`·`error`·`no-bunch`·`ready`)다. `usePhotoBox`가 호출 지점이고 내 프로필(기본 번치)·멤버·사진 목록 query를 합쳐 만든다. 날짜를 아는 사진과 모르는 사진은 따로 받아 한 목록으로 합치고, 목록은 마지막 쪽까지 이어서 불러온다(사진함 화면은 `progressive`로 첫 쪽이 오면 먼저 보이고 남은 쪽이 있으면 `data.more`가 `loading`·`error`).
- 멤버 필터는 화면 안 상태다(기본 「전체」). 번치가 바뀌면(`bunch.id`) 화면을 새로 시작해 「전체」로 돌아간다.
- 처리 중(`processing`)·실패(`failed`) 사진과 이미지 로딩 실패(`onError`)는 회색 자리표시이고 접근성 이름은 「처리 중인 사진」·「불러오지 못한 사진」이다.
- 아코디언은 열림 상태를 스스로 갖는다. 열고 닫는 모션은 화면 설계서의 값(340ms, `cubic-bezier(0, 0, 0.35, 1)`)이다. 높이는 `Accordion`이, 좌우 여백·모서리는 이 화면이 같은 값으로 전환하고 `prefers-reduced-motion`에서는 즉시 바뀐다.

- 선택 모드는 화면 안 상태다(`hooks/usePhotoSelectionFlow.tsx`). 서버·기기 동작은 `PhotoBoxActions`(`savePhotos`·`deletePhotos`)로 받고, `usePhotoBox`가 준다. 삭제는 응답을 기다리지 않는다(#490, QA 2차 S3). 「삭제하기」를 누르는 즉시 고른 사진을 목록 캐시에서 빼고 선택 모드를 끝내며, 성공하면 「N장 삭제했어요」, 실패하면 사진을 되돌리고 고른 선택을 되살려 바로 다시 시도할 수 있게 한다(그 사이 새로 고르기 시작했으면 선택은 덮지 않고 실패만 알림). 목록은 끝난 뒤 뒤에서 다시 받는다. 저장은 사진마다 상세 API로 원본 주소를 받아 쉘의 `saveImagesToAlbum`에 넘겨 기기 앨범에 저장하며(`api/albumSave.ts`, 저장 권한이 거부되어 있으면 `SaveResult.blocked`로 알려 「사진 접근 권한이 필요해요」 창을 띄우고 선택을 유지, 앱이 아니면 안내 토스트만), 날짜 변경(`POST …/photos/date`)은 mutation 뒤 목록을 다시 받아 반영한다. 삭제·날짜 변경에서 고른 사진이 그사이 지워져 거절되면(`PHOTO_004`, `MissingPhotosError`) 사라진 사진만 선택에서 빼고 「선택한 사진 중 N장이 사진함에서 사라져 선택이 해제됐어요.」를 띄우며 선택 모드는 유지한다(서버가 사라진 사진을 알려 주지 않으면 일반 실패로 다룬다). 끌어서 옮기기는 「삭제된 사진이에요」 토스트만 띄운다.
- 선택 모드 동안 `HideMainTabBar`를 렌더해 `(main)` layout이 탭 막대를 숨기고 `--main-tab-bar-*` 변수를 0으로 되돌린다. 「⋯」는 막대가 있을 때와 같은 10px 간격(`float-gap`)으로 화면 끝 위에 놓인다(Figma 사진함_07은 간격 0이지만 막대와 같은 간격으로 맞추기로 했다). iOS 쉘에서는 시스템 탭 바를 숨기는 경로가 없어 선택 모드에도 탭 바가 남는다(`docs/specs/photo-box.md` 확인 항목).
- 사진함 토스트는 모두 목록 폭(343px)이고 탭 막대가 보이면 막대 위 16px에 뜬다(`toast()`의 `tab-bar` 앵커, `Toast.spec.md`). 선택 모드를 끝낸 직후의 완료 토스트는 막대가 다시 나타난 뒤 다음 프레임에 위치를 다시 재서 막대 위에 놓인다. 선택 모드 중에는 막대가 숨겨져 기본 위치다.

## UI와 접근성

- Component mapping: 헤더는 `core`의 `Header`+`AccountSwitcher`+`TextButton`, 필터 칩은 `ChipButton`(`solid`·`avatar`, size L), 아코디언은 `Accordion`, 사진 칸은 `PhotoThumbnail`(`onImageError` 추가), 「+」는 `FloatingButton icon="add"`, 번치 없음 버튼은 `Button`.

## 디자이너 확인 항목

- 칩 높이: Figma 화면 인스턴스는 40px인데 `ChipButton` L 컴포넌트는 38px이다. 화면 값(40)을 따랐다.
- 빈 상태·번치 없음 일러스트: Figma 5991:162053·5991:162448·5878:79966의 SVG를 `src/shared/assets/images/empty/`에 두고 `next/image`로 표시한다(장식이라 `alt=""`).
- `AccountSwitcher`: Figma에서 대표 이미지가 삭제되어 이름과 화살표만 보인다(`977:8709`).
- 로딩·오류·처리 중 사진의 모양은 Figma에 없어 이 PR에서 정한 값이다.
- 삭제·날짜 바꾸기 확인 창 문구: 기능명세서 3.3.5·3.4.1 원문대로 상황별로 다르다. 삭제는 내가 올린 사진만(한 장 「이 사진을 삭제할까요?」, 여러 장 「선택한 사진 N장을 삭제할까요?」), 관리자가 다른 멤버 사진만(「다른 멤버가 업로드한 사진이에요.」), 관리자가 내 사진과 다른 멤버 사진을 함께(「다른 멤버가 업로드한 사진이 포함되어 있어요.」), 함께 올린 사진만(「내가 올린 사진을 삭제할까요?」 / 「사진은 그대로 유지되고, 업로더 목록에서 내 이름만 사라져요.」), 혼자 올린 사진과 함께 올린 사진이 섞임(「선택한 사진 N장을 삭제할까요?」 / 「삭제 이후에는 복구할 수 없어요.」 + 「다른 멤버도 올린 사진 M장은 사진함에 남아요.」)을 `getDeleteKind`로 나눈다. 날짜 바꾸기는 관리자가 다른 멤버 사진만 고르면 「다른 멤버가 올린 사진이에요.」, 내 사진과 섞거나 함께 올린 사진이 있으면 「다른 멤버가 업로드한 사진이 포함되어 있어요.」이고, 둘째 줄은 「날짜를 변경하면 사진함에서 변경된 날짜로 보여요.」, 버튼은 「취소」/「변경하기」다(`getDateConfirmKind`). 사진이 사라질 때 그중 작성 중인 번들에 쓰인 사진(`usedInDraftBundle`)이 있으면 「삭제 이후에는 복구할 수 없어요.」 줄만 「작성 중인 번들에 쓰인 사진도 있어요. 삭제하면 번들에서도 빠지고 복구할 수 없어요.」로 바꾼다(`removesDraftBundlePhoto`, 함께 올린 사진에서 내 이름만 빠지는 경우는 그대로). 헤더의 번치 이름을 누르면 번치 탭과 같은 번치 전환 시트가 열리고(`PhotosRoute`가 조합해 `bunchSwitcher`로 넘김), 사진함은 머무는 동안 20초마다 목록을 다시 받는다.
- 선택 모드에서 처리 중·실패 사진(회색 자리표시)은 고를 수 없게 했다. 기획 확인이 필요하다.
- 저장하는 동안의 로딩은 사진마다가 아니라 페이지 전체다(Figma 사진함_12): 화면 전체를 `overlay-dim-subtle`로 덮고 가운데에 디자이너가 전달한 `loading.json`(로티)을 재생한다. 덮는 동안 아래 화면은 눌러도 반응하지 않는다. 점 크기는 Figma 지름 9.3px에 가깝게 원본(70×28)을 1.6배(112×45, 지름 약 8.8px)로 그렸다. 사진 선택 시 오버레이(투명도)와 인디케이터 배경은 설계서 값(150ms, `cubic-bezier(0, 0, 0.35, 1)`)으로 전환하고 `prefers-reduced-motion`에서는 즉시 바뀐다.
