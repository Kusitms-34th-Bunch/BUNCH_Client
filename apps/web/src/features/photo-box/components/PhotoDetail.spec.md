# 페이지: 사진 상세(`/photos/[photoId]`)

## 메타데이터

- Route: `/photos/[photoId]`(`apps/web/src/app/(app)/photos/[photoId]/page.tsx`). 하단 탭이 없는 화면이라 `(main)` 밖에 둔다.
- Status: 헤더·큰 사진·올린 멤버 배지·좌우 스와이프·확대·더보기 메뉴(저장·날짜 바꾸기·삭제)·없는 사진 처리 구현됨(fixture와 목 동작, headless Chrome 375×812 실측. 실기기 전). 날짜 바꾸기 시트 연결됨(목 동작).
- 디자인 출처: Figma `사진함_16·17·18·21·22`와 화면 설계서 상세 보드(`1861:36350`, 날짜 변경 시트는 `1861:36652`). 이슈 #128.
- 기능 spec: `docs/specs/photo-box.md`의 3.5 사진 상세. 라이브러리 결정: `docs/decisions/records/015-photo-detail-swiper.md`.

## 목적과 범위

### 포함

- 헤더: 뒤로가기, 촬영 날짜(사진함과 같은 형식: 올해는 「8월 16일 일요일」, 올해가 아니면 「2025년 12월 24일」, 없으면 「날짜 미확인」), 더보기. 장소 줄은 없다.
- 큰 사진은 원본 비율로 폭 가득, 세로 가운데에 놓는다. 오른쪽 위(위 12px, 오른쪽 16px)에 올린 멤버 `UploaderBadge`를 두고 함께 올린 사진은 세로로 여러 개 쌓는다.
- 한 번 누르면 헤더와 배지가 200ms(`cubic-bezier(0, 0, 0.35, 1)`)로 서서히 숨고, 다시 누르면 보인다. 확대하면 숨고 원래 크기로 돌아오면 다시 보인다. 숨긴 상태는 사진을 넘겨도 유지한다. 더블탭(확대)은 헤더 토글로 세지 않는다.
- 좌우 스와이프로 사진함 순서의 이전·다음 사진으로 넘기고 처음·끝에서 멈춘다. 넘길 때마다 주소(`/photos/{id}`)만 바꿔(Next 이동 없이) 새로고침·공유가 현재 사진을 가리킨다.
- 더보기 메뉴(헤더 아래 오른쪽 정렬, 위에서 아래로 열림): 저장(모두), 날짜 바꾸기·삭제(올린 멤버·관리자만, 다른 멤버 사진이면 저장만).
- 저장: 화면 전체 dim + 점 3개 로딩(`PageLoading`), 완료 토스트 「이미지 저장이 완료되었어요.」, 실패 「일시적인 오류가 발생했어요. 다시 시도해 주세요」.
- 삭제: 목록과 같은 확인 창(「삭제하기」/「취소」) 뒤 삭제. 사진이 사라지면 사진함으로 돌아가 「사진함에서 사진 1장이 삭제되었어요.」, 함께 올린 사진에서 내 이름만 빠지면 상세에 머문다(토스트 없음, 배지만 갱신).
- 없는 사진(삭제됨·잘못된 id·형식이 틀린 id)은 「삭제된 사진이에요」 토스트 뒤 사진함으로 이동(`replace`).

### 범위 외(추후 작업 예정)

- 날짜 바꾸기 시트(Figma `1861:36652`): DS `DateChangeSheet`에 `defaultDate`로 현재 사진의 촬영 날짜를 넘겨 그 날짜를 고른 채 그 달로 연다(촬영 날짜를 모르면 선택 없이 오늘 달). 페이지마다 첫 선택 상태가 달라 시트가 아니라 화면이 정한다. 오늘 이후는 비활성이고 다른 날짜를 골라야 저장할 수 있다. 저장하면 `changePhotoDates([id], date)`로 날짜(시각 유지)를 바꾸고 시트를 닫으며 「사진 날짜가 변경되었어요.」 토스트를 띄운다. 사진함 순서가 바뀌면 슬라이드를 현재 사진 위치에 다시 맞춘다. 실패하면 오류 토스트를 띄우고 시트를 그대로 둔다. 시트가 열린 동안에는 방향키로 사진을 넘기지 않는다. 확인 항목: 관리자가 다른 멤버 사진의 날짜를 바꿀 때의 확인 문구는 원문이 없어 연결하지 않았다.
- API 연동: 사진 상세 조회·저장·삭제는 `usePhotoBox`의 fixture와 목 동작이다. 연결하면 이 hook만 바꾼다.
- 다음 이동·새로고침 때가 아니라 다른 멤버가 지운 사진을 보는 중에 바로 알리는 동작(실시간 반영 없음, 기능 spec 3.1.1).

## Route와 접근

- Path·params: `photoId`는 외부 입력이라 route 경계(`parsePhotoId`)에서 영문·숫자·밑줄·하이픈 64자 이하만 통과시키고, 아니면 `undefined`로 화면에 넘겨 없는 사진과 같은 안내로 처리한다.
- 접근 수준: 번치 멤버만. 인증·번치 소속 확인은 API와 로그인이 연결될 때 route 단계에서 한다(지금은 fixture라 열려 있다). `/photos`와 마찬가지로 연결 전 운영 노출은 릴리스 게이트로 따로 추적한다.
- 직접 URL: 돌아갈 기록이 없으면 뒤로가기는 사진함으로 이동(`replace`), 있으면 `back()`. 새로고침 시 현재 `photoId`로 다시 열린다. 기록 유무는 `window.history.length > 1`로만 판단해서, 외부 사이트에서 같은 탭으로 들어오면 `back()`이 앱 밖으로 나가고 새 탭이면 사진함으로 간다(앱 안 이동 여부를 구분하는 신호는 Next 내부 값이라 쓰지 않았다).
- 접근 제어의 릴리스 게이트: 로그인·번치 소속 확인은 API 연결 때 route 단계에서 한다. 미로그인·번치 비소속일 때 redirect 대상과 원래 목적지 보존 여부는 미정이다. 추적할 이슈 번호는 로그인·API 연결 이슈가 생길 때 적는다.
- `metadata`: 제목 「사진 상세」, 검색 제외. 동적 segment라 요청마다 렌더된다.

## 상태와 흐름

- 사진 목록은 `usePhotoBox`(fixture)에서 받아 `getDetailOrder`로 사진함 순서(날짜 섹션 최신순, 섹션 안 최근 촬영순)로 정렬하고, 촬영 날짜를 모르는 사진은 맨 뒤에 둔다.
- 화면 안 상태: 현재 사진 id, 탭으로 숨김, 확대로 숨김, 메뉴 열림·마운트, 삭제 확인 창, 저장·삭제 진행. 숨김은 `탭 숨김 || 확대 숨김`이다.
- 슬라이드는 전체 장수만큼 두되 현재 사진 앞뒤 한 장만 이미지를 그린다.
- 저장·삭제가 도는 동안은 더보기를 `aria-disabled`로 막고(포커스 유지) 메뉴 선택을 무시한다.

## 데이터 의존성

- Query: 없음(fixture). 연결 시 사진 상세는 목록 query 캐시에서 읽고 삭제·저장 후 목록 query를 무효화한다(`docs/specs/photo-box.md`의 후보 키).
- API 계약 확인 항목: 사진 상세에 필요한 필드(원본 URL, 올린 멤버들의 현재 프로필, 촬영 날짜와 출처), 삭제 시 「내 이름만 빠짐」과 「사라짐」의 구분 응답.

## UI와 접근성

- Component mapping: 헤더는 `core`의 `Header`+`HeaderIconButton`·`IconButton`, 배지는 `UploaderBadge`, 메뉴는 공통 `PhotoActionMenu`(DS `Menu`), 삭제 확인 창은 `DeleteConfirmDialog`, 로딩은 `PageLoading`, 스와이프·확대는 Swiper.
- Semantic·heading: 화면 제목 `h1`(「사진 상세」, 화면에는 숨김), 현재 위치(「N장 중 M번째 사진」)는 항상 마운트된 `role="status"`, 사진은 `alt`가 있는 `img`, 처리 중·실패 사진은 이름이 있는 자리표시.
- 키보드: 방향키 좌우로 사진을 넘기고(Swiper `Keyboard`), 포커스 가능한 「이전 사진」·「다음 사진」 버튼(평소 숨김, 포커스 때 보임, 처음·끝에서는 `aria-disabled`라 포커스를 잃지 않음)과 「사진 확대/축소」 버튼(`aria-pressed`)이 스와이프·핀치의 대체다. 메뉴·삭제 확인 창이 열려 있거나 저장·삭제가 도는 동안은 방향키 이동을 끈다. 헤더를 숨긴 상태에서도 포커스가 들어오면 다시 보인다(`focus-within`).
- 요청 중: 저장·삭제가 도는 동안 사진 영역은 `inert`이고(헤더는 더보기 포커스를 유지하려고 열어 둠), 삭제는 확인 창을 연 시점의 사진을 지운다(그 사이 넘겨져도 다른 사진을 지우지 않음). 현재 사진 앞뒤가 아닌 빈 슬라이드는 `aria-hidden`이다.
- 메뉴: 열면 첫 항목에 포커스, Esc·바깥 누름·Tab 이탈로 닫고 포커스는 더보기로 돌아온다. 동작 줄이기에서는 헤더·배지 전환과 메뉴 모션이 즉시 바뀐다.

## 디자이너·기획 확인 항목

- 삭제 확인 창 문구: 상세용 확인 창이 Figma에 따로 없어 목록과 같은 「선택한 사진을 삭제할까요?」(장수는 뺌)를 쓴다. 상세에서도 「선택한」이 맞는지와 종류별 문구 원문이 없는 점을 확인해야 한다.
- 메뉴 높이: Figma 163px, DS `Menu`는 160px(항목 3개)으로 3px 차이(컴포넌트 기준).
- 숨긴 헤더·배지를 키보드·스크린 리더로 접근하게 한 방식(포커스가 들어오면 보임)은 Figma에 없는 접근성 판단이다.
- 큰 사진이 화면보다 세로로 길 때는 폭 가득이라 위아래가 잘릴 수 있다(확대로 이동). 긴 사진의 맞춤 방식은 Figma에 없다.
- 확대 최대 배율(3배)과 더블탭 확대 동작은 Figma에 값이 없어 정한 값이다.
- 포인터 전용 사용자(키보드 없이 마우스·헤드포인터)의 단일 포인터 대체: 지금은 숨김 버튼이라 마우스 드래그 말고 눌러서 넘기는 수단이 없다. 화면 가장자리 탭 영역이나 상시 노출 화살표 같은 대체는 디자인 결정이 필요하다(WCAG 2.5.1·2.5.7).
- 확대 중 이동: 키보드로 확대한 사진 안에서 이동하는 방법이 없다(확대 중 방향키는 슬라이드 이동). 패닝 키 동작을 정할지 확인이 필요하다.
- 숨긴 헤더와 스크린 리더: 숨김은 투명도뿐이라 접근성 트리에 남지만, VoiceOver·TalkBack의 접근성 포커스는 `focus-within`을 일으키지 않아 보이지 않는 채 읽힌다. 실기기 낭독으로 확인한다.
- Swiper `A11y`의 자체 안내와 위치 안내(`role=status`)가 겹쳐 낭독될 수 있다. 삭제 후 사진함으로 이동할 때 포커스 위치는 Next에 맡겨져 있다. 둘 다 스크린 리더로 확인한다.
