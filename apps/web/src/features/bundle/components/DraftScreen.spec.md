# 페이지: 번들 작성(`/bunch/drafts/[draftId]`)

## 메타데이터

- Route: `/bunch/drafts/[draftId]`(`apps/web/src/app/(app)/bunch/drafts/[draftId]/page.tsx`). 하단 탭이 없는 화면이라 `(main)` 밖에 둔다.
- Status: 헤더·연결 끊김 배너·참여 멤버·제목·사진 목록·위치·날짜·코멘트·공개 범위·나가기와 역할별 권한, 업로드 조건 구현됨(fixture와 목 동작, headless Chrome 375×812 실측. 실기기 전).
- 디자인 출처: Figma 화면 설계서 `1998:31389`, 최종 화면 `3220:59525`, 수정 가이드 `3043:63821`, 권한 및 업로드 조건 `2084:22177`, 나가기 확인 창 `2082:49691`. 이슈 #152.
- 기능 spec: `docs/specs/bundle-create.md`의 4.3 공동 편집.

## 목적과 범위

### 포함

- 고정 헤더: 뒤로가기, 저장 상태(「저장 완료」, 저장 중에는 「저장 중」 뒤에 점이 0→1→2개로 600ms마다 바뀜), 「업로드」. 연결이 끊기면 헤더 아래에 고정 배너(「인터넷 연결을 확인해 주세요.」+「재시도」).
- 영역 순서: 참여 멤버, 제목\*, 사진과 캡션, 위치·날짜, 코멘트\*, 공개 범위\*, 나가기(참여 멤버에게만).
- 참여 멤버: 역할 배지 하나(관리자 > 공동 관리자 > 초안 생성자), 다른 멤버 카드의 삭제 버튼(초안 생성자와 참여 중인 관리자에게만, 초안 생성자·내 카드 제외), 맨 끝 「추가」 카드(참여 멤버에게만).
- 제목: 40자까지, 40자에 닿으면 「제목은 40자까지 쓸 수 있어요.」.
- 사진: 가로로 넘기는 목록(첫 장 왼쪽 16px 여백, 사진 300px·간격 12px)과 가운데 사진의 캡션(2줄, 없으면 「캡션 추가...」). 보기만 한다.
- 위치(최대 3개)와 날짜: 위치는 검색 시트에서 고르고 바로 반영, 날짜는 달력 시트(`DateChangeSheet`)나 추천 날짜 칩.
- 코멘트: 내 카드가 맨 위, 내 카드만 입력(400자), 다른 멤버가 쓰는 중이면 점 애니메이션.
- 공개 범위: 「멤버 공개」·「공개」 라디오(처음에는 아무것도 고르지 않고, 발행하려면 하나를 골라야 함).
- 나가기: 확인 창(「번들에서 나가시겠어요?」) 뒤 번치 홈으로 이동.
- 업로드 조건(제목, 사진 1장 이상, 참여 멤버 2명 이상, 참여 멤버 전원 코멘트, 저장 안 된 변경 없음, 연결 끊김 아님)과 「업로드」 활성·안내.

### 범위 외(추후 작업 예정)

- 서버 연동 전부: 초안 조회·저장·발행, 장소 검색, 실시간 편집 반영, 편집 잠금. 지금은 `useDraft`의 fixture와 메모리 상태이며, 바꿀 때마다 1초 뒤 「저장 완료」로 돌아오는 목 동작이다. 연결하면 이 hook만 바꾼다.
- 「추가」 카드의 동작(참여 멤버 관리 화면): 참여 멤버 추가·삭제 이슈에서 연결한다. 지금은 카드만 권한에 맞게 보이고 눌러도 아무 일이 없다. 멤버 삭제 버튼은 내보내기 확인 창(「○○님을 번들에서 내보낼까요?」, Figma `2091:62913`)까지 연결했고 확인하면 그 멤버와 코멘트가 목 상태에서 빠진다. 멤버 관리 화면의 추가·제외 토스트는 그 이슈에서 한다.
- 사진·캡션을 눌렀을 때 사진 상세 화면 이동, 「+ 사진 추가」: 사진 상세·사진 추가 이슈에서 연결한다.
- 업로드 요청: 조건을 모두 채운 권한자가 누르면 확인 창(「번들을 업로드할까요?」 + 「업로드한 번들은 멤버들과 공유되며, 업로드 이후 수정할 수 있어요.」)을 열고, 「업로드」를 눌러야 `onPublish`를 부른다. container가 업로드 API를 연결하지 않았다.
- 다른 멤버가 편집 중인 제목·위치·날짜를 누르면 「다른 멤버가 편집 중일 땐 수정할 수 없어요.」 토스트(Figma `2060:37684`)를 띄우고 입력·시트 열기를 막는다. 사진 캡션은 이 화면에서 입력하지 않아 토스트 대상이 아니다.

## Route와 접근

- Path·params: `draftId`는 외부 입력이라 route 경계(`parseDraftId`)에서 영문·숫자·밑줄·하이픈 64자 이하만 통과시키고, 아니면 `undefined`로 화면에 넘겨 없는 초안과 같은 안내로 처리한다. fixture에는 `draft-1`만 있다.
- 접근 수준: 번치 멤버만. 인증·번치 소속 확인은 API와 로그인이 연결될 때 route 단계에서 한다(지금은 fixture라 열려 있다). 미로그인·번치 비소속의 redirect 대상은 미정이다.
- 화면 안 접근 구분: 참여 멤버가 아닌 번치 멤버는 보기만 하고 고치려 하면 「참여 멤버만 편집할 수 있어요」를 안내한다. 이는 route guard가 아니라 화면 안 action gate다.
- 직접 URL: 돌아갈 기록이 없으면 뒤로가기는 번치 홈으로 이동(`replace`), 있으면 `back()`. 뒤로가기는 묻지 않는다. 기록 유무는 `window.history.length > 1`로만 판단한다.
- 없는 초안(삭제됨·발행됨·잘못된 id)은 「삭제된 번들이에요」 토스트 뒤 번치 홈으로 이동(`replace`).
- `metadata`: 제목 「번들 작성」, 검색 제외.

## 상태와 흐름

- 권한 표는 `docs/specs/bundle-create.md`의 표를 `getDraftAccess`·`canRemoveMember`가 구현한다. 참여 여부는 `draft.members`에 내 id가 있는지로 정하고, 발행 권한은 초안 생성자이거나 번치 관리자·공동 관리자인 참여 멤버다.
- 「업로드」는 항상 그려 두고 조건을 못 채우면 `aria-disabled`로 흐리게 한다. 누르면 이유를 안내한다: 참여 멤버가 아님 → 「참여 멤버만 편집할 수 있어요」, 권한 없음 → 「번치 관리자와 해당 번들 생성자만 업로드할 수 있어요.」, 필수 항목 부족·저장 중·연결 끊김 → 「필수 항목을 모두 입력해야 업로드 할 수 있어요.」.
- 위치는 3개가 차면 「추가」 행이 사라지고, 0개이면 「위치 추가」 한 줄만 보인다.
- 위치 검색 시트: 검색 전에는 안내(「태그한 위치는 함께 보여요」), 검색하면 결과(이름·주소) 또는 「검색 결과가 없어요」. 결과를 누르면 바로 추가하고 닫는다. 열 때마다 처음 상태로 돌아가고, 이전 검색의 늦은 응답은 버린다.
- 연결 끊김은 브라우저의 `online`·`offline` 이벤트로 판단한다. 서버에 닿는지까지는 알 수 없고, 「재시도」는 지금 상태를 다시 읽을 뿐이다.

## 데이터 의존성

- Query: 없음(fixture). 연결 시 `bundleKeys.draft(draftId)`와 장소 검색 query를 쓴다(`docs/specs/bundle-create.md`의 후보 키).
- API 계약 확인 항목: 초안 전체 상태와 내 권한·역할 값(웹은 응답의 권한 값으로 버튼 표시를 정함), 편집 중 정보, 장소 검색, 발행 요청.

## UI와 접근성

- Component mapping: 헤더는 `core`의 `Header`+`HeaderIconButton`·`TextButton`, 배너는 `ErrorBanner`, 멤버는 `MemberCard`·`AddMemberCard`, 제목은 `BundleTextInput`, 사진은 `BundlePhoto`, 위치·날짜는 `SelectionFieldGroup`·`SelectionField`와 `BottomSheet`·`SearchField`·`LocationListItem`·`DateChangeSheet`, 코멘트는 `BundleCommentCard`, 공개 범위는 `RadioCard`, 나가기 확인은 `Dialog`.
- Semantic·heading: 화면 제목 `h1`(「번들 작성」, 화면에는 숨김), 각 영역은 `BundleTitle`을 `aria-labelledby`로 가리키는 `section`. 저장 상태와 사진 위치(「N장 중 M번째 사진」)는 `role="status"`.
- 키보드: 위치·날짜 줄과 지우기, 추천 칩, 라디오, 「나가기」 모두 `button`·`radio`다. 확인 창은 최초 포커스가 「취소」(Dialog 기본)에 있다.
- 읽기 전용: 제목·코멘트 입력란은 `readOnly`라 포커스는 받되 고칠 수 없다. 참여 멤버가 아니면 닿았을 때 안내한다.
- 동작 줄이기: 「저장 중」 점은 움직이지 않는다.

## 디자이너·기획 확인 항목

- 위치 개수: 기능 spec은 번들당 1개, Figma 수정 가이드(`3043:63821`)는 3개까지(3개면 「추가」 행 없음)라 3개로 구현했다. 기능 spec의 문구를 바꿔야 한다.
- 공개 범위: Figma 시안은 「멤버 공개」·「공개」에 「공개」가 기본으로 골라져 있고, 설계서 설명 표는 「비공개」·「공개」라고 적혀 있다. 시안 문구로 구현했다. 기능명세서 수정본(4.3.9)이 「기본값 없음」이라 이를 따라 처음에는 아무것도 고르지 않고 발행 조건에 넣었다(권한 문서의 「기본값 공개」와 다름, 기획 확인 필요).
- 공개 범위 옆 안내 아이콘의 툴팁 문구가 기획에 없어 장식으로만 두었다.
- 나가기 확인 창: 초안 생성자도 같은 문구(「번들에서 나가시겠어요?」)를 쓴다. 생성자가 나가면 초안이 삭제되고 이동 뒤 토스트로 알린다(팀 결정, 기획 확인 필요).
- 디자인 시스템 `SelectionField`의 추천 칩이 있는 줄은 높이 102px(세로 여백 16px)인데 이 화면의 Figma는 94px(여백 12px)다. 컴포넌트 기준이 바뀐 것이라 이 이슈에서는 고치지 않았고, 날짜 줄이 8px 크다.
- 다른 멤버가 위치·날짜를 편집 중일 때 제목 옆에 그 멤버 프로필을 보이는 표시는 `SelectionField`가 아바타를 받지 않아 구현하지 않았다(제목·사진·코멘트는 구현).
- 위치 줄을 눌러 값을 바꾸는 동작은 기획에 없어 연결하지 않았다.
- 위치 검색 시트에 닫기 버튼이 없다(Figma에 없음). 닫는 방법이 ESC·끌어내리기·바깥 누름뿐이라 스크린 리더·스위치 사용자용 닫기 컨트롤을 둘지 확인이 필요하다.
- 사진 가로 목록: 스크롤 영역에 포커스 가능한 요소가 없어 Safari(iOS 쉘 WebView 포함)에서 키보드로 두 번째 사진 이후를 볼 수 없을 수 있다. 캡션도 가운데 사진 것만 DOM에 있어 나머지는 읽히지 않는다. 사진 상세 이슈에서 사진·캡션을 눌러 상세로 가는 흐름이 생기면 함께 정한다.
- 위치·날짜를 고르거나 지운 뒤 포커스: 누른 요소가 사라져(예: 위치 0개 → 그룹으로 교체, 추천 칩 사라짐) 포커스가 `body`로 갈 수 있다. 복귀 정책이 필요하다(`SelectionField` 문서에도 호출하는 쪽 책임으로 적혀 있다).
- 업로드를 못 하는 이유 안내: 저장 중·연결 끊김에서도 「필수 항목을 모두 입력해야 업로드 할 수 있어요.」를 쓴다. 원인에 맞는 문구가 기획에 없어 확인이 필요하다.
- 다른 멤버가 코멘트를 쓰는 중이라는 표시는 점 애니메이션(`role="img"` 이름)이라 상태 변화로 읽히지 않는다. 제목은 낭독 영역을 항상 두어 읽힌다.
- 저장 상태는 바뀔 때마다(`저장 중` ↔ `저장 완료`) polite로 읽혀 타이핑 중 자주 낭독될 수 있다. 실제 저장 연결 뒤 빈도를 보고 조정한다.
- 비참여자가 입력란·라디오에 닿거나 방향키를 누를 때마다 토스트가 뜬다. 보기 전용임을 입력란 모양으로 알 수 없어 시각 처리(스타일) 확인이 필요하다.
- 위치 검색은 Enter(제출)에서만 실행하고, 코멘트 입력란에는 필수(`aria-required`) 표시가 없다(디자인 시스템 컴포넌트 한계).
