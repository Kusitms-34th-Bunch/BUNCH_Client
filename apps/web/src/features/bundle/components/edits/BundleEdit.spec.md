# 페이지: 발행 번들 수정(`/bunches/[bunchId]/bundles/[bundleId]/edit`)

## 메타데이터

- Route: `apps/web/src/app/(app)/bunches/[bunchId]/bundles/[bundleId]/edit/page.tsx`와 사진 추가 `…/edit/photos/add/page.tsx`. 두 화면은 같은 `layout.tsx`의 `BundleEditProvider`가 든 편집 값을 본다.
- Status: 수정 화면, 저장, 나가기 확인, 사진 추가(사진함)를 구현했다(가짜 서버, 실서버·실기기 전).
- 디자인 출처: Figma `BUNCH - 작업파일`의 수정 화면 `6163:183410`(기본)과 `6163:183470`(스크롤 + 코멘트를 눌렀을 때의 토스트).
- 기능 spec: `docs/specs/feed.md` 6.2.12(수정), 4.3.1·4.3.4·4.3.6·4.3.7(공동 편집 화면을 다시 씀).
- 이슈: #423.

## 목적과 범위

### 포함

- 메인 관리자가 발행한 번들의 **제목, 날짜, 사진(추가·삭제·순서), 위치(최대 3개)**를 고쳐 「저장」 한 번으로 서버에 보낸다(`PUT …/bundles/{id}/published`). 저장 전까지 서버에 반영하지 않는다(공동 편집의 자동 저장과 다름).
- 공동 편집 화면의 `DraftTitleField`·`DraftPhotos`·`DraftPlaceDate`·`DraftMembers`·`DraftComments`와 사진 추가 화면(`DraftPhotoAdd`)을 다시 쓴다. 차이는 아래와 같다.
  - 헤더는 뒤로가기만 있다(저장 상태·더보기·편집 중 표시 없음). 하단은 「업로드」 대신 「저장」이다.
  - 「픽하기 >」가 없다. 참여 멤버는 보기만 하고(X·「추가」 카드 없음) 코멘트 카드는 흐리게 잠가 누르면 「업로드된 코멘트는 수정 불가해요.」만 띄운다(입력·포커스 없음).
  - 실시간 연결·presence·자동 저장·다른 멤버의 편집 표시가 없다. 서버 값은 화면을 열 때 한 번만 받고 편집 중에는 다시 받지 않는다.
- 「저장」은 바뀐 내용이 있고 제목이 비어 있지 않을 때만 켜진다. 누르면 「수정한 내용을 저장할까요?」 / 「변경된 내용이 기존 번들에 반영돼요.」(「취소」·「저장」)를 거쳐 저장하고, 상세로 돌아가 「번들을 수정했어요」를 띄운다. 저장하는 동안은 로딩이 화면을 덮는다.
- 바뀐 내용이 없으면 뒤로가기는 바로 상세로, 있으면 「수정을 그만둘까요?」 / 「수정한 내용은 저장되지 않아요.」(「나가기」·「계속 수정」)를 거친다.
- 썸네일을 누르면 수정 중 사진 크게 보기(`edit/photos/[photoId]/viewer`)가 열리고, 같은 편집 상태를 보며 ⋯ 메뉴에서 사진을 뺄 수 있다. 마지막 1장은 뺄 수 없다(「사진을 삭제할 수 없어요」). 사진 추가는 사진함에서 가져오고, 적용해도 서버에는 보내지 않고 이 화면의 편집 값에 더한다.

### 범위 외

- 내 갤러리에서 가져오기(작성 화면과 같이 사진함이 가득 찼을 때의 안내만, 기기 사진 선택은 사진함 API 이슈 #344).
- 픽·참여 멤버·코멘트·공개 범위 수정(공개 범위는 6.2.15 화면).
- 제목의 금칙어 거부 안내(서버 응답 형태가 정해지면 후속 이슈로 처리).
- 브라우저·기기의 뒤로가기 제스처 가로채기(헤더 뒤로가기만 확인을 거친다).

## Route와 접근

- `(app)` route이며 `robots: noindex`다. 서버 숫자 id로 바꿀 수 없는 주소는 `notFound()`로 막는다.
- 메인 관리자(OWNER)만 쓴다. 우리 번치가 아니거나 메인 관리자가 아니면 「권한이 변경되어 해당 기능을 이용할 수 없어요.」 뒤 상세로 `replace`한다. 저장 때 서버가 권한 없음(`AUTH_002`)을 주면 같은 안내와 함께 상세를 새로 받게 한다.
- 없는 번들(`RESOURCE_001`)·그사이 삭제됨은 안내 없이 상세로 보내 그 화면이 삭제 안내를 맡고, 발행 전 초안(`BUNDLE_002`)은 작성 화면으로 보낸다.
- 전환은 상세 → 수정, 수정 → 사진 추가 모두 `bunchDrill`이고 `FEED_PATHS.transitionIds`로 경계를 잡는다.
- 상세 더보기(메인 관리자)의 「수정하기」(`FEED_PATHS.bundleEdit`)가 진입점이다.

## 데이터 의존성

- 읽기: `GET …/bundles/{id}`(`bundleEditQueryOptions`: 열 때마다 새로, 이후 `staleTime: Infinity`), 내 프로필·번치 멤버(역할 판단).
- 쓰기: `PUT …/bundles/{id}/published`(`editPublishedBundle`). 사진은 남긴 번들 사진의 `bundlePhotoId` 또는 사진함 원본의 `photoId`, 위치는 보낸 순서가 자리(`position`), 날짜 없음은 필드를 생략한다. 같은 요청 ID를 다시 보내지 않고 호출마다 새 `X-Request-Id`를 쓴다.
- 오류: `BUNDLE_003`(편집하는 사이 서버 값이 바뀜)은 최신 값을 받아 두고 「일시적인 오류가 발생했어요. 다시 시도해 주세요」(저장 실패와 같은 문구)를 띄운다. 서버에서 바뀐 필드(제목·날짜·사진·위치)의 내 편집은 버리고 최신 값을 보이며, 바뀌지 않은 필드의 편집은 남겨 다시 저장하게 한다(전체 목록을 덮어쓰는 저장이라 다른 곳의 변경을 지우지 않기 위함, 명세에 없는 처리라 확인 필요). `BUNDLE_002`·`RESOURCE_001`은 상세로 보내고, 그 밖의 오류는 같은 문구를 띄우고 화면에 머문다.
- 저장하면 서버가 돌려준 값이 새 기준이 되고, `onSaved`가 피드·번들 상세 캐시를 비워 상세가 새로 받게 한다(feature끼리 직접 잇지 않으려고 route의 `BundleEditRoute`가 연결).

## 결정과 가정

- 참여 멤버의 「추가」 카드: Figma 두 node에는 있지만 6.2.12가 「참여 멤버는 보기만」이고 멤버를 고칠 수 없어 **숨긴다**(사용자 결정).
- 하단 안내문: 명세에 문구가 없어 **작성 화면의 현재 문구 「코멘트와 픽하기는 업로드 이후 수정이 불가해요」를 유지**한다. Figma `6163:183470`은 「코멘트와 픽한 사진은 …」으로 달라 디자이너 확인이 필요하다(사용자 결정).
- `6163:183470`에 보이는 멤버 카드 삭제 X·상태 점·제목 옆 프로필은 공동 편집 화면에서 복사된 잔여로 보고 구현하지 않았다(명세는 편집 중 표시·멤버 수정이 없음).
- 제목이 비면 서버가 400이라 「저장」을 끈다(명세의 「바뀐 내용이 있을 때만 활성」에 더한 조건, 별도 문구 없음).
- 「저장」 버튼 모양: 기본 `Button`(Figma 버튼에 겹친 10% 검정은 눌림·비활성 상태 표현으로 보고 `disabled` 스타일을 따름).
