## 목적과 범위

### 포함

- 멤버 선택(첫 단계): 「누구와 함께 만들까요?」 아래에 나를 뺀 번치 멤버를 한 줄씩 보이고(역할 배지 포함), 오른쪽 「추가하기」 칩을 누르면 「추가됨」이 되며 다시 누르면 해제된다. 1명 이상 추가해야 하단 「다음」이 켜지고 사진 선택으로 이동한다. 추가한 멤버는 사진 선택의 멤버 칩 범위가 된다.
- 사진 선택: 멤버 필터(「전체」 기본에 앞 단계에서 고른 멤버와 나만, 선택 개수 표시), 「촬영 날짜를 확인할 사진」 아코디언, 촬영 날짜별 3열 사진과 선택 순서 번호, 선택·해제, 최대 20장(21번째는 「번들에는 사진을 20장까지 담을 수 있어요.」).
- 헤더 오른쪽 「추천 번들 보기」(sparkles 아이콘 텍스트 버튼)는 늘 켜져 있고 누르면 추천 번들 시트가 열린다. 하단 고정 「이전」은 멤버 선택으로 돌아가고, 「다음」은 1장 이상 골라야 켜지며 누르면 화면 전체 로딩 뒤 작성 화면으로 이동한다.
- 추천 번들 시트: 2줄 제목, 카드 목록(대표 사진·번들명·멤버 칩과 「외 N명」·사진 수·날짜), 「>」는 선택을 바꾸지 않고 상세로 이동, 추천이 없으면 빈 상태. 시안에 「적용하기」가 없어 카드를 누르면 바로 적용한다(누른 카드는 시트를 다시 열면 선택 모양).
- 적용(카드를 누르면): 고른 사진이 없으면 바로 추천 사진을 추천 순서대로 선택하고 그 날짜 섹션으로 스크롤하며 「추천 번들 사진 N장이 선택되었어요.」. 고른 사진이 있으면 시트를 내리고 「추천 번들 사진으로 변경할까요?」 확인 창을 거친다(「취소」는 시트를 다시 올리고 선택 유지, 「변경하기」는 기존 선택을 풀고 추천 사진만 선택).
- 추천 번들 상세: 헤더에 번들명, 추천 순서를 지킨 날짜별 3열 사진(선택 원·번호 없음), 사진은 뷰어로 가는 링크.
- 뷰어: 헤더에 촬영 날짜, 원본 비율 사진과 올린 멤버 배지, 좌우 이동, 한 번 누르면 헤더·배지 숨김. 저장·날짜 변경·삭제는 없다.

### 범위 외

- 사진함·추천 번들 조회와 초안 생성 서버 연동(목 데이터), 번들 만들기 요청의 중복 방지·실패 안내, 번치 멤버 1명·초안 10개 초과 안내(서버 규칙이 필요).
- 이 화면으로 들어오는 경로: 번치 홈 「+」·「첫 번들 만들기」는 멤버 선택(`/bunch/bundles/new/members`)으로 들어온다. 사진함 선택 모드의 「번들 만들기」는 이 화면을 거치지 않고 바로 초안을 만든다(기능 spec의 사용자 흐름과 route 절).

## Route와 접근

- 네 route 모두 하단 탭 밖의 `(app)` route이며 `robots: noindex`다. 추천 id·사진 id는 route 경계에서 형식을 검증하고(`parseRecommendationId`·`parsePhotoId`), 틀리거나 없으면 「추천 번들이 삭제됐어요. 다시 확인해 주세요.」 토스트 뒤 사진 선택 화면으로 돌아가 시트를 다시 보여 준다.
- 멤버를 고르지 않고 사진 선택(`/bunch/bundles/new`)으로 들어오면(새로고침·직접 주소) 멤버 선택으로 `replace` 이동한다. 사진 선택의 「이전」과 멤버 선택의 뒤로 가기는 돌아갈 기록이 없으면 각각 멤버 선택·번치 홈으로 이동한다.
- 선택 상태는 layout의 provider가 클라이언트 메모리에 들고 있어 상세·뷰어를 다녀와도 유지되고, 이 흐름을 벗어나면 사라진다(뒤로 가기는 선택을 버린다, 기획 4.1). 새로고침하거나 상세·뷰어 주소로 바로 들어오면 선택 없이 새로 시작한다.
- 직접 주소로 들어와 돌아갈 기록이 없으면 뒤로 가기가 사진 선택은 번치 홈(`/bunch`), 상세는 사진 선택, 뷰어는 상세로 이동한다.
- 상세 진입·복귀는 앱 전환 규칙(`AppTransitions`)의 슬라이드 200ms다. 사진 선택과 상세 화면 DOM에 `data-ssgoi-transition`(고정 id)을 달았고, 뷰어 전환은 시안에 없어 기본 동작이다. headless Chrome 375px에서 프레임을 재 약 185ms(새 화면 324→0, 이전 화면 0→-375)를 확인했다.

## 상태와 흐름

- 이 화면 뒤의 임시 이동 `/bunch/drafts/draft-1`은 작성 화면(#152, PR #160)이 머지돼야 열린다. 그 전에는 404다.
- 사진함을 못 불러오면(오류·번치 없음) 상세·뷰어는 사진 선택 화면으로 돌아가 그 화면의 안내를 보인다. 적용하면 멤버 필터를 「전체」로 되돌려 고른 사진이 가려지지 않게 하고, 추천 사진이 모두 사라졌으면 기존 선택을 지우지 않고 「추천 번들이 삭제됐어요. 다시 확인해 주세요.」만 안내한다.
- 사진 상태는 사진함 `usePhotoBox`(사진함 API)를 그대로 쓴다. 로딩은 `PageLoading`(기존 로티 dim), 오류·번치 없음은 사진함의 화면을 쓴다.
- 「번들 만들기」는 로딩(`PageLoading`)을 보이고 본문을 `inert`로 막은 뒤, 고른 사진과 멤버 선택에서 고른 참여 멤버(나 제외)로 초안 생성 API(`POST …/bundles`, 멱등 키·`participantMemberIds` 필수)를 불러 만든 초안으로 이동한다(`/bunch/drafts/{id}?from=home`, 작성 화면의 뒤로가기는 거쳐 온 사진 선택이 아니라 번치 홈으로 `replace`한다, 기능 spec 4.3.1). 고른 사진이 사진함에서 사라졌으면(`PHOTO_004`) 그 사진을 선택에서 빼고 안내한다.

## 데이터 의존성

- 사진·멤버: `@/features/photo-box`의 `usePhotoBox`, 순수 함수(`splitPhotos`, `filterByMember`, `toggleSelection`, `countSelectedByMember`)와 `MemberFilter`·`UndatedPhotos`·`PhotoCell`·`PhotoSelectionProvider`·`PhotoDetailSlide`. 사진 목록의 출처가 사진함이고 선택 모드 UI가 같아 가져다 쓴다. 이 PR이 feature 사이의 첫 import라, 세 번째 사용처가 생기면 `shared`로 올리는 것을 제안한다.
- 추천 번들: `fixtures/recommendation.fixture.ts`(가짜 서버 시작 데이터의 사진 1~13번을 추천 순서로 나눔, 추천 목록 API가 없어 샘플). 번들명은 기획의 제목 생성 로직이 내려줄 값이라 임시 이름이다.

## UI와 접근성

- 사용 컴포넌트: `Header`, `TextButton`, `Button`(`tertiary`·`primary`), `ProfileListItem`, `BottomSheet`, `SuggestedBundleCard`, `ConfirmDialog`, `PhotoThumbnail`, `ChipButton`(사진함 `MemberFilter`), `Accordion`(사진함 `UndatedPhotos`).
- 날짜 제목은 13px SemiBold(Figma `Body-4-SemiBold`)라 사진함의 14px과 다르다.
- 고른 개수는 항상 마운트된 `role="status"`로 알린다. 사진 칸은 선택 상태·순서를 읽어 주는 사진함의 칸을 그대로 쓴다.
- 멤버 선택의 「추가하기/추가됨」 칩은 `ChipButton`(M)이며 이름은 보이는 글자로 시작하는 「추가하기, <이름>」·「추가됨, <이름>」으로 상태를 따라 바뀌고(음성 제어가 보이는 글자로 부를 수 있게), 눌림 상태는 `aria-pressed`로도 전한다. 추가한 멤버 수는 항상 마운트된 `role="status"`로 알린다.
- 헤더 「추천 번들 보기」는 `TextButton`(sm, sparkles 16px 장식 아이콘)이다. sparkles 아이콘은 Figma 아이콘 프레임(`93:2623`)의 `Line/Icon-S·M·L/sparkles`(`4940:97799`·`97794`·`97789`)에서 가져와 24·20·16 캔버스에 도형을 그대로 두고 위치만 맞춰 만들었다.
- 시트 제목은 시각 제목이 없는 빈 상태에서도 `sr-only`로 두어 `dialog` 이름을 유지한다.

## 디자이너 확인 항목

- 사진을 고른 뒤 「이전」으로 돌아가 멤버를 해제하면, 그 멤버가 올린 사진이 이미 담겨 있어도 선택에서 빼지 않는다(칩만 사라짐). 해제한 멤버의 사진도 같이 풀어야 하는지 확인이 필요하다.
- 추천 번들 시트에 「적용하기」 버튼이 없다(`5664:100243`). 카드를 누르면 바로 적용하는 것으로 구현했고, 고른 카드를 해제하는 동작은 없앴다. 의도와 맞는지 확인이 필요하다.
- 사진 선택의 멤버 칩에 나도 포함하는지 시안에서 알 수 없다. 나(참여자)를 칩 맨 앞쪽 순서대로 포함했다.
- 앞 단계에서 고른 멤버가 초안 참여자로 실제 반영되는지는 서버 계약이 필요하다. 지금 초안 생성 API는 사진 id만 받고 참여자는 생성 뒤 별도 API로 추가하므로, 이번에는 화면 상태(칩 범위)만 반영했다.
- 사진 선택의 「전체」가 모든 사진인지 고른 멤버가 올린 사진만인지 시안에서 알 수 없다. 지금은 사진함 전체를 보인다.
- 추천 번들 시트 빈 상태의 가운데 이미지가 Figma에 회색 사각형(112px)뿐이다. 일러스트가 정해지기 전이라 같은 크기의 장식 블록으로 두었다.
- 추천 번들 카드의 번들명은 기획의 제목 생성 로직을 기다린다(임시 이름 「성수동 러닝 모임」).
- 날짜 확인 아코디언을 펼친 모습, 사진이 하나도 없을 때의 화면은 이 화면 시안이 없어 사진함의 같은 화면을 그대로 쓴다.
- 이 화면의 진입(번치 홈 「+」)은 번치 홈 이슈에서 연결한다.
