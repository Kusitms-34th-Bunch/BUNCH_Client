# 페이지: 번들 만들기 사진 선택·추천 번들(`/bunch/bundles/new`)

## 메타데이터

- Route: `/bunch/bundles/new`(`apps/web/src/app/(app)/bunch/bundles/new/page.tsx`), 추천 번들 상세 `/bunch/bundles/new/recommendations/[recommendationId]`, 뷰어 `…/photos/[photoId]`. 세 화면은 같은 `layout.tsx`의 `BundleSelectProvider`를 써서 고른 사진과 시트 열림을 공유한다.
- Status: 사진 선택, 추천 번들 시트(미선택·선택·빈 상태), 사진 선택 변경 확인, 추천 상세, 뷰어, 적용 토스트, 상세 슬라이드(200ms)를 구현했다(사진함 fixture와 추천 fixture, 개발 서버 headless Chrome 375×812에서 동작·모양 확인, 실기기 전).
- 디자인 출처: Figma 화면 설계서 `1998:28015`, 메인 `2060:38676`·`2060:38876`, 시트 `2060:38722`·`2060:38780`·`2121:37628`, 변경 확인 `2060:45262`, 상세 `2060:38861`, 뷰어 `2060:38839`. 이슈 #161.
- 기능 spec: `docs/specs/bundle-create.md`의 4.1~4.2.

## 목적과 범위

### 포함

- 사진 선택: 멤버 필터(「전체」 기본, 선택 개수 표시), 「촬영 날짜를 확인할 사진」 아코디언, 촬영 날짜별 3열 사진과 선택 순서 번호, 선택·해제, 최대 20장(21번째는 「번들에는 사진을 20장까지 담을 수 있어요.」).
- 하단 고정 두 버튼: 「추천 번들」은 늘 켜져 있고 「번들 만들기」는 1장 이상 골라야 켜진다. 누르면 화면 전체 로딩 뒤 작성 화면(#152)으로 이동한다.
- 추천 번들 시트: 2줄 제목, 카드 목록(대표 사진·번들명·멤버 칩과 「외 N명」·사진 수·날짜), 카드 하나 선택(다시 누르면 해제), 「>」는 선택을 바꾸지 않고 상세로 이동, 하단 「적용하기」(카드를 고르기 전 비활성), 추천이 없으면 빈 상태.
- 적용: 고른 사진이 없으면 바로 추천 사진을 추천 순서대로 선택하고 그 날짜 섹션으로 스크롤하며 「추천 번들 사진 N장이 선택되었어요.」. 고른 사진이 있으면 시트를 내리고 「추천 번들 사진으로 변경할까요?」 확인 창을 거친다(「취소」는 시트를 다시 올리고 선택 유지, 「변경하기」는 기존 선택을 풀고 추천 사진만 선택).
- 추천 번들 상세: 헤더에 번들명, 추천 순서를 지킨 날짜별 3열 사진(선택 원·번호 없음), 사진은 뷰어로 가는 링크.
- 뷰어: 헤더에 촬영 날짜, 원본 비율 사진과 올린 멤버 배지, 좌우 이동, 한 번 누르면 헤더·배지 숨김. 저장·날짜 변경·삭제는 없다.

### 범위 외

- 사진함·추천 번들 조회와 초안 생성 서버 연동(목 데이터), 번들 만들기 요청의 중복 방지·실패 안내, 번치 멤버 1명·초안 10개 초과 안내(서버 규칙이 필요).
- 이 화면으로 들어오는 경로: 번치 홈 「+」·「첫 번들 만들기」는 번치 홈 이슈에서 연결한다. 사진함 선택 모드의 「번들 만들기」는 이 화면을 거치지 않고 바로 초안을 만든다(기능 spec의 사용자 흐름과 route 절).

## Route와 접근

- 세 route 모두 하단 탭 밖의 `(app)` route이며 `robots: noindex`다. 추천 id·사진 id는 route 경계에서 형식을 검증하고(`parseRecommendationId`·`parsePhotoId`), 틀리거나 없으면 「추천 번들이 삭제됐어요. 다시 확인해 주세요.」 토스트 뒤 사진 선택 화면으로 돌아가 시트를 다시 보여 준다.
- 선택 상태는 layout의 provider가 클라이언트 메모리에 들고 있어 상세·뷰어를 다녀와도 유지되고, 이 흐름을 벗어나면 사라진다(뒤로 가기는 선택을 버린다, 기획 4.1). 새로고침하거나 상세·뷰어 주소로 바로 들어오면 선택 없이 새로 시작한다.
- 직접 주소로 들어와 돌아갈 기록이 없으면 뒤로 가기가 사진 선택은 번치 홈(`/bunch`), 상세는 사진 선택, 뷰어는 상세로 이동한다.
- 상세 진입·복귀는 앱 전환 규칙(`AppTransitions`)의 슬라이드 200ms다. 사진 선택과 상세 화면 DOM에 `data-ssgoi-transition`(고정 id)을 달았고, 뷰어 전환은 시안에 없어 기본 동작이다. headless Chrome 375px에서 프레임을 재 약 185ms(새 화면 324→0, 이전 화면 0→-375)를 확인했다.

## 상태와 흐름

- 이 화면 뒤의 임시 이동 `/bunch/drafts/draft-1`은 작성 화면(#152, PR #160)이 머지돼야 열린다. 그 전에는 404다.
- 사진함을 못 불러오면(오류·번치 없음) 상세·뷰어는 사진 선택 화면으로 돌아가 그 화면의 안내를 보인다. 적용하면 멤버 필터를 「전체」로 되돌려 고른 사진이 가려지지 않게 하고, 추천 사진이 모두 사라졌으면 기존 선택을 지우지 않고 「추천 번들이 삭제됐어요. 다시 확인해 주세요.」만 안내한다.
- 사진 상태는 사진함 `usePhotoBoxFixture`(목 데이터, 번들 연동 이슈에서 API 기반으로 교체)를 그대로 쓴다. 로딩은 `PageLoading`(기존 로티 dim), 오류·번치 없음은 사진함의 화면을 쓴다.
- 「번들 만들기」는 로딩(`PageLoading`)을 보이고 본문을 `inert`로 막은 뒤 목 지연 후 샘플 초안(`draft-1`)으로 이동한다. 초안 생성 API 연결 전의 임시 동작이다.

## 데이터 의존성

- 사진·멤버: `@/features/photo-box`의 `usePhotoBoxFixture`, 순수 함수(`splitPhotos`, `filterByMember`, `toggleSelection`, `countSelectedByMember`)와 `MemberFilter`·`UndatedPhotos`·`PhotoCell`·`PhotoSelectionProvider`·`PhotoDetailSlide`. 사진 목록의 출처가 사진함이고 선택 모드 UI가 같아 가져다 쓴다. 이 PR이 feature 사이의 첫 import라, 세 번째 사용처가 생기면 `shared`로 올리는 것을 제안한다.
- 추천 번들: `fixtures/recommendation.fixture.ts`(사진함 샘플 사진을 추천 순서로 나눔). 번들명은 기획의 제목 생성 로직이 내려줄 값이라 임시 이름이다.

## UI와 접근성

- 사용 컴포넌트: `Header`, `Button`(`tertiary`·`primary`), `BottomSheet`, `SuggestedBundleCard`, `ConfirmDialog`, `PhotoThumbnail`, `ChipButton`(사진함 `MemberFilter`), `Accordion`(사진함 `UndatedPhotos`).
- 날짜 제목은 13px SemiBold(Figma `Body-4-SemiBold`)라 사진함의 14px과 다르다.
- 고른 개수는 항상 마운트된 `role="status"`로 알린다. 사진 칸은 선택 상태·순서를 읽어 주는 사진함의 칸을 그대로 쓴다.
- 시트 하단 「적용하기」 줄은 Figma `Frame 179`처럼 위가 투명하고 아래로 갈수록 흰색인 그라데이션 배경으로 목록 위에 띄우고, 목록 끝에 버튼 높이만큼 여백을 둬 마지막 카드가 가려지지 않는다. 빈 곳은 터치가 목록으로 통과한다.
- 시트 제목은 시각 제목이 없는 빈 상태에서도 `sr-only`로 두어 `dialog` 이름을 유지한다.

## 디자이너 확인 항목

- 추천 번들 시트 빈 상태의 가운데 이미지가 Figma에 회색 사각형(112px)뿐이다. 일러스트가 정해지기 전이라 같은 크기의 장식 블록으로 두었다.
- 추천 번들 카드의 번들명은 기획의 제목 생성 로직을 기다린다(임시 이름 「성수동 러닝 모임」).
- 날짜 확인 아코디언을 펼친 모습, 사진이 하나도 없을 때의 화면은 이 화면 시안이 없어 사진함의 같은 화면을 그대로 쓴다.
- 이 화면의 진입(번치 홈 「+」)은 번치 홈 이슈에서 연결한다.
