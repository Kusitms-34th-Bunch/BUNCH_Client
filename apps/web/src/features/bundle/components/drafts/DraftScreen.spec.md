# 페이지: 번들 작성(`/bunch/drafts/[draftId]`)

## 메타데이터

- Route: `/bunch/drafts/[draftId]`(`apps/web/src/app/(app)/bunch/drafts/[draftId]/page.tsx`). 하단 탭이 없는 화면이라 `(main)` 밖에 둔다.
- Status: 헤더·연결 끊김 배너·참여 멤버·제목·사진 목록·위치·날짜·코멘트와 역할별 권한, 업로드 조건 구현됨(fixture와 목 동작, headless Chrome 375×812 실측. 실기기 전). #267 개편으로 헤더 「⋯」(번들 나가기), 아래 고정 「업로드」, 공개 범위 별도 화면(`/bunch/drafts/[draftId]/visibility`)으로 바꿨다(단위·컴포넌트 테스트 통과, 새 구조의 브라우저 렌더 비교는 못 함).
- 디자인 출처(#267 개편): 작성 화면 `5664:100786`·`100844`·`102521`·`102873`·`102075`, 더보기 메뉴 `5699:105934`, 번들 나가기 모달 `5664:90707`·`5699:106127`, 공개 범위 `5699:105991`·`106016`·`106041`, 편집 중 모달 `5699:106129`. 이전 출처: Figma 화면 설계서 `1998:31389`, 최종 화면 `3220:59525`, 수정 가이드 `3043:63821`, 권한 및 업로드 조건 `2084:22177`, 나가기 확인 창 `2082:49691`. 이슈 #152.
- 기능 spec: `docs/specs/bundle-create.md`의 4.3 공동 편집.

## 목적과 범위

### 포함

- 고정 헤더: 뒤로가기, 저장 상태(「저장 완료」, 저장 중에는 「저장 중」 뒤에 점이 0→1→2개로 600ms마다 바뀜, 18px SemiBold), 오른쪽 「⋯」 더보기(참여 멤버에게만, 「번들 나가기」 하나, 아이콘은 `transition-left`). 연결이 끊기면 헤더 아래에 고정 배너(「인터넷 연결을 확인해 주세요.」+「재시도」).
- 영역 순서(Figma `5664:100786`·`5367:146358`): 참여 멤버, 제목\*, 사진, 코멘트\*, 위치·날짜. 맨 아래 고정 「업로드」 버튼. 공개 범위와 「나가기」 영역은 이 화면에서 빠졌다.
- 참여 멤버: 역할 배지 하나(관리자 > 공동 관리자 > 초안 생성자), 무언가 편집 중인 멤버 카드는 프로필 오른쪽 아래에 초록 점(Figma `Status Badge` 10px, `MemberCard`의 `editing`), 다른 멤버 카드의 삭제 버튼(초안 생성자와 참여 중인 관리자에게만, 초안 생성자·내 카드 제외), 맨 끝 「추가」 카드(참여 멤버에게만).
- 제목: 40자까지, 40자에 닿으면 「제목은 40자까지 쓸 수 있어요.」.
- 사진(Figma `5367:146358`): 130px 정사각 사진이 10px 간격으로 가로로 이어지고 사진마다 오른쪽 위 X(삭제), 맨 끝에 「사진 추가」 타일. 제목 줄 오른쪽 「픽하기 >」는 대표 사진 투표 화면(`/bunch/drafts/[draftId]/pick`)으로 가고, 사진을 누르면 사진 상세(크게 보기)로 간다. 삭제는 참여 멤버가 하며 2장 이상이면 「사진을 삭제할까요?」 확인 뒤, 1장이면 「사진을 삭제할 수 없어요」 안내만 한다. 다른 멤버가 편집 중인 사진은 지울 수 없다. 「사진 추가」는 초안 생성자·관리자·공동 관리자(참여 멤버)에게만 보이고 20장이면 숨는다.
- 위치(최대 3개)와 날짜: 위치는 검색 시트에서 고르고 바로 반영, 날짜는 달력 시트(`DateChangeSheet`)나 추천 날짜 칩. 위치를 고르면 제목 앞 아이콘이 햄버거 핸들로 바뀌고 그 핸들을 잡아 위아래로 끌어 순서를 바꾼다(`SortableLocationGroup`, `@dnd-kit`). 핸들에 포커스를 두고 Space로 잡아 방향키로 옮기고 Space로 놓는다(Esc 취소). 하나뿐이거나 다른 멤버가 편집 중이거나 참여 멤버가 아니면 끌 수 없고 눌렀을 때 이유를 안내한다.
- 코멘트: 내 카드가 맨 위, 내 카드만 입력(400자), 다른 멤버가 쓰는 중이면 점 애니메이션. 제목 옆 프로필은 지금 코멘트를 쓰는 멤버만 보인다(쓰는 사람이 없으면 아무도 없음). 카드 목록 아래에 「* 코멘트와 픽하기는 업로드 이후 수정이 불가해요」(12px Medium, `text-quaternary`, Figma `5730:142491`)를 두고, 그 아래에 위치·날짜가 온다.
- 공개 범위(별도 화면 `/bunch/drafts/[draftId]/visibility`, `DraftVisibilityScreen`): 「번들의 공개 범위를 설정해 주세요」 아래 「전체 공개」(비공개 번치면 「일부 공개」, 팔로워도 볼 수 있음)·「멤버 공개」 카드 중 하나를 골라야 「업로드」가 켜지고, 누르면 이 화면에서 「업로드 중」과 dim 로딩을 보이며 발행하고, 끝나면 「업로드가 완료되었어요」 토스트와 함께 번치 홈으로 이동한다(완료 모달은 시안에 없음). 작성 화면에서 공개 범위 화면으로 넘어가 그려지는 동안에도 페이지 로딩을 보인다.
- 나가기: 헤더 「⋯」의 「번들 나가기」 → 확인 창 뒤 번치 홈으로 이동. 일반 멤버는 「번들에서 나가시겠어요?」(작성한 코멘트가 삭제됨), 초안 생성자는 「번들에서 나갈까요?」(번들이 삭제되고 되돌릴 수 없음).
- 업로드 조건(제목, 사진 1장 이상, 참여 멤버 2명 이상, 참여 멤버 전원 코멘트, 저장 안 된 변경 없음, 연결 끊김 아님)과 「업로드」 활성·안내.

### 범위 외(추후 작업 예정)

- 서버 연동: 초안 조회·저장·참여자·발행은 `useDraft`가 번들 API(가짜 서버)로 처리한다. 입력은 바로 화면에 반영하고 멈춘 뒤 1초 안에 필드별 버전으로 저장하며, 충돌이면 최신 상세를 받아 입력을 이어서 저장한다. 위치는 서버에 필드가 없어 이 화면에서만 들고 있고, 사진 구성·순서 변경과 장소 검색은 서버 연동 전이라 이 화면에서만 바뀐다. 실시간 편집 반영(STOMP·presence)은 후속이다. 서버에서 편집권(lease)이 없어져 저장에 편집권이 필요 없다.
- 「추가」 카드의 동작(참여 멤버 관리 화면): 참여 멤버 추가·삭제 이슈에서 연결한다. 지금은 카드만 권한에 맞게 보이고 눌러도 아무 일이 없다. 멤버 삭제 버튼은 내보내기 확인 창(「○○님을 번들에서 내보낼까요?」, Figma `2091:62913`)까지 연결했고 확인하면 그 멤버와 코멘트가 목 상태에서 빠진다. 멤버 관리 화면의 추가·제외 토스트는 그 이슈에서 한다.
- 사진을 누르면 그 사진의 상세(크게 보기, `/bunch/drafts/[draftId]/photos/[photoId]/viewer`)로 이동한다(`router.push`, 작성 화면과 같은 슬라이드). 직접 주소로 들어와 돌아갈 기록이 없으면 뒤로 가기는 작성 화면으로 간다.
- 「+ 사진 추가」 시트·사진함·갤러리 가져오기는 사진 추가 이슈에서 연결한다.
- 업로드: 조건(공개 범위 제외)을 모두 채운 권한자가 아래 「업로드」를 누르면 `onUpload`로 공개 범위 화면에 간다. 이전의 「번들을 업로드할까요?」 확인 창은 시안에 없어 없앴다. 누른 순간 나 말고 편집 중인 멤버가 있으면(`draft.editing`, 코멘트 작성 중 포함) 「편집 중인 멤버가 있어요」 창(「취소」·「계속하기」)을 먼저 열고 「계속하기」를 눌러야 넘어간다. 편집 중이어도 업로드는 막지 않는다. 발행 요청은 공개 범위 화면이 `actions.publish`로 보낸다.
- 다른 멤버가 편집 중인 제목·위치·날짜를 누르면 「다른 멤버가 편집 중일 땐 수정할 수 없어요.」 토스트(Figma `2060:37684`)를 띄우고 입력·시트 열기를 막는다.

## Route와 접근

- Path·params: `draftId`는 외부 입력이라 route 경계(`parseDraftId`)에서 영문·숫자·밑줄·하이픈 64자 이하만 통과시키고, 아니면 `undefined`로 화면에 넘겨 없는 초안과 같은 안내로 처리한다. fixture에는 `draft-1`만 있다.
- 접근 수준: 번치 멤버만. 인증·번치 소속 확인은 API와 로그인이 연결될 때 route 단계에서 한다(초안 조회가 번치 멤버가 아니면 403으로 돌려주고 화면은 「삭제된 번들」 안내로 이동한다). 미로그인·번치 비소속의 redirect 대상은 미정이다.
- 화면 안 접근 구분: 참여 멤버가 아닌 번치 멤버는 보기만 하고 고치려 하면 「참여 멤버만 편집할 수 있어요」를 안내한다. 이는 route guard가 아니라 화면 안 action gate다.
- 직접 URL: 돌아갈 기록이 없으면 뒤로가기는 번치 홈으로 이동(`replace`), 있으면 `back()`. 뒤로가기는 묻지 않는다. 기록 유무는 `window.history.length > 1`로만 판단한다.
- 없는 초안(삭제됨·발행됨·잘못된 id)은 「번들이 삭제됐어요」·「번들이 업로드됐어요」 안내 창과 「확인」 뒤 번치 홈으로 이동한다(`DraftMissingGate`).
- `metadata`: 제목 「번들 작성」, 검색 제외.

## 상태와 흐름

- 권한 표는 `docs/specs/bundle-create.md`의 표를 `getDraftAccess`·`canRemoveMember`가 구현한다. 참여 여부는 `draft.members`에 내 id가 있는지로 정하고, 발행 권한은 초안 생성자이거나 번치 관리자·공동 관리자인 참여 멤버다.
- 아래 「업로드」는 항상 그려 두고 조건을 못 채우면 `aria-disabled`로 흐리게 한다. 공개 범위 화면은 내용 조건(제목·사진·멤버·코멘트)이나 권한이 없으면 직접 주소로 들어와도 작성 화면으로 돌려보낸다. 누르면 이유를 안내한다: 참여 멤버가 아님 → 「참여 멤버만 편집할 수 있어요」, 권한 없음 → 「번치 관리자와 해당 번들 생성자만 업로드할 수 있어요.」, 필수 항목 부족·저장 중·연결 끊김 → 「필수 항목을 모두 입력해야 업로드 할 수 있어요.」.
- 위치는 3개가 차면 「추가」 행이 사라지고, 0개이면 「위치 추가」 한 줄만 보인다.
- 위치 검색 시트: 검색 전에는 안내(「태그한 위치는 함께 보여요」), 검색하면 결과(이름·주소) 또는 「검색 결과가 없어요」. 결과를 누르면 바로 추가하고 닫는다. 열 때마다 처음 상태로 돌아가고, 이전 검색의 늦은 응답은 버린다.
- 연결 끊김은 브라우저의 `online`·`offline` 이벤트로 판단한다. 서버에 닿는지까지는 알 수 없고, 「재시도」는 지금 상태를 다시 읽을 뿐이다.

## 데이터 의존성

- Query: `bundleKeys.detail(bunchId, bundleId)`(상세, 저장·발행 성공 응답으로 캐시 갱신). 장소 검색 query는 장소 검색 API가 정해진 뒤 추가한다.
- API 계약 확인 항목: 초안 전체 상태와 내 권한·역할 값(웹은 응답의 권한 값으로 버튼 표시를 정함), 편집 중 정보, 장소 검색, 발행 요청.

## UI와 접근성

- Component mapping: 헤더는 `core`의 `Header`+`HeaderIconButton`과 더보기 `IconButton`+`PhotoActionMenu`(`DraftMenu`), 아래 업로드는 `Button`, 배너는 `ErrorBanner`, 멤버는 `MemberCard`·`AddMemberCard`, 제목은 `BundleTextInput`, 사진은 `BundlePhotoEditor`, 위치·날짜는 `SelectionFieldGroup`·`SelectionField`와 `BottomSheet`·`SearchField`·`LocationListItem`·`DateChangeSheet`, 코멘트는 `BundleCommentCard`, 공개 범위 화면은 `DescriptionRadioCard`, 나가기 확인은 `Dialog`.
- Semantic·heading: 화면 제목 `h1`(「번들 작성」, 화면에는 숨김), 각 영역은 `BundleTitle`을 `aria-labelledby`로 가리키는 `section`. 저장 상태와 사진 위치(「N장 중 M번째 사진」)는 `role="status"`.
- 키보드: 위치·날짜 줄과 지우기, 추천 칩, 「⋯」 더보기와 메뉴 항목(Esc·바깥 누름·Tab으로 닫힘), 「업로드」는 `button`·`menuitem`이고 공개 범위 화면의 카드는 `radio`다. 확인 창은 최초 포커스가 「취소」(Dialog 기본)에 있다.
- 읽기 전용: 제목·코멘트 입력란은 `readOnly`라 포커스는 받되 고칠 수 없다. 참여 멤버가 아니면 닿았을 때 안내한다.
- 동작 줄이기: 「저장 중」 점은 움직이지 않는다.

## 디자이너·기획 확인 항목

- 위치 개수: 기능 spec은 번들당 1개, Figma 수정 가이드(`3043:63821`)는 3개까지(3개면 「추가」 행 없음)라 3개로 구현했다. 기능 spec의 문구를 바꿔야 한다.
- 공개 범위 화면의 선택지: 시안이 두 가지다(「전체 공개」+「멤버 공개」, 「일부 공개」+「멤버 공개」). 앞의 툴팁 문구(비공개 번치에서 「공개」로 올리면 팔로워만 볼 수 있음)에 맞춰 번치가 비공개면 「일부 공개」로 보이게 구현했다. 맞는 기준인지 확인이 필요하다. 번치 홈 데이터를 못 읽는 동안은 공개 번치로 본다.
- 이전 작성 화면에 있던 공개 범위 옆 안내 아이콘·툴팁은 새 시안에 없어 뺐다(`visibilityTooltip` 문구만 남아 있다).
- 나가기 확인 창: 시안이 일반 멤버(「번들에서 나가시겠어요?」)와 초안 생성자(「번들에서 나갈까요?」, 번들 삭제 안내)로 나뉘어 둘로 구현했다. 참여 멤버 관리 화면의 내 카드 X도 같은 창을 쓴다.
- 디자인 시스템 `SelectionField`의 추천 칩이 있는 줄은 높이 102px(세로 여백 16px)인데 이 화면의 Figma는 94px(여백 12px)다. 컴포넌트 기준이 바뀐 것이라 이 이슈에서는 고치지 않았고, 날짜 줄이 8px 크다.
- 다른 멤버가 위치·날짜를 편집 중일 때 제목 옆에 그 멤버 프로필을 보이는 표시는 `SelectionField`가 아바타를 받지 않아 구현하지 않았다(제목·사진·코멘트는 구현).
- 위치 줄을 눌러 값을 바꾸는 동작은 기획에 없어 연결하지 않았다.
- 위치 검색 시트에 닫기 버튼이 없다(Figma에 없음). 닫는 방법이 ESC·끌어내리기·바깥 누름뿐이라 스크린 리더·스위치 사용자용 닫기 컨트롤을 둘지 확인이 필요하다.
- 위치·날짜를 고르거나 지운 뒤 포커스: 누른 요소가 사라져(예: 위치 0개 → 그룹으로 교체, 추천 칩 사라짐) 포커스가 `body`로 갈 수 있다. 복귀 정책이 필요하다(`SelectionField` 문서에도 호출하는 쪽 책임으로 적혀 있다).
- 업로드를 못 하는 이유 안내: 저장 중·연결 끊김에서도 「필수 항목을 모두 입력해야 업로드 할 수 있어요.」를 쓴다. 원인에 맞는 문구가 기획에 없어 확인이 필요하다.
- 다른 멤버가 코멘트를 쓰는 중이라는 표시는 점 애니메이션(`role="img"` 이름)이라 상태 변화로 읽히지 않는다. 제목은 낭독 영역을 항상 두어 읽힌다.
- 저장 상태는 바뀔 때마다(`저장 중` ↔ `저장 완료`) polite로 읽혀 타이핑 중 자주 낭독될 수 있다. 실제 저장 연결 뒤 빈도를 보고 조정한다.
- 비참여자가 입력란·라디오에 닿거나 방향키를 누를 때마다 토스트가 뜬다. 보기 전용임을 입력란 모양으로 알 수 없어 시각 처리(스타일) 확인이 필요하다.
- 위치 검색은 Enter(제출)에서만 실행하고, 코멘트 입력란에는 필수(`aria-required`) 표시가 없다(디자인 시스템 컴포넌트 한계).

- 시안(`5664:100786`)의 「사진」 제목 옆 「픽하기 >」 링크와 「코멘트와 픽하기는 업로드 이후 수정이 불가해요」 안내는 대표 사진 투표 화면이 정해진 뒤 연결한다. 지금 작성 화면에는 없다.
- 공개 범위 화면에서 업로드하는 동안 브라우저·OS 뒤로 가기로 빠져나가면 발행은 됐는데 작성 화면이 로딩에 머물 수 있다(발행 직후 화면 이동이 이 화면에 묶여 있음). 드문 경로라 이탈 방지는 넣지 않았다.
- 업로드 중 화면(`5699:106041`)의 로딩은 시안의 「Core Glints Ripple」이 아니라 앱 공통 `PageLoading`을 쓴다(로딩 컴포넌트 교체는 다른 브랜치에서 진행하므로 그쪽 결과에 맞춘다).

- 작성 중 번들이 삭제됐거나 다른 멤버가 업로드하면 어느 화면에서든 「번들이 삭제됐어요」·「번들이 업로드됐어요」 안내 창(「확인」 하나, Figma `5618:81986`·`81997`)이 뜨고 「확인」을 눌러야 번치 홈으로 이동한다(`DraftMissingGate`, layout). 업로드한 멤버 이름은 응답에 없어 「다른 멤버가」로 안내한다.
- 「사진 추가」는 초안 생성자·관리자·공동 관리자에게만 보이게 했다(`canAddPhoto`, 발행 권한과 같음). 기존 기능 spec은 참여 멤버 모두였는데 사용자 지시로 바꿨고, 사진 추가 화면도 같은 권한(`canAddPhoto`)으로 맞췄다.
- 대표 사진 투표(`/bunch/drafts/[draftId]/pick`, Figma `5699:103571`~`103708`)의 픽 데이터는 서버 모델이 없어 이 탭의 메모리에만 있다(새로고침하면 사라짐, `useDraftPicks`). 한 사람이 여러 사진을 픽할 수 있는지, 픽한 사진이 번들에 어떻게 남는지는 기획 확인이 필요하다.
- 번치 홈 플로팅 버튼은 번치 멤버가 2명 미만이면 번들 만들기로 가지 않고 「함께할 멤버가 없어요」 창(「취소」·「초대하기」, Figma `5618:81971`)을 띄운다. 「초대하기」는 멤버 초대 화면으로 간다.

- 내가 제목이나 내 코멘트에 포커스를 둔 동안은 내 멤버 카드에 초록 점이, 제목·코멘트 제목 옆에 내 프로필이 보인다(서버 실시간 편집 상태가 없어 이 화면의 포커스로 판단하며, 다른 멤버의 편집 상태는 `draft.editing`). 제목에서 코멘트로 옮기면 표시도 옮겨 간다.
- 헤더 뒤로 가기·더보기 버튼은 40px 터치 영역의 양옆 8px을 레이아웃 폭에 넣지 않는다(`HeaderIconButton` `-mx-s4`, 더보기 `-mr-s4`). 이전에는 터치 영역이 폭을 차지해 제목이 Figma(48px)보다 8px 오른쪽에서 시작했다. 같은 버튼을 쓰는 다른 화면 헤더도 같이 바뀐다.
- 사진 삭제 확인 창의 설명은 「삭제한 사진은 복구할 수 없어요.」이고, 멤버가 픽한 사진이면 제목·설명이 「멤버들이 픽한 사진이에요」·「사진을 삭제하면 픽도 함께 삭제되며, 복구할 수 없어요.」로 바뀐다(Figma `5699:104483`, 작성 화면·사진 상세 공통). 픽 데이터는 아직 탭 메모리라 새로고침하면 사라진다.
- 하단 「업로드」 버튼을 눌러 나는 안내 토스트(업로드 못 하는 이유, 공개 범위 선택 안내, 발행 요청 실패)는 하단 버튼 영역 위에 뜬다(Figma `5664:102873`은 위 테두리에서 10px였으나 2026-11-10부터 아래 규칙으로 통일). 하단 버튼 영역은 `PageShell`의 bottom 슬롯이라 `wrapper` 앵커로 영역 위 4px에 뜬다(2026-11-10, 이전 `bottomOffset` 65는 제거). 하단 버튼 영역에는 위 테두리(border-tertiary)가 있다. 그 밖의 토스트도 같은 규칙이라 이 화면에서는 모두 버튼 영역 위에 뜬다.
- 대표 사진 투표의 「픽하기 모션」(Figma `5699:103708`, 3.4s 한 번)은 모션 데이터의 키프레임·이징 그대로 `pickMotion.module.css`(생성 파일)로 구현했다. 사진을 새로 픽할 때만 재생하고 해제·동작 줄이기 설정에서는 재생하지 않는다. 브라우저에서 시안과 겹쳐 본 시각 검증은 하지 못했다. 「삭제된 사진이에요」 안내 창(`5699:103606`)은 구현했으나, 시안의 윗줄 문구 「픽한 사진이 번들에 남아요.」(일반 상태는 「번들이 업로드되면 누가 픽했는지 보여요.」)가 어떤 조건의 변형인지 확인이 필요하다.
