# 페이지: 번들 사진 추가(`/bunch/drafts/[draftId]/photos/add`)

## 메타데이터

- Route: `apps/web/src/app/(app)/bunch/drafts/[draftId]/photos/add/page.tsx`. 작성 화면·캡션 화면과 같은 `layout.tsx`의 `DraftProvider`가 들고 있는 초안 상태를 본다.
- Status: 사진 선택, 적용, 빠지는 사진 확인, 나가기 확인, 20장 한도·편집 중 잠금을 구현했다(목 데이터, 실기기·서버 전).
- 디자인 출처: 화면설계서 `2034:26391`, 가져오기 시트 `1782:33039`, 사진 선택 `1782:33283`·`1782:33237`·`2060:38500`, 적용 결과 `1782:32859`, 빠짐 확인 `1782:33018` 주변 화면, 나가기 확인 `2091:62148`. 이슈 #193.
- 기능 spec: `docs/specs/bundle-create.md`의 4.3.7.

## 목적과 범위

### 포함

- 캡션 화면의 「+ 사진 추가」 → `PhotoImportSheet`(「어디서 사진을 가져올까요?」). 「번치 사진함에서 가져오기」는 이 화면으로 이동한다.
- 사진 선택: 번들 만들기 첫 화면과 같은 본문(`SelectPhotoList`: 멤버 필터, 「촬영 날짜를 확인할 사진」, 날짜별 3열, 선택 순서 번호). 지금 번들 사진이 번들 순서대로 선택된 채 열리고, 더 고르면 번호가 이어 붙으며 풀면 당겨진다. 헤더에는 뒤로 가기만 있고 제목 글자는 없다.
- 하단 「적용하기」: 선택이 처음과 같으면(순서까지) 꺼져 있다. 새로 고른 사진은 번들 맨 뒤에 캡션 없이 붙고, 이미 있던 사진은 캡션을 지킨다. 적용하면 「변경사항이 적용되었어요.」 토스트와 함께 이전(캡션) 화면으로 돌아간다.
- 푼 사진이 있으면 「사진 N장이 번들에서 빠져요」 / 「빠진 사진의 픽도 함께 사라져요.」 확인(「적용하기」·「취소」)을 거친다.
- 변경이 있는데 뒤로 가면 「저장하지 않고 나갈까요?」 / 「변경한 내용이 반영되지 않아요.」(「나가기」·「취소」). 변경이 없으면 바로 나간다.
- 최대 20장. 사진함에 대응이 없는(갤러리에서 온) 번들 사진도 한도에 포함하고 선택 목록에는 나타나지 않는다. 넘기려 하면 「번들에는 사진을 20장까지 담을 수 있어요.」.
- 다른 멤버가 편집 중인 사진은 풀 수 없고 「다른 멤버가 편집 중일 땐 수정할 수 없어요.」를 띄운다.
- 「내 갤러리에서 가져오기」: 사진함이 가득 차면(1000장) 「사진함이 가득 찼어요.」만 띄운다. 가득 차지 않았을 때 기기 사진함을 여는 일은 연결 전이다(`usePhotoGalleryImport`가 호출 지점).

### 범위 외

- 기기 사진 선택(네이티브 bridge), 사진함 업로드 규칙과 로딩·결과 토스트, 서버 연동, 다른 멤버가 그 사이 바꾼 사진과의 합치기.
- 사진 추가·빼기 뒤 캡션 화면의 목록 스크롤 위치 보정.

## Route와 접근

- `(app)` route이며 `robots: noindex`다. 참여 멤버가 아니면 「참여 멤버만 편집할 수 있어요」 토스트 뒤 작성 화면으로 `replace`한다. 없는 초안은 「삭제된 번들이에요」 뒤 번치 홈으로 이동한다.
- 전환은 캡션 화면과 슬라이드 200ms(`bundleSlide`, 화면설계서 「사진함 이동 Interaction」 Slide In/Out·Ease In·200ms)이고 `BUNDLE_PATHS.transitionIds.photoAdd`로 경계를 잡는다.
- 캡션 화면에서 앱 안으로 들어왔을 때만(`lib/photoAddEntry.ts`의 메모리 표시) 뒤로 가기·적용 뒤 이동이 `router.back()`으로 캡션 화면에 돌아간다. 직접 주소·새로고침 진입이면 이전 기록이 무엇인지 알 수 없어 첫 사진의 캡션 화면으로 `replace`한다.
- 가져오기 시트의 카드는 연타해도 출처를 한 번만 처리하고, 시트가 다시 열리면 풀린다.

## 상태와 흐름

- 선택 상태는 이 화면의 로컬 상태이고 적용할 때만 `useDraft`의 `replacePhotos`로 초안에 반영한다. 계산은 `lib/photoAdd.ts`의 순수 함수(초기 선택, 한도, 변경 여부, 빠질 사진, 적용 결과, 잠금 판정)다.
- 사진함 사진 → 번들 사진은 id `draft-<사진함 id>`와 `sourcePhotoId`로 이어진다.

## UI와 접근성

- 화면 제목 `h1`(「사진 추가」)은 `sr-only`로 하나 두고, 선택 장수는 `role="status"`로 알린다. 확인 창은 「취소」가 기본 초점이다.
