# 페이지: 번들 참여 멤버 관리(`/bunch/drafts/[draftId]/members`)

## 메타데이터

- Route: `/bunch/drafts/[draftId]/members`(`apps/web/src/app/(app)/bunch/drafts/[draftId]/members/page.tsx`). 작성 화면과 같은 `layout.tsx`의 `DraftProvider`가 초안 상태를 들고 있어, 두 화면을 오가도 같은 초안을 본다.
- Status: 멤버 추가·내보내기·스스로 나가기, 카드 이동 애니메이션, 토스트를 구현했다(목 데이터, 개발 서버 headless Chrome 375×812에서 동작·모양 확인, 실기기 전).
- 디자인 출처: Figma 화면 설계서 `2034:22714`, 화면 `2060:42900`, 확인 모달 `2060:43016`·`2060:42986`, 토스트 `2060:42957`·`2060:42928`. 이슈 #166.
- 기능 spec: `docs/specs/bundle-create.md`의 4.3.2.

## 목적과 범위

### 포함

- 「멤버 추가하기」: 번치 멤버 중 아직 참여하지 않은 멤버를 프로필·이름·「추가하기」로 나열한다. 누르면 확인 없이 참여 멤버 맨 아래로 옮기고 「{이름}님이 번들 참여 멤버에 추가되었어요.」를 띄운다. 추가할 멤버가 없으면 영역을 숨긴다.
- 「참여 멤버」: 프로필(오른쪽 아래 역할 배지)·이름(내 카드는 「(나)」)·삭제 버튼(X).
  - 내 카드의 X는 참여 멤버 누구에게나 보이고 「번들에서 나가시겠어요?」 확인 뒤 번치 홈으로 이동한다.
  - 다른 멤버 카드의 X는 초안 생성자와 참여 중인 관리자(공동 관리자 포함)에게만 보이고, 초안 생성자 카드에는 다른 사람에게 보이지 않는다(`lib/permissions.ts`의 `canRemoveMember`).
  - 다른 멤버의 X는 「{이름}님을 번들에서 내보낼까요?」 확인 뒤 그 멤버를 「멤버 추가하기」로 돌려보내고 「{이름}님이 번들 참여 멤버에서 제외되었어요.」를 띄운다.
- 초안 생성자도 일반 멤버와 같은 확인 창(「번들에서 나가시겠어요?」)을 보고, 나가면 작성 중인 번들이 삭제되어 「작성 중인 번들을 삭제했어요.」 토스트와 함께 번치 홈으로 이동한다. 작성 화면 맨 아래 「나가기」와 같은 확인 창(`LeaveDraftDialog`)이다.
- 나가기·내보내기는 그 멤버의 코멘트만 지운다(사진·캡션·제목 등 공용 내용은 남김). 목 데이터에서는 내보내기만 코멘트를 지워 보이고, 스스로 나가기는 번치 홈으로 이동하며 상태가 사라지는 것으로 대신한다(삭제는 서버 연동 뒤).
- 카드가 목록 사이를 옮겨갈 때와 아래 카드가 밀릴 때 Smart Animation, Gentle, 400ms(`useMoveAnimation`, `docs/architecture/motion.md`).

### 범위 외

- 멤버 조회·추가·삭제 서버 연동, 더해진·빠진 멤버 알림, 실시간 반영(목 데이터와 메모리 상태).
- 번치 멤버가 번치를 나가는 경우의 자동 정리, 참여 멤버 1명일 때 발행 안내.

## Route와 접근

- `(app)` route이며 `robots: noindex`다. 초안 id는 layout에서 형식을 검증하고(`parseDraftId`), 없는 초안은 「삭제된 번들이에요」 토스트 뒤 번치 홈으로 이동한다.
- 작성 화면 ↔ 이 화면 이동에는 온보딩과 같은 슬라이드(300ms, 뒤로 가기는 반대)가 걸린다(`AppTransitions`, `BUNDLE_PATHS.transitionIds`).
- 진입은 작성 화면 참여 멤버 가로 목록 맨 끝 「추가」 카드(`router.push`)다. 뒤로가기는 직접 주소로 들어와 돌아갈 기록이 없으면 작성 화면으로 이동한다.
- 참여 멤버가 아닌 사람도 목록을 볼 수는 있으나 「추가하기」와 X는 보이지 않는다(작성 화면의 「추가」 카드 자체가 참여 멤버에게만 보인다).

## 상태와 흐름

- 상태는 `useDraft`(layout `DraftProvider`)의 `members`·`comments`이고, 번치 멤버 전체는 `bunchMembers`(번치 멤버 API)다. 더하거나 뺀 내용은 서버(참여자 추가·제외 API) 응답으로 반영되어 작성 화면의 참여 멤버 카드와 코멘트 목록에 나타난다.
- 이 흐름을 벗어나면(작성 화면 밖으로 나가면) 상태는 초기화된다. 새로고침해도 초기화된다.

## UI와 접근성

- 사용 컴포넌트: `Header`(뒤로가기만), `ProfileListItem`(`action` 슬롯), `ChipButton`(M), `RoleBadge`(ProfileListItem 내부), 확인 창 `Dialog`.
- 「추가하기」 칩과 X 버튼은 이름을 넣은 접근성 이름(「효찬 추가하기」, 「은우 내보내기」, 내 카드는 「번들에서 나가기」)을 쓴다.
- 확인 창은 되돌릴 수 없는 동작이라 최초 포커스가 「취소」에 있다.
- 동작 줄이기에서는 카드 이동 애니메이션을 끈다.

## 디자이너 확인 항목

- Figma 최신 프레임 `1782:32089`은 참여 멤버 행이 흐리지 않은 기본 상태이고 X가 `#121212`(`icon-primary`)다. 처음 본 프레임 `2060:42900`의 40% 흐림은 시안 오류로 보고 기본 상태로 구현했다.
- 내 카드 X: 최신 프레임 `1782:32089`의 「지예(나)」 행에는 X가 없지만, 기능명세서 4.3.2는 내 카드에 X를 보이도록 정해 X를 두었다(팀 결정). 기획 확인이 필요하다.
- 초안 생성자의 나가기 모달은 팀 결정으로 일반 멤버와 같은 문구를 쓴다(기능명세서 4.3.2 상세 동작 6의 「작성 중인 번들이 삭제돼요」 안내 문구는 쓰지 않음). 초안이 삭제된다는 사실은 이동 뒤 토스트로만 알리므로 기획 확인이 필요하다. Figma `2060:43016`의 모달은 문구(「번들에서 나갈까요?」·「내가 남긴 코멘트가…」)가 달라 따르지 않았다.
