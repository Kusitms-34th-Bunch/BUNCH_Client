# 페이지: 번치 분위기 선택(번치 만들기 3단계)

## 메타데이터

- Route: `/onboarding/create/mood`(`apps/web/src/app/(app)/onboarding/create/mood/page.tsx`)
- Status: UI와 선택 동작 구현됨(`next build` 렌더를 Figma 값과 측정으로 대조함). 분위기 카드 내용과 번치 생성 요청은 미연결(「번치 만들기」는 완료 화면으로 이동만 함). 실기기 검증 전
- 디자인 출처: Figma `Bunch/Create/Personality`(node `791:3424` 미선택, `791:3449` 선택, `791:11665` 중단 확인 모달). 화면설계서는 `온보딩_04`(node `791:10735`).

## 목적과 범위

### 포함

- 번치 분위기를 하나 고르는 마지막 단계의 UI와 선택 동작, 헤더 뒤로 가기의 중단 확인 모달(1~3단계 공통 `ExitCreateBunchDialog`).
- 구성: 헤더(뒤로 가기), `Stepper`(3단계 중 3단계), 제목 「우리 번치는 어떤 분위기인가요?」, 분위기 카드 4개(2열×2행, 단일 선택), 하단 「이전」·「번치 만들기」.
- 카드를 고르면 「번치 만들기」가 활성화된다. 다른 카드를 고르면 기존 선택이 해제된다.

### 범위 외

- 분위기 카드의 이름·그래픽(설계서 "그래픽 추후 전달"), 번치 생성 요청과 완료 화면(`CREATE-04`) 이동, 요청 중 중복 탭 방지.
- 피드 화면, 화면 전환 애니메이션(`onboarding.spec.md`의 확인할 항목). 진행 표시줄 전환은 구현했다.

## Route와 접근

- Path·params·search: `/onboarding/create/mood`. params와 search는 없다.
- 접근 권한·guard: 아직 없다(로그인 미구현). 입력값은 `create/layout.tsx`의 provider가 보관하므로 URL로 직접 열면 1·2단계 입력이 비어 있다.
- Layout·redirect·navigation: `(app)` group의 `AppFrame` 안에서 `PageShell`을 한 번 쓴다. 「이전」은 `router.back()`, 모달의 「나가기」는 `router.replace(ONBOARDING_PATHS.feed)`다.

## 상태와 흐름

- 초기 진입: 아무 카드도 선택되지 않고 「번치 만들기」는 비활성이다. 2단계에서 돌아온 경우 이미 고른 카드가 남아 있다.
- 선택: 카드 전체가 눌린다. 선택된 카드는 어둡게(`overlay-pressed`) 표시된다.
- 헤더 뒤로 가기: 이동 없이 모달을 연다. 모달 안에서 최초 초점은 「계속 만들기」다.
- 「나가기」: 이름·공개 범위·소개·분위기를 모두 비우고 피드로 이동한다(`replace`). 「계속 만들기」와 ESC는 모달만 닫고 화면과 입력값은 그대로다. 바깥 터치는 무시된다.
- 나간 뒤 브라우저 기록의 1·2단계로 뒤로 가면 provider가 새로 만들어져 빈 입력으로 시작한다(코드로만 확인, 브라우저 실행은 미검증).
- 「번치 만들기」: 누르면 생성 요청 없이 완료 화면(`/onboarding/create/complete`, `bunchCreated.spec.md`)으로 `router.push`한다(아래 확인할 항목).

## 데이터 의존성

- Query와 enabled 조건: 없음.
- Mutation·cache 영향: 없음. 생성 요청은 미연결이라 번치는 실제로 만들어지지 않는다.
- API 계약 확인 항목: 번치 생성 요청 필드(이름·공개 범위·소개·분위기), 분위기 값의 종류, 성공 시 완료 화면 이동, 실패 안내.

## UI와 접근성

- Component mapping: `CreateBunchFrame`(헤더·진행 표시줄, `bunchBasicInfo.spec.md`), `PageHeader`(제목만), `fieldset`·`legend`(화면 안 숨김)+라디오 카드(이 feature 안의 `label`, 임시 그래픽 자리), `Button`(`secondary` 이전 / `primary` 번치 만들기), 모달은 `Dialog` 부품 조합이고 `overlay-kit`의 `overlay.open`(`useExitCreateBunchDialog`)으로 연다.
- Keyboard·focus·accessible name: 카드는 숨긴 라디오라 방향키로 선택을 옮기고 초점 시 윤곽선이 보인다. 카드 이름은 임시로 「분위기 1~4」(숨김 텍스트)이며 그룹 이름은 화면 질문과 같은 「우리 번치는 어떤 분위기인가요?」(숨김 legend)다. 「번치 만들기」는 비활성일 때 native `disabled`다.
- 모달: `role="alertdialog"`, 제목·설명 자동 연결. `ConfirmDialog`는 ESC를 취소 쪽(`onCancel`)으로 처리해 「나가기」를 취소 자리에 두면 ESC로 나가지므로, `Dialog.Confirm`(나가기)·`Dialog.Cancel`(계속 만들기)을 조합했다.
- Responsive·긴 텍스트·overflow: 카드는 `grid-cols-2`로 폭에 맞춰 늘어난다(375px에서 165.5px). 가로 넘침 없음.

## 확인할 항목

- 분위기 카드 내용 (확정 필요): 설계서가 "그래픽 추후 전달"이라 이름·그래픽·값이 없다. 임시로 「분위기 1~4」와 회색 상자로 두었다. 확정되면 라벨·그래픽·`Mood` 값을 교체한다.
- 선택 표시 (미정, 디자이너 확인): 선택은 검정 20% 겹침만으로 보인다. 임시 카드 색에서는 선택/미선택 대비가 약 1.7:1(계산값)이라 색만으로 전달된다. Figma에 없는 표시는 넣지 않았고, 그래픽 확정 때 선택 표시 필요 여부를 확인한다.
- 비활성 사유 (미정): 「번치 만들기」 비활성 이유를 알리는 안내는 Figma에 없다(1·2단계와 같은 패턴, 디자이너 협의).
- 카드 색 (제안): Figma 회색 `#d9d9d9`는 같은 토큰이 없어 가장 가까운 `surface-tertiary`(#eaeaea)를 썼다. 그래픽이 들어오면 사라질 임시 값이다.
- 「번치 만들기」 (확정 필요): 설계서는 "번치 생성 요청 → 성공 시 완료 화면(CREATE-04) 이동, 요청 중 중복 탭 방지"다. 생성 API가 없어 요청 없이 완료 화면으로 이동만 연결했다. 요청을 연결할 때 1·2단계 입력 누락(직접 진입)을 검증하고 비어 있으면 1단계로 보낸다(연결 이슈의 필수 조건). 요청이 없는 채로 develop에 머지하면 이 화면에서 만들어지지 않았는데 완료 화면이 뜨는 상태임을 PR 본문에 알린다.
- 모달 문구 (확정): 설계서 5번 설명은 "홈으로 이동해요"이고 Figma 프레임은 "피드로 이동해요"다. Figma 프레임 문구를 썼다. 기획 확인.
- 피드 경로 (미정): 「나가기」는 `ONBOARDING_PATHS.feed`(현재 `/`)로 간다. 홈의 피드 탭 route가 정해지면 값을 바꾼다. 설계서는 "홈 화면의 피드 탭"이다.
- 모달 한글 줄바꿈 (미정): 설명이 Figma에서는 "…사라지고 / 피드로 이동해요."로 어절 단위로 나뉘는데 `Dialog`는 글자 단위로 나뉜다("피/드로"). 공용 `Dialog`의 `word-break` 문제라 디자인 시스템 쪽에서 확인한다.
- 「이전」 (확정, 설계서와 다름): 설계서는 "2단계로 이동"이고 구현은 `router.back()`이다. 직접 진입 시 이전 기록으로 나갈 수 있다.
- 시작 화면의 닫기(X) (미정): 같은 모달을 쓰도록 설계서(`온보딩_01`)에 있으나 이번 범위에서 연결하지 않았다(`onboarding.spec.md`).
