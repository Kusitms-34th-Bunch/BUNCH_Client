# 페이지: 초대 링크 확인 로딩(초대장 로티)

## 메타데이터

- Route: `/onboarding/join/motion`(`apps/web/src/app/(app)/onboarding/join/motion/page.tsx`)
- Status: 구현됨(headless Chromium 375×734 렌더에서 로티가 재생되고 자동 이동함. 89프레임 전환 시점은 단위 검증, 실제 기기 체감 검증 전). 실기기 검증 전
- 디자인 출처: Figma `Bunch/Join/Loading`(node `791:3177`)과 디자이너가 전달한 로티 `Invite_Animation.json`. 화면설계서는 `온보딩_번치 참여`(node `791:9342`)의 ①.

## 목적과 범위

### 포함

- 초대 링크를 확인하는 동안 중앙에 초대장 일러스트(로티)를 한 번 재생하고, 끝나면 초대 확인 화면(`BunchJoinInvitation.spec.md`)으로 자동 이동한다. 헤더·하단 영역은 없다.
- 로티는 120프레임, 30fps라 약 4초다. 연보라(`#f1f2ff`) 원은 프레임 58~89에 커지고 그 뒤 약 1초는 변화 없이 끝난다. 정지한 채 기다리지 않게 원이 다 커진 시점(프레임 89, 약 2.97초)에 넘어가고, 프레임 80부터 화면 배경이 같은 연보라로 번져(300ms, `ease-out`) 다음 화면 배경과 이어진다. 같은 시점에 `data-app-background` 표식을 전달해 상단 상태 바·하단 홈 인디케이터의 Safe Area 배경도 300ms ease-out으로 함께 바뀐다.

### 범위 외

- 번치 정보 조회 API. 지금은 재생 시간이 곧 로딩 시간이다. API가 생기면 응답을 기다리는 동안 재생하고(최소 한 번 재생), 실패 처리를 정한다.
- 상태 바·홈 인디케이터(기기 요소).

## Route와 접근

- Path·params·search: `/onboarding/join/motion`. params·search는 없다(링크를 받아 조회하는 연결은 API와 함께 정한다).
- 접근 권한·guard: 아직 없다. URL로 바로 열려도 재생 후 초대 확인 화면으로 간다.
- Layout·redirect·navigation: `(app)` group의 `AppFrame` 안에서 `PageShell`을 한 번 쓴다. 끝나면 `router.replace`로 이동해 뒤로 가기로 돌아오지 않는다(입력 화면 → 초대 확인 화면 사이 기록에 남지 않는다).

## 상태와 흐름

- 초기 진입: 로티 라이브러리와 자산을 동적으로 불러온 뒤 자동 재생한다. 불러오는 동안은 빈 화면이다. 재생 중 `router.prefetch`로 초대 확인 페이지를 미리 준비한다(개발 모드에서는 prefetch 효과가 제한될 수 있다).
- 이동: 프레임 89 이상이면 초대 확인 화면으로 한 번만 이동한다. 끝(`complete`)은 프레임 이벤트가 오지 않을 때의 대비이며 중복 이벤트는 무시한다.
- 재생 실패(라이브러리·자산을 못 받거나 재생 오류): 화면이 멈추지 않게 바로 다음 화면으로 넘긴다.
- 동작 줄이기(`prefers-reduced-motion: reduce`): 로티를 불러오지 않고 0.8초 뒤 넘어간다(`motion.md`는 정지 프레임을 권하지만 이 장면에는 의미 있는 정지 프레임이 없어 생략).

## UI와 접근성

- Component mapping: `PageShell`(main만), `InviteAnimation`(로티 재생, `lottie-react`의 `LottieLight`). 로티와 자산은 `lib/lottieLight.ts`로 light 엔진만 동적 import한다(빌드에서 엔진 하나 약 164KB와 래퍼 47KB만 내려받는다. `LottieLight`를 모듈 전체에서 가져오면 엔진 세 빌드가 모두 내려받아진다).
- 접근성: 로티는 장식이라 `aria-hidden`이고, 불러오는 중이라는 안내 「초대받은 번치 정보를 불러오는 중이에요.」를 화면에는 보이지 않는 `h1`로 전달한다(처음부터 들어 있는 글자는 `role="status"`가 알리지 않아서 쓰지 않았다). 동작 줄이기에서는 0.8초 동안 보이는 글자가 없는 흰 화면이다(시각 안내는 Figma에 없어 두지 않았다, 확인할 항목).
- Responsive: 로티는 375×734 장면을 `meet`로 맞춘다. 기기에서 상태 바(44px)와 홈 인디케이터(34px)를 뺀 영역이 734px라 정확히 맞는다.

## 확인할 항목

- 직접 진입·새로고침 (임시): 입력 화면을 거치지 않고 URL로 열거나 새로고침해도 재생 후 초대 확인 화면으로 간다. 링크로 번치를 식별하는 API가 없어 막을 근거가 없다. API가 생기면 링크가 없거나 유효하지 않을 때 입력 화면으로 되돌린다.
- 브라우저·기기 뒤로 가기 (미구현): 이 화면에는 헤더·모달이 없어 뒤로 가기로 입력 화면에 돌아간다(중단 모달을 거치지 않음). 모바일 쉘의 하드웨어 뒤로 가기 처리 때 다시 정한다.
- 화면 전환 (규칙 없음): `AppTransitions`에 입력 → 로딩·로딩 → 초대 확인 규칙이 없어 슬라이드 없이 바로 바뀐다. 설계서에 이 구간의 전환 지정이 없다.
- 로딩 길이 (미정): API가 생기면 응답이 4초보다 빠르거나 느릴 수 있다. 응답이 빨라도 끝까지 재생할지(디자이너 확인)와 느릴 때 반복·정지를 어떻게 할지 정한다.
- 이동 방식 (확정): `replace`. 로딩 화면에 뒤로 가기 헤더는 없다.
