## 목적과 범위

### 포함

- 뒤로 가기만 있는 헤더(제목 없음, 이름은 화면 밖 `h1` 「약관 및 개인정보」).
- 「이용약관」 묶음의 서비스 이용약관, 「개인정보 처리 및 동의」 묶음의 개인정보 처리방침으로 가는 링크(`/my/terms/service`·`/my/terms/privacy`).
- 「추가 개인정보 수집 및 동의」 줄: 제목, 밑줄 「전문보기」(`/my/terms/demographics`), 오른쪽 토글.
- 토글을 누르면 동의 확인 창(꺼짐 → 켜짐) 또는 철회 확인 창(켜짐 → 꺼짐)을 띄운다. 토글은 누르는 순간 바뀌지 않고 확인 창에서 「동의하기」·「동의 철회」를 눌러야 바뀐다(기능명세서 7.4.5 상세 3).
- 저장 중에는 확인 창을 닫거나 다시 누를 수 없다(연타는 첫 탭만, 7.4.5 예외).
- 처리가 끝나도 토스트는 띄우지 않는다(7.4.5 상세 4 제안).

### 범위 외

- 동의 상태 조회·동의·철회의 서버 연동. 서버 API가 없어 이 기기(브라우저 저장소)에만 저장하는 임시 값(`hooks/useDemographicsConsent.ts`)으로 UI를 확인한다. 계약이 정해지면 query·mutation으로 바꾸고 이 hook은 지운다.
- 동의서 버전·일시 기록(7.4.5 로직 1)과 철회 시 출생연도·성별 삭제는 서버가 맡는다. 임시 구현은 동의 여부만 저장한다.
- 약관 원문 내용(`TermsDocument`).

## 상태와 흐름

- 초기: 화면을 바로 그린다. 동의 상태는 이 기기에 저장된 값이고, 없으면 동의하지 않은 상태(토글 꺼짐)다.
- 동의하기 → 토글이 켜지고 창이 닫힌다. 동의 철회 → 토글이 꺼지고 창이 닫힌다. 값은 이 기기에만 저장하고 프로필 수정의 출생연도·성별 활성 여부가 이 값을 따른다.
- 뒤로 가기: MY(`/my`)로 돌아간다. MY → 이 화면은 Dissolve / Ease out / 200ms다(Figma 메뉴 인터랙션).

## UI와 접근성

- 묶음 모양은 MY 메뉴와 같은 `MenuSection`(제목 `h2`, 목록 `ul`)을 쓴다. 약관 링크는 `MenuLabel`, 토글은 core `Toggle`이다.
- 토글은 `role="switch"`이고 이름은 줄 제목(`aria-labelledby`)이다. 「전문보기」는 링크 이름에 항목 이름을 화면 밖 글자로 이어 붙여 구분한다.
- 확인 창은 `ConfirmDialog`(alertdialog)이고 취소·확인 버튼을 둔다.
