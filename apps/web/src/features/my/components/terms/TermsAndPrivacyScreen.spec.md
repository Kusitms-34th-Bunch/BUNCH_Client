## 목적과 범위

### 포함

- 뒤로 가기만 있는 헤더(제목 없음, 이름은 화면 밖 `h1` 「약관 및 개인정보」).
- 「이용약관」 묶음의 서비스 이용약관, 「개인정보 처리 및 동의」 묶음의 개인정보 처리방침으로 가는 링크(`/my/terms/service`·`/my/terms/privacy`).
- 「추가 개인정보 수집 및 이용 동의」 줄: 제목, 밑줄 「전문보기」(`/my/terms/demographics`), 오른쪽 토글.
- 토글을 누르면 동의 확인 창(꺼짐 → 켜짐) 또는 철회 확인 창(켜짐 → 꺼짐)을 띄운다. 토글은 누르는 순간 바뀌지 않고 확인 창에서 「동의하기」·「동의 철회」를 눌러야 바뀐다(기능명세서 7.4.5 상세 3).
- 저장 중에는 확인 창을 닫거나 다시 누를 수 없다(연타는 첫 탭만, 7.4.5 예외).
- 처리가 끝나도 토스트는 띄우지 않는다(7.4.5 상세 4 제안).
- 동의 상태는 들어올 때마다 서버에서 다시 받는다(7.4.4 로직 1). 받기 전과 받지 못했을 때는 토글을 누를 수 없다.

### 범위 외

- 동의 일시 기록(7.4.5 로직 1), 철회 시 출생연도·성별 삭제(로직 2), 같은 요청 중복 처리(로직 4)는 서버가 맡는다. 앱은 동의서 현재 버전만 함께 보낸다.
- 약관 원문 내용(`TermsDocument`).

## 상태와 흐름

- 초기: 화면을 바로 그린다. 동의 상태를 받기 전에는 토글이 꺼진 비활성이고, 받으면 그 상태로 바뀐다(받아 둔 값이 있으면 먼저 보이고 다시 받음).
- 불러오기 실패: 토스트 「일시적인 오류가 발생했어요. 다시 시도해 주세요」를 띄우고 토글은 누를 수 없게 둔다(7.4.4 예외). 받아 둔 값이 있어도 다시 받기에 실패했으면 누를 수 없다. 토스트는 화면에 들어온 뒤 한 번만 띄운다(앱 복귀로 다시 받다 실패해도 반복하지 않음). 약관 링크는 그대로 쓸 수 있다.
- 동의하기 → 서버에 저장한 뒤 응답으로 토글이 켜지고 창이 닫힌다. 동의 철회 → 저장 뒤 토글이 꺼지고 창이 닫힌다. 프로필 수정은 들어올 때 이 상태를 다시 받아 출생연도·성별 영역을 정한다.
- 저장 실패: 창을 닫고 토글은 원래 상태로 두며 같은 토스트를 띄운다(7.4.5 예외, mutation 공통 `meta.errorMessage`).
- 뒤로 가기: MY(`/my`)로 돌아간다. MY → 이 화면은 Dissolve / Ease out / 200ms다(Figma 메뉴 인터랙션).

## UI와 접근성

- 데이터: `useAdditionalInfo`(`queries/additionalInfo.ts`) → `getAdditionalInfo`(`GET /members/me/additional-info`), `useUpdateAdditionalInfoConsentMutation` → `updateAdditionalInfoConsent`(`PUT /members/me/additional-info-consent`, `agreed`와 `GET /auth/terms`의 DEMOGRAPHICS 버전, 버전이 없거나 약관 조회가 실패하면 빼고 보내 철회가 막히지 않음). 성공하면 진행 중인 조회를 취소한 뒤 응답으로 `myKeys.additionalInfo()`를 바꾼다. 개인정보라 캐시 영속화하지 않는다.
- 묶음 모양은 MY 메뉴와 같은 `MenuSection`(제목 `h2`, 목록 `ul`)을 쓴다. 약관 링크는 `MenuLabel`, 토글은 core `Toggle`이다.
- 토글은 `role="switch"`이고 이름은 줄 제목(`aria-labelledby`)이다. 「전문보기」는 링크 이름에 항목 이름을 화면 밖 글자로 이어 붙여 구분한다.
- 확인 창은 `ConfirmDialog`(alertdialog)이고 취소·확인 버튼을 둔다.
