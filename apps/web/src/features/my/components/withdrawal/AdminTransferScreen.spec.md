## 목적과 범위

### 포함

- 내가 메인 관리자인 번치를 번치마다 `BunchAccordion`으로 보여 준다. 처음에는 모두 접혀 있다(설계서 4번, 탈퇴하기(6)).
- 번치를 펼치면 「멤버」 아래에 넘겨받을 수 있는 멤버가 나온다. 번치마다 한 명만 고른다. 같은 번치에서 다른 멤버를 고르면 바뀌고, 다른 번치의 선택은 그대로다(5-1·5-2번).
- 본인은 후보에 넣지 않는다(4번). 공동 관리자는 역할 배지를 붙이고 이름 뒤에 「공동 관리자」를 낭독한다.
- 모든 번치의 새 관리자를 고르기 전에는 「다음」이 비활성이다. 누르면 권한을 넘기고 탈퇴 안내로 돌아간다(5-3번).
- 돌아온 탈퇴 안내에서 「다음」을 다시 누르면 남은 메인 관리자 번치로 다시 판단한다. 모두 넘겼으면 최종 탈퇴 확인으로 간다(`WithdrawalScreen.spec.md`).

### 범위 외

- 메인 관리자 확인·권한 이전 API. 계약에 없다.
  - 번치 목록과 이전 결과는 메모리 저장소(`hooks/useOwnedBunches.ts`)에 둔다. 처음 값은 fixture 번치 두 개이고, 새로고침하면 처음 값으로 돌아간다. API가 생기면 query와 mutation으로 바꾸고 요청 중 중복 방지·실패 안내를 함께 넣는다.
- 넘기기 전 확인 창과 완료 안내. 설계서에 없다.
- 멤버가 나뿐인 번치. 설계서에 없어 fixture에 두지 않았다(아래 확인할 항목).

## Route와 접근

- Path·params·search: `/my/withdrawal/transfer`, 없음. 입구는 탈퇴 안내의 권한 이전 안내 창 「권한 넘기러 가기」.
- 접근 권한·guard: `(app)` 그룹 기준을 따른다. 추가한 guard는 없다. 넘길 번치가 없을 때 직접 들어오면 빈 목록과 비활성 「다음」만 보인다(낭독용 진행 문구도 두지 않는다).
- Layout·navigation: page가 전환 경계(`data-ssgoi-transition="/my/withdrawal/transfer"`)를 두고, 탈퇴 안내와 미는 slide(`menuSubSlide`)로 오간다. 뒤로 가기는 `useBackOr(MY_PATHS.withdrawal)`이다. 완료 뒤에는 탈퇴 안내의 「권한 넘기러 가기」로 들어왔으면(`markTransferFromGuide`) 뒤로 가기로 돌아가고, 주소로 바로 들어왔으면 탈퇴 안내로 `replace`한다. 항상 `replace`하면 정상 흐름에서 탈퇴 안내가 기록에 두 번 남는다.

## 상태와 흐름

- 초기 진입: 모든 번치 접힘, 선택 없음, 「다음」 비활성.
- 「다음」: 저장소에서 넘긴 번치를 빼고 탈퇴 안내로 돌아간다. 누른 뒤에는 「다음」을 막아 돌아가는 전환 중 두 번 되돌아가지 않게 한다. 돌아가는 전환 동안 목록이 비지 않도록 화면은 들어올 때의 목록을 유지한다.

## UI와 접근성

- Component mapping:

| Figma           | 값                                                  | 사용한 컴포넌트·토큰                           |
| --------------- | --------------------------------------------------- | ---------------------------------------------- |
| 헤더            | 뒤로 가기(`#BCBEC2`), 제목 없음                     | `Header` + `HeaderIconButton tone="subtle"`    |
| 목록 위치       | 헤더 아래 16, 좌우 16                               | `pt-s8 px-padding-p8`                          |
| 번치 카드       | `Bunch_Accordion_Status`, 카드 사이 6               | `BunchAccordion`, `gap-s3`                     |
| 펼친 안쪽       | 좌우 10, 「멤버」 Body-4-SemiBold `#969AA0`·좌우 10 | `px-padding-p5`, `typography-body-4-semi-bold` |
| 「멤버」과 목록 | 사이 8, 멤버 사이 2                                 | `mb-s4`, `gap-s1`                              |
| 멤버            | `Profile Radio Card`(공동 관리자 배지)              | `ProfileRadioCard`                             |
| 「다음」        | SolidButton 48                                      | `Button`(primary)                              |

- Semantic: 화면 제목은 Figma에 없어 낭독용 `h1`(「관리자 권한 넘기기」)만 둔다. 번치 이름은 `h2` 안의 펼침 버튼이다. 번치마다 멤버를 `fieldset`으로 묶고, `legend`는 보이는 「멤버」 앞에 번치 이름을 낭독용으로 붙인다(예: 「퇴근런클럽 멤버」).
- Keyboard·focus: 펼침 버튼과 라디오는 기본 탭 순서를 따른다. 같은 번치의 라디오는 같은 `name`이라 방향키로 옮긴다.
- 「다음」 설명: 막힌 이유와 남은 번치 수를 낭독용 문구(「모든 번치에서 새 관리자를 골라 주세요. 2개 중 1개 골랐어요.」)로 `aria-describedby`에 연결한다. 접힌 카드는 선택 여부가 보이지 않아 이 문구로 진행 상황을 알린다.
- Interaction: 펼침·접힘(Smart Animate / Ease out / 200ms)은 디자인 시스템 `BunchAccordion` 기본 동작이다.

## 확인할 항목

- 카드 사이 간격 (제안): Figma는 펼친 카드 아래 10, 접힌 카드 사이 6으로 다르다. 탈퇴하기(6)의 접힌 목록 기준인 6으로 맞췄다.
- 화면 제목 (제안): Figma에 제목이 없어 낭독용 제목만 두었다. 보이는 안내 문구가 필요한지 디자인에 확인한다.
- 이전 대상 범위 (확인 필요): 일반 멤버도 메인 관리자로 받을 수 있는지, 멤버가 나뿐인 번치는 어떻게 하는지 기획에 확인한다. 지금은 공동 관리자와 일반 멤버를 모두 후보로 둔다.
- 접힌 카드의 선택 표시 (확인 필요): Figma 접힌 카드에는 고른 멤버가 보이지 않아, 접으면 어느 번치를 골랐는지 알 수 없다. 카드에 고른 멤버 이름을 보일지 디자인에 확인한다.
- 돌아온 뒤 확인 체크 (확인 필요): 넘기고 돌아오면 탈퇴 안내 화면이 새로 그려져 「안내 사항을 모두 확인했어요.」 체크가 풀린다. 설계서 5-3은 돌아와 「다음」을 누른다고만 적어, 체크 유지가 필요한지 기획에 확인한다.
- 메인 관리자 확인·권한 이전 API (확인 필요): 계약이 정해지면 저장소를 query·mutation으로 바꾼다.
