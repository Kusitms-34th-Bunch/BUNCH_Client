# [제품명] 비주얼 아이덴티티

> 실제 색상·폰트·톤이 확정된 뒤에 채운다. 비어 있는 동안은 `docs/architecture/styling-and-tokens.md`의 "아직 확정되지 않은 체계를 먼저 만들지 않는다" 원칙에 따라 값을 추측하지 않는다.

## 톤과 무드

제품이 주고 싶은 인상을 1~2문장으로. ("신뢰감 있고 차분한" / "발랄하고 친근한" 같은 방향성만 적고, 느낌을 색으로 바로 연결하지 않는다.)

## 색상 팔레트와 역할

값이 아니라 역할부터 정한다. 값은 실제 디자인이 나온 뒤 채운다.

| 역할 (semantic)                  | 용도              | 값  |
| -------------------------------- | ----------------- | --- |
| `brand`                          | 주요 액션, 포인트 |     |
| `surface`                        | 배경·카드 면      |     |
| `text`                           | 본문·제목         |     |
| `border`                         | 구분선·외곽선     |     |
| `danger` / `warning` / `success` | 상태 피드백       |     |

hex 값을 직접 쓰지 않고 역할 이름으로 참조한다. `docs/architecture/styling-and-tokens.md`의 token 기준을 따른다.

## 타이포그래피

- 폰트 패밀리(본문/제목 구분 여부)
- 크기·weight 스케일(토큰 몇 단계로 둘지)
- 한글 본문 최소 크기(가독성 하한선)

## 컴포넌트 스타일링

버튼·카드·입력창 같은 공통 요소의 기본값. 상태별(hover/focus/disabled/error) 표현까지 포함한다. `docs/architecture/design-system-components.md`의 생성 구조와 함께 쓴다.

## 레이아웃 원칙

- 간격 스케일(4px 배수 등 기준 단위)
- grid·여백 철학
- 반응형 breakpoint

## 깊이와 elevation

shadow·레이어 구분이 필요하면 단계를 정의한다. 필요 없는 제품이면 "사용하지 않음"으로 명시한다.

## Do's and Don'ts

이 제품에서 피해야 할 패턴(예: 특정 그라데이션, 과도한 그림자)을 구체적으로 적는다. 일반론("AI 티 안 나게")이 아니라 실제 토큰·값 기준으로 적는다.

## 반응형 동작

breakpoint별 레이아웃 변화, 터치 타겟 최소 크기.

## Agent 참고용 요약

이 문서를 읽고 구현할 agent가 바로 참조할 수 있는 핵심 토큰·색상 치트시트. 위 내용의 중복이 아니라, 구현 중 가장 자주 찾아볼 값만 압축한다.
