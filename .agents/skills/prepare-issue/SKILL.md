# 이슈 준비

## 목표

작업 내용을 이슈 폼 칸에 맞게 정리한다. 이슈 본문이 폼과 다른 모양이면 `create-work-branch` workflow가 브랜치를 만들지 못하므로, 폼과 같은 모양을 보장하는 것이 핵심이다.

## 입력 점검

1. `.github/ISSUE_TEMPLATE/issue.yml`을 읽는다. 칸 이름(label)과 브랜치 타입 선택지가 정본이다. 이 skill에 복제하지 않는다.
2. `.github/scripts/parse_issue.py`에서 workflow가 읽는 칸(`parse_form_field`)과 브랜치명 정제 규칙을 확인한다.
3. `docs/conventions/git.md`의 이슈 생성 절을 읽는다.
4. 내용이 모자라 칸을 채울 수 없으면 추측하지 말고 필요한 것을 한 번에 묻는다. 알 수 있는 정보는 묻지 않는다.

## 칸 채우기

- 제목: 접두사 없는 짧은 자연어 한 줄. 접두사 `[Type] #번호 - `는 이슈를 열 때 workflow가 붙이고, PR 제목도 이 제목에서 만들어진다. 함수·컴포넌트 이름과 장문 서술은 쓰지 않는다.
- 브랜치명: 영문 소문자·숫자·하이픈(`^[a-z0-9]+(-[a-z0-9]+)*$`). 번호는 넣지 않는다. 이슈 번호는 만들어진 뒤에 정해진다.
- 브랜치 타입: `issue.yml`의 선택지 중 하나. 버그는 `fix`, 새 기능은 `feat`, 구조 개선은 `refactor`, 문서는 `docs`, 설정·도구는 `chore`.
- 상세 내용: 무엇을 왜 하는지. 버그는 무엇이 잘못됐는지, 어떻게 재현하는지, 원래 어떻게 돼야 하는지.
- 체크리스트: 실제로 할 일을 `- [ ]` 항목으로 적는다.

작업 하나에 이슈 하나다. 서로 다른 목적을 한 이슈에 묶지 않는다.

## 출력

기본 결과는 칸별 초안과 `gh issue create --title "<제목>" --body-file <파일>` 명령이다. 본문을 저장할 파일 경로를 명시한다. 내용을 준비한 뒤 `gh auth status`를 확인하며, 인증을 대신 시도하지 않는다.

**인증이 있고 초안만 요청한 것이 아니면** 내용과 명령을 보여 주고 "이슈를 만들까요?"를 사용자에게 묻는다. 실행 질문에 긍정한 경우에만 제시한 범위를 만든다. 이미 같은 범위를 승인했다면 다시 묻지 않고, 범위가 바뀌면 새로 승인받는다. 규칙이나 설명에 동의한 답변은 실행 승인으로 보지 않는다.

- 본문은 폼으로 만든 이슈와 같은 모양으로 쓴다. 칸마다 `### <issue.yml의 label>` heading 아래에 빈 줄을 두고 값을 적는다. heading은 `issue.yml`과 한 글자도 다르면 안 되므로, 만들기 전에 다시 대조한다.
- 임시 파일에 본문을 쓰고 `gh issue create --title "<제목>" --body-file <파일>`로 만든다. 라벨과 담당자는 workflow가 붙이므로 `--label`·`--assignee`를 주지 않는다.
- 만든 뒤 이슈 번호와 URL, 곧 생길 브랜치 이름(`<번호>-<타입>/<브랜치명>`)을 알려 준다. 브랜치는 workflow가 만들기 때문에 몇 초 걸린다.

**인증이 없거나 사용자가 "명령만"·"초안만"을 원하면** 실행 여부를 묻지 않고 명령과 함께, 웹의 `New issue` → 이슈 폼에 칸마다 복사해 붙일 수 있게 **칸마다 코드 블록 하나씩** 준다: 제목, 브랜치명, 브랜치 타입, 상세 내용, 체크리스트.

## 여러 이슈를 한 번에

`prepare-feature-scope`의 이슈 후보처럼 여러 개를 받으면 이슈마다 칸 내용을 목록으로 한 번에 보여 주고, 승인 한 번으로 만든다. 일부만 승인하면 그것만 만든다.

- 선행 단위가 있으면 선행 이슈부터 순서대로 만들고, 뒤 이슈의 상세 내용에 `선행: #번호`를 적는다. 번호는 만든 뒤에야 알 수 있으므로 앞 이슈의 번호를 받아서 채운다.
- 만든 뒤 이슈별 번호, URL, 곧 생길 브랜치 이름을 표로 알려 준다.
- 후보가 spec의 "구현 단위와 이슈" 표에서 왔다면, 만든 이슈 번호를 그 표의 이슈 칸에 채운다. 이 파일 변경은 이슈와 별개이므로 커밋하지 않고 알린다.
- 인증이 없으면 이슈별로 칸마다 코드 블록을 준다. 단위 목록은 spec에 이미 기록돼 있으므로, 사용자가 이슈를 만든 뒤 번호를 알려 주면 표를 채운다.

## 규칙

- 공개 저장소가 될 예정이므로 수익 모델, 팀원 이름, 개인정보, 토큰을 이슈에 쓰지 않는다.
- AI 출처 문구와 확인하지 않은 사실을 넣지 않는다.
- 이슈를 만들었다면 만들었다고 쓰고, 초안만 줬다면 만들지 않았다고 쓴다.
