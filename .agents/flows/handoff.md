# 작업 인계 흐름

미완료 작업의 세션 간 인계는 `docs/workflows/development.md`의 "미완료 작업 인계" 기준에 따라 로컬 메모를 남긴다. 아래는 작업 결과를 보고할 때의 절차다.

구현 시작 시 같은 문서의 "worktree를 만드는 기준"으로 작업 위치·세션 수를 선택한다. 동시 구현으로 정한 추가 작업만 "별도 세션 실행과 링크"에 따라 인계문을 작성하고 `yarn agent:session --agent <codex|claude>`로 실행한다. 메인 세션은 자신이 쓰는 CLI를 `--agent`로 명시하며, 실패해도 다른 CLI로 자동 전환하지 않는다. 실제 세션 ID·링크·프로세스 상태를 확인하고, 실패하면 우회하지 않고 보고한다.

1. 요청 결과와 변경 파일·소유 경계를 한 문단으로 요약한다.
2. 실제 실행한 명령과 결과를 적고, 미실행 검증과 이유를 분리한다.
3. API·route·design system·automation 변경이면 영향을 받는 consumer와 수동 확인 항목을 적는다.
4. 남은 위험, 의도적으로 제외한 범위, 다음 작업이 필요한 조건을 명시한다.
5. 구조·계약·운영 규칙이 장기 제약을 만들면 decision 기록, 반복 장애면 troubleshooting 기록을 안내한다.

검증되지 않은 완료를 선언하거나, 실제로 수행하지 않은 test·build·배포를 보고하지 않는다.
