# 017: 웹 하단 탭 전환은 짧은 동시 크로스페이드로 하고, iOS 앱은 시스템 기본 전환을 유지한다

- 상태: accepted
- 기록일: 2026-11-01
- 구현 상태(2026-11-01 확인): 미구현. 지금 웹 탭 전환에는 페이지 전환이 등록되어 있지 않아 즉시 바뀐다. 구현은 별도 이슈에서 한다.

## 배경

- 하단 탭(피드·사진함·번치·MY)을 오갈 때 화면이 툭 바뀌어 자연스럽지 않다는 의견이 나왔다.
- 사진함과 번치 탭의 헤더는 왼쪽 번치 전환(대표 이미지·이름·화살표)이 같고, 오른쪽 버튼과 뒤 배경만 다르다. 같은 부분은 그대로 보이고 다른 부분만 바뀌는 느낌을 원했다.
- 같은 방식의 WebView 앱에서 탭 사이에 80ms 정도의 동시 크로스페이드를 써서 이런 느낌을 낸 사례를 확인했다. 탭 막대는 전환 밖에 두어 고정하고, 헤더는 탭마다 화면 안에 그대로 둔 구조였다.
- iOS 쉘은 시스템 탭 바와 탭마다 WebView를 쓴다([012](./012-ios-system-tab-bar.md)). 웹에서 넣는 페이지 전환은 iOS 앱의 탭 전환에 적용되지 않는다.

## 결정

- 웹 탭 막대를 쓰는 환경(브라우저·안드로이드)에서 네 탭 사이 이동에 동시 크로스페이드를 넣는다.
  - 나가는 화면은 불투명도 1→0, 들어오는 화면은 0→1로 같은 시간에 바뀐다. 위치 이동은 넣지 않는다.
  - 시간은 80ms, 곡선은 등속이다(제안, 디자이너 확인 전).
  - 탭 막대는 `(main)` layout에 있어 전환 대상 밖이라 그대로 남는다.
  - 헤더는 탭마다 화면 안에 둔다. 공통 헤더로 올리지 않는다.
  - 동작 줄이기 설정에서는 전환 없이 바뀐다.
- iOS 앱은 시스템 탭 바의 기본 동작(즉시 전환)을 유지한다.

## 검토한 대안

- **즉시 전환 유지**: 가장 단순하고 iOS 기본과 같지만, 웹에서 탭을 오갈 때 화면이 끊겨 보인다는 의견에 답하지 못한다.
- **탭 공통 헤더(헤더를 `(main)` layout으로 올리고 오른쪽 버튼·배경만 전환)**: 공통 부분이 정확히 이어지지만, 사진함 「선택」처럼 화면 상태에 따라 바뀌는 버튼을 layout으로 넘기는 연결이 필요하다. iOS 앱에서는 탭마다 WebView가 따로라 효과가 없다.
- **SSGOI 기본 `fade`(순차)**: 나가는 화면이 사라진 뒤 들어오는 화면이 나타나 그 사이 빈 순간이 생긴다. 탭처럼 자주 오가는 이동에는 동시 크로스페이드가 낫다.
- **iOS 앱도 같은 전환을 위해 WebView 하나와 웹 탭 막대로 되돌리기**: 웹 전환이 앱에도 그대로 적용되지만 [012](./012-ios-system-tab-bar.md)의 시스템 탭 바(Liquid Glass·끌기·접근성)를 잃는다.
- **iOS 쉘에서 탭 전환에 크로스페이드 넣기**: 시스템 탭 바의 전환 애니메이션을 바꾸는 방법이다. 지금 쓰는 expo-router 네이티브 탭(불안정 API)이 이 설정을 열어 주는지 확인하지 않았다.

## 영향

- 탭 page마다 SSGOI 전환 대상(`data-ssgoi-transition`)을 달고, `AppTransitions.tsx`에 네 탭 사이 규칙과 동시 크로스페이드 전환을 추가한다. 기존 `fade`는 순차라 그대로 쓰지 않는다.
- 탭은 하루에도 여러 번 오가는 요소라 [motion.md](../../architecture/motion.md)의 빈도 기준상 모션을 최소화한다. 80ms 투명도 전환만 쓰는 것은 그 기준 안에서 고른 값이다.
- 웹과 iOS 앱의 탭 전환 느낌이 다르다. 이 차이는 [012](./012-ios-system-tab-bar.md)의 탭 바 크기 차이와 같은 성격으로 보고 디자이너와 공유한다.

## 검증 / 후속 작업

- 별도 이슈에서 구현한다. 측정할 것: 탭 이동마다 전환 시간이 80ms 근처인지, 흰 화면 깜빡임이 없는지, 탭 막대가 고정되는지, 탭별 스크롤 위치가 남는지.
- 80ms와 등속 곡선을 디자이너와 확인한다.
- 구현하면 이 기록의 구현 상태와 `motion.md`의 페이지 전환 절을 갱신한다.

## 재검토 조건

- 디자이너가 탭 전환 값이나 방식을 따로 정하면 그 값으로 바꾼다.
- iOS 앱에서도 같은 느낌이 필요하다고 정하면, 쉘의 탭 전환 설정 가능 여부를 조사한 뒤 [012](./012-ios-system-tab-bar.md)과 함께 다시 정한다.
- 탭 page가 무거워져 전환 중 끊김이 생기면 전환을 끄거나 시간을 줄인다.
