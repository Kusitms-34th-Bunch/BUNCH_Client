# 019: 화면 접근 제어는 `(app)` layout의 클라이언트 가드가 서버의 가입 상태로 한다

- 상태: accepted
- 기록일: 2026-11-09
- 구현 상태(2026-11-09 확인): 구현됨(#259). `features/auth/components/AuthGate.tsx`, `lib/accessPolicy.ts`, `queries/session.ts`, `app/(app)/layout.tsx`.

## 배경

- 로그인 상태(비로그인·가입 중·가입 완료)에 따라 들어갈 수 있는 화면이 다르다(기능명세 1.2.7·1.2.8). 기능 spec(`docs/specs/login-signup.md`)은 「서버(layout·route 경계)에서 세션을 확인해 redirect」를 제안했다.
- 인증 토큰은 httpOnly 쿠키라 브라우저 코드가 읽지 못하고, 가입 상태는 백엔드의 `GET /members/me/onboarding`(가입 중·가입 완료 모두 호출 가능)이 알려 준다.
- Next 서버 컴포넌트는 쿠키를 새로 쓸 수 없다. 액세스 토큰이 만료됐을 때의 재발급(`reissue`)은 지금 브라우저 클라이언트(`browserClient`)가 401을 받아 처리한다.
- 앱은 WebView 안에서 돌고, 로그인 상태 확인 중 보여 줄 화면이 필요하다.

## 결정

- `(app)` layout의 `AuthGate`(클라이언트 컴포넌트)가 TanStack Query로 `members/me/onboarding`을 읽어 현재 경로의 접근 여부를 판단하고, 막아야 하면 `router.replace`로 보낸다. 판단 규칙은 순수 함수 `resolveAccess`에 둔다.
  - 비로그인(401): 로그인만 / 가입 중: 약관(미동의), 약관·프로필(동의) / 가입 완료: 로그인·가입 화면 밖 전체.
  - 판단 기준은 항상 서버가 준 값이다. 브라우저에 저장한 값으로 통과시키지 않는다.
- 상태를 확인하는 동안과 다른 화면으로 보내는 동안은 화면을 그리지 않고 `PageLoading`(앱 공통 로딩)만 보인다. 확인에 실패하면(401 외) 화면을 열지 않고 안내와 다시 시도를 보인다.
- 상태가 바뀌는 동작(로그인·약관 저장·가입 완료)은 `sharedKeys.session()`을 무효화(로그인은 새로 읽기)하고 기다린 뒤 이동한다.
- 데이터 보호는 가드가 아니라 백엔드 API가 한다(토큰 없음 401, 가입 중 403). 가드는 화면 이동 경험을 맞추는 장치다.

## 검토한 대안

- **서버 컴포넌트·`proxy.ts`에서 쿠키와 백엔드 호출로 redirect**: 화면이 깜빡이지 않고 명세의 제안과 같다. 하지만 서버가 쿠키를 새로 쓸 수 없어 토큰 만료 때의 재발급을 `proxy.ts`에 새로 만들어야 하고, 이번 범위에 비해 위험이 크다.
- **쿠키 존재만 `proxy.ts`에서 확인**: 가입 상태를 구분하지 못해 상태별 이동을 못 한다.
- **앱 저장소(localStorage)에 상태를 두고 판단**: 서버 값과 어긋날 수 있고 문서의 접근 제어 원칙(저장 값만으로 통과시키지 않기)에 어긋난다.

## 결과와 한계

- 화면을 열 때마다 서버를 한 번 읽는다(캐시는 기본 staleTime 5분). iOS 쉘은 탭마다 WebView가 따로라 앱 실행 때 탭 수만큼 읽는다.
- 서버가 화면을 직접 막지 않는다. 가드가 없는 주소로 데이터를 요청하면 백엔드가 막는다.
- 사용 중 세션이 끝난 경우(재발급까지 실패한 401)는 `browserClient`의 `onUnauthorized`가 연결되지 않아 가드가 다음 상태 확인 때만 로그인으로 보낸다.
- 로그인 직후 가입 상태는 가드가 보는 같은 query key에 `setQueryData`로 채운다. 같은 key를 `fetchQuery`로 다시 읽으면 데이터가 없던 가드가 로딩으로 바뀌어 로그인 화면이 사라진다(테스트로 고정). 이동은 로그인 쪽이 하고, 가입 완료 사용자는 `replace`라 가드의 `replace`와 겹쳐도 기록이 늘지 않는다.
- 약관 저장·가입 완료가 이 key를 갱신하도록 연결되기 전에는 실서버에서 가입 흐름이 가드에 되돌려질 수 있다(MSW 기본 응답은 가입 완료라 개발·테스트에서는 드러나지 않는다). 연결 작업(#259의 약관·프로필)과 함께 머지한다.
- 가입 중 사용자의 로그인 화면은 막지 않는다. 약관의 뒤로가기가 로그인으로 돌아오는 것이 기획(1.3.5)이고 로그아웃이 아직 연결되지 않았기 때문이다.

## 다시 검토할 조건

- 화면 깜빡임이나 첫 화면 지연이 실기기에서 문제가 되면 서버 쪽 확인(`proxy.ts` 재발급 포함)을 다시 검토한다.
- 사용 중 세션 만료를 한곳에서 처리해야 하면 `onUnauthorized`를 연결한다.
