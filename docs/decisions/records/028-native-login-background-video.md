# 028: iOS 쉘의 로그인 배경 영상은 네이티브로 재생한다

- 상태: proposed
- 기록일: 2026-11-20
- 구현 상태(2026-11-20 확인): iOS 쉘 첫 화면과 웹 로그인 화면에 구현됨(#474). 웹 단위 테스트와 쉘 타입 검사·테스트만 통과했고, 실기기 재생·저전력 모드·앱 전환은 확인하지 못했다. `expo-video`가 새로 들어가 개발 빌드를 다시 만들어야 한다.

## 배경

로그인 화면 배경은 25초짜리 소리 없는 영상(`login.mp4`, 2.8MB)을 반복한다. 처음에는 웹 `<video>`로 그렸는데, iOS WebView에서 아래 문제가 이어졌다.

- 로그아웃 뒤 앱 안에서 이동해 들어오면 React가 `muted`를 속성 없이 넣어 자동 재생이 막히고 재생 버튼만 보였다. 소리를 직접 끄고 재생해 고쳤다.
- 저전력 모드는 사용자 동작 없는 영상 재생을 거부한다. 쉘의 `mediaPlaybackRequiresUserAction={false}`로도 풀리지 않았다(실기기 확인).
- 같은 mp4를 `<img>`로 넣으면 저전력 모드에서도 움직였지만, 앱을 1초 나갔다 오면 WebView가 흰 화면으로 남고 개발 메뉴의 재시작도 듣지 않았다(실기기 확인). 원인은 확정하지 못했다.
- 앱을 나갔다 오면 영상이 멈춘 채 남았다. 웹의 `visibilitychange`로 다시 재생하게 했지만 불안정했다(실기기 확인).

## 결정

- iOS 쉘 첫 화면(`app/index.tsx`)에서는 로그인 배경 영상을 쉘이 `expo-video`로 WebView 뒤에 그린다. 영상 파일은 앱에 넣어 네트워크 없이 재생한다.
- 웹은 로그인 화면에 들어오면 bridge `setNativeLoginBackground(true)`로 요청한다. 쉘이 `true`를 돌려주면 웹은 자기 영상·첫 프레임·바탕을 빼고 버튼만 그린다. 이 표식(`data-app-background="login-video"`)이 있으면 바깥 틀(`AppFrame`)·화면 전환 틀(`AppTransitions`)·로그인 route 틀의 흰 바탕도 비우고, 겹침(검정 그라데이션)은 `AppFrame`이 Safe Area까지 그린다(#605, 화면 안에 두면 디졸브 중 WebKit이 위아래 Safe Area를 잘라 그림). 표식은 로그인 화면이 쉘의 `true`를 받았을 때만 붙어 다른 화면·브라우저는 그대로 흰 바탕이다.
- 쉘이 답하기 전에는 웹이 첫 프레임만 보인다. `false`·오류·1초 무응답(이 메서드가 없는 이전 쉘)이면 웹 영상을 쓴다. 탭 화면 WebView·안드로이드·브라우저도 웹 영상을 쓴다.
- 동작 줄이기 설정이면 웹은 영상을 요청하지 않고 첫 프레임만 둔다.
- 화면을 떠나면 웹이 `false`로 영상을 걷는다. 웹이 정리 신호를 보내지 못하는 경우(새 문서 로드, 탭 화면으로 전환)를 위해 쉘도 첫 화면 WebView가 새 문서를 불러오기 시작할 때와 첫 화면이 사라질 때 영상을 걷는다.
- 쉘 영상은 소리 없이 반복하고, 다른 앱의 음악을 끊지 않으며(`audioMixingMode: 'mixWithOthers'`), 화면 꺼짐을 막지 않는다. 앱이 뒤로 가면 멈추고 앞으로 오면 이어서 재생한다. 장식이라 보조 기술에서 숨긴다.

## 비교한 대안

- **웹 `<video>`만 쓰기**: 저전력 모드에서는 멈춘 첫 프레임만 보이고, 앱 전환 뒤 멈춤도 남는다.
- **저전력 모드에서 `<img>`로 바꿔 넣기**: 움직이긴 했지만 앱 전환 뒤 흰 화면이 나왔다. 앱이 멈추는 위험이 배경이 움직이는 이득보다 크다.
- **첫 터치 때 다시 재생**: 코드는 작지만 첫 화면이 멈춰 있다가 손을 대야 움직인다.

## 결과

- 쉘이 WebView 밖에 네이티브 UI를 하나 더 갖는다. 탭 바(012)·플로팅 버튼(026) 다음 세 번째 예외다.
- 첫 화면 WebView는 영상을 까는 동안 바탕이 투명하다. 첫 화면 바탕색은 웹 로그인 배경과 같은 어두운 색(#121212)이라, 영상 첫 프레임 전에도 흰 화면이 비치지 않는다.
- 영상 파일이 웹(`apps/web/public/videos/login.mp4`)과 쉘(`apps/mobile-shell/assets/login-background/login.mp4`)에 하나씩 있다. 영상을 바꾸면 두 곳을 함께 바꾼다. 앱 용량이 약 2.8MB 늘었다.
- 브라우저·안드로이드의 웹 영상 경로(로그아웃 뒤 재생 수정, 재생 버튼 덮개, 돌아왔을 때 다시 재생)는 그대로 유지한다.

## 다시 검토할 조건

- 실기기에서 투명 WebView와 네이티브 영상의 겹침이 어긋나거나(인트로 → 로그인 전환 등) 성능 문제가 보이면 다시 정한다.
- 안드로이드를 출시 대상에 넣으면 안드로이드도 네이티브 영상으로 옮길지 정한다.
- 로그인 배경 디자인이 영상이 아닌 것으로 바뀌면 이 예외를 없앤다.
