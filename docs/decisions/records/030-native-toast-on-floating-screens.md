# 030: 네이티브 플로팅 버튼이 떠 있는 화면의 토스트는 쉘이 네이티브로 띄운다

- 상태: proposed
- 기록일: 2026-11-22
- 구현 상태(2026-11-22 확인): iOS 26 쉘의 번치 홈·사진함(네이티브 플로팅 버튼이 떠 있는 동안)에 구현됨(#503). 웹·bridge·쉘 단위 테스트와 타입 검사만 통과했고, 실기기 모양·모션·VoiceOver 낭독·액션 버튼은 확인하지 못했다. 쉘 변경이라 앱 업데이트가 필요하다.

## 배경

iOS 26 쉘은 플로팅 버튼을 탭 WebView 위에 네이티브 Liquid Glass로 그린다(026). 웹 토스트는 WebView 안이라 z-index와 상관없이 그 버튼 뒤에 깔렸다(Expo 실기기 확인). 탭 막대가 있는 화면은 토스트가 탭 막대 위 16px에 떠 버튼과 겹친다. 플로팅 버튼의 유리 질감은 지키기로 했다(웹 버튼으로 되돌리지 않음).

## 결정

- 네이티브 플로팅 버튼이 떠 있는 탭 화면의 아래쪽 토스트는 쉘이 네이티브로 그린다. 그 밖의 화면, 위쪽 토스트(`position: 'top'`), 브라우저, 이 메서드가 없는 이전 쉘은 웹 토스트를 쓴다.
- 디자인 시스템 `toast()`는 앱이 등록한 표시 방법(`setToastPresenter`)에 아래쪽 토스트를 먼저 맡기고, 맡지 않으면 웹 토스트를 그린다. 웹 앱은 `useNativeFloatingButton`이 네이티브 버튼을 쓰는 화면에 있는 동안 등록한다(`useNativeToastPresenter`). 시트·대화상자·로딩으로 버튼을 잠시 지운 동안에도 유지해, 시트를 닫자마자 띄운 토스트가 웹으로 그려진 뒤 다시 나온 버튼에 가리거나 떠 있던 토스트가 사라지지 않게 한다.
- bridge는 `showNativeToast`(탭·id·문구·아이콘·액션 이름·노출 시간·폭)와 `hideNativeToast`, 액션 버튼 눌림 이벤트 `nativeToastAction`을 둔다. 액션 동작은 웹에 남고 쉘은 눌림만 돌려준다. 쉘이 거절하면 웹이 같은 토스트를 웹으로 다시 띄운다.
- 쉘 토스트는 디자인 시스템 Toast의 모양(색·모서리·여백·글자, 성공 아이콘, 액션 버튼), 모션(등장 350ms·퇴장 200ms, 5px 이동, 동작 줄이기에서는 투명도만), 노출 시간(3초·액션 5초), 대체 규칙(한 번에 하나)을 따른다. 위치는 아래 여백(탭 바 포함) 위 16px이라 탭 막대가 있으면 탭 막대 위 16px이다. 플로팅 버튼(아래 여백 위 10px)과 같은 기준이어서, 탭 막대를 숨긴 사진함 선택 모드에서도 토스트가 버튼과 겹치는 모양이 탭 막대 화면과 같다(버튼 아래 끝보다 6px 위, 사용자 결정). 탭 화면에서 플로팅 버튼보다 위에 그린다. VoiceOver에는 `announceForAccessibility`로 문구를 알린다.
- 쉘 글꼴은 Pretendard 1.3.9 Regular·SemiBold(otf, npm `pretendard` 레지스트리 sha512 확인)를 탭 레이아웃이 `expo-font`의 `useFonts`로 미리 불러온다(Expo Go에서도 동작). 불러오기 전에 뜬 토스트는 시스템 글꼴이다.

## 비교한 대안

- **토스트가 떠 있는 동안 버튼을 흐리게**: 구현해 봤으나 사용자가 받아들이지 않았다. 리뷰에서 `expo-glass-effect`가 투명도가 낮아진 뒤 유리 효과를 다시 설치하지 않을 수 있다는 점도 나왔다.
- **토스트를 버튼 위로 올리기, 폭을 버튼 앞에서 끊기**: 웹만 고치면 되지만 탭 막대 기준 위치나 Figma 폭과 달라진다.
- **플로팅 버튼을 웹 버튼으로**: z-index로 풀리지만 유리 질감을 잃는다(사용자가 제외).
- **모든 토스트를 네이티브로**: 섞어 쓰지 않지만 브라우저·이전 쉘용 웹 토스트가 어차피 남아 두 벌 관리는 같고 범위만 커진다.

## 결과

- 웹뷰 밖 네이티브 UI의 네 번째 예외다(탭 막대 012, 플로팅 버튼 026, 로그인 영상 028).
- 토스트 디자인을 웹(`packages/design-system/src/components/core/toast/`)과 쉘(`apps/mobile-shell/src/toast/NativeToast.tsx`) 두 곳에서 관리한다. 한쪽을 바꾸면 다른 쪽도 바꾼다. 웹의 `backdrop-blur-[2px]`는 쉘에 없다.
- 쉘 변경이라 앱 업데이트 전까지는 지금처럼 웹 토스트가 버튼 뒤에 깔린다.
- 웹 토스트와 다른 점: 웹이 다른 토스트로 바꾸거나 닫으면(`hideNativeToast`) 퇴장 모션 없이 사라지고, 아래로 밀어 닫기가 없다(자동으로 닫히지 않는 아래쪽 토스트는 지금 쓰는 곳이 없음). 누르고 있는 동안 노출 시간이 멈추지 않는다. 액션 버튼은 보이는 크기 32는 그대로 두고 누르는 범위만 위아래 6씩 넓혔다.

## 다시 검토할 조건

- 플로팅 버튼을 웹으로 바꾸거나, 다른 화면에도 WebView 위 네이티브 UI가 생기면 범위를 다시 정한다.
- 두 벌의 모양이 자주 어긋나면 모든 토스트를 쉘로 옮기는 방안을 다시 본다.
