# 024: 번들 제목은 Automerge 문서로 병합하고 WASM은 초안 화면에서만 불러온다

- 상태: accepted
- 날짜: 2026-11-15
- 구현 상태: 구현됨(#359). 개발 서버의 `title/crdt` 병합 동작은 아직 확인하지 못함

## 배경

여러 멤버가 같은 번들 제목을 동시에 고친다(잠금 없음). v5 명세는 제목을 서버가 준 `titleCrdtState`(Automerge 전체 저장 문서)에서 불러 같은 `title` 텍스트를 splice하고, `PATCH …/title/crdt`로 전체 저장 문서를 보내 서버가 병합하게 한다. 응답과 TITLE 이벤트도 같은 문서를 주므로 클라이언트가 로컬 문서에 병합한다.

## 결정

- `@automerge/automerge@3.2.1`을 쓴다. 서버가 같은 문서 형식(Automerge 전체 저장)을 쓰므로 직접 구현하지 않는다.
- 브라우저 기본 진입점은 번들러 WASM(`fullfat_bundler`)을 요구해 Next 설정이 필요하다. 대신 `@automerge/automerge/slim`과 `automerge.wasm.base64`를 **동적 import**로 불러 `initializeBase64Wasm`으로 초기화한다. 설정 변경이 없고 번들러에 상관없이 동작하며, WASM(약 3MB 청크)은 번들 초안 화면에서 제목을 다룰 때만 내려받는다.
- 문서를 다루는 코드는 `features/bundle/lib/titleCrdt.ts` 한 곳에 두고, 문자열 규칙(NFC·trim, 40 grapheme)은 WASM이 필요 없는 `lib/title.ts`로 분리한다.
- 입력은 이전 문자열과의 차이(공통 앞·뒤 제외)를 splice 한 번으로 문서에 반영한다. 문서를 새로 만들거나 제목을 통째로 대입하지 않는다. 같은 문서를 다시 병합해도 결과가 같다.
- 입력 중 원격 변경은 문서에는 바로 병합하고, 한글 조합 중에는 화면 반영만 조합이 끝난 뒤로 미룬다. 커서·선택 영역은 바뀐 위치를 따라 옮긴다.
- 병합 결과가 40 grapheme을 넘으면 자르지 않고 안내하며, 줄일 때까지 발행을 막는다(`TITLE_TOO_LONG`).
- 연결이 끊겨 보내지 못한 입력은 보관·재전송하지 않는다(명세). 재연결하면 최신 상세로 문서를 맞춘다.

## 대안

- **번들러 WASM 진입점**: 청크 분리는 자동이지만 Next·Turbopack 설정과 테스트 환경에 따라 동작이 달라진다.
- **마지막 저장 우선(PUT 전체 문자열)**: 동시 편집 시 다른 멤버의 변경을 덮어써 잃는다. 호환 경로로만 남아 있다.
- **직접 구현한 문자열 병합(OT 등)**: 서버 문서 형식과 맞지 않는다.

## 결과와 위험

- 제목 입력이 WASM 초기화 뒤에야 가능하다(문서를 불러오기 전에는 입력을 받지 않는다). 초안 상세가 먼저 오므로 보통 체감되지 않는다.
- WASM 청크를 받지 못하면 입력란이 읽기 전용으로 남는다. 연결 끊김과 같이 다뤄 「인터넷 연결을 확인해 주세요.」 배너를 보이고, 「재시도」로 다시 불러온다(명세에 없는 별도 문구를 만들지 않음).
- 문서는 변경 이력이 쌓여 커질 수 있다(서버 한도 256KiB).

## 다시 검토할 조건

- Automerge 주 버전이 올라 진입점이 바뀌면 초기화 방식을 다시 본다.
- 제목 외 필드도 CRDT로 바뀌면 문서 로딩을 공용으로 올린다.
