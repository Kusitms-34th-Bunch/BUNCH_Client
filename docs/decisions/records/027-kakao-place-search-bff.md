# 027: 번들 위치 검색은 웹 BFF가 카카오 로컬 API를 대신 호출한다

- 상태: accepted
- 기록일: 2026-11-16
- 구현 상태(2026-11-16 확인): `GET /api/places/search`와 번들 공동 편집의 위치 검색 시트에 구현됨. 실제 카카오 호출은 아직 확인하지 못했다.

## 배경

번들 위치(기능 spec 4.3.10)는 사용자가 검색해서 고른 장소만 저장한다. 백엔드에는 장소 검색 API가 없고 검색 공급자 호출과 검색 키는 프론트 책임이라고 정해졌다(API 명세 v5 「번들 장소 작업 적용」). 위치 권한은 받지 않고 키워드로만 검색한다.

## 결정

- 브라우저가 카카오를 직접 부르지 않고, 웹 BFF(`src/app/api/places/search/route.ts`)가 카카오 로컬 API의 키워드 검색과 주소 검색을 함께 불러 결과를 합쳐 돌려준다.
- 키는 서버 환경 변수 `KAKAO_REST_API_KEY`에만 두고 `NEXT_PUBLIC_`를 붙이지 않는다. 키가 없으면 검색은 503이다.
- 로그인한 사용자(access 쿠키)만 쓸 수 있고, 검색어는 2자 이상 50자 이하만 받는다. 응답에는 위치마다 `provider`(`kakao`)·`externalId`·`name`·`address`만 담고 좌표는 쓰지 않으며 캐시하지 않는다.
- 카카오 무료 쿼터(키워드 검색·주소 검색 각각 일 10만 건, 월 전체 300만 건, 개발자 계정의 첫 번째 활성화 앱만 무료, 2026-11-16 확인)를 아끼려고 키워드 검색을 먼저 부르고 결과가 5건보다 적을 때만 주소 검색을 더한다. 같은 검색어는 서버에서 3분(인스턴스별 최선 노력), 화면에서 5분 재사용하고, 다른 글자를 입력해 요청을 취소하면 BFF가 카카오 호출도 끊는다. 검색 시트는 두 글자 이상부터 입력이 400ms 멈추면 자동 검색한다.
- 백엔드에는 `provider`·`externalId`·`name`·`address`로 저장한다. 키워드 결과의 `externalId`는 카카오 장소 id, 주소 결과는 `address:` 뒤에 주소 문자열이다.

## 비교한 대안

- **브라우저에서 카카오를 직접 호출**: 키가 브라우저에 노출된다. 키 도메인 제한으로 줄일 수 있지만 쉘(WebView)의 출처와 맞춰야 하고 노출 자체를 피하는 편이 안전하다.
- **백엔드에 검색 API 추가 요청**: 서버가 검색을 하지 않기로 했다(API 명세).
- **키워드 검색만 사용**: 지역명·주소 검색 결과(예: 「서울특별시 여의도동」)가 빠진다. 기능 spec의 예시가 장소와 지역을 함께 보여 주므로 주소 검색도 합친다.

## 결과

- 배포 환경에 `KAKAO_REST_API_KEY`를 설정해야 한다(`docs/workflows/web-deployment.md`).
- 인증된 사용자가 반복 호출로 일 쿼터를 소진시킬 수 있다(호출 제한은 아직 없음). 쿼터를 넘으면 카카오가 429를 돌려줘 위치 검색이 막힌다. 운영 전에 호출 제한과 약관(저장 가능한 필드)을 확인해야 한다.
- 백엔드가 `provider` 값을 `kakao`로 받는지 실호출에서 확인해야 한다.
