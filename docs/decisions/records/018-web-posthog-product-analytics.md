# 018: 웹 제품 분석에 PostHog를 쓰고 화면 녹화는 하지 않는다

- 상태: accepted
- 기록일: 2026-11-07
- 구현 상태(2026-11-10 확인): 운영 적용 구현(#295). 운영 빌드에서만 수집하고, 약관에 동의한 회원만 opt-in한다. UT 회차 초기화(`startNewAnalyticsUser`)는 UT 종료로 제거. 개인정보 처리방침의 수집 항목·국외 이전(미국) 기재는 저장소 밖에서 확인 필요

## 배경과 결정

사용성 테스트(UT)에서 참가자가 어떤 버튼을 어떤 순서로 눌렀고 어디서 막혔는지 다시 보고, 운영에서도 퍼널·재방문 같은 제품 지표를 보기 위해 `apps/web`에 `posthog-js`를 도입한다. PostHog Cloud(US) 무료 플랜으로 시작한다.

- 클릭 자동 수집과 페이지 이동 수집만 쓴다. SDK 기본값 묶음(`defaults`)을 날짜로 고정하고, 반응 없는 클릭과 클릭 히트맵을 함께 켠다. 연타 클릭은 자동 수집에 포함된다.
- 화면 녹화(Session replay)는 하지 않는다. 코드에서 `disable_session_recording`으로 끄므로 프로젝트 설정에서 켜도 녹화되지 않는다. 클릭 흐름만으로 막힌 지점을 볼 수 있고, 녹화는 번치 사진·닉네임 같은 비공개 콘텐츠를 담게 된다.
- 오류 수집은 Sentry가 맡는다(ADR 006). PostHog의 예외 수집은 끈다.
- (UT 기간) 가짜 서버 빌드이고 `NEXT_PUBLIC_POSTHOG_KEY`가 있을 때만 SDK를 늦게 불러와 초기화했다. 지금 수집 조건은 아래 「운영 적용」을 따른다.
- 설문·대화 위젯·제품 투어·성능 수집은 코드에서 끈다. 프로젝트 설정만으로 참가자 화면에 UI가 뜨거나 수집 범위가 넓어지지 않게 한다.
- PostHog 프로젝트 설정에서 클라이언트 IP를 버린다(Discard client IP data). 국가·도시 위치는 IP를 버리기 전에 붙는다.

## UT와 운영의 차이

- UT 빌드(2026-11 종료, 코드 제거): 키를 넣으면 처음부터 수집했다. 동의는 진행자가 참가자가 화면을 처음 열기 전에 받았다. 참가자가 바꾼 번들 제목처럼 버튼 글자로 보이는 입력은 전송될 수 있어, UT에서는 개인정보를 입력하지 않도록 안내하는 것으로 대신했다(샘플 데이터 환경이라 코드 정제는 운영 적용 조건으로 미룸). UT는 팀 휴대폰의 Expo Go로 진행했고, 진행자 장치의 회차 초기화가 새 익명 사용자로 바꿔 회차별 기록을 나눴다.
- 운영: 약관·개인정보 처리방침 동의 뒤에만 수집하도록(기본 수집 끔, 동의 시 켬) 후속 작업에서 연결한다. (구현과 실제 적용은 아래 「운영 적용」) 개인정보 처리방침에 수집 항목과 국외 이전(미국)을 적어야 한다.
- 자동 수집이 보내는 값: 현재 주소·이전 주소(경로와 query, hash는 제외), 누른 요소와 상위 요소의 속성(`src`·`href`·`alt`·`data-*`·`aria-label`), 버튼·링크 글자. 입력값은 보내지 않는다(SDK가 입력 요소의 값과 대부분의 속성을 버림).
- 운영 적용 전 완료 조건(Sentry의 ADR 006 정제와 맞춤): `before_send`로 주소의 query와 초대 경로를 지우고, 이미지 `src`(서명된 사진 주소일 수 있음)·`alt`·`href`를 속성 수집에서 뺀다. 닉네임·코멘트 같은 사용자 글자가 섞이는 영역에는 `ph-no-capture`를 붙인다(구현은 `mask_all_text`로 대신했다, 아래 「운영 적용」). 수집은 약관 동의 뒤에만 켠다(`opt_out_capturing_by_default` + 동의 시 `opt_in_capturing`). 이때 가짜 서버 빌드에서만 켜는 조건(`posthog.ts`의 `analyticsKey`)을 동의 opt-in과 함께 바꾼다. 조건만 지우고 opt-in을 빠뜨리면 동의 없이 수집된다.

## 대안과 재검토 조건

- Microsoft Clarity: 녹화·히트맵은 무제한 무료지만 퍼널·재방문 같은 제품 지표가 약하다. 운영에서도 제품 지표를 볼 예정이라 도구를 하나로 묶었다.
- Maze: 실제 웹사이트 테스트는 유료다.
- 무료 한도(이벤트 월 100만 건)를 넘거나, 녹화가 꼭 필요해지거나, 수집 데이터를 국내에 두어야 하면 재검토한다.

## 검증

`src/shared/config/posthog.test.ts`(수집 조건, 초기화 옵션, 동의·회원 교체·철회, 주소 정제), `features/auth/components/AuthGate.analytics.test.tsx`(가입 상태별 동의 연결), web lint·typecheck·build. 개발 서버는 수집하지 않으므로 실제 수집은 운영 배포에서 동의한 회원으로 로그인해 PostHog Activity에 이벤트가 쌓이고 주소의 query·ID·글자가 빠졌는지 확인한다.

## 운영 적용(2026-11-10, #295)

위 「운영 적용 전 완료 조건」을 아래처럼 구현했다(`src/shared/config/posthog.ts`).

- 수집 범위: 운영 빌드(`NODE_ENV=production`, 가짜 서버 꺼짐)에서 키가 있을 때만 수집한다. 개발·가짜 서버 빌드의 클릭이 운영 지표에 섞이지 않게 하려는 것이다. UT 빌드처럼 동의 없이 처음부터 수집하는 모드는 없앴다.
- 동의: `AuthGate`가 서버의 가입 상태를 읽어 약관에 동의한 회원일 때만 SDK를 불러와 `opt_in_capturing`한다(`setAnalyticsConsent(memberId)`). 앱 시작 때 SDK를 불러오지 않으므로, 같은 기기에 이전 회원의 동의가 남아 있어도 가입 상태를 확인하기 전에는 수집되지 않는다. 로그아웃은 문서를 새로 열어 정리 코드가 돌지 않으므로, 이 기기에서 마지막으로 동의한 회원 ID(localStorage, 분석 도구로 보내지 않음)와 다르면 `opt_in` 전에 `reset`해 익명 ID를 새로 만든다(쿠키 만료로 바뀐 경우도 포함). 같은 문서에서 비로그인·미동의로 바뀌면 `opt_out_capturing` 뒤 `reset`한다. `opt_out_capturing_by_default`도 켜 둔다.
- 주소 정제: `before_send`로 이벤트·사용자 속성의 주소·경로 값에서 query와 hash를 지우고(초대 코드·토큰), 숫자 ID 구간을 `:id`로 바꾼다(회원·번치·사진 ID). 히트맵(`$heatmap_data`)은 주소를 객체 키로 보내므로 키도 정제하고, 누른 요소 묶음(`$elements_chain`)의 속성 값도 정제한다.
- 글자·속성: 사용자 글자 영역마다 `ph-no-capture`를 붙이는 대신 `mask_all_text`로 요소 글자를 모두 보내지 않는다. 번들 제목·닉네임이 버튼 글자와 접근성 이름에 섞여 영역을 빠짐없이 표시하기 어렵기 때문이다. `src`·`srcset`·`alt`·`href`·`aria-label`·`title` 속성도 뺀다. 그래서 클릭은 요소 종류·위치·화면 경로로만 구분된다. 특정 버튼을 구분해야 하면 사용자 글자가 없는 `data-*` 표식을 붙인다.
- 남은 확인: 실제 PostHog 프로젝트에서 이벤트 속성에 주소 query·ID·글자가 남지 않는지는 운영 키로 확인하지 않았다(SDK 소스와 단위 테스트 기준). 개인정보 처리방침(`features/auth/constants/termsDocuments.ts`의 `privacy`)은 2026-11-10 기준 서비스 이용약관을 복사한 임시 문구라 수집 항목·국외 이전이 없다. 기획 요청으로 처리방침 반영 전에 운영 키를 넣어 수집을 시작했고(2026-11-10), 처리방침에 수집 항목·국외 이전을 넣는 일은 기획에 요청했다. 약관 버전이 바뀌면 기존 동의 회원의 재동의 여부도 함께 정한다.
