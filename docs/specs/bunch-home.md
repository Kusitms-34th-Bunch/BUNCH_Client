# 기능: 번치 메인·상세 (기능명세서 5장)

> Status: Draft
> Date: 2026-11-10(기능명세서 1110판, 2026-11-10 기준)

기능명세서의 **5장 번치(메인/상세)**를 구현 범위로 정리한 문서다. 5장은 5.1~5.12로 나뉜다.

- 5.1 번치 메인 탭, 5.2 번치 전환 시트, 5.3 작성 중인 번들, 5.4 더보기 메뉴
- 5.5 프로필 편집, 5.6 멤버 관리, 5.7 차단 목록, 5.8 나가기, 5.9 삭제
- 5.10 다른 번치 프로필, 5.11 팔로워·팔로잉, 5.12 알림

기능 ID(BUNCH·MEMBER·FEED·NOTI·DRAFT·PROFILE)와 명세서 절 번호(5.2.3 등)로 원본과 대조한다. 번들 만들기·공동 편집은 `docs/specs/bundle-create.md`, 사진함은 `docs/specs/photo-box.md`가 맡는다.

이 spec은 web·백엔드·알림(푸시)에 걸쳐 `docs/specs/`에 둔다. 번치 메인은 `apps/web/src/features/bunch-home/`(#162)에 있고, 화면 spec은 그 폴더의 `components/home/BunchHomeScreen.spec.md`다.

## 목적

- 지금 보고 있는 번치의 대표 화면을 둔다. 번치 프로필 이미지, 소개, 함께 만든 번들을 한곳에 보여준다(5.1.1).
- 한 계정으로 여러 번치에 속한 사람이 번치를 바로 전환한다.
- 번치 관리(프로필, 멤버, 차단, 나가기, 삭제)와 다른 번치와의 관계(팔로우, 차단, 신고), 번치 단위 알림을 제공한다.

## 문제 정의

- 번치 전환이 앱 전체의 기준(사진함, 번들, 알림, 팔로우 명의)을 모두 새 번치로 바꾼다. 전환을 한곳에서 일관되게 다뤄야 한다(5.2.2 로직 2).
- 다른 관리자가 번치를 삭제하거나 내가 내보내져도 목록에서 바로 사라지면 무슨 일이 있었는지 알 수 없다. 접근 불가 상태와 안내가 필요하다(5.2.3).
- 역할(메인 관리자, 공동 관리자, 일반 멤버)에 따라 보이는 메뉴와 할 수 있는 일이 다르다. 서버가 요청 시점의 역할로 다시 판단해야 한다.

## 범위 외 항목

- 번들 만들기, 추천 번들, 공동 편집, 작성 중인 번들 삭제 처리(4장, `bundle-create.md`). 이 문서는 번치 메인에서 들어가는 입구만 둔다.
- 번치 만들기·초대 참여(2장). 번치 추가는 번치 시작 선택 화면(2.1.1)으로 보내기만 한다.
- 뭉치(번치 캐릭터)와 단계. 1110판에서 서비스에서 빠졌고, 그 자리는 번치 프로필 이미지다(5.1.3).
- 실시간 반영. 번치 탭 진입, 앱 복귀, 당겨서 새로고침 때만 다시 불러온다(5.1.1 로직 2).
- 알림 설정 화면(MY 범위). 푸시 발송은 서버가 한다.

## 대상 사용자와 접근 권한

번치 멤버만 그 번치의 메인을 본다. 역할별 권한은 아래와 같고, 서버가 요청 시점의 역할로 다시 판단한다.

| 동작                                         | 일반 멤버 | 공동 관리자 | 메인 관리자 |
| -------------------------------------------- | --------- | ----------- | ----------- |
| 메인 보기, 전환, 멤버 초대, 나가기           | 가능      | 가능        | 가능        |
| 번치 정보 바꾸기, 번치 삭제, 관리자 넘기기   | 불가      | 불가        | 가능        |
| 공동 관리자 지정·해제                        | 불가      | 불가        | 가능        |
| 멤버 내보내기(메인 관리자는 내보낼 수 없음)  | 불가      | 가능        | 가능        |
| 다른 멤버 사진 삭제·날짜 변경                | 불가      | 가능        | 가능        |
| 다른 번치 차단(기능명세 5.10.4·5.10.5)       | 가능      | 가능        | 가능        |
| 다른 번치 차단 해제(5.6.2, 서버가 다시 검증) | 불가      | 가능        | 가능        |
| 신고, 팔로우, 팔로우 요청 승인·거절          | 가능      | 가능        | 가능        |

번들 권한은 번들 최초생성자가 따로 있다(Figma 「역할별 권한보기」 `2500:54066`). 「일부」는 그 번들에 참여한 경우만이다.

| 번들 동작                                       | 메인 관리자 | 공동 관리자 | 번들 최초생성자 |
| ----------------------------------------------- | ----------- | ----------- | --------------- |
| 작성 중인 번들 업로드·삭제                      | 일부        | 일부        | 가능            |
| 번들 멤버 내보내기(최초생성자는 내보낼 수 없음) | 일부        | 일부        | 가능            |
| 발행된 번들 수정·삭제                           | 가능        | 불가        | 불가            |

- 메인 관리자는 번치마다 1명이고 아무도 내보낼 수 없다. 메인 관리자가 나가려면 새 메인 관리자를 지정한다(5.8.2).
- 작성 중인 번들 삭제 권한은 4장 기준(초안 생성자, 참여 중인 관리자)을 따른다(5.3.2).

## 사용자 흐름과 route

모든 화면은 `apps/web`의 route이고 WebView에 표시된다. `/bunch` 외의 path는 **제안**이며 구현 전에 확정한다.

| 화면(명세 절)                | path(제안)                                                                            | 진입·이탈                                                           |
| ---------------------------- | ------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| 번치 메인 (5.1)              | `/bunch`                                                                              | 하단 탭. 뒤로가기 없음. 소속 번치가 없으면 번치 없음(5.1.7)         |
| 번치 전환 시트 (5.2)         | `/bunch` 위 바텀시트                                                                  | 헤더 번치 이름. 전환은 확인 없이 즉시                               |
| 작성 중인 번들 탭 (5.3.1)    | `/bunch` 안의 탭                                                                      | 메인 번들 탭 영역. 카드 → 공동 편집(`/bunch/drafts/[draftId]`)      |
| 더보기 메뉴 (5.4)            | `/bunch/menu`(확정)                                                                   | 헤더 「⋯」. 역할별 메뉴                                             |
| 프로필 편집 (5.5)            | `/bunch/menu/profile`(확정)                                                           | 메인 관리자만                                                       |
| 멤버 관리·역할 안내 (5.6)    | `/bunch/members`, `.../roles`(확정)                                                   | 더보기 「멤버 관리」, 프로필 「멤버」                               |
| 차단 목록 (5.7)              | `/bunch/menu/blocked`(확정)                                                           | 더보기 「차단 목록」                                                |
| 나가기·관리자 지정 (5.8)     | `/bunch/menu/leave`(확정)                                                             | 더보기 「번치 나가기」. 메인 관리자는 지정 화면                     |
| 번치 삭제 안내·확인 (5.9)    | `/bunch/menu/delete`·`/bunch/menu/delete/confirm`(확정)                               | 메인 관리자만. 안내 → 문구 입력 확인                                |
| 다른 번치 프로필·멤버 (5.10) | `/bunches/[bunchId]`·`.../members`(확정)                                              | 피드 번치 이름, 팔로워·팔로잉 목록                                  |
| 팔로워·팔로잉·요청 (5.11)    | 내 번치 `/bunch/follows`·`.../requests`, 다른 번치 `/bunches/[bunchId]/follows`(확정) | 프로필 「팔로워」·「팔로잉」(`?tab=following`). 누른 쪽 탭으로 열림 |
| 알림 목록 (5.12)             | `/bunch/notifications`(확정)                                                          | 번치 메인·피드 헤더 알림. 행 → 종류별 화면                          |

- 현재 번치는 앱 공통 상태다. 전환하면 사진함, 번들 만들기, 알림, 팔로우·신고 명의가 모두 새 번치 기준이 된다(5.2.2 로직 2).
- 전환한 번치를 마지막 사용 번치로 저장하고 앱을 다시 열면 그 번치로 들어온다(5.2.2 로직 1).
- 진행 중인 사진 업로드는 시작한 번치에 저장한다(5.2.2 로직 3).

## 요구사항

### 필수 (Must Have)

번치 메인 (5.1)

- [x] 헤더: 번치 이름·화살표(누르면 전환 시트), 알림, 더보기. 헤더에는 프로필 이미지를 두지 않는다. 이름이 길면 말줄임(5.1.2). (#162)
- [ ] 알림 아이콘: 지금 번치에 안 읽은 알림이 있으면 빨간 점(5.1.2).
- [x] 번치 프로필 이미지: 헤더 아래 배경 띠 오른쪽에 원형으로 크게 둔다(5.1.3). 사진이 없으면 서버는 빈 값을 주고 앱이 분위기(2.2.9)의 기본 이미지를 고른다. 발행 번들 수에 따라 바뀌지 않는다. #300에서 구현했다.
- [ ] 같은 이미지를 전환 목록(5.2.1), 피드·번들 상세의 번치 정보(6.1.3, 6.2.2), 다른 번치 프로필(5.10.1)에 쓴다(5.1.3 로직 2).
- [x] 프로필: 이름, 비공개면 자물쇠, 한 줄 소개, 팔로워·팔로잉·멤버 수, 같은 줄 오른쪽 「콕한 장소」 버튼(5.1.4). (#162)
- [x] 「콕한 장소」 → 우리 번치의 콕 화면(5.1.4 상세 6, 콕 8.1, `docs/specs/pinned-places.md`). (#257)
- [x] 소개의 줄바꿈 유지(5.1.4). (#162)
- [ ] 팔로워·팔로잉·멤버를 누르면 각 목록으로 이동(5.1.4). 팔로워·팔로잉은 연결(#192). 멤버는 1110판에서 「멤버 리스트 화면」으로 간다고 바뀌었고, 멤버 관리(5.6.1)와 같은 화면인지 확인한 뒤 연결한다(아래 확인 필요).
- [x] 번들 탭 영역: 아이콘 탭 두 개(사진 「번들」, 연필 「작성 중인 번들」), 들어오면 「번들」 탭, 발행 번들 3열 그리드, 「멤버 공개」 칸의 멤버 아이콘(5.1.5). 1110판이 Figma와 같은 구조로 바뀌었다. (#162)
- [x] 「번들」 탭 빈 상태 「추억은 많은데, 번들은 아직!」 + 「첫 번들 만들기」 → 참여 멤버 고르기(4.1.1)(5.1.5). (#162)
- [ ] 발행된 번들을 누르면 번들 상세(6.2.1), 아래로 스크롤하면 이어서 불러오기(5.1.5). 삭제된 번들이면 「삭제된 번들이에요.」 토스트 후 새로고침.
- [x] 오른쪽 아래 「+」(번들 만들기 → 참여 멤버 고르기 4.1.1) 고정(5.1.6). 멤버가 1명이면 「함께할 멤버가 없어요」 모달. (#162)
- [x] 번치 없음(5.1.7): 「참여 중인 번치가 없어요」, 「새 번치 만들기」·「초대 링크로 참여하기」(1110판 문구, 구현은 아직 「초대 링크 참여하기」). 헤더·「+」 없음. 나간 번치 기준(fixture), 서버 목록 기준은 API 연결 때. (#180)

번치 전환 (5.2)

- [x] 시트: 「번치 전환하기」, 닫기, 지금 번치는 맨 위에 흐리게(누를 수 없음), 「알림 N개」, 「접근 불가」(5.2.1). (#162)
- [x] 다른 번치를 누르면 확인 없이 전환, 「{번치 이름} 번치로 전환했어요.」(5.2.2). (#162)
- [x] 접근 불가 번치를 누르면 삭제·내보내짐 안내, 「번치 목록에서 삭제」로 목록에서 제거(5.2.3). (#162)
- [ ] 보고 있던 번치가 삭제·내보내짐: 같은 안내 후 최근 번치 또는 번치 없음으로 이동(5.2.3 상세 동작 4).
- [x] 「새로운 번치 추가하기」 → 번치 시작 선택(5.2.4). 소속 번치 10개면 「참여할 수 있는 번치는 최대 10개예요.」. (#162, 10개 토스트는 #313)
- [x] 전환 목록·마지막 사용 번치 저장·접근 불가 안내 삭제를 서버에 연결(`members/me/bunches`, `last-used`, `bunch-access-notices`). (#313)

작성 중인 번들 (5.3)

- [x] 탭과 삭제 확인(5.3.1, 5.3.2). 번치 메인 안의 「작성 중인 번들」 탭과 가운데 확인 모달로 구현했다. 1110판도 별도 화면 없이 탭·모달이다. 빈 상태 「아직 작성 중인 번들이 없어요」 / 「함께한 순간을 하나의 기록으로 남겨보세요.」. (#162)
- [ ] 삭제 확인 내용 「삭제한 번들은 다시 복구할 수 없지만, 사용된 사진은 사진함에 그대로 남아요.」(5.3.2). 구현 문구와 같다. 삭제 실패는 「일시적인 오류가 발생했어요. 다시 시도해 주세요」 토스트 후 모달 유지.
- [ ] 휴지통은 삭제 권한이 있는 사람에게만, 삭제 후 「작성 중인 번들을 삭제했어요.」(5.3.2).

번치 관리 (5.4~5.9)

- [x] 더보기 메뉴: 역할별 메뉴(5.4.1). 메뉴 화면과 일반 멤버·공동 관리자의 나가기 확인 창. 각 관리 화면 연결은 해당 이슈. (#169)
- [x] 프로필 편집: 이미지·이름(1자 이상 12자 이하, 중복 확인)·소개(1자 이상 50자 이하)·공개 범위, 「저장하기」 한 번에 저장(5.5). 화면·검증·토스트(#172). 서버 저장(`PUT /bunches/{id}/profile`, 대표 사진 포함)과 이름 중복 확인을 연결(#327).
- [x] 멤버 관리: 「멤버 N/8명」, 역할 배지, 역할별 관리 모달(지정·해제·넘기기·내보내기)(5.6). 화면·확인 창·토스트와 권한 안내(fixture). 서버 처리는 API 연결 때. (#175)
- [x] 차단 목록과 차단 해제(5.7). 목록·확인 창·토스트·빈 상태(fixture), 일반 멤버는 목록만. 서버 처리는 API 연결 때. (#178)
- [x] 나가기: 일반 멤버·공동 관리자는 확인만, 메인 관리자는 새 관리자 지정 후 나가기, 혼자면 삭제 안내(5.8). 나간 뒤 남은 번치로 이동·토스트, 없으면 번치 없음(fixture). 서버 처리와 지정 대상 유효성 검사는 API 연결 때. (#180)

다른 번치·관계·알림 (5.10~5.12)

## 상태

- 번치 메인: 로딩, 오류(토스트 「일시적인 오류가 발생했어요. 다시 시도해 주세요」), 번치 없음, 번들 없음, 목록.
- 전환 시트: 목록 로딩 실패 시 토스트 후 시트를 닫는다. 전환 실패 시 지금 번치에 그대로 있는다.
- 접근 불가: 「번치 목록에서 삭제」 실패 시 토스트, 행은 그대로 둔다.
- 버튼 연타는 첫 탭만 처리한다(전환, 저장, 팔로우).

## 확인할 항목

### 기획·디자인

- 번들 영역 구조: 1110판(5.1.5·5.3)이 아이콘 탭 두 개, 3열 그리드, 탭 안 작성 중 목록, 삭제 확인 모달로 바뀌어 Figma와 같아졌다(이전 판은 「우리의 번들 N」·2열·별도 목록 화면·시트).
- 작성 중 카드 모양: 1110판은 왼쪽 대표 사진, 오른쪽 제목, 제목 아래 참여 멤버 프로필 최대 3개 + 「외 N명」이다. 구현 `BundleCard`는 Figma 기준이라 그대로 두고, 디자인과 다른지 확인한다.
- 번치 프로필 이미지(5.1.3): 1110판은 배경 띠 오른쪽에 원형 프로필 이미지를 두고, 아래쪽이 프로필 영역과 겹친다. #300에서 최신 Figma대로 바꿨다. 이미지 로딩 실패 때 기본 이미지로 바꾸는 처리는 아직 없다.
- 배경 띠 색은 분위기(2.2.9) 색을 연하게 칠한다(색은 디자인 기준). 지금의 `characterType`별 색과 같은 값인지 확인한다.
- 접근 불가 번치: 화면설계서 7번은 「Disabled, Interaction 미적용」, 명세 5.2.3은 누르면 안내다. 지금은 명세를 따른다.
- 접근 불가 안내를 바깥 누름으로 닫는 동작(5.2.3)과 디자인 시스템 확인 창(바깥 누름 막음)의 차이.
- 「콕한 장소」 버튼(이전 이름 「가볼 곳」)은 1110판 5.1.4에 들어왔다(깃발 아이콘 + 「콕한 장소」, 상세 동작은 콕 8.1).
- 역할별 권한 표: #175에서 Figma 「역할별 권한보기」(`2500:54066`) 기준으로 위 표를 맞췄다. 서버 권한 규칙은 백엔드와 확인한다.
- 알림 목록은 「알림」 프레임(`1892:36947`, 설정 안내 줄·알림 카드·「모두 읽음」)으로 구현했다(#186). 헤더 알림 아이콘의 안 읽은 점은 GUI 프레임에 없어 「번치 메인 API 연결, 알림 점」 단위에서 정한다.
- 1110판: 알림 목록 입구에 피드 헤더(6.1.2)가 더해졌고, 뒤로가기는 들어온 화면(번치 메인 또는 피드)으로 간다(5.12.1).
- 1110판: 역할별 권한 안내(5.6.2)는 역할 변경 알림(11~13번)으로도 들어오고, 뒤로가기는 들어온 경로(멤버 관리, 알림 목록, 푸시 전 화면, 번치 메인)로 나뉜다. 구현은 아직 이전 기준(멤버 관리로만 돌아감).
- 1110판: 번치 메인의 멤버 수는 「멤버 리스트 화면」으로 간다(5.1.4 상세 5). 멤버 관리(5.6.1)와 다른 화면인지 기획에 확인한다.
- 나가기·삭제 뒤 화면(`3086:68145`, `3086:67903`)은 다른 번치 메인에 토스트를 띄운다. 남은 번치가 없을 때 번치 없음(`1892:36523`)으로 가는지 확인한다.
- route path: 더보기 메뉴 `/bunch/menu`는 #169, 멤버 관리 `/bunch/members`·`/bunch/members/roles`는 #175, 차단 목록 `/bunch/menu/blocked`는 #178, 나가기 `/bunch/menu/leave`는 #180, 번치 삭제 `/bunch/menu/delete`·`/bunch/menu/delete/confirm`은 #184, 알림 목록 `/bunch/notifications`는 #186, 다른 번치 프로필 `/bunches/[bunchId]`·`/bunches/[bunchId]/members`는 #189에서 확정했다. 나머지는 「사용자 흐름과 route」 표의 제안이고 해당 단위에서 확정한다.

### 백엔드

- 접근 불가 번치를 30일 뒤 자동으로 목록에서 빼는 시점과 응답 형태(5.2.3 로직 2).
- 마지막 사용 번치는 서버에 저장한다(`PUT /bunches/{id}/last-used`, #313). 저장 뒤 기본 번치(`members/me`)가 그 번치로 바뀌는지 확인한다.
- 1110판: 번치 응답의 뭉치 유형·단계 대신 분위기와 프로필 사진(없으면 빈 값)을 내려주는지(5.1.3 로직 1).
- 1110판: 같은 번치(현재 번치 명의)는 같은 대상을 첫 신고부터 24시간 동안 최대 2번 신고할 수 있다. 3번째는 접수하지 않고 「이미 신고가 접수되어 검토 중이에요.」(5.10.7). 같은 번치의 다른 멤버 신고도 함께 센다.
- 1110판: 이미 다른 멤버가 처리한 팔로우 요청을 누르면 먼저 처리된 결과를 유지하고 「이미 처리된 팔로우 요청이에요」 토스트 후 행을 뺀다(5.11.2). 요청이 취소·삭제됐으면 토스트 없이 뺀다.
- 1110판: 나가거나 내보내진 멤버의 기존 번들 코멘트는 작성자 「작성자」, 내용 「삭제된 코멘트입니다」로 보인다. 같은 계정이 다시 들어오면 참여 멤버·픽·코멘트를 복구하고, 사진함에서 지운 사진은 복구하지 않는다(5.6.5, 5.8.1). 다시 들어오면 일반 멤버다.
