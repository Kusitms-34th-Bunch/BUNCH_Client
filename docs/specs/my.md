# 기능: 마이페이지 (기능명세서 7장)

> Status: In Progress
> Date: 2026-11-08

기능명세서의 **7장 마이**를 구현 범위로 정리한 문서다. 7장은 여섯 부분으로 나뉜다.

- 7.1 마이페이지: 화면 구성, 프로필 영역
- 7.2 개인 프로필 수정: 사진 변경·권한·편집, 닉네임, 출생연도·성별, 저장
- 7.3 알림 설정: 앱 푸시 전체, 받을 알림 5종, 기기 알림 권한 꺼짐
- 7.4 서비스 이용약관·개인정보처리방침과 불러오기 실패
- 7.5 문의하기·로그아웃
- 7.6 탈퇴하기: 안내, 확인 체크, 관리자 권한 넘기기, 최종 확인

기능 ID(USER·NOTI·AUTH)와 명세서 절 번호(7.2.5 등)로 원본과 대조한다. 화면 UI는 이미 `apps/web/src/features/my`에 있고, 화면별 세부 계약은 아래 co-located spec이 맡는다. 이 문서는 7장 전체 범위와 **지금 구현과 명세가 다른 점**을 모은다.

| 화면                  | co-located spec                                                                        |
| --------------------- | -------------------------------------------------------------------------------------- |
| 마이페이지            | `apps/web/src/features/my/components/home/MyScreen.spec.md`                            |
| 개인 프로필 수정      | `apps/web/src/features/my/components/profile/ProfileEditScreen.spec.md`                |
| 알림 설정             | `apps/web/src/features/my/components/notifications/NotificationSettingsScreen.spec.md` |
| 탈퇴 안내             | `apps/web/src/features/my/components/withdrawal/WithdrawalScreen.spec.md`              |
| 관리자 권한 넘기기    | `apps/web/src/features/my/components/withdrawal/AdminTransferScreen.spec.md`           |
| 프로필 사진 선택·편집 | `apps/web/src/shared/components/profile/ProfilePhotoField.spec.md`                     |

## 목적

- 번치와 상관없는 내 계정 설정(프로필, 알림, 약관, 문의, 로그아웃, 탈퇴)을 한곳에서 다룬다.
- 탈퇴할 때 지워지는 것과 남는 것을 알리고, 관리자로 있는 번치는 권한을 넘긴 뒤에만 탈퇴하게 한다.

## 문제 정의

- 화면은 만들었지만 내 정보·프로필 수정·알림 설정·탈퇴 API가 연결되지 않아 fixture 값을 보여 주고 저장하지 않는다.
- 명세 개정으로 화면 spec에 남겨 둔 확인 항목 일부(권한 넘긴 뒤 체크 유지, 나 혼자 있는 번치, 이전 대상 범위)에 답이 생겼다. 구현에 반영해야 한다.

## 범위 외 항목

- 가입 때의 프로필 설정·권한 요청(1장, `login-signup.md`). 입력 규칙은 그대로 다시 쓴다(7.2.1 로직 2).
- 번치 나가기·관리자 변경 자체(5장, `bunch-home.md`). 탈퇴는 같은 처리를 부른다(7.6.3 로직 1, 7.6.4 로직 2).
- 알림 목록과 알림 종류 정의(5.12). 이 문서는 종류별 푸시 설정만 둔다.
- 약관 원문 내용(확정되면 반영, 7.4.1 상세 5).

## 대상 사용자와 접근 권한

가입을 마친 사람이면 소속 번치가 없어도 모든 화면을 쓸 수 있다(7.1.1 로직 2). 현재 번치를 바꿔도 내용은 같다(7.1.1 로직 1).

- 출생연도·성별은 다른 사용자에게 보이지 않고 분석에만 쓴다(7.2.6 로직 2).
- 알림 설정은 계정 단위로 모든 번치·기기에 적용하고, 기기 알림 권한만 기기마다 따른다(7.3.1 로직 1·4).
- 관리자 권한 넘기기가 필요한 것은 다른 멤버가 있는 번치의 메인 관리자뿐이다. 공동 관리자 역할은 탈퇴하면 함께 사라진다(7.6.2 로직 2).

## 요구사항

### 필수 (Must Have)

체크는 화면 UI 기준이다. API 연결이 필요한 항목은 연결 전까지 체크하지 않는다.

마이페이지 (7.1, USER-03)

- [x] 헤더 「MY」, 프로필 행(이미지·닉네임·「>」, 행 전체가 프로필 수정 입구), 메뉴 3묶음(알림 / 약관 및 정책 / 고객지원).
- [ ] 들어올 때마다 내 프로필을 다시 불러온다. 실패하면 오류 토스트, 메뉴는 그대로 쓴다(7.1.1 로직 3, 예외).
- [x] 사진이 없으면 기본 프로필 이미지(7.1.2 로직).

개인 프로필 수정 (7.2, USER-03)

- [x] 지금 값으로 채우고 「프로필 수정하기」 비활성. 하나 이상 바뀌고 모두 규칙에 맞을 때만 활성, 원래대로 돌리면 다시 비활성(7.2.7 상세 1·2).
- [x] 바꾼 내용이 있는데 뒤로가기 → 「저장하지 않고 나갈까요?」 / 「변경한 내용이 반영되지 않아요.」 / 나가기·취소 모달(7.2.1 상세 7).
- [x] 사진 선택지: 등록한 사진이 있으면 「앨범에서 사진 선택하기」·「기본 이미지 적용하기」·「취소」, 기본 이미지면 「기본 이미지 적용하기」 없음(7.2.2 상세 1).
- [ ] 사진 접근 권한: 처음이면 OS 요청 창, 거부 상태면 「사진 접근 권한이 필요해요」 / 취소·설정으로 이동 모달(7.2.3). 기기 bridge 필요.
- [x] 원형 자르기 편집, 1:1 저장(7.2.4).
- [ ] 큰 사진 처리 중 로딩 「사진을 불러오는 중」(7.2.4 상세 7).
- [ ] 닉네임 중복 확인: 입력을 멈추고 0.5초 뒤 확인, 「이미 사용 중인 닉네임이에요」·「사용 가능한 닉네임이에요」. 지금 내 닉네임과 같으면 확인하지 않는다. 확인 실패면 오류 토스트와 버튼 비활성(7.2.5).
- [x] 출생연도·성별: 가입과 같은 규칙, 칩 다시 누르면 선택 해제, 비공개 안내 문구(7.2.6).
- [ ] 출생연도를 모두 지우면 「출생연도 없음」으로 저장(7.2.6 상세 1).
- [ ] 저장: 로딩 중 다시 누를 수 없음, 같은 요청 한 번만 저장(요청 키). 성공 → 마이페이지 + 「프로필을 수정했어요.」(체크 아이콘). 저장 직전 닉네임 중복 → 입력란 Error와 버튼 비활성. 실패 → 오류 토스트, 입력 유지(7.2.7).

알림 설정 (7.3, NOTI-03)

- [x] 「앱 푸시 알림」 전체 토글과 「받을 알림」 5종. 전체를 끄면 종류별 토글은 값 그대로 비활성, 다시 켜면 그 값으로 돌아온다(7.3.2).
- [x] 받을 알림 5개가 모두 꺼지면 「앱 푸시 알림」도 자동으로 끈다(7.3.3 상세 3).
- [ ] 누르면 바로 저장. 실패하면 토글을 되돌리고 오류 토스트, 연타는 마지막 상태만 저장(7.3.2·7.3.3 예외).
- [x] 기기 알림 권한이 꺼지면 배너 「알림 설정이 꺼져 있어요.」와 모든 토글 비활성(7.3.4 상세 1·2).
- [ ] 「설정으로 이동」과 앱 복귀 때 권한 다시 확인(7.3.4 상세 3·4). bridge 필요.
- [ ] 설정값 로딩 실패 → 오류 토스트 후 이전 화면(7.3.1 예외).

약관 (7.4, AUTH-04)

- [x] 뒤로가기만 있는 헤더와 가입 때와 같은 원문(7.4.1 로직 1).
- [ ] 맨 위 「시행일자: YYYY. MM. DD」·「버전 N」(7.4.1 상세 3).
- [ ] 원문을 서버에서 받아 앱 업데이트 없이 바꾼다. 실패하면 빨간 배너 「연결이 끊겼어요.」·「재시도」와 가운데 「약관을 불러오지 못했어요」 안내(7.4.1 로직 2, 7.4.3).

문의하기·로그아웃 (7.5, USER-08·USER-06)

- [x] 문의하기 확인 창 「'카카오톡'에서 열기」 / 「오픈채팅 상담 채널로 이동해요.」 / 취소·열기(7.5.1).
- [ ] 오픈채팅 링크를 서버 설정값으로 받는다. 열지 못하면 오류 토스트(7.5.1 로직 1, 예외).
- [x] 로그아웃 확인 창 「로그아웃할까요?」 / 취소·로그아웃, 성공하면 뒤로 돌아올 수 없게 이동(7.5.2 상세).
- [ ] 이 기기의 푸시 토큰 연결 해제(7.5.2 로직 1). 쉘 bridge 필요.

탈퇴하기 (7.6, USER-07)

- [x] 안내 화면(삭제되는 정보 5개, 남는 기록 1개), 확인 체크와 「다음」 활성(7.6.1·7.6.2).
- [x] 관리자 권한 넘기기를 마치고 돌아오면 체크 상태를 유지해 「다음」이 활성인 채로 보인다(7.6.1 로직 1).
- [ ] 「다음」마다 서버에 다른 멤버가 있는 번치 중 메인 관리자인 번치를 묻는다. 실패하면 오류 토스트, 안내 화면 유지(7.6.2 상세 3, 로직 1).
- [x] 관리자 번치가 있으면 「관리자로 있는 번치가 있어요」 안내 창, 없으면 최종 확인 창(7.6.2·7.6.3 상세 1).
- [x] 권한 넘기기: 번치별 접기·펼치기, 나를 뺀 멤버 중 한 명, 고른 번치는 연보라 상태, 모두 골라야 「다음」(7.6.3 상세 3·4).
- [x] 나 혼자 있는 번치는 목록에 넣지 않고 탈퇴할 때 함께 삭제한다(7.6.3 로직 4).
- [ ] 고른 멤버가 그사이 나감 → 오류 토스트 후 목록 다시 불러오기. 이전 실패 → 오류 토스트(7.6.3 예외).
- [ ] 최종 처리: 로딩 중 버튼 막기, 직전에 관리자 번치를 다시 확인해 남았으면 안내 창, 성공하면 Entry로(7.6.4 상세 3, 로직 1). 실패 → 오류 토스트와 안내 화면 유지.

### 있으면 좋은 것 (Nice to Have)

- 전체 OFF로 막힌 종류별 토글의 낭독용 안내 문구(`NotificationSettingsScreen.spec.md` 확인할 항목).

## 상태

- 로딩: 마이페이지 프로필, 프로필 수정 진입, 알림 설정값, 약관 원문, 닉네임 중복 확인, 저장·탈퇴·권한 이전 요청 중 버튼.
- 빈 상태: 프로필 사진 없음(기본 이미지), 출생연도·성별 없음.
- 오류: 기본 문구는 「일시적인 오류가 발생했어요. 다시 시도해 주세요」다.
  - 프로필 로딩(마이페이지는 메뉴 유지, 프로필 수정은 마이페이지로), 알림 설정 로딩(이전 화면으로), 중복 확인, 프로필 저장, 토글 저장(되돌림), 문의 링크 열기, 로그아웃, 관리자 확인, 권한 이전, 탈퇴 처리.
  - 사진: 「이 사진은 사용할 수 없어요」(형식·손상·처리 실패).
  - 닉네임: 「이미 사용 중인 닉네임이에요」, 출생연도: 「출생연도를 다시 확인해 주세요.」
  - 약관: 배너 「연결이 끊겼어요.」 + 「약관을 불러오지 못했어요」 / 「네트워크가 불안정해요. 잠시 후에 다시 시도해 주세요.」 재시도해도 실패하면 그대로 둔다.
- 성공: 「프로필을 수정했어요.」(체크 아이콘).

## API 계약

생성 타입(`packages/api-core/src/generated/openapi.ts`, 2026-11-08 기준)에는 `GET /api/v1/members/me`와 `GET /api/v1/members/nickname-availability`만 있다. 나머지가 나오면 `assess-api-contract`로 이 표를 endpoint로 바꾼다.

| 관리자 권한 이전    | 번치별 새 관리자(관리자 변경 5.6과 같은 처리)                                    | 7.6.3       | 없음       |
| 탈퇴                | 처리 직전 관리자 번치 재확인, 모든 기기 로그인·푸시 토큰 해제                    | 7.6.4       | 없음       |

- 캐시: 프로필을 저장하면 마이페이지가 바로 새 값을 보여야 하므로 내 프로필 query를 고친다. 다른 사람 화면은 다시 들어올 때 반영한다(7.2.7 로직 3).
- 알림 토글은 바로 저장하고 실패하면 되돌린다. 연타는 마지막 값만 보낸다.
