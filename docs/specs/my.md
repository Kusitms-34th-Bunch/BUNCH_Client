# 기능: 마이페이지 (기능명세서 7장)

> Status: In Progress
> Date: 2026-11-10
> 기준 판: 기능명세서 1110판(2026-11-10)

기능명세서의 **7장 마이**를 구현 범위로 정리한 문서다. 7장은 여섯 부분으로 나뉜다.

- 7.1 마이페이지: 화면 구성, 프로필 영역
- 7.2 개인 프로필 수정: 사진 변경·권한·편집, 닉네임, 저장
- 7.3 알림 설정: 앱 푸시 전체, 받을 알림 4종, 기기 알림 권한 꺼짐
- 7.4 서비스 이용약관·개인정보처리방침과 불러오기 실패
- 7.5 문의하기·로그아웃
- 7.6 탈퇴하기: 안내, 확인 체크, 관리자 권한 넘기기, 최종 확인

기능 ID(USER·NOTI·AUTH)와 명세서 절 번호(7.2.5 등)로 원본과 대조한다. 화면 UI는 이미 `apps/web/src/features/my`에 있고, 화면별 세부 계약은 아래 co-located spec이 맡는다. 이 문서는 7장 전체 범위와 **지금 구현과 명세가 다른 점**을 모은다.

| 화면                  | co-located spec                                                                        |
| --------------------- | -------------------------------------------------------------------------------------- |
| 마이페이지            | `apps/web/src/features/my/components/home/MyScreen.spec.md`                            |
| 개인 프로필 수정      | `apps/web/src/features/my/components/profile/ProfileEditScreen.spec.md`                |
| 알림 설정             | `apps/web/src/features/my/components/notifications/NotificationSettingsScreen.spec.md` |
| 탈퇴 안내             | `apps/web/src/features/my/components/withdrawal/WithdrawalScreen.spec.md`              |
| 관리자 권한 넘기기    | `apps/web/src/features/my/components/withdrawal/AdminTransferScreen.spec.md`           |
| 프로필 사진 선택·편집 | `apps/web/src/shared/components/profile/ProfilePhotoField.spec.md`                     |

## 목적

- 번치와 상관없는 내 계정 설정(프로필, 알림, 약관, 문의, 로그아웃, 탈퇴)을 한곳에서 다룬다.
- 탈퇴할 때 지워지는 것과 남는 것을 알리고, 관리자로 있는 번치는 권한을 넘긴 뒤에만 탈퇴하게 한다.

## 문제 정의

- 화면은 만들었지만 내 정보·프로필 수정·알림 설정·탈퇴 API가 연결되지 않아 fixture 값을 보여 주고 저장하지 않는다.
- 명세 개정으로 화면 spec에 남겨 둔 확인 항목 일부(권한 넘긴 뒤 체크 유지, 나 혼자 있는 번치, 이전 대상 범위)에 답이 생겼다. 구현에 반영해야 한다.
- 1110판에서 빠졌던 출생연도·성별 수정(7.2.6)이 다시 들어왔고, 약관 메뉴가 「약관 및 개인정보」 한 줄로 합쳐져 그 안에서 추가 개인정보 수집 동의를 켜고 끈다(7.4.4·7.4.5, #345). 받을 알림을 모두 꺼도 「앱 푸시 알림」을 끄지 않도록 바뀌었다(7.3.3 상세 3).

## 범위 외 항목

- 가입 때의 프로필 설정·권한 요청(1장, `login-signup.md`). 입력 규칙은 그대로 다시 쓴다(7.2.1 로직 2).
- 번치 나가기·관리자 변경 자체(5장, `bunch-home.md`). 탈퇴는 같은 처리를 부른다(7.6.3 로직 1, 7.6.4 로직 2).
- 알림 목록과 알림 종류 정의(5.12). 이 문서는 종류별 푸시 설정만 둔다.
- 약관 원문 내용(확정되면 반영, 7.4.1 상세 5).
- 추가 개인정보 동의 상태의 서버 연동. 동의 상태 조회·동의·철회 API가 없어 이 기기에만 저장하는 임시 값으로 UI를 만들었다(#345). 계약이 정해지면 연결한다.

## 대상 사용자와 접근 권한

가입을 마친 사람이면 소속 번치가 없어도 모든 화면을 쓸 수 있다(7.1.1 로직 2). 현재 번치를 바꿔도 내용은 같다(7.1.1 로직 1).

- 출생연도·성별은 추가 개인정보 수집·이용에 동의한 사람만 고칠 수 있다. 동의하지 않았으면 프로필 수정에서 비활성으로 보이고 값은 비어 있다(7.2.6).
- 알림 설정은 계정 단위로 모든 번치·기기에 적용하고, 기기 알림 권한만 기기마다 따른다(7.3.1 로직 1·4).
- 관리자 권한 넘기기가 필요한 것은 다른 멤버가 있는 번치의 메인 관리자뿐이다. 공동 관리자 역할은 탈퇴하면 함께 사라진다(7.6.2 로직 2).

## 요구사항

### 필수 (Must Have)

체크는 화면 UI 기준이다. API 연결이 필요한 항목은 연결 전까지 체크하지 않는다.

마이페이지 (7.1, USER-03)

- [x] 헤더 「MY」, 프로필 행(이미지·닉네임·「>」, 행 전체가 프로필 수정 입구), 메뉴 3묶음(알림 / 서비스 정보 / 고객지원). 「서비스 정보」는 「약관 및 개인정보」 한 줄이다(#345).
- [x] 들어올 때마다 내 프로필을 다시 불러온다. 실패하면 오류 토스트, 메뉴는 그대로 쓴다(7.1.1 로직 3, 예외). `MyRoute`·`useMyProfile`(#324)
- [x] 사진이 없으면 기본 프로필 이미지(7.1.2 로직).

개인 프로필 수정 (7.2, USER-03)

- [x] 지금 값으로 채우고 「프로필 수정하기」 비활성. 하나 이상 바뀌고 모두 규칙에 맞을 때만 활성, 원래대로 돌리면 다시 비활성(7.2.7 상세 1·2).
- [x] 바꾼 내용이 있는데 뒤로가기 → 「저장하지 않고 나갈까요?」 / 「변경한 내용이 반영되지 않아요.」 / 나가기·취소 모달(7.2.1 상세 7).
- [x] 사진 선택지: 등록한 사진이 있으면 「앨범에서 사진 선택하기」·「기본 이미지 적용하기」·「취소」, 기본 이미지면 「기본 이미지 적용하기」 없음(7.2.2 상세 1).
- [ ] 사진 접근 권한: 처음이면 OS 요청 창, 거부 상태면 「사진 접근 권한이 필요해요」 / 취소·설정으로 이동 모달(7.2.3). 기기 bridge 필요.
- [x] 원형 자르기 편집, 1:1 저장(7.2.4).
- [ ] 큰 사진 처리 중 로딩 「사진을 불러오는 중」(7.2.4 상세 7).
- [x] 닉네임 중복 확인(#324): 입력을 멈추고 0.5초 뒤 확인하고, 이미 쓰는 닉네임이면 「이미 사용 중인 닉네임이에요」. 지금 내 닉네임과 같으면 확인하지 않는다. 확인 실패면 오류 토스트와 버튼 비활성(7.2.5).
- [x] 사용할 수 있는 닉네임이면 문구를 보이지 않고, 확인 중일 때만 안내를 보인다(사용자 결정 2026-11-12, 가입 프로필 작성과 같음). 명세 7.2.5 상세 4·1.4.4의 「사용 가능한 닉네임이에요」는 두지 않는다.
- [x] 특수문자·이모지·줄바꿈이 섞인 텍스트를 붙여넣으면 허용하지 않는 문자만 빼고 넣는다(7.2.5 예외, #324). 입력 칸이 가입과 공용이라 가입 화면에도 적용된다.
- [ ] 한글 조합 중에는 글자 수로 끊지 않는다(7.2.5 예외). 입력 칸 `maxLength`의 브라우저 기본 동작에 기대고 있어 실기기에서 확인한다.
- [x] 출생연도·성별 칸(7.2.6, #345): 추가 개인정보에 동의하지 않았으면 칸과 비공개 안내를 숨기고(Figma는 비활성 표시, 사용자 요청으로 변경), 동의했으면 저장된 값을 채워 고칠 수 있다. 값 저장은 프로필 저장 API가 배포되면 연결한다.
- [x] 약관 및 개인정보 화면(7.4.4·7.4.5, #345): 서비스 이용약관·개인정보 처리방침 이동, 추가 개인정보 수집 동의 토글과 「전문보기」, 동의·철회 확인 창. 토글은 확인 창에서 확인해야 바뀐다. 동의 상태는 서버 API가 없어 이 기기(브라우저 저장소)에만 저장하는 임시 값이다.
- [ ] 저장: 로딩 중 다시 누를 수 없음, 같은 요청 한 번만 저장(요청 키). 성공 → 마이페이지 + 「프로필을 수정했어요.」(체크 아이콘). 저장 직전 닉네임 중복 → 입력란 Error와 버튼 비활성. 실패 → 오류 토스트, 입력 유지(7.2.7).

알림 설정 (7.3, NOTI-03)

- [x] 「앱 푸시 알림」 전체 토글과 「받을 알림」 4종. 전체를 끄면 종류별 토글은 값 그대로 비활성, 다시 켜면 그 값으로 돌아온다(7.3.2).
- [x] 받을 알림 4개를 모두 꺼도 「앱 푸시 알림」은 켜진 채로 둔다(7.3.3 상세 3, 1110판). 자동 OFF를 뺐다(#332).
- [x] 누르면 바로 저장. 실패하면 토글을 되돌리고 오류 토스트, 연타는 같은 scope로 순서대로 보내 마지막 상태가 남는다(7.3.2·7.3.3 예외, #332). 서버 알림 키 21개와 토글 4개의 대응은 `lib/notificationPreferences.ts`.
- [x] 기기 알림 권한이 꺼지면 배너 「알림 설정이 꺼져 있어요.」와 모든 토글 비활성(7.3.4 상세 1·2).
- [x] 「설정으로 이동」과 앱 복귀 때 권한 다시 확인(7.3.4 상세 3·4, #332). 쉘 bridge `getPermissionStatus`로 상태만 읽는다(권한 창 없음). 실기기 확인 전.
- 내보내짐(14번)·번치 삭제(15번)·번치 공개 범위 바뀜(16번) 푸시는 어느 토글에도 묶지 않는다. 앱 푸시 알림이 켜져 있으면 항상 보낸다(7.3.2 로직 4, 7.3.3 로직 1). 화면에는 줄이 없다.
- [x] 설정값 로딩 실패 → 이전 화면으로 돌아가 그 화면에서 오류 토스트(7.3.1 예외, #332).

약관 (7.4, AUTH-04)

- [x] 뒤로가기만 있는 헤더와 가입 때와 같은 원문(7.4.1 로직 1).
- [x] 맨 위 「시행일자: YYYY. MM. DD」·「버전 N」(7.4.1 상세 3). 앱이 가진 원문의 값을 보인다(서버 `GET /auth/terms`는 종류·버전 문자열만 주고 시행일자·원문이 없다).
- [ ] 원문을 서버에서 받아 앱 업데이트 없이 바꾼다. 실패하면 빨간 배너 「연결이 끊겼어요.」·「재시도」와 가운데 「약관을 불러오지 못했어요」 안내(7.4.1 로직 2, 7.4.3).

문의하기·로그아웃 (7.5, USER-08·USER-06)

- [x] 문의하기 확인 창 「'카카오톡'에서 열기」 / 「오픈채팅 상담 채널로 이동해요.」 / 취소·열기(7.5.1).
- [ ] 오픈채팅 링크를 서버 설정값으로 받는다(7.5.1 로직 1). 서버에 해당 API가 없어 `MY_CONTACT_URL` 상수를 쓴다.
- [x] 링크를 열지 못하면 오류 토스트(7.5.1 예외, #324). 브라우저 팝업 차단은 구분하지 못한다.
- [x] 로그아웃 확인 창 「로그아웃할까요?」 / 취소·로그아웃, 성공하면 뒤로 돌아올 수 없게 이동(7.5.2 상세).
- [ ] 다시 로그인하면 마지막으로 보던 번치로 들어간다(7.5.2 로직 4, 1.2.8). 번치 API 연결 뒤 한다.
- [x] 로그아웃 때 이 기기의 푸시 연결 해제(7.5.2 로직 1, #337). 세션을 지우기 전에 `DELETE /members/me/push-devices/{installationId}`로 해제하고, 해제가 실패하거나 3초가 지나도 로그아웃은 계속한다(3초를 넘기면 늦게 나가는 해제 요청이 세션 삭제와 겹쳐 실패해 서버에 연결이 남을 수 있어, 서버가 세션 폐기 때 기기 연결도 정리하는지 백엔드 확인이 필요하다). 실기기 확인 전.
- [x] 가입을 마친 로그인 상태의 쉘에서 이 기기의 푸시 토큰을 `PUT /members/me/push-devices/{installationId}`로 등록한다(#337). 앱을 열 때·앞으로 돌아올 때·회원이 바뀔 때(로그아웃 없이 세션이 끝난 뒤 다른 계정으로 로그인하는 경우 포함) 값이 바뀌었으면 다시 등록한다. 로그아웃이 실패하면 해제했던 기기를 다시 등록한다. iOS(APNs)만 한다. 실기기 확인 전.
- [ ] 푸시 알림이 실제로 오는지 확인은 미룬다. 알림을 보내는 서비스(서버 발송 기능)가 아직 구현되지 않아, 지금은 기기 등록·해제 요청이 성공하는지까지만 확인할 수 있다. 발송 서비스가 생기면 수신, 권한 거부 기기 제외, 로그아웃 후 미수신, 계정 전환 후 이전 계정 알림 미수신을 확인한다.

탈퇴하기 (7.6, USER-07)

- [x] 안내 화면(삭제되는 정보 5개, 남는 기록 1개), 확인 체크와 「다음」 활성(7.6.1·7.6.2).
- [x] 관리자 권한 넘기기를 마치고 돌아오면 체크 상태를 유지해 「다음」이 활성인 채로 보인다(7.6.1 로직 1).
- [ ] 「다음」마다 서버에 다른 멤버가 있는 번치 중 메인 관리자인 번치를 묻는다. 실패하면 오류 토스트, 안내 화면 유지(7.6.2 상세 3, 로직 1).
- [x] 관리자 번치가 있으면 「관리자로 있는 번치가 있어요」 안내 창, 없으면 최종 확인 창(7.6.2·7.6.3 상세 1).
- [x] 권한 넘기기: 번치별 접기·펼치기, 나를 뺀 멤버 중 한 명, 고른 번치는 연보라 상태, 모두 골라야 「다음」(7.6.3 상세 3·4).
- [x] 나 혼자 있는 번치는 목록에 넣지 않고 탈퇴할 때 함께 삭제한다(7.6.3 로직 4).
- [ ] 고른 멤버가 그사이 나감 → 오류 토스트 후 목록 다시 불러오기. 이전 실패 → 오류 토스트(7.6.3 예외).
- [ ] 최종 처리: 로딩 중 버튼 막기, 직전에 관리자 번치를 다시 확인해 남았으면 안내 창, 성공하면 Entry로(7.6.4 상세 3, 로직 1). 실패 → 오류 토스트와 안내 화면 유지.

## 상태

- 로딩: 마이페이지 프로필, 프로필 수정 진입, 알림 설정값, 약관 원문, 닉네임 중복 확인, 저장·탈퇴·권한 이전 요청 중 버튼.
- 빈 상태: 프로필 사진 없음(기본 이미지).
- 오류: 기본 문구는 「일시적인 오류가 발생했어요. 다시 시도해 주세요」다.
  - 프로필 로딩(마이페이지는 메뉴 유지, 프로필 수정은 마이페이지로), 알림 설정 로딩(이전 화면으로), 중복 확인, 프로필 저장, 토글 저장(되돌림), 문의 링크 열기, 로그아웃, 관리자 확인, 권한 이전, 탈퇴 처리.
  - 사진: 「이 사진은 사용할 수 없어요」(형식·손상·처리 실패).
  - 닉네임: 「이미 사용 중인 닉네임이에요」
  - 약관: 배너 「연결이 끊겼어요.」 + 「약관을 불러오지 못했어요」 / 「네트워크가 불안정해요. 잠시 후에 다시 시도해 주세요.」 재시도해도 실패하면 그대로 둔다.
- 성공: 「프로필을 수정했어요.」(체크 아이콘).

- 캐시: MY 화면(`useMyProfile`)은 들어올 때마다 내 프로필(key `['me']`)을 다시 불러온다(7.1.1 로직 3). 같은 key를 쓰는 번치 홈·번들 화면은 기본 staleTime을 유지하고, MY 진입 재조회로 갱신된 값을 함께 받는다. 프로필 수정 화면은 처음 받은 값을 고정해, 편집 중 재조회가 와도 바뀐 내용 판단이 흔들리지 않게 한다. 프로필을 저장하면 마이페이지가 바로 새 값을 보여야 하므로 내 프로필 query를 고친다. 다른 사람 화면은 다시 들어올 때 반영한다(7.2.7 로직 3).
- 알림 토글은 바로 저장(optimistic)하고 실패하면 되돌린다. 같은 `scope`로 순서대로 보내 연타해도 마지막 값이 서버에 남는다. 다른 요청이 남아 있으면 응답으로 캐시를 덮어쓰지 않는다.
- 탈퇴 처리(7.6.4 로직 2)는 서버가 맡는다. 혼자 있는 번치 삭제, 남이 만든 초안 속 내 코멘트 삭제를 한다. 업로드된 번들 속 코멘트는 「작성자」·「삭제된 코멘트입니다」로 보인다. 댓글·답글은 「작성자」·「삭제된 댓글입니다」로 보인다. 다른 멤버에게 알리지 않는다(로직 5).
