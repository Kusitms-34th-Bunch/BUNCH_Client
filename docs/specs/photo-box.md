# 기능: 사진함 (기능명세서 3장)

> Status: Draft
> Date: 2026-10-24

기능명세서의 **3장 사진함**(3.1 사진함 탭, 3.2 사진 올리기, 3.3 선택 모드, 3.4 날짜 바꾸기, 3.5 사진 상세, 3.6 멤버가 나간 뒤 사진 정리)을 구현 범위로 정리한 문서다. 기능 ID(PHOTO)와 명세서 절 번호(3.2.2 등)로 원본과 대조한다. 번들 만들기(4장)는 `docs/specs/bundle-create.md`가 맡고, 이 문서는 사진함에서 번들 만들기로 넘기는 경계(3.3.4)만 정한다.

이 spec은 web·mobile-shell·bridge·백엔드에 걸치고 구현 위치가 아직 확정되지 않아 `docs/specs/`에 둔다. 사진함 화면은 `apps/web`의 하단 탭 `/photos`(`(app)/(main)` route group)에 두고, feature는 `apps/web/src/features/photo-box/`(제안)로 정해지면 그 위치로 옮긴다.

## 목적

번치 멤버가 함께한 순간의 사진을 번들을 만들기 전에 먼저 한곳에 모으게 한다. 모인 사진은 날짜별로 보고, 멤버별로 거르고, 여러 장을 골라 저장·삭제·날짜 조정·번들 만들기로 이어 간다.

## 문제 정의

- 지금은 번치 사진을 함께 쌓아 둘 공간이 없다. 번들을 만들려면 각자 휴대폰에서 그날 사진을 다시 찾아야 한다.
- 추천 번들(4.2)은 사진함의 사진과 촬영 날짜·시각을 재료로 쓴다. 사진함과 촬영 날짜 처리가 먼저 있어야 추천이 동작한다.
- 위치 정보는 쓰지 않기로 확정했다(내부 기획 문서). 사진에 든 위치 메타데이터는 서버로 보내기 전에 앱에서 지워야 하므로, 업로드는 웹만으로 끝나지 않고 쉘(네이티브)의 처리가 필요하다.

## 범위 외 항목

- 번들 만들기·추천 번들·공동 편집(4장, `docs/specs/bundle-create.md`). 사진함에서 넘기는 경계(3.3.4)만 이 문서에 둔다.
- 번치 전환 목록, 번치 만들기·초대 참여 화면(2장·BUNCH 범위). 번치 없음 화면(3.1.6)은 그 화면으로 가는 버튼만 둔다.
- 실시간 반영. 다른 멤버의 업로드·삭제는 진입·앱 복귀·당겨서 새로고침 때만 반영한다(3.1.1).
- 휴지통·복구, NEW 배지, 업로드 진행 표시(명세에서 하지 않기로 함).
- 장소·지도 표시(위치를 저장하지 않음).
- 멤버가 나간 뒤의 사진 정리(3.6.1)는 서버 처리다. 웹은 삭제된 사진을 만났을 때의 처리만 맡는다.

## 대상 사용자와 접근 권한

번치 멤버만 그 번치의 사진함을 본다. 동작별 권한은 아래와 같고, 서버가 요청 시점의 역할로 다시 판단한다.

| 동작                    | 일반 멤버                   | 관리자(공동 관리자 포함)              |
| ----------------------- | --------------------------- | ------------------------------------- |
| 보기, 올리기, 앨범 저장 | 가능                        | 가능                                  |
| 날짜 바꾸기             | 내가 올린 사진만            | 모든 사진(다른 멤버 사진이면 확인 창) |
| 삭제                    | 내가 올린 사진만            | 모든 사진(다른 멤버 사진이면 확인 창) |
| 끌어서 날짜 옮기기      | 내가 올린 사진만 끌 수 있음 | 모든 사진(다른 멤버 사진이면 확인 창) |

- 함께 올린 사진(여러 멤버가 같은 사진을 올려 한 장으로 합쳐진 사진)은 올린 사람 모두가 "내가 올린 사진"으로 다룬다.
- 일반 멤버가 다른 멤버 사진을 섞어 고르면 날짜 바꾸기·삭제를 실행하지 않고 토스트로 알린다(3.3.5, 3.4.1).

## 사용자 흐름과 route

모든 화면은 `apps/web`의 route이고 WebView에 표시된다. 아래 path는 **제안**이며 구현 전에 확정한다.

| 화면(명세 절)            | path(제안)            | 진입·이탈                                                             |
| ------------------------ | --------------------- | --------------------------------------------------------------------- |
| 사진함 탭 (3.1)          | `/photos`             | 하단 탭. 뒤로가기 없음. 소속 번치가 없으면 번치 없음 화면(3.1.6)      |
| 사진 올리기 시트 (3.2.1) | `/photos` 위 바텀시트 | 「+」. 앨범 선택(3.2.2) 또는 카메라(3.2.3)로 이어짐                   |
| 선택 모드 (3.3)          | `/photos` 상태        | 헤더 「선택」. 하단 탭 막대 숨김. 번치 전환·다른 탭 이동 시 선택 해제 |
| 날짜 바꾸기 시트 (3.4.1) | 현재 화면 위 바텀시트 | 선택 모드 메뉴 또는 사진 상세 더보기                                  |
| 사진 상세 (3.5)          | `/photos/[photoId]`   | 사진 탭. 좌우로 이전·다음 사진. 뒤로가기 → 사진함                     |

- 현재 번치는 앱 공통 상태(번치 홈·전환과 공유)에서 받는다. 번치를 전환하면 멤버 필터를 「전체」로, 선택 모드를 해제한다(3.1.1).
- 다른 탭에 갔다 오면 선택 모드는 풀고 스크롤 위치는 유지한다(3.1.1).
- 업로드 대상 번치는 「+」를 누른 시점의 번치로 고정한다. 업로드 중 번치를 바꿔도 원래 번치에 저장한다(3.2.1).
- iOS 쉘에서는 하단 탭이 시스템 탭 바라(결정 기록 012) 선택 모드의 "하단 탭 막대 숨김"을 웹 막대처럼 처리할 수 없다. 처리 방식은 확인할 항목이다.

## 요구사항

### 필수 (Must Have)

사진함 탭 (3.1.1~3.1.5, PHOTO-04)

- [ ] 헤더(번치 대표 이미지·이름·전환 화살표, 「선택」)는 상단에 고정하고, 멤버 필터 칩과 사진 목록은 함께 스크롤한다. 오른쪽 아래 「+」는 고정한다.
- [ ] 멤버 필터 칩: 「전체」 + 현재 번치 멤버(프로필 이미지·닉네임), 하나만 선택, 가로 스크롤. 사진이 없는 멤버도 칩을 보인다. 나간 멤버의 칩은 없다. 함께 올린 사진은 올린 멤버 모두의 칩에서 보인다.
- [ ] 선택 모드에서는 칩마다 고른 사진 수를 붙인다(「전체 (N)」, 멤버 칩은 그 멤버가 올린 장수, 0장이면 숫자 없음). 고르거나 풀 때마다 바로 갱신하고, 함께 올린 사진은 올린 멤버 모두에게 센다.
- [ ] 사진은 촬영 날짜(사용자가 바꾼 날짜 우선) 섹션으로 나누고 최신 날짜가 위, 섹션 안은 최근 촬영이 앞, 같은 시각이면 업로드 순이다. 한 줄 3장 정사각형이다.
- [ ] 섹션 날짜는 올해면 「9월 28일 일요일」, 올해가 아니면 「2025년 9월 28일」(요일 없음) 형식이다.
- [ ] 무한 스크롤로 이어 불러온다. 한 번에 불러올 장수는 개발에서 정한다(첫 화면 예: 60장). 다음 페이지 실패 시 이미 보인 사진은 두고, 자동 재시도 뒤에도 실패하면 로딩을 숨겼다가 다시 스크롤하면 재시도한다.
- [ ] 촬영 날짜가 없는 사진은 날짜 섹션에 넣지 않고 「촬영 날짜를 확인할 사진 N장」 영역(기본 접힘, 펼치면 업로드 최신순 3열)에만 둔다. N은 선택한 멤버 기준이고 0장이면 영역을 숨긴다.
- [ ] 썸네일은 모두 같은 모양이다(NEW·날짜 배지 없음). 업로드 직후 처리 중이거나 이미지 로딩에 실패하면 회색 자리표시를 보인다.
- [ ] 빈 상태 문구: 사진 없음 「첫 번째 사진을 공유해 보세요」, 선택한 멤버의 사진 없음 「첫 사진을 기다리고 있어요!」.
- [ ] 이미 삭제된 사진을 누르면 「삭제된 사진이에요」 토스트 후 목록을 새로 불러온다.
- [ ] 이 탭의 토스트는 하단 3초이고, 액션 버튼(업로드 결과의 「다시 시도」, 끌기 뒤 「되돌리기」)이 붙으면 5초다. 등장·퇴장은 Figma 공통 모션(`0, 0, 0.35, 1`·350ms·5px 이동·투명도 0%↔100%)이며 구현은 `Toaster`(`docs/architecture/motion.md`의 "공통 모션")가 맡는다.

번치 없음 (3.1.6, PHOTO-04·BUNCH-06)

- [ ] 소속 번치가 0개면 헤더·필터·「+」 없이 안내(「참여 중인 번치가 없어요」)와 「새 번치 만들기」(2.2.2)·「초대 링크로 참여하기」(2.5.1) 버튼을 보인다. 하단 탭은 그대로다.

사진 올리기 (3.2, PHOTO-01·02·03·09)

- [ ] 「+」 → 시트(「{번치 이름}에 사진 올리기」, 「앨범에서 선택」·「카메라로 찍기」). 사진함이 1,000장이면 시트를 열지 않고 「사진함이 가득 찼어요.」.
- [ ] 앨범: 한 번에 최대 50장, 고르기를 마치면 확인 화면 없이 바로 업로드를 시작하고 사진함으로 돌아온다. 취소하면 아무것도 하지 않는다. iOS 「선택한 사진만 허용」이면 허용된 사진 안에서만 고른다.
- [ ] 카메라: 촬영한 1장을 바로 올리고, 촬영 시각을 촬영 날짜로 쓴다.
- [ ] 업로드 중에는 진행 표시와 중간 토스트를 두지 않고, 다 올라간 사진부터 목록에 넣는다.
- [ ] 끝나면 결과 토스트 하나: 전부 성공 「N장의 사진을 사진함에 추가했어요.」, 일부 「N장을 추가했어요. M장은 올리지 못했어요.」, 전부 실패 「사진을 올리지 못했어요.」. 실패 이유(형식·30MB 초과·한도·네트워크)는 M에 함께 센다.
- [ ] 네트워크 실패가 있을 때만 결과 토스트에 「다시 시도」(5초)를 붙이고, 누르면 네트워크로 실패한 사진만 다시 올린다. 다시 올려도 같은 업로드 묶음 ID를 유지한다.
- [ ] 허용 형식 JPEG·PNG·HEIC·WebP, 1장 30MB 이하, 1인 하루 500장, 번치당 1,000장. 한도를 넘는 사진은 한도까지만 올리고 나머지는 결과 토스트에 센다.
- [ ] 저장 이미지는 긴 변 2560px 한 장이다.
- [ ] **서버로 보내기 전에 앱에서** EXIF의 촬영 날짜·시간만 뽑고, GPS를 포함한 위치 메타데이터(EXIF·XMP 등)를 모두 지운다. 서버는 위치 없는 이미지와 촬영 날짜·시간만 받는다. 촬영 정보가 없어도 업로드는 성공이다.
- [ ] 한 번에 고른 사진에는 같은 업로드 묶음 ID를 붙인다(추천 번들 4.2.7에서 사용).
- [ ] 사진마다 따로 저장하고 같은 사진을 다시 시도해도 1장만 저장한다. 다른 멤버가 이미 올린 같은 사진은 한 장으로 합치고 올린 사람을 모두 기록한다. 내가 이미 올린 사진은 제외한다.
- [ ] 사진·카메라 권한이 거부돼 있으면 「권한 설정이 필요해요」 모달(「취소」/「설정 열기」)을 보인다.
- [ ] 업로드 중 번치를 나가면 남은 업로드를 멈춘다(이미 올라간 사진은 서버가 3.6.1로 정리).

선택 모드와 메뉴 (3.3.1~3.3.2, PHOTO-06)

- [ ] 「선택」 → 「취소」로 바뀌고 사진마다 빈 원, 누른 순서대로 번호(1, 2, 3…)와 어둡게 표시, 다시 누르면 해제되고 뒤 번호가 당겨진다. 「+」는 「⋯」로 바뀐다. 사진을 눌러도 상세로 가지 않는다.
- [ ] 최대 50장. 51번째는 선택되지 않고 「사진은 한 번에 50장까지 고를 수 있어요.」.
- [ ] 「⋯」 메뉴: 「저장」·「번들 만들기」·「날짜 바꾸기」, 구분선 아래 빨간 「삭제」. 0장이면 「⋯」 비활성. 역할과 관계없이 4개 모두 보인다.
- [ ] 실행 직전(모달·시트의 확정 버튼 포함) 고른 사진 중 지워진 사진이 있으면 실행하지 않는다. 지워진 사진을 선택에서 빼고 번호를 다시 매기고, 목록을 새로 불러온 뒤 「선택한 사진 중 N장이 사진함에서 사라져 선택이 해제됐어요.」. 선택 모드는 유지한다.

저장 (3.3.3, 3.5.2, PHOTO-05·06)

- [ ] 확인 없이 바로 휴대폰 앨범에 저장한다. 저장 중 사진마다 점 3개 로딩, 완료하면 선택 모드를 끝내고 「이미지 저장이 완료되었어요.」.
- [ ] 보관된 이미지(긴 변 2560px, 위치 없음)를 그대로 저장하고 함께 올린 사진은 1장으로 저장한다.
- [ ] 일부 실패: 저장된 사진은 선택에서 빼고 실패한 사진만 남기며 「N장은 저장하지 못했어요. 다시 시도해 주세요.」. 전부 실패: 「일시적인 오류가 발생했어요. 다시 시도해 주세요」, 선택 유지.
- [ ] 저장 중 다른 탭으로 가도 저장은 계속하고, 돌아와도 결과 토스트는 띄우지 않는다.

번들 만들기로 넘기기 (3.3.4, PHOTO-06·DRAFT-01)

- [ ] 1~20장이면 「이 사진들로 번들을 만들까요?」 모달(「아니요」/「예」), 「예」 → 초안 생성(4.1.3) 후 공동 편집 화면으로 이동. 21장 이상이면 모달 없이 「번들에는 사진을 20장까지 담을 수 있어요.」, 선택 유지. 고른 번호 순서가 번들 사진 순서다.

삭제 (3.3.5, PHOTO-07)

- [ ] 고른 사진에 따라 확인 창 문구를 고른다: 내가 올린 사진만, 관리자가 다른 멤버 사진만 또는 섞어 고름, 함께 올린 사진에서 내 이름만 빠짐, 혼자 올린 사진과 함께 올린 사진이 섞임, 작성 중인 번들에 쓰인 사진이 사라짐. 버튼은 「삭제하기」/「취소」.
- [ ] 「삭제하기」 → 사라지는 사진은 목록에서 바로 빠지고, 함께 올린 사진은 내 배지만 빠진다. 「사진함에서 사진 N장이 삭제되었어요.」(N은 실제로 사라진 장수, 0장이면 토스트 없음). 선택 모드를 끝낸다.
- [ ] 일반 멤버가 다른 멤버 사진을 섞어 고르면 삭제하지 않고 「내가 올린 사진만 삭제할 수 있어요.」.
- [ ] 휴지통 없이 영구 삭제한다. 발행된 번들의 사진은 남고, 작성 중인 번들에서는 그 사진과 캡션이 빠진다(서버 처리).

날짜 바꾸기 (3.4.1, PHOTO-04)

- [ ] 바텀시트(닫기 X, 「저장」), 월 달력(이전·다음 달 날짜 빈칸, 오늘 이후 흐리게·선택 불가, 오늘 표시 없음). 처음에는 항상 오늘이 속한 달을 아무 표시 없이 연다. 한 날짜만 고르고, 고르기 전에는 「저장」 비활성.
- [ ] 「저장」 → 날짜를 '사용자 지정'으로 저장(시각은 유지)하고 시트를 닫는다. 사진함에서는 선택 모드를 끝내고 바뀐 섹션으로 옮기며, 사진 상세에서는 헤더 날짜를 바꾼다. 토스트 「사진 날짜가 변경되었어요.」(되돌리기 없음).
- [ ] 여러 장은 전부 성공 또는 전부 실패. 실패하면 「일시적인 오류가 발생했어요. 다시 시도해 주세요」, 시트 유지.
- [ ] 관리자가 다른 멤버 사진이나 함께 올린 사진을 포함하면 저장 전에 확인 창을 띄운다. 일반 멤버가 다른 멤버 사진을 섞으면 「내가 올린 사진만 날짜를 바꿀 수 있어요.」.

끌어서 날짜 옮기기 (3.4.2, PHOTO-04)

- [ ] 선택 모드에서만, 권한 있는 사진을 길게 누르면 반투명해지고 끌 수 있다. 짧게 누르면 선택·해제다. 끄는 사진은 그 한 장이고 선택 여부와 무관하다.
- [ ] 다른 날짜 섹션의 사진 사이로 끌면 주변 사진이 비켜 자리를 보여 주고, 화면 위·아래 끝에서 자동 스크롤한다. 놓으면 그 섹션 날짜로 바꾸고 「사진 날짜가 변경되었어요.」 + 「되돌리기」(원래 날짜·자리로 복원).
- [ ] 이미 있는 섹션으로만 옮길 수 있다. 원래 섹션이나 섹션 밖에 놓으면 아무것도 바꾸지 않는다. 실패하면 원래 자리로 돌리고 오류 토스트.

사진 상세 (3.5, PHOTO-05·07)

- [ ] 헤더: 뒤로가기, 촬영 날짜(사진함과 같은 형식, 없으면 「날짜 미확인」), 더보기. 장소 줄 없음.
- [ ] 사진 오른쪽 위에 올린 멤버 프로필 배지(현재 프로필 사진), 함께 올린 사진이면 세로로 여러 개.
- [ ] 한 번 누르거나 확대하면 헤더·배지를 서서히 숨기고, 다시 누르면 보인다. 좌우로 사진함 순서상 이전·다음 사진, 처음·끝에서 멈춘다. 숨긴 상태는 넘겨도 유지한다.
- [ ] 더보기: 「저장」(모두), 「날짜 바꾸기」·「삭제」(올린 멤버·관리자만). 사진이 사라지게 삭제하면 사진함으로 돌아가 삭제 토스트, 내 배지만 빠지면 상세에 머문다.
- [ ] 보던 사진이 지워지면 다음 이동·새로고침 때 「삭제된 사진이에요」 후 사진함으로 돌아간다.

### 있으면 좋은 것 (Nice to Have)

- [ ] 끌어 옮긴 사진의 섹션 안 순서 저장(3.4.2 로직 4, 개발과 결정).
- [ ] 당겨서 새로고침 외에 앱 복귀 시 자동 갱신의 간격 제한.

## 상태

- 로딩: 첫 목록 로딩, 다음 페이지 로딩(목록 맨 아래), 썸네일 회색 자리표시(처리 중·로딩 실패), 저장 중 점 3개, 날짜 변경 저장 중.
- 빈 상태: 사진 없음, 선택한 멤버의 사진 없음, 날짜 미확인 사진 0장(영역 숨김), 소속 번치 0개(번치 없음 화면).
- 오류: 목록 로딩 실패, 다음 페이지 실패, 업로드 일부·전부 실패, 사진함 가득 참, 권한 거부, 저장 일부·전부 실패, 삭제 실패, 날짜 변경 실패, 끌기 실패, 삭제된 사진 접근, 선택 중 사진 사라짐. 오류 토스트 기본 문구는 「일시적인 오류가 발생했어요. 다시 시도해 주세요」이다.
- 성공: 업로드 결과 토스트, 저장 완료, 삭제 완료(N장), 날짜 변경(되돌리기는 끌기에만).
- 접근성: 선택 원과 번호는 스크린 리더에 선택 상태·순서로 읽혀야 하고(체크박스 의미), 끌어 옮기기는 같은 결과를 달력 시트로도 낼 수 있어 대체 경로가 있다. 필터 칩은 하나만 선택되는 그룹(radio 의미)이다.

## API 계약

백엔드 명세가 아직 없다. 아래는 화면이 필요로 하는 동작 목록이며 method·path·필드는 **확인할 항목**이다. 웹은 범용 BFF 프록시(`docs/architecture/api-boundary.md`)로 호출하므로 Route Handler를 따로 만들지 않는다.

| 동작                  | 입력                                                            | 출력                                                                         | 사용 절      |
| --------------------- | --------------------------------------------------------------- | ---------------------------------------------------------------------------- | ------------ |
| 사진 목록             | 번치, 멤버 필터, 커서                                           | 날짜 섹션별 사진(썸네일 URL·처리 상태·올린 멤버들·날짜·날짜 출처), 다음 커서 | 3.1.3, 3.1.4 |
| 날짜 미확인 사진 목록 | 번치, 멤버 필터                                                 | 사진 목록, 장수                                                              | 3.1.5        |
| 멤버 목록             | 번치                                                            | 멤버(프로필 이미지·닉네임·역할)                                              | 3.1.2        |
| 사진 업로드           | 번치, 이미지(위치 제거됨), 촬영 날짜·시간(선택), 업로드 묶음 ID | 사진 또는 합쳐진 사진, 실패 사유(형식·용량·한도)                             | 3.2.2, 3.2.3 |
| 사진함 사용량         | 번치                                                            | 장수(1,000장 판단), 내 오늘 업로드 장수                                      | 3.2.1        |
| 사진 상세             | 사진                                                            | 원본 URL, 날짜, 올린 멤버들, 내 권한(날짜 변경·삭제)                         | 3.5          |
| 날짜 바꾸기           | 사진들, 날짜                                                    | 전부 성공·전부 실패                                                          | 3.4.1, 3.4.2 |
| 삭제                  | 사진들                                                          | 사라진 사진 수, 내 배지만 빠진 사진 수                                       | 3.3.5        |
| 지워진 사진 확인      | 고른 사진들                                                     | 아직 있는 사진                                                               | 3.3.1, 3.3.3 |

- 인증과 인가: BFF 쿠키 세션. 권한(올린 멤버·관리자)은 서버가 요청마다 판단하고, 웹은 응답의 권한 값으로 메뉴 표시만 정한다.
- 업로드는 multipart다. 1장 30MB까지 BFF를 거치므로 배포처의 요청 본문 크기 제한을 함께 확인한다(`docs/architecture/api-boundary.md`). presigned URL 직접 업로드로 갈지도 확인할 항목이다.
- 실패 시 오류 코드와 정확한 문구: 서버 코드를 확인한 뒤 채운다. 화면 문구는 위 요구사항의 문구를 쓴다.
- Query key 후보(`docs/architecture/data-layer.md` 규칙): `photoKeys.list(bunchId, memberFilter)`(infinite), `photoKeys.undated(bunchId, memberFilter)`, `photoKeys.detail(photoId)`, `bunchKeys.members(bunchId)`. 업로드·삭제·날짜 변경 뒤에는 `photoKeys.all`을 invalidate한다.

## Bridge 계약(제안)

현재 bridge의 `pickGalleryImage`는 1장만 고르고 촬영을 제공하지 않는다. 아래가 필요하며 시그니처와 zod schema는 구현 단위에서 확정한다.

| 메서드(제안)        | 입력          | 출력                                                             | 쓰는 곳      |
| ------------------- | ------------- | ---------------------------------------------------------------- | ------------ |
| `pickGalleryImages` | 최대 장수(50) | 사진들(위치 제거된 이미지, 촬영 날짜·시간), 취소, 권한 거부 구분 | 3.2.2        |
| `capturePhoto`      | -             | 사진 1장(위치 제거, 촬영 시각), 취소, 권한 거부 구분             | 3.2.3        |
| `saveImagesToAlbum` | 이미지 URL들  | 사진별 성공·실패, 권한 거부                                      | 3.3.3, 3.5.2 |
| `openAppSettings`   | -             | -                                                                | 권한 모달    |

- 위치 제거와 촬영 날짜 추출은 쉘이 서버 전송 전에 한다. 웹이 받은 이미지에 위치가 남아 있으면 안 된다.
- 앨범 저장에는 iOS '사진 추가' 권한 문구(`app.json`)가 필요하다.

## 완료 기준

- 위 필수 요구사항이 모두 체크되고, 각 단위의 화면 상태(로딩·빈·오류·성공)를 테스트나 Storybook으로 확인한다.
- 업로드한 사진을 서버에서 받았을 때 위치 메타데이터가 없고 촬영 날짜·시간이 있다(실기기 확인).
- 일반 멤버·관리자 권한별로 날짜 바꾸기·삭제 결과가 명세와 같다.
- 선택 중 사진이 사라지는 경우의 처리(3.3.1)를 테스트로 확인한다.

## 확인할 항목

### 백엔드

1. 위 9개 동작의 method·path·필드·오류 코드와 페이지 크기.
2. 업로드 방식: BFF multipart(본문 크기 제한)인지 presigned URL 직접 업로드인지, 2560px 변환을 앱과 서버 중 어디서 하는지.
3. 같은 사진 판단 기준(해시 등)과 함께 올린 사진의 표현 방식.
4. 끌어 옮긴 사진의 섹션 안 순서 저장 여부(3.4.2 로직 4).
5. 사진 처리 상태(업로드 직후 처리 중)를 목록 응답이 주는지.

### 기술·환경

1. iOS 쉘에서 선택 모드 중 시스템 탭 바를 숨기는 방법(현재 bridge는 웹이 탭 화면 시작·종료만 알림).
2. HEIC 처리와 2560px 리사이즈를 네이티브에서 할지.
3. 끌어서 옮기기의 WebView 제스처 체감(`docs/architecture/web-interface-guidelines.md` "Drag와 제스처", 실기기 확인).
4. 저장 중 앱이 백그라운드로 갈 때 저장을 이어 가는 범위(3.3.3).
