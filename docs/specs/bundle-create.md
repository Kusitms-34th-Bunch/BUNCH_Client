# 기능: 번들 만들기 (기능명세서 4장)

> Status: Draft
> Date: 2026-10-24

기능명세서의 **4장 번들 만들기**(4.1 사진 고르기·초안 생성, 4.2 추천 번들, 4.3 공동 편집)를 구현 범위로 정리한 문서다. 기능 ID(DRAFT·GROUP·BUNDLE)와 명세서 절 번호(4.3.5 등)로 원본과 대조한다. 사진함(3장)은 `docs/specs/photo-box.md`가 맡는다. 번들은 번치 멤버들이 함께 만드는 그룹 게시물이고, 초안(작성 중인 번들)을 참여 멤버가 함께 다듬어 발행한다.

이 spec은 web·백엔드(추천 계산, 실시간 편집)에 걸치고 구현 위치가 정해지지 않아 `docs/specs/`에 둔다. feature는 `apps/web/src/features/bundle/`(제안)로 정해지면 그 위치로 옮긴다.

## 목적

- 사진함의 사진을 골라 번들 초안을 만든다. 직접 고르거나, 서버가 함께 찍은 사진을 묶어 추천한 번들을 적용해 한 번에 고른다.
- 참여 멤버가 제목·사진·캡션·위치·날짜·공개 범위를 함께 다듬고, 각자 코멘트를 남긴 뒤 발행한다.

## 문제 정의

- 지금은 번치 멤버가 함께 게시물을 만들 수단이 없다. 한 사람이 사진을 모아 올리는 방식이 아니라, 각자 사진·글을 보태 하나의 기록으로 만드는 것이 BUNCH의 핵심 동작이다.
- 같은 날 여러 멤버가 찍은 사진은 각자 폰에 흩어져 있다. 사진함에 모인 사진을 서버가 묶어 추천해야 번들을 빠르게 만들 수 있다(4.2).
- 여러 멤버가 같은 초안을 동시에 고치므로, 자동 저장·실시간 반영·편집 잠금이 없으면 내용이 서로 덮어써진다(4.3.13, 4.3.14).

## 범위 외 항목

- 작성 중인 번들 목록과 초안 삭제(4.4), 발행된 번들 상세·수정·피드 노출, 뭉치 단계 계산. 이 문서는 해당 화면으로 넘기는 경계만 정한다.
- 추천 번들 계산(4.2.7 사진 묶기, 4.2.8 10장 고르기, 4.2.9 갱신·사라짐)의 구현. 서버가 맡고, 웹은 결과(추천 번들 목록·사진·제목)만 보여준다. 규칙 요약은 아래 "추천 번들의 서버 규칙"에 둔다.
- 알림 발송(초안 참여, 코멘트 미작성 24·72시간, 발행). 알림 명세 범위다.
- AI로 사진 내용을 보고 제목을 짓는 방식(백엔드 검토 중, 확정 전).
- 글자 단위 동시 편집(문서 편집기 방식). 영역 잠금으로 대신한다(4.3.14 로직 4).

## 대상 사용자와 접근 권한

번들 만들기와 초안 보기는 번치 멤버만 할 수 있다. 서버가 요청 시점의 역할·참여 여부로 다시 판단하고, 웹은 응답의 권한 값으로 버튼 표시만 정한다.

| 동작                               | 참여 멤버(일반) | 초안 생성자       | 참여 중인 관리자  | 참여 멤버 아닌 번치 멤버(관리자 포함) |
| ---------------------------------- | --------------- | ----------------- | ----------------- | ------------------------------------- |
| 초안 보기                          | 가능            | 가능              | 가능              | 가능(보기 전용)                       |
| 제목·사진·캡션·위치·날짜·공개 범위 | 가능            | 가능              | 가능              | 불가                                  |
| 내 코멘트                          | 가능            | 가능              | 가능              | 불가                                  |
| 멤버 추가                          | 가능            | 가능              | 가능              | 불가                                  |
| 다른 멤버 빼기                     | 불가            | 가능              | 가능(생성자 제외) | 불가                                  |
| 스스로 빠지기                      | 가능            | 가능(초안 삭제됨) | 가능              | -                                     |
| 발행                               | 불가            | 가능              | 가능              | 불가                                  |

- 역할 배지는 하나만 보인다: 관리자(노란 왕관) > 공동 관리자(회색 왕관) > 초안 생성자(연필) > 없음. 서버는 역할과 초안 생성자 여부를 따로 주고 웹이 우선순위로 고른다(4.3.2 로직 8).
- 발행 후 공개 범위·위치·날짜는 관리자와 초안 생성자가 바꿀 수 있다(4.3.9~4.3.11).

## 사용자 흐름과 route

모든 화면은 `apps/web`의 route이고 WebView에 표시된다. 아래 path는 **제안**이며 구현 전에 확정한다. 번들 화면은 하단 탭 밖의 별도 화면이라 하단 탭 막대를 보이지 않는다(4.1.1).

| 화면(명세 절)                     | path(제안)                                      | 진입·이탈                                                               |
| --------------------------------- | ----------------------------------------------- | ----------------------------------------------------------------------- |
| 번들 만들기 (4.1)                 | `/bunch/bundles/new`                            | 번치 홈 「+」·「첫 번들 만들기」. 뒤로가기는 선택을 버림                |
| 추천 번들 시트 (4.2.1~4.2.4)      | 번들 만들기 위 바텀시트                         | 「추천 번들」. 「적용하기」로 선택 반영                                 |
| 추천 번들 상세·뷰어 (4.2.5~4.2.6) | `/bunch/bundles/new/recommendations/[id]`(제안) | 카드 「>」. 보기 전용, 뒤로가기 → 시트                                  |
| 공동 편집 (4.3.1)                 | `/bunch/drafts/[draftId]`                       | 초안 생성 직후, 작성 중인 번들 목록(4.4.1). 뒤로가기는 묻지 않음        |
| 참여 멤버 관리 (4.3.2)            | `/bunch/drafts/[draftId]/members`               | 참여 멤버의 「추가」 카드                                               |
| 캡션 화면 (4.3.5)                 | `/bunch/drafts/[draftId]/photos`                | 사진·캡션 영역                                                          |
| 크게 보기 (4.3.6)                 | `/bunch/drafts/[draftId]/photos/[photoId]`      | 캡션 화면에서 사진                                                      |
| 사진함에서 가져오기 (4.3.7)       | `/bunch/drafts/[draftId]/photos/add`            | 「+ 사진 추가」 시트. 「적용하기」 또는 뒤로가기(변경 있으면 확인 모달) |

- 사진함 선택 모드의 「번들 만들기」(3.3.4)는 번들 만들기 화면을 거치지 않고 바로 초안을 만들어 공동 편집으로 간다.
- 초안이 삭제되거나 발행된 뒤 들어오면 「삭제된 번들이에요」 등 안내 후 이전 화면으로 돌아간다(4.3.1, 4.4.2).

## 요구사항

### 필수 (Must Have)

번들 만들기 화면 (4.1.1, DRAFT-01·GROUP-02)

- [ ] 헤더(뒤로가기, 「번들 만들기」), 멤버 필터 칩(사진함 3.1.2와 같은 동작, 칩마다 고른 장수 표시), 「촬영 날짜를 확인할 사진 N장」 아코디언, 날짜 섹션별 3열 목록. 「선택」·「+」 없이 들어오자마자 고를 수 있다.
- [ ] 하단 고정 버튼: 「추천 번들」(테두리)·「번들 만들기」. 사진을 눌러도 사진 상세로 가지 않는다. 날짜 바꾸기·삭제·올리기는 이 화면에 없다.
- [ ] 이미 다른 번들에 쓰인 사진, 날짜 미확인 사진도 고를 수 있다. 칩을 바꿔도 고른 사진과 번호는 유지한다.
- [ ] 빈 상태: 사진함에 사진 없음 「아직 사진이 없어요.」·「사진함에 사진을 올리면 번들을 만들 수 있어요.」(「번들 만들기」 비활성), 선택한 멤버 사진 없음 「첫 사진을 기다리고 있어요!」.

사진 선택과 초안 생성 (4.1.2~4.1.3, DRAFT-01·GROUP-04)

- [ ] 누른 순서대로 번호, 다시 누르면 해제·당김. 1~20장, 21번째는 선택되지 않고 「번들에는 사진을 20장까지 담을 수 있어요.」. 고르는 동안은 서버에 저장하지 않는다.
- [ ] 「번들 만들기」는 0장이면 비활성, 누르면 로딩·중복 요청 차단, 성공하면 공동 편집으로 간다.
- [ ] 번치 멤버가 1명이면 만들지 않고 「번들은 멤버가 2명 이상일 때 만들 수 있어요. 멤버를 초대해 주세요.」. 작성 중인 초안이 10개면 「번들 초안은 최대 10개까지 만들 수 있어요. 기존 초안을 발행하거나 삭제해 주세요.」.
- [ ] 고른 사진 중 삭제된 사진이 있으면 만들지 않고, 선택에서 빼 번호를 다시 매긴 뒤 「선택한 사진 중 N장이 사진함에서 삭제되어 선택이 해제됐어요.」.
- [ ] 서버 규칙: 참여 멤버 = 만든 사람 + 고른 사진을 올린 멤버, 첫 사진이 대표 사진, 추천 번들을 적용했으면 기본 제목은 추천 제목이고 '추천으로 만든 번들'로 기록, 초안에 들어간 사진은 추천 계산에서 빠짐.

추천 번들 시트·카드 (4.2.1~4.2.2, GROUP-02)

- [ ] 시트 제목(2줄)과 카드 목록(개수 제한 없이 서버 순서대로 세로 스크롤), 하단 고정 「적용하기」(카드 선택 전 비활성). 아래로 끌거나 바깥을 누르면 닫히고 화면의 선택은 그대로다.
- [ ] 카드: 대표 사진(추천 사진 순서의 1번), 제목 + 「>」, 올린 멤버 닉네임 칩(넘치면 마지막을 「{닉네임} 외 N명」), 사진 수(6–10장)·날짜(자정을 넘긴 묶음은 「10월 19일~20일」, 올해가 아니면 연도 표시). 장소는 없다.
- [ ] 「>」를 뺀 영역을 누르면 하나만 선택(강조 테두리), 다시 누르면 해제. 「>」는 상세 화면으로 가고 선택은 바꾸지 않는다.
- [ ] 추천 번들이 없으면 제목·「적용하기」 없이 빈 상태(「아직 추천할 번들이 없어요」)를 보인다.

추천 번들 적용과 변경 확인 (4.2.3~4.2.4, GROUP-03)

- [ ] 「적용하기」 → 시트를 닫고 추천 사진 전부를 추천 순서대로 번호를 붙여 선택하고, 그 날짜 섹션(이틀이면 첫날)으로 스크롤한다. 「추천 번들 사진 N장이 선택되었어요.」. 적용만으로는 서버에 저장하지 않는다.
- [ ] 이미 1장 이상 선택돼 있으면 먼저 「추천 번들 사진으로 변경할까요?」 모달(뒤의 시트는 내려감). 「변경하기」는 기존 선택을 모두 풀고 추천 사진만 선택, 「취소」는 시트를 다시 올리고 카드 선택과 기존 선택을 유지한다.
- [ ] 적용 후에도 사진을 빼거나 더 고를 수 있다(합계 20장). 적용 사이 사진 일부가 지워졌으면 남은 사진만 선택하고 N도 남은 장수로 보인다.
- [ ] 여러 번 적용했으면 마지막에 적용한 추천 번들을 초안 생성 요청에 함께 보낸다.

추천 번들 상세·뷰어 (4.2.5~4.2.6, GROUP-02)

- [ ] 상세: 헤더(뒤로가기, 추천 제목), 추천에 담긴 사진(6~10장)을 날짜 섹션별 3열로 추천 순서대로 보인다(선택 원·번호 없음). 진입 시 서버에서 최신 사진을 다시 조회한다. 그 사이 추천이 사라졌으면 들어가지 않고 「추천 번들이 삭제됐어요. 다시 확인해 주세요.」 후 시트 목록을 새로고침한다.
- [ ] 뷰어: 헤더(뒤로가기, 촬영 날짜), 원본 비율, 올린 멤버 배지, 좌우로 추천 순서 이동(처음·끝에서 멈춤), 한 번 누르면 헤더·배지 숨김. 저장·날짜 변경·삭제는 없다.

공동 편집 화면 (4.3.1, DRAFT-02)

- [ ] 헤더(뒤로가기, 저장 상태, 「업로드」)와 연결 끊김 배너는 고정, 그 아래만 스크롤한다. 영역 순서: 참여 멤버, 번들 제목*, 사진과 캡션, 위치, 날짜, 코멘트*, 공개 범위*, 맨 아래 「나가기」(참여 멤버에게만).
- [ ] 참여 멤버가 아닌 사람은 보기만 하고, 편집하려 하면 「참여 멤버만 편집할 수 있어요」.

참여 멤버 (4.3.2, DRAFT-02·15)

- [ ] 가로 카드(프로필·역할 배지·닉네임). 다른 멤버 카드의 X는 초안 생성자와 참여 중 관리자에게만, 초안 생성자 카드에는 남에게 X가 없다. 맨 끝 「추가」 카드 → 참여 멤버 관리 화면.
- [ ] 관리 화면: 「멤버 추가하기」(참여하지 않은 번치 멤버, 「추가하기」 즉시 반영 + 「{닉네임}님이 번들 참여 멤버에 추가되었어요.」, 추가할 멤버가 없으면 영역 숨김), 「참여 멤버」(내 카드에 「(나)」, X).
- [ ] 다른 멤버 빼기는 「{닉네임}님을 번들에서 내보낼까요?」 확인 후 그 멤버의 코멘트만 지운다(사진·캡션·제목 등 공용 내용은 남김). 「{닉네임}님이 번들 참여 멤버에서 제외되었어요.」.
- [ ] 스스로 빠지기: 「번들에서 나가시겠어요?」 → 내 코멘트 삭제, 번치 홈으로 이동, 이후 보기 전용. 초안 생성자는 「번들에서 나갈까요?」 → 초안 삭제, 번치 홈으로 이동, 「작성 중인 번들을 삭제했어요.」.
- [ ] 권한 없는 빼기를 서버가 거부하면 「다른 멤버는 초안을 만든 멤버나 참여 중인 관리자만 뺄 수 있어요」.

제목 (4.3.3, DRAFT-05)

- [ ] 입력란(placeholder 「번들 제목을 입력해주세요.」), 최대 40자, 줄바꿈 불가(붙여넣은 줄바꿈은 공백), 앞뒤 공백 제거 후 판단, 이모지 가능, 글자 수 표시 없음. 40자에 닿으면 「제목은 40자까지 쓸 수 있어요.」(빨간 글씨).
- [ ] 입력란에서 나가거나 입력이 1초 멈추면 자동 저장. 한 번에 한 명만 편집(잠금).

사진 보기·캡션·순서 (4.3.4~4.3.5, DRAFT-03·04·14)

- [ ] 공동 편집 화면: 가로로 넘기는 사진(가운데 크게, 옆 일부) + 가운데 사진 캡션(2줄, 넘치면 「…」, 없으면 「캡션 추가...」). 사진이나 캡션을 누르면 캡션 화면. 이 화면에서는 순서·추가를 바꾸지 않는다.
- [ ] 캡션 화면: 헤더(뒤로가기, 「사진」), 가로 사진 + 페이지 점, 캡션 입력란(줄바꿈 가능, 전체 표시, 최대 200자, 넘으면 「캡션은 200자까지 쓸 수 있어요」 토스트), 사진 오른쪽 위 X(참여 멤버만), 마지막 장 「+ 사진 추가」 카드(20장이면 없음).
- [ ] 사진 빼기: 2장 이상일 때만. 캡션 없으면 바로, 캡션 있으면 「캡션이 작성된 사진이에요」 확인, 1장이면 「사진을 삭제할 수 없어요」 모달. 사진함의 사진은 남는다.
- [ ] 순서 바꾸기: 길게 눌러(약 0.5초) 떠오르게 하고 좌우로 끌어 끼워 넣는다. 손을 뗄 때 한 번만 저장하고 캡션은 사진을 따라간다. 맨 앞 사진이 대표 사진이다. 「+ 사진 추가」 뒤로는 못 옮긴다. 키보드가 올라와 있거나 사진이 1장이면 떠오르지 않는다. 앱이 백그라운드로 가면 끌기를 취소한다.
- [ ] 잠금은 사진 한 장 단위다. 다른 멤버가 편집 중인 사진은 캡션·빼기·옮기기 모두 막고 「다른 멤버가 편집 중일 땐 수정할 수 없어요.」. 다른 사진의 순서는 누구나 동시에 바꿀 수 있고, 바뀐 순서는 실시간으로 반영된다(움직임 애니메이션 없이 결과만).
- [ ] 편집 중 그 사진이 초안에서 빠지면(사진함 원본 삭제, 올린 멤버가 나감) 「사진함에서 삭제된 사진이에요.」 후 공동 편집 화면으로 돌아간다.
- [ ] 공동 편집 밖에서 마지막 사진까지 사라지면 초안은 자동 삭제되고, 보던 멤버에게 「삭제된 번들이에요」 안내 후 이전 화면으로 돌려보낸다.

크게 보기 (4.3.6, DRAFT-03·04)

- [ ] 헤더(뒤로가기, 촬영 날짜, ⋯), 원본 비율, 올린 멤버 배지, 좌우로 번들 순서 이동, 누르거나 확대하면 헤더·배지 숨김. ⋯ 메뉴: 「저장」(앨범 저장, 사진함 3.5.2와 같음), 「삭제」(캡션 화면 X와 같은 빼기, 참여 멤버에게만).

사진 추가 (4.3.7, DRAFT-03)

- [ ] 「+ 사진 추가」 → 시트(「어디서 사진을 가져올까요?」, 「번치 사진함에서 가져오기」·「내 갤러리에서 가져오기」).
- [ ] 사진함에서 가져오기: 번들 만들기 화면과 같은 구성에 지금 번들 사진이 순서대로 선택된 채 열린다. 더 고르면 번호가 이어 붙고 풀면 당겨진다. 최대 20장. 다른 멤버가 편집 중인 사진은 풀 수 없다. 처음 상태와 같거나 0장이면 「적용하기」 비활성. 푼 사진이 있으면 「사진 N장이 번들에서 빠져요」 확인. 적용하면 「변경사항이 적용되었어요.」. 변경을 두고 뒤로가면 「저장하지 않고 나갈까요?」.
- [ ] 적용은 내가 바꾼 것(더한 사진, 푼 사진)만 서버에 보내고, 그 사이 다른 멤버가 바꾼 내용은 덮어쓰지 않는다. 합쳐서 20장을 넘으면 적용하지 않고 20장 초과 토스트.
- [ ] 갤러리에서 가져오기: 최대 「20 − 지금 장수」장, 사진함 업로드 규칙(사진함 3.2.2: 형식·용량·위치 제거·촬영 날짜·업로드 묶음·같은 사진 합치기·한도)으로 사진함에 올리면서 번들 맨 뒤에 붙인다. 올라가는 동안 칸에 로딩. 일부 실패는 3.2.2와 같은 결과 토스트(「다시 시도」 없음). 사진함이 가득 차면 선택창을 열지 않고 「사진함이 가득 찼어요.」.

코멘트 (4.3.8, DRAFT-06)

- [ ] 참여 멤버별 카드(내 카드가 맨 위, 「(나)」). 내 카드만 바로 입력, 최대 400자(줄바꿈·이모지 가능, 넘으면 「코멘트는 400자까지 쓸 수 있어요.」), 미작성 카드에는 「코멘트를 남기면 번들을 발행할 수 있어요.」. 공백·줄바꿈만은 미작성으로 본다.
- [ ] 코멘트는 잠그지 않고 쓰는 중 표시만 한다. 관리자도 남의 코멘트를 고치거나 지울 수 없다.

공개 범위 (4.3.9, DRAFT-07)

- [ ] 「멤버 공개」·「공개」 카드(라디오, 하나만). 기본값 없음, 한 번 고르면 해제 불가. 툴팁으로 공개 번치·비공개 번치에서의 「공개」 의미를 설명한다. 바꾸면 바로 저장.

위치 (4.3.10, DRAFT-17)

- [ ] 위치 줄(없으면 「위치 추가」 + 「>」, 있으면 이름 + X). 누르면 거의 전체 높이의 검색 시트(placeholder 「장소나 주소를 검색해 주세요」, 검색 전 안내, 결과는 이름 + 주소). 결과를 누르면 바로 저장하고 닫는다. 번들당 1개.
- [ ] 키워드 검색만 한다. 현재 위치·내 주변 검색은 없고 위치 권한도 받지 않는다. 저장 값은 이름·주소·외부 ID이고 좌표는 저장하지 않는다.
- [ ] 시트를 연 상태가 편집 중(잠금, 프로필만 표시). 검색 실패는 오류 토스트, 검색어 유지.

날짜 (4.3.11, DRAFT-18)

- [ ] 날짜 줄(없으면 「날짜 추가」 + 「>」 + 추천 날짜 칩 최대 3개, 있으면 날짜 + X). 칩을 누르면 바로 등록, 줄을 누르면 달력 시트(사진함 3.4.1과 같은 모양, 등록돼 있으면 그 날짜 선택 상태).
- [ ] 추천 날짜: 초안 사진의 날짜(사용자 지정 날짜 포함, 미확인 제외) 중 사진이 많은 날부터 최대 3개, 같으면 이른 날이 앞. 추천 번들로 만든 초안은 그 추천 날짜(이틀이면 첫날)를 맨 앞에 둔다. 날짜를 정하기 전에는 사진이 바뀌면 칩을 다시 계산한다.
- [ ] 번들 날짜를 정해도 사진함 사진의 날짜는 바뀌지 않는다. 달력 시트를 연 상태가 편집 중(잠금).

업로드(발행) (4.3.12, BUNDLE-01)

- [ ] 발행 조건(사진 1장 이상, 제목 1자 이상, 공개 범위 선택, 참여 멤버 2명 이상, 참여 멤버 모두 코멘트, 저장 안 된 변경 없음)을 모두 만족하고 권한이 있을 때만 「업로드」 활성. 위치·날짜·캡션은 조건이 아니다.
- [ ] 누르면 「번들을 업로드할까요?」 확인 후 발행한다. 같은 요청 키로 재시도해도 한 번만 발행된다.
- [ ] 권한 없는 참여 멤버가 누르면 「번치 관리자와 해당 번들 생성자만 업로드할 수 있어요.」, 참여 멤버가 아니면 「참여 멤버만 편집할 수 있어요」, 권한은 있는데 조건 미충족이면 「필수 항목을 모두 입력해야 업로드 할 수 있어요.」.
- [ ] 화면을 보는 사이 역할·참여 여부가 바뀌면 「업로드」 활성 여부를 바로 바꾼다.

편집 중 표시·잠금 (4.3.13, DRAFT-10)

- [ ] 다른 멤버가 편집 중인 영역 제목 옆에 그 멤버의 프로필, 글 영역(제목·캡션·코멘트)에는 「···」 애니메이션도 함께. 위치·날짜는 프로필만. 「사진」 옆에는 사진을 편집 중인 멤버를 모두 모아 보인다.
- [ ] 편집 시작 기준: 제목 입력란, 캡션 입력란(사진마다), 위치 검색 시트, 날짜 달력 시트. 끝나면(입력란에서 나감, 시트 닫음, 화면 나감) 바로 풀린다. 거의 동시에 시작하면 서버에 먼저 도착한 사람이 편집한다.
- [ ] 편집 중인 멤버의 연결이 끊기면 15초 뒤, 입력 없이 1분이 지나면 잠금을 푼다(1분의 경우 입력한 내용은 저장).

자동 저장·실시간 반영 (4.3.14, DRAFT-08·09·12)

- [ ] 저장 버튼 없이 자동 저장한다. 사진·순서·공개 범위·위치·날짜는 할 때마다, 제목·캡션·코멘트는 입력란에서 나갈 때와 입력이 1초 멈출 때 저장한다. 내 저장 요청은 한 초안 안에서 순서대로 하나씩 보낸다.
- [ ] 헤더 저장 상태: 「저장 중」(점 애니메이션) / 「저장 완료」(회색). 내 편집만 반영하고 글자 위치는 고정한다. 공동 편집 화면 헤더에만 둔다.
- [ ] 다른 멤버가 바꾼 참여 멤버·제목·사진·순서·캡션·코멘트는 새로고침 없이 반영한다. 실시간 반영은 공동 편집 화면에만 필요하다.
- [ ] 연결이 끊기면 헤더 아래 고정 빨간 배너(「인터넷 연결을 확인해 주세요.」 + 「재시도」), 저장 안 된 편집은 화면과 기기에 남겨 두고 계속 다시 보낸다. 배너가 있는 동안 「업로드」 비활성. 연결되면 내 편집을 먼저 보내고 최신 초안을 다시 불러와 맞춘 뒤 「저장 완료」.
- [ ] 인터넷 문제가 아닌 거부(참여 멤버에서 빠짐, 초안 삭제·발행)는 보기 전용 전환이나 삭제·발행 안내로 처리한다.

### 있으면 좋은 것 (Nice to Have)

- [ ] 저장 안 된 편집이 있는 채로 앱을 끄면 다음 실행에서 기기에 남은 내용을 보낸다(4.3.14 예외, 어려우면 1초 저장으로 대신).

## 추천 번들의 서버 규칙(요약)

웹이 직접 계산하지 않지만, 화면 결과를 검증할 때 기준이 되므로 요약한다. 숫자(4시간, 3장, 6장, 밤 10시~새벽 3시, 2시간)는 초기 기준이며 운영하며 조정한다.

- 재료: 촬영 날짜가 있는 사진함 사진(사용자 지정 날짜 우선). 날짜 미확인 사진, 초안·발행 번들에 쓰인 사진은 뺀다. 위치와 AI 분석은 쓰지 않는다.
- 묶기(4.2.7): 날짜별로 모으고, 촬영 시각 공백이 4시간 이상이거나 앞뒤에 겹치는 멤버가 없으면 나눈다(양쪽 3장 이상일 때만). 밤 10시 이후와 다음 날 새벽 3시 이전 사진이 2시간 이내면 잇는다. 시각 없는 사진은 같은 업로드 묶음 → 같은 멤버 → 사진 많은 묶음 순으로 붙인다.
- 조건: 연사 정리 후 6장 이상, 올린 멤버 2명 이상인 묶음만 추천한다.
- 10장 고르기(4.2.8): 연사 정리 후 10장 이하면 전부, 넘으면 멤버마다 1장 이상(적게 올린 멤버부터) + 나머지는 시간대가 고르게. 순서는 촬영 시각 순, 시각 없는 사진은 같은 날 뒤에 업로드 순.
- 제목: 상황(특별한 날, 첫 묶음, 전원 참여, 30일 이상 만에, 자정 넘김, 기본 요일·시간대)별 문장 묶음에서 15자 이내로 뽑는다. 같은 목록·최근 사용 문장은 피하고, 한 번 정한 제목은 바꾸지 않는다. 문장 묶음은 서버가 관리한다.
- 갱신(4.2.9): 사진 추가·삭제·날짜 변경, 초안 생성·삭제가 있으면 그 날짜와 앞뒤 날짜를 마지막 변경 5분 뒤 한 번 다시 계산한다. 반영까지 몇 분 걸릴 수 있다.
- 사라짐: 마지막 사진 추가 후 30일 동안 쓰지 않았거나 조건이 깨지거나 그 추천으로 초안을 만들면 목록에서 빠진다. 사라진 추천에 사진이 더해지면 같은 제목으로 다시 나타난다.
- 목록 순서: 최근 사진이 추가된 순 → 올린 멤버가 많은 순 → 사진이 많은 순. 번치 멤버 모두 같은 목록을 본다. NEW 표시·알림은 없다.

## 상태

- 로딩: 사진 목록, 추천 목록·상세, 초안 생성 중(버튼 로딩), 공동 편집 화면 로딩, 저장 중 표시, 갤러리 업로드 중 칸 로딩, 위치 검색 중, 발행 요청 중.
- 빈 상태: 사진함 사진 없음, 선택한 멤버 사진 없음, 날짜 미확인 0장, 추천 번들 없음, 추가할 번치 멤버 없음, 추천 날짜 없음(모두 날짜 미확인), 위치 검색 전.
- 오류: 목록·추천 로딩 실패, 초안 생성 실패(멤버 1명, 초안 10개, 사진 삭제됨, 서버 오류), 추천 삭제됨, 편집 잠금 충돌, 글자 수 초과, 사진 빼기 불가, 20장 초과, 갤러리 업로드 일부 실패, 위치 검색 실패, 날짜 저장 실패, 연결 끊김, 권한 거부(빼기·발행), 초안 삭제·발행됨. 오류 토스트 기본 문구는 「일시적인 오류가 발생했어요. 다시 시도해 주세요」이다.
- 성공: 초안 생성 후 이동, 추천 적용 토스트, 멤버 추가·제외 토스트, 사진 추가 적용 토스트, 저장 완료 표시, 발행.
- 접근성: 사진 선택 번호는 선택 상태·순서로 읽혀야 한다. 길게 눌러 순서 바꾸기는 키보드·스크린 리더용 대체(예: 앞·뒤로 옮기기 동작)가 필요하다. 편집 잠금·「···」 표시와 저장 상태, 연결 끊김 배너는 상태 변화로 읽혀야 한다(live region).

백엔드 명세가 아직 없다. 아래는 화면이 필요로 하는 동작 목록이며 method·path·필드는 **확인할 항목**이다. 일반 요청은 범용 BFF 프록시로 호출한다(`docs/architecture/api-boundary.md`).

- 인증과 인가: BFF 쿠키 세션. 권한은 서버가 요청 시점에 판단하고, 응답의 내 권한·역할 값으로 버튼을 정한다.
- 실시간 구독은 범용 프록시(요청·응답 1회 전달)로는 전달할 수 없다. SSE 스트리밍을 BFF로 넘길지, 짧은 수명의 전용 토큰을 BFF가 발급해 브라우저가 백엔드에 직접 연결할지(CORS 필요) 정해야 한다. 정해지면 결정 기록을 남긴다.
- 장소 검색은 외부 API(예: 카카오 로컬 키워드 검색) 키가 필요하므로 BFF Route Handler나 백엔드가 대신 호출한다. 브라우저에 키를 노출하지 않는다.
- 실패 시 오류 코드와 정확한 문구: 서버 코드를 확인한 뒤 채운다. 화면 문구는 위 요구사항의 문구를 쓴다.
- Query key 후보: `bundleKeys.recommendations(bunchId)`, `bundleKeys.recommendation(id)`, `bundleKeys.draft(draftId)`, `bundleKeys.placeSearch(keyword)`. 초안은 실시간 이벤트로 `setQueryData`를 갱신하고, 재연결 뒤에는 `draft(draftId)`를 다시 불러온다. 초안 생성 뒤에는 `photoKeys.all`(추천 계산 영향)과 작성 중인 번들 목록을 invalidate한다.

## 완료 기준

- 위 필수 요구사항이 모두 체크되고, 각 화면의 로딩·빈·오류·성공 상태를 테스트나 Storybook으로 확인한다.
- 두 기기(또는 두 브라우저)로 같은 초안을 열어 제목·캡션 잠금, 순서 동시 변경, 코멘트 실시간 반영, 연결 끊김 뒤 재전송이 명세와 같게 동작한다.
- 발행 조건과 권한별 「업로드」 활성 여부, 같은 요청 키 재시도의 1회 발행을 테스트로 확인한다.
- 추천 번들을 적용해 만든 초안의 기본 제목·대표 사진·추천 날짜 칩이 추천과 같다.

## 확인할 항목

### 백엔드

1. 위 12개 동작의 method·path·필드·오류 코드.
2. 실시간 전송 방식(SSE·WebSocket)과 인증, 이벤트 형태, 재연결 시 놓친 변경을 받는 방법.
3. 편집 잠금의 서버 표현(영역 키, 15초 연결 감지 방식, 1분 무입력 판단을 서버와 앱 중 어디서 하는지).
4. 사진 순서 동시 변경의 기준 위치 표현(앞뒤 사진 ID 등)과 충돌 응답.
5. 사진함에서 가져오기의 "차이만 반영" 요청 형태(4.3.7 예외).
6. 장소 검색 API 선택과 호출 주체, 호출 제한.
7. 추천 번들의 "사라짐" 이후 다시 나타날 때 ID가 유지되는지(카드 선택·상세 진입에 영향).

### 기술·환경

1. 길게 눌러 순서 바꾸기·자동 넘김의 WebView 제스처 체감과 진동(햅틱) 처리(`docs/architecture/web-interface-guidelines.md` "Drag와 제스처", 실기기 확인).
2. 앱이 백그라운드·종료될 때 저장 안 된 편집을 기기에 남기는 방법(저장소, 용량, 개인정보).
3. 공동 편집 화면에서 키보드가 올라올 때 고정 헤더·배너와 입력란 위치(iOS WebView).
4. 갤러리에서 가져오기의 업로드는 사진함 bridge(`docs/specs/photo-box.md`의 `pickGalleryImages`)를 그대로 쓴다.
