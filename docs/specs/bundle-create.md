# 기능: 번들 만들기 (기능명세서 4장)

> Status: Draft
> Date: 2026-10-24(2026-11-09 기능명세서 수정본 반영)
> 기준 문서: `BUNCH_기능명세서_사진함_번들만들기_1109.md`(기능명세서 엑셀 3.1.1~4.3.14 변환본). 명세서가 바뀌면 이 날짜와 파일명을 같이 갱신한다.

기능명세서의 **4장 번들 만들기**(4.1 참여 멤버·사진 고르기·초안 생성, 4.2 추천 번들, 4.3 공동 편집)를 구현 범위로 정리한 문서다. 기능 ID(DRAFT·GROUP·BUNDLE)와 명세서 절 번호(4.3.5 등)로 원본과 대조한다. 사진함(3장)은 `docs/specs/photo-box.md`가 맡는다. 번들은 번치 멤버들이 함께 만드는 그룹 게시물이고, 초안(작성 중인 번들)을 참여 멤버가 함께 다듬어 발행한다.

이 spec은 web·백엔드(추천 계산, 실시간 편집)에 걸치고 구현 위치가 정해지지 않아 `docs/specs/`에 둔다. feature는 `apps/web/src/features/bundle/`(제안)로 정해지면 그 위치로 옮긴다.

## 목적

- 함께 만들 멤버를 먼저 고르고, 사진함의 사진을 골라 번들 초안을 만든다. 사진은 직접 고르거나, 서버가 함께 찍은 사진을 묶어 추천한 번들을 적용해 한 번에 고른다.
- 참여 멤버가 제목·사진·위치·날짜를 함께 다듬고, 마음에 드는 사진을 픽하고, 각자 코멘트를 남긴 뒤 공개 범위를 골라 발행한다.

## 문제 정의

- 지금은 번치 멤버가 함께 게시물을 만들 수단이 없다. 한 사람이 사진을 모아 올리는 방식이 아니라, 각자 사진·글을 보태 하나의 기록으로 만드는 것이 BUNCH의 핵심 동작이다.
- 같은 날 여러 멤버가 찍은 사진은 각자 폰에 흩어져 있다. 사진함에 모인 사진을 서버가 묶어 추천해야 번들을 빠르게 만들 수 있다(4.2).
- 여러 멤버가 같은 초안을 잠금 없이 동시에 고친다. 자동 저장·실시간 반영·동시 편집 처리 기준이 없으면 내용이 서로 덮어써진다(4.3.13, 4.3.14).

## 범위 외 항목

- 작성 중인 번들 목록과 초안 삭제(5.3), 발행된 번들 상세·수정·피드 노출, 뭉치 단계 계산. 이 문서는 해당 화면으로 넘기는 경계만 정한다.
- 추천 번들 계산(4.2.7 사진 묶기, 4.2.8 10장 고르기, 4.2.9 갱신·사라짐)의 구현. 서버가 맡고, 웹은 결과(추천 번들 목록·사진·제목)만 보여준다. 규칙 요약은 아래 "추천 번들의 서버 규칙"에 둔다.
- 알림 발송(초안 참여, 코멘트 미작성 24·72시간, 추천 번들 생성, 발행). 알림 명세 범위다.
- AI로 사진 내용을 보고 제목을 짓는 방식(백엔드 검토 중, 확정 전).

## 대상 사용자와 접근 권한

번들 만들기와 초안 보기는 번치 멤버만 할 수 있다. 서버가 요청 시점의 역할·참여 여부로 다시 판단하고, 웹은 응답의 권한 값으로 버튼 표시만 정한다.

| 동작                        | 참여 멤버(일반) | 초안 생성자       | 참여 중인 관리자  | 참여 멤버 아닌 번치 멤버(관리자 포함) |
| --------------------------- | --------------- | ----------------- | ----------------- | ------------------------------------- |
| 초안 보기                   | 가능            | 가능              | 가능              | 가능(보기 전용)                       |
| 제목·사진·위치·날짜         | 가능            | 가능              | 가능              | 불가                                  |
| 사진 픽                     | 가능            | 가능              | 가능              | 불가(보기만)                          |
| 내 코멘트                   | 가능            | 가능              | 가능              | 불가                                  |
| 멤버 추가                   | 가능            | 가능              | 가능              | 불가                                  |
| 다른 멤버 빼기              | 불가            | 가능              | 가능(생성자 제외) | 불가                                  |
| 스스로 빠지기               | 가능            | 가능(초안 삭제됨) | 가능              | -                                     |
| 발행(공개 범위 고르기 포함) | 불가            | 가능              | 가능              | 불가                                  |

- 역할 배지는 하나만 보인다: 관리자(노란 왕관) > 공동 관리자(회색 왕관) > 초안 생성자(연필) > 없음. 서버는 역할과 초안 생성자 여부를 따로 주고 웹이 우선순위로 고른다(4.3.2 로직 8).
- 발행 후 공개 범위·위치·날짜는 메인 관리자만 바꿀 수 있다. 코멘트와 픽은 메인 관리자를 포함해 누구도 수정·삭제할 수 없다(4.3.5, 4.3.8~4.3.11). 이 spec의 범위는 발행 전 초안이라 발행 후 수정은 발행된 번들 상세 명세에서 다룬다.

## 사용자 흐름과 route

모든 화면은 `apps/web`의 route이고 WebView에 표시된다. 아래 path는 **제안**이며 구현 전에 확정한다. 번들 화면은 하단 탭 밖의 별도 화면이라 하단 탭 막대를 보이지 않는다(4.1.1).

| 화면(명세 절)                     | path                                                                      | 진입·이탈                                                                  |
| --------------------------------- | ------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 참여 멤버 고르기 (4.1.1)          | `/bunch/bundles/new/members`                                              | 번치 홈 「+」·「첫 번들 만들기」, 사진함 선택 모드 「번들 만들기」         |
| 사진 고르기 (4.1.2~4.1.4)         | `/bunch/bundles/new`                                                      | 참여 멤버 고르기 「다음」. 「이전」·뒤로가기는 고른 멤버·사진을 유지(제안) |
| 추천 번들 시트 (4.2.1~4.2.4)      | 사진 고르기 위 바텀시트                                                   | 헤더 「추천 번들 보기」. 「적용하기」로 선택 반영                          |
| 추천 번들 상세·뷰어 (4.2.5~4.2.6) | `/bunch/bundles/new/recommendations/[id]`, 뷰어 `…/photos/[photoId]`      | 카드 「>」. 보기 전용, 뒤로가기 → 시트                                     |
| 공동 편집 (4.3.1)                 | `/bunch/drafts/[draftId]`                                                 | 초안 생성 직후, 작성 중인 번들 탭(5.3.1), 알림. 뒤로가기는 들어온 곳으로   |
| 참여 멤버 관리 (4.3.2)            | `/bunch/drafts/[draftId]/members`                                         | 참여 멤버의 「추가」 카드                                                  |
| 픽 (4.3.5)                        | `/bunch/drafts/[draftId]/pick`                                            | 사진 영역 「픽하기 >」. 뒤로가기 → 공동 편집                               |
| 크게 보기 (4.3.6)                 | `/bunch/drafts/[draftId]/photos/[photoId]`(뷰어 path는 코드 정리 때 확정) | 공동 편집 썸네일, 픽 화면 사진. 뒤로가기 → 들어온 화면                     |
| 사진함에서 가져오기 (4.3.7)       | `/bunch/drafts/[draftId]/photos/add`                                      | 「사진 추가」 시트. 「적용하기」 또는 뒤로가기(변경 있으면 확인 모달)      |
| 공개 범위 설정 (4.3.9)            | `/bunch/drafts/[draftId]/visibility`                                      | 공동 편집 「업로드」. 뒤로가기는 고른 공개 범위를 버림                     |

- 사진함 선택 모드의 「번들 만들기」(3.3.4)는 참여 멤버 고르기를 거쳐 사진 고르기 없이 바로 초안을 만들고 공동 편집으로 간다.
- 공동 편집의 뒤로가기는 들어온 곳으로 간다. 작성 중인 번들 탭에서 왔으면 그 탭, 번치 홈에서 만들었으면 번치 홈, 사진함에서 만들었으면 사진함(선택 모드는 끝남)이다.
- 보는 사이 초안이 삭제되거나 발행되면 공동 편집과 하위 화면 어디서든 닫을 수 없는 모달을 띄운다(4.3.1). 「확인」은 각각 작성 중인 번들 탭과 번들 상세로 간다.

## 요구사항

### 필수 (Must Have)

참여 멤버 고르기 (4.1.1, DRAFT-01·15)

- [ ] 번치 멤버가 나 1명이면 이동하지 않고 「함께할 멤버가 없어요」 모달(「취소」/「초대하기」)을 띄운다. 작성 중인 번들이 10개면 이동하지 않고 「번들 초안은 최대 10개까지 만들 수 있어요.」.
- [ ] 헤더는 뒤로가기만, 제목 「누구와 함께 만들까요?」. 멤버 카드(프로필·역할 배지·닉네임)에 「추가하기」/「추가됨」 토글. 나는 목록에 없고 처음부터 참여 멤버다.
- [ ] 하단 「다음」은 1명 이상 고르면 활성이고 연타는 첫 탭만 처리한다. 고르는 동안은 서버에 저장하지 않는다. 고른 멤버가 나가면 다시 불러올 때 뺀다.
- [ ] 「다음」은 사진 고르기로 간다. 사진함에서 왔으면 바로 초안을 만들고, 뒤로가기는 사진함 선택 모드로 돌아가 고른 사진을 유지한다.

사진 고르기 화면 (4.1.2, DRAFT-01·GROUP-02)

- [ ] 헤더(뒤로가기, 「추천 번들 보기」), 멤버 필터 칩(사진함 3.1.2와 같은 동작, 칩마다 고른 장수 표시), 「촬영 날짜를 확인할 사진 N장」 아코디언, 날짜 섹션별 3열 목록. 「선택」·「+」 없이 들어오자마자 고를 수 있다.
- [ ] 하단 고정 버튼: 「이전」(테두리)·「다음」. 사진을 눌러도 사진 상세로 가지 않는다. 날짜 바꾸기·삭제·올리기는 이 화면에 없다.
- [ ] 이미 다른 번들에 쓰인 사진, 날짜 미확인 사진, 참여 멤버로 고르지 않은 멤버의 사진도 고를 수 있다. 칩을 바꿔도 고른 사진과 번호는 유지한다.
- [ ] 빈 상태: 사진함에 사진 없음 「아직 사진이 없어요.」·「사진함에 사진을 올리면 번들을 만들 수 있어요.」(「다음」 비활성), 선택한 멤버 사진 없음 「첫 사진을 기다리고 있어요!」.

사진 선택과 초안 생성 (4.1.3~4.1.4, DRAFT-01·GROUP-04)

- [ ] 누른 순서대로 번호, 다시 누르면 해제·당김. 1~20장, 21번째는 선택되지 않고 「번들에는 사진을 20장까지 담을 수 있어요.」. 고르는 동안은 서버에 저장하지 않는다.
- [ ] 「다음」은 0장이면 비활성, 누르면 로딩·중복 요청 차단, 성공하면 공동 편집으로 간다.
- [ ] 그사이 번치 멤버가 1명이 되면 만들지 않고 「함께할 멤버가 없어요」 모달. 작성 중인 초안이 10개면 「번들 초안은 최대 10개까지 만들 수 있어요. 기존 초안을 발행하거나 삭제해 주세요.」.
- [ ] 사진 고르기 경로에서 고른 사진 중 삭제된 사진이 있으면 만들지 않고, 선택에서 빼 번호를 다시 매긴 뒤 「선택한 사진 중 N장이 사진함에서 삭제되어 선택이 해제됐어요.」. 사진함 경로는 3.3.4 예외를 따른다.
- [ ] 서버 규칙: 참여 멤버 = 만든 사람 + 고른 멤버(사진을 올린 멤버라도 고르지 않으면 아님), 첫 사진이 대표 사진, 추천 번들을 적용했으면 기본 제목은 추천 제목이고 '추천으로 만든 번들'로 기록, 아니면 빈 제목. 초안에 들어간 사진은 추천 계산에서 빠진다. 고른 멤버가 나갔으면 빼고 만든다.

추천 번들 시트·카드 (4.2.1~4.2.2, GROUP-02)

- [ ] 시트 제목(2줄)과 카드 목록(개수 제한 없이 서버 순서대로 세로 스크롤), 하단 고정 「적용하기」(카드 선택 전 비활성). 아래로 끌거나 바깥을 누르면 닫히고 화면의 선택은 그대로다.
- [ ] 카드: 대표 사진(추천 사진 순서의 1번), 제목 + 「>」, 올린 멤버 닉네임 칩(넘치면 마지막을 「{닉네임} 외 N명」), 사진 수(6~~10장)·날짜(자정을 넘긴 묶음은 「10월 19일~~20일」, 올해가 아니면 연도 표시). 장소는 없다.
- [ ] 「>」를 뺀 영역을 누르면 하나만 선택(강조 테두리), 다시 누르면 해제. 「>」는 상세 화면으로 가고 선택은 바꾸지 않는다.
- [ ] 추천 번들이 없으면 제목·「적용하기」 없이 손잡이와 빈 상태(이미지, 「아직 추천할 번들이 없어요」, 「함께한 순간이 쌓이면 번들을 추천해 드릴게요.」)를 보인다.

추천 번들 적용과 변경 확인 (4.2.3~4.2.4, GROUP-03)

- [ ] 「적용하기」 → 시트를 닫고 추천 사진 전부를 추천 순서대로 번호를 붙여 선택하고, 그 날짜 섹션(이틀이면 첫날)으로 스크롤한다. 「추천 번들 사진 N장이 선택되었어요.」. 적용만으로는 서버에 저장하지 않는다.
- [ ] 이미 1장 이상 선택돼 있으면 먼저 「추천 번들 사진으로 변경할까요?」 모달(뒤의 시트는 내려감). 「변경하기」는 기존 선택을 모두 풀고 추천 사진만 선택, 「취소」는 시트를 다시 올리고 카드 선택과 기존 선택을 유지한다.
- [ ] 적용 후에도 사진을 빼거나 더 고를 수 있다(합계 20장). 적용 사이 사진 일부가 지워졌으면 남은 사진만 선택하고 N도 남은 장수로 보인다. 추천을 적용해도 고른 참여 멤버는 바뀌지 않는다.
- [ ] 여러 번 적용했으면 마지막에 적용한 추천 번들을 초안 생성 요청에 함께 보낸다.

추천 번들 상세·뷰어 (4.2.5~4.2.6, GROUP-02)

- [ ] 상세: 헤더(뒤로가기, 추천 제목), 추천에 담긴 사진(6~10장)을 날짜 섹션별 3열로 추천 순서대로 보인다(선택 원·번호 없음). 진입 시 서버에서 최신 사진을 다시 조회한다. 그 사이 추천이 사라졌으면 들어가지 않고 「추천 번들이 삭제됐어요. 다시 확인해 주세요.」 후 시트 목록을 새로고침한다.
- [ ] 뷰어: 헤더(뒤로가기, 촬영 날짜), 원본 비율, 올린 멤버 배지, 좌우로 추천 순서 이동(처음·끝에서 멈춤), 한 번 누르면 헤더·배지 숨김. 저장·날짜 변경·삭제는 없다.

공동 편집 화면 (4.3.1, DRAFT-02)

- [ ] 헤더(뒤로가기, 저장 상태, ⋯)와 하단 「업로드」는 고정, 그 사이만 스크롤한다. 제목은 없다. 영역 순서: 참여 멤버, 번들 제목*, 사진, 코멘트*, 위치, 날짜.
- [ ] ⋯ 메뉴 「번들 나가기」(빨간 글씨)는 참여 멤버에게만 보인다.
- [ ] 참여 멤버가 아닌 사람은 보기만 하고, 편집하려 하면 「참여 멤버만 편집할 수 있어요」. 어느 영역도 잠그지 않는다.
- [ ] 보는 사이 초안이 삭제되면 「번들이 삭제됐어요」 모달(「확인」 → 작성 중인 번들 탭), 다른 멤버가 업로드하면 「번들이 업로드됐어요」·「{닉네임}님이 번들을 업로드해 더 이상 편집할 수 없어요.」 모달(「확인」 → 번들 상세). 하위 화면에서도 같고 바깥을 눌러도 닫히지 않는다.

참여 멤버 (4.3.2, DRAFT-02·15)

- [ ] 가로 카드(프로필·닉네임 앞 역할 배지). 지금 이 초안에 들어와 있는 멤버는 프로필 오른쪽 아래에 초록 점을 붙인다. 다른 멤버 카드의 X는 초안 생성자와 참여 중 관리자에게만, 초안 생성자 카드에는 남에게 X가 없고, 내 카드에는 X가 없다. 맨 끝 「추가」 카드 → 참여 멤버 관리 화면.
- [ ] 관리 화면: 헤더는 뒤로가기만. 「멤버 추가하기」(참여하지 않은 번치 멤버, 「추가하기」 즉시 반영 + 「{닉네임}님이 번들 참여 멤버에 추가되었어요.」, 추가할 멤버가 없으면 영역 숨김), 「참여 멤버」(프로필 오른쪽 아래 역할 배지, 내 카드에 「(나)」, X). 추가·내보내기로 카드가 목록 사이를 옮겨갈 때는 Smart Animation, Gentle, 400ms다.
- [ ] 다른 멤버 빼기는 「{닉네임}님을 번들에서 내보낼까요?」 / 「{닉네임}님이 남긴 코멘트가 삭제되며, 복구할 수 없어요.」(「내보내기」/「취소」) 후 그 멤버의 코멘트와 픽을 지운다(사진·제목·위치·날짜는 남김). 「{닉네임}님이 번들 참여 멤버에서 제외되었어요.」.
- [ ] 스스로 빠지기(관리 화면의 내 카드 X, ⋯ 「번들 나가기」): 「번들에서 나갈까요?」 / 「작성한 코멘트는 삭제되며, 다시 참여해도 복구할 수 없어요.」(「나가기」 빨간색/「취소」) → 번치 홈으로 이동, 이후 보기 전용.
- [ ] 초안 생성자는 같은 동작에 「번들을 만든 멤버가 나가면 번들이 삭제되고, 되돌릴 수 없어요.」 모달을 띄운다. 「나가기」 → 초안 삭제, 번치 홈으로 이동, 「작성 중인 번들을 삭제했어요.」. 관리자이면서 초안 생성자여도 같다.
- [ ] 편집 중 빠진 멤버는 바로 보기 전용이 되고 「번들 참여 멤버에서 제외되어 보기만 할 수 있어요.」. 권한이 바뀌어 서버가 거부하면 「권한이 변경되어 해당 기능을 이용할 수 없어요.」 후 X를 숨긴다.

제목 (4.3.3, DRAFT-05)

- [ ] 입력란(placeholder 「제목을 입력해주세요.」), 긴 제목은 여러 줄로 감싸 보인다. 최대 40자, 줄바꿈 불가(붙여넣은 줄바꿈은 공백), 앞뒤 공백 제거 후 판단, 이모지 가능, 글자 수 표시 없음. 40자에 닿으면 「제목은 40자까지 쓸 수 있어요」(빨간 글씨).
- [ ] 입력란에서 나가거나 입력이 1초 멈추면 자동 저장한다. 잠그지 않고 글자 단위로 합친다. 합친 결과가 40자를 넘으면 자르지 않고 같은 오류를 보이며, 40자 이하가 될 때까지 업로드할 수 없다.

사진 보기·빼기·순서 (4.3.4, DRAFT-03·04)

- [ ] 제목 「사진」과 오른쪽 「픽하기 >」, 그 아래 가로 스크롤 썸네일, 맨 끝 「사진 추가」 칸(20장이면 없음). 썸네일을 누르면 크게 보기, 「픽하기 >」는 첫 사진부터 픽 화면이다. 사진 캡션은 없다.
- [ ] 썸네일 오른쪽 위 X(참여 멤버만): 픽이 없으면 「사진을 삭제할까요?」 / 「삭제한 사진은 복구할 수 없어요.」, 픽이 있으면 「멤버들이 픽한 사진이에요」 / 「사진을 삭제하면 픽도 함께 삭제되며, 복구할 수 없어요.」(「삭제하기」 빨간색/「취소」). 문구는 누른 순간의 픽 수로 고른다. 1장이면 「사진을 삭제할 수 없어요」 / 「번들에는 최소 1장의 사진이 있어야 해요.」. 사진함의 사진은 남는다.
- [ ] 순서 바꾸기: 썸네일을 길게 눌러 진동과 함께 떠오르게 하고 좌우로 끌어 끼워 넣는다. 화면 끝에서 자동 스크롤한다. 손을 뗄 때 한 번만 저장하고 픽은 사진을 따라간다. 맨 앞 사진이 대표 사진이다. 「사진 추가」 뒤로는 못 옮기고 사진이 1장이면 떠오르지 않는다. 앱이 백그라운드로 가면 끌기를 취소한다.
- [ ] 끄는 동안 다른 멤버의 변경은 미뤘다가 손을 뗀 뒤 한 번에 반영한다. 끄던 사진이 지워졌으면 손을 뗄 때 「다른 멤버가 삭제한 사진이에요.」와 함께 없앤다.
- [ ] 공동 편집 밖에서 마지막 사진까지 사라지면 초안은 자동 삭제되고 보던 멤버에게 「번들이 삭제됐어요」 모달을 띄운다.

픽 (4.3.5, DRAFT-14)

- [ ] 헤더는 뒤로가기만. 「번들이 업로드되면 누가 픽했는지 보여요.」, 「마음에 드는 사진을 픽해보세요」, 가운데 큰 사진과 옆 일부, 좌우로 번들 순서 이동, 픽 버튼, 「N명이 픽했어요」와 닉네임 칩(내 칩 강조, 0명이면 숨김).
- [ ] 픽 버튼: 「이 사진 픽하기」 ↔ 「사진을 픽했어요」(애니메이션). 사진마다 여러 장 픽할 수 있다. 누르면 바로 저장하고 연타는 마지막 상태만 저장한다. 실패하면 되돌리고 오류 토스트. 사진 영역을 누르면 크게 보기다.
- [ ] 다른 멤버의 픽과 사진 목록·순서는 실시간으로 반영하지 않고 다시 들어올 때 불러온다. 보던 사진이 빠졌으면 픽할 때 「삭제된 사진이에요」 / 「삭제된 사진은 픽할 수 없어요.」 모달 후 다음 사진을 보인다.
- [ ] 참여 멤버가 아니면 보기만 한다. 픽은 발행 조건이 아니다. 발행 후에는 누구도 바꿀 수 없다.

크게 보기 (4.3.6, DRAFT-03·04)

- [ ] 헤더(뒤로가기, 촬영 날짜, ⋯), 원본 비율, 올린 멤버 배지(사진함 원본을 올린 멤버, 날짜도 원본의 촬영 날짜), 좌우로 번들 순서 이동, 누르거나 확대하면 헤더·배지 숨김. 뒤로가면 들어온 화면에 마지막으로 본 사진을 보인다.
- [ ] ⋯ 메뉴: 「저장」(앨범 저장, 사진함 3.5.2와 같음), 「삭제」(4.3.4 X와 같은 빼기, 참여 멤버에게만). 지워진 사진이면 「사진함에서 삭제된 사진이에요.」 후 들어온 화면으로 돌아간다.

사진 추가 (4.3.7, DRAFT-03)

- [ ] 「사진 추가」 → 시트(「어디서 사진을 가져올까요?」, 「번치 사진함에서 가져오기」·「내 갤러리에서 가져오기」).
- [ ] 사진함에서 가져오기: 사진 고르기 화면과 같은 구성에 지금 번들 사진이 순서대로 선택된 채 열린다. 더 고르면 번호가 이어 붙고 풀면 당겨진다. 최대 20장. 처음 상태와 같거나 0장이면 「적용하기」 비활성. 푼 사진이 있으면 「사진 N장이 번들에서 빠져요」 / 「빠진 사진의 픽도 함께 사라져요.」 확인. 적용하면 「변경사항이 적용되었어요.」. 변경을 두고 뒤로가면 「저장하지 않고 나갈까요?」.
- [ ] 적용은 내가 바꾼 것(더한 사진, 푼 사진)만 서버에 보내고, 그 사이 다른 멤버가 바꾼 내용은 덮어쓰지 않는다. 합쳐서 20장을 넘으면 적용하지 않고 20장 초과 토스트. 0장이 되면 나중 요청을 거부하고 「사진을 삭제할 수 없어요」 모달.
- [ ] 갤러리에서 가져오기: 최대 「20 − 지금 장수」장, 사진함 업로드 규칙(사진함 3.2.2: 형식·용량·위치 제거·촬영 날짜·업로드 묶음·같은 사진 합치기·한도)으로 사진함에 올리면서 번들 맨 뒤에 붙인다. 올라가는 동안 칸에 로딩. 일부 실패는 3.2.2와 같은 결과 토스트(「다시 시도」 없음). 사진함이 가득 차면 「사진함이 가득 찼어요.」, 하루 한도면 「오늘 이 번치에 올릴 수 있는 사진을 모두 올렸어요.」이고 선택창을 열지 않는다.

코멘트 (4.3.8, DRAFT-06)

- [ ] 참여 멤버별 카드(내 카드가 맨 위, 「(나)」). 내 카드만 바로 입력, 최대 400자(줄바꿈·이모지 가능, 넘으면 「코멘트는 400자까지 쓸 수 있어요.」), 미작성 카드에는 「코멘트를 남기면 번들을 업로드할 수 있어요.」. 공백·줄바꿈만은 미작성으로 본다.
- [ ] 다른 멤버가 쓰는 글자는 그 카드에 바로 보인다. 카드 아래 「* 코멘트와 픽하기는 업로드 이후 수정이 불가해요」를 모두에게 보인다. 관리자도 남의 코멘트를 고치거나 지울 수 없다.

공개 범위 설정 (4.3.9, DRAFT-07)

- [ ] 공동 편집의 「업로드」 다음 화면이다. 헤더는 뒤로가기만, 제목 「번들의 공개 범위를 설정해 주세요」. 처음에는 아무것도 고르지 않은 상태이고 뒤로가면 고른 값을 버린다.
- [ ] 보기: 공개 번치 「전체 공개」·「멤버 공개」, 비공개 번치 「일부 공개」·「멤버 공개」(라디오 카드, 하나만). 보기 아래 「* 업로드 이후에는 관리자만 수정하거나 삭제할 수 있어요.」.
- [ ] 하단 「업로드」는 고르면 활성이고, 누르면 화면을 어둡게 덮고 로딩, 버튼은 「업로드 중」(비활성). 요청 중에는 뒤로갈 수 없다.
- [ ] 누른 순간 조건이 깨지면 공동 편집으로 돌아가 「필수 항목을 모두 입력해야 업로드 할 수 있어요.」, 권한이 사라지면 「번치 관리자와 해당 번들 생성자만 업로드할 수 있어요.」. 네트워크 오류는 오류 토스트이고 고른 값을 유지해 같은 요청 키로 다시 보낸다.

위치 (4.3.10, DRAFT-17)

- [ ] 코멘트 아래 위치 영역(없으면 「위치 추가」 + 「>」, 있으면 줄마다 「≡」 + 이름 + X, 1~2개면 「+ 위치 추가」). 누르면 거의 전체 높이의 검색 시트(placeholder 「장소나 주소를 검색해 주세요」, 검색 전 「태그한 위치는 함께 보여요」 안내, 결과는 이름 + 주소). 결과를 누르면 바로 저장하고 닫는다. 번들당 최대 3개이고 3개가 차면 「+ 위치 추가」가 사라진다.
- [ ] 줄을 누르면 다른 위치로 바꾸고, X는 그 위치만 지운다. 「≡」를 끌어 순서를 바꾸고 손을 뗄 때 저장한다. 첫 번째 위치가 피드·상세의 대표다.
- [ ] 키워드 검색만 한다. 현재 위치·내 주변 검색은 없고 위치 권한도 받지 않는다. 저장 값은 이름·주소·외부 ID·순서이고 좌표는 저장하지 않는다.
- [ ] 잠그지 않는다. 동시에 넣어 3개를 넘으면 못 들어간 사람에게 「위치는 최대 3개까지 추가할 수 있어요.」. 이미 추가한 위치를 고르면 시트를 닫고 「이미 추가한 위치에요.」. 검색 실패는 오류 토스트, 검색어 유지.

날짜 (4.3.11, DRAFT-18)

- [ ] 날짜 줄(없으면 「날짜 추가」 + 「>」 + 추천 날짜 칩 최대 3개, 있으면 날짜 + X). 칩을 누르면 바로 등록, 줄을 누르면 달력 시트(사진함 3.4.1과 같은 모양, 등록돼 있으면 그 날짜 선택 상태).
- [ ] 추천 날짜: 초안 사진의 날짜(사용자 지정 날짜 포함, 미확인 제외) 중 사진이 많은 날부터 최대 3개, 같으면 이른 날이 앞. 추천 번들로 만든 초안은 그 추천 날짜(이틀이면 첫날)를 맨 앞에 둔다. 날짜를 정하기 전에는 사진이 바뀌면 칩을 다시 계산한다.
- [ ] 번들 날짜를 정해도 사진함 사진의 날짜는 바뀌지 않는다. 잠그지 않고 마지막으로 저장된 값으로 맞춘다.

업로드(발행) (4.3.12, BUNDLE-01)

- [ ] 맨 아래 고정 「업로드」는 발행 조건(사진 1장 이상, 제목 1~40자, 참여 멤버 2명 이상, 참여 멤버 모두 코멘트, 연결됨)을 모두 만족하고 권한이 있을 때만 활성이다. 위치·날짜·픽은 조건이 아니고 공개 범위는 다음 단계에서 고른다.
- [ ] 누르면 공개 범위 설정으로 간다. 별도 업로드 확인 창은 없다. 다른 멤버의 편집 중 표시가 하나라도 있으면 먼저 「편집 중인 멤버가 있어요」 + 「지금 업로드하면 작성 중인 내용 일부가 반영되지 않을 수 있어요.」(「취소」·「계속하기」)를 띄운다. 어느 쪽인지는 누른 순간 기준이다.
- [ ] 발행은 공개 범위 설정의 최종 「업로드」 시점에 서버에 저장된 내용으로 되고, 조건·권한도 그때 서버가 다시 본다. 같은 요청 키로 재시도해도 한 번만 발행된다(요청 키는 발행 API 연동 때).
- [ ] 성공하면 번치 메인 「번들」 탭 맨 위로 이동하고 「번들을 업로드했어요.」.
- [ ] 권한 없는 참여 멤버가 누르면 「번치 관리자와 해당 번들 생성자만 업로드할 수 있어요.」, 참여 멤버가 아니면 「참여 멤버만 편집할 수 있어요.」, 권한은 있는데 조건 미충족이면 「필수 항목을 모두 입력해야 업로드 할 수 있어요.」.
- [ ] 화면을 보는 사이 역할·참여 여부가 바뀌면 「업로드」 활성 여부를 바로 바꾼다.

편집 중 표시 (4.3.13, DRAFT-10)

- [ ] 잠금은 없다. 표시가 있어도 그 영역을 편집할 수 있다. 제목은 「번들 제목」 옆, 코멘트는 「코멘트」 옆에 입력 중인 멤버의 프로필을 모두 보인다. 사진·픽·위치·날짜는 표시 없이 결과만 반영한다(제안).
- [ ] 실제로 입력할 때만 표시한다. 입력을 멈추고 3초 뒤, 입력란·화면을 나가거나 앱이 백그라운드로 가면 바로, 연결이 끊기면 15초 뒤 해제한다.

자동 저장·실시간 반영 (4.3.14, DRAFT-08·09·12)

- [ ] 저장 버튼 없이 자동 저장한다. 사진·순서·픽·위치·날짜는 할 때마다, 제목·코멘트는 입력란에서 나갈 때와 입력이 1초 멈출 때 저장한다. 내 저장 요청은 한 초안 안에서 순서대로 하나씩 보낸다.
- [ ] 헤더 저장 상태: 「저장 중」(점 애니메이션) / 「저장 완료」(회색). 내 편집만 반영하고 글자 위치는 고정한다. 공동 편집 화면 헤더에만 둔다.
- [ ] 다른 멤버가 바꾼 참여 멤버·제목·사진·순서·코멘트·위치·날짜는 새로고침 없이 반영한다. 픽 화면은 다시 들어올 때 반영한다.
- [ ] 동시 편집은 서버 도착 순서로 처리하고 충돌을 묻지 않는다. 삭제가 이동보다 우선이고, 기준 사진이 지워지면 그 자리에 놓는다. 동시 추가로 20장을 넘으면 도착 순서대로 넣고 「사진은 최대 20장까지 담을 수 있어요. N장만 추가했어요.」.
- [ ] 연결이 끊기면 헤더 아래 빨간 배너(「인터넷 연결을 확인해 주세요.」 + 「재시도」)를 보이고 편집을 막는다. 편집 동작은 흐리게 하지 않고 반응만 없앤다. 끊긴 동안의 수정은 받지 않고 보내지 못한 수정은 버린다. 다시 연결되면 최신 초안을 불러와 맞추고 배너를 숨긴다.
- [ ] 재연결 뒤 초안이 삭제·발행됐으면 4.3.1 모달을, 참여 멤버에서 빠졌으면 보기 전용을 적용한다.

## 추천 번들의 서버 규칙(요약)

웹이 직접 계산하지 않지만, 화면 결과를 검증할 때 기준이 되므로 요약한다. 숫자(4시간, 3장, 6장, 밤 10시~새벽 3시, 2시간)는 초기 기준이며 운영하며 조정한다.

- 재료: 촬영 날짜가 있는 사진함 사진(사용자 지정 날짜 우선). 날짜 미확인 사진, 초안·발행 번들에 쓰인 사진은 뺀다. 위치와 AI 분석은 쓰지 않는다.
- 묶기(4.2.7): 날짜별로 모으고, 촬영 시각 공백이 4시간 이상이거나 앞뒤에 겹치는 멤버가 없으면 나눈다(양쪽 3장 이상일 때만). 밤 10시 이후와 다음 날 새벽 3시 이전 사진이 2시간 이내면 잇는다. 시각 없는 사진은 같은 업로드 묶음 → 같은 멤버 → 사진 많은 묶음 순으로 붙인다.
- 조건: 연사 정리 후 6장 이상, 올린 멤버 2명 이상인 묶음만 추천한다.
- 10장 고르기(4.2.8): 연사 정리 후 10장 이하면 전부, 넘으면 멤버마다 1장 이상(적게 올린 멤버부터) + 나머지는 시간대가 고르게. 순서는 촬영 시각 순, 시각 없는 사진은 같은 날 뒤에 업로드 순.
- 제목: 상황(특별한 날, 첫 묶음, 전원 참여, 30일 이상 만에, 자정 넘김, 기본 요일·시간대)별 문장 묶음에서 15자 이내로 뽑는다. 같은 목록·최근 사용 문장은 피하고, 한 번 정한 제목은 바꾸지 않는다. 문장 묶음은 서버가 관리한다.
- 갱신(4.2.9): 사진 추가·삭제·날짜 변경, 초안 생성·삭제가 있으면 그 날짜와 앞뒤 날짜를 마지막 변경 5분 뒤 한 번 다시 계산한다. 반영까지 몇 분 걸릴 수 있다.
- 사라짐: 마지막 사진 추가 후 30일 동안 쓰지 않았거나 조건이 깨지거나 그 추천으로 초안을 만들면 목록에서 빠진다. 30일로 사라진 추천은 정보를 지우고, 그 날짜에 사진이 더해져 조건을 채우면 새 제목의 새 추천으로 만든다. 묶음이 나뉘거나 합쳐져도 기존 추천을 끝내고 새 제목으로 만든다.
- 목록 순서: 최근 사진이 추가된 순 → 올린 멤버가 많은 순 → 사진이 많은 순. 번치 멤버 모두 같은 목록을 본다. 새 추천이 생기면 번치 멤버 전원에게 알림을 보내고, 갱신에는 보내지 않는다. 번치 홈에는 안내 영역이 없다.

## 상태

- 로딩: 멤버 목록, 사진 목록, 추천 목록·상세, 초안 생성 중(버튼 로딩), 공동 편집 화면 로딩, 저장 중 표시, 갤러리 업로드 중 칸 로딩, 위치 검색 중, 발행 요청 중(화면 dim + 로딩).
- 빈 상태: 사진함 사진 없음, 선택한 멤버 사진 없음, 날짜 미확인 0장, 추천 번들 없음, 추가할 번치 멤버 없음, 추천 날짜 없음(모두 날짜 미확인), 위치 검색 전.
- 오류: 목록·추천 로딩 실패, 초안 생성 실패(멤버 1명, 초안 10개, 사진 삭제됨, 서버 오류), 추천 삭제됨, 픽 저장 실패, 글자 수 초과, 사진 빼기 불가, 20장 초과, 갤러리 업로드 일부 실패, 위치 검색 실패, 날짜 저장 실패, 연결 끊김, 권한 거부(빼기·발행), 초안 삭제·발행됨. 오류 토스트 기본 문구는 「일시적인 오류가 발생했어요. 다시 시도해 주세요」이다.
- 성공: 초안 생성 후 이동, 추천 적용 토스트, 멤버 추가·제외 토스트, 사진 추가 적용 토스트, 저장 완료 표시, 발행 토스트.
- 접근성: 사진 선택 번호는 선택 상태·순서로 읽혀야 한다. 길게 눌러 순서 바꾸기는 키보드·스크린 리더용 대체(예: 앞·뒤로 옮기기 동작)가 필요하다. 편집 중 표시와 저장 상태, 연결 끊김 배너는 상태 변화로 읽혀야 한다(live region).

- 실시간 구독은 범용 프록시(요청·응답 1회 전달)로는 전달할 수 없다. SSE 스트리밍을 BFF로 넘길지, 짧은 수명의 전용 토큰을 BFF가 발급해 브라우저가 백엔드에 직접 연결할지(CORS 필요) 정해야 한다. 정해지면 결정 기록을 남긴다.
- 장소 검색은 외부 API(예: 카카오 로컬 키워드 검색) 키가 필요하므로 BFF Route Handler나 백엔드가 대신 호출한다. 브라우저에 키를 노출하지 않는다.
- 실패 시 오류 코드와 정확한 문구: 서버 코드를 확인한 뒤 채운다. 화면 문구는 위 요구사항의 문구를 쓴다.
- Query key 후보: `bundleKeys.recommendations(bunchId)`, `bundleKeys.recommendation(id)`, `bundleKeys.draft(draftId)`, `bundleKeys.placeSearch(keyword)`. 초안은 실시간 이벤트로 `setQueryData`를 갱신하고, 재연결 뒤에는 `draft(draftId)`를 다시 불러온다. 초안 생성 뒤에는 `photoKeys.all`(추천 계산 영향)과 작성 중인 번들 목록을 invalidate한다.

## 완료 기준

- 위 필수 요구사항이 모두 체크되고, 각 화면의 로딩·빈·오류·성공 상태를 테스트나 Storybook으로 확인한다.
- 두 기기(또는 두 브라우저)로 같은 초안을 열어 제목 글자 단위 합치기, 순서 동시 변경, 코멘트 실시간 반영, 연결 끊김 뒤 재동기화가 명세와 같게 동작한다.
- 발행 조건과 권한별 「업로드」 활성 여부, 같은 요청 키 재시도의 1회 발행을 테스트로 확인한다.
- 추천 번들을 적용해 만든 초안의 기본 제목·대표 사진·추천 날짜 칩이 추천과 같다.

## 확인할 항목

### 백엔드

1. 위 13개 동작의 method·path·필드·오류 코드.
2. 실시간 전송 방식(SSE·WebSocket)과 인증, 이벤트 형태, 재연결 시 놓친 변경을 받는 방법.
3. 제목 글자 단위 합치기 방식(CRDT 등)과 편집 중 표시·접속 초록 점의 서버 표현(15초 연결 감지 방식).
4. 사진 순서 동시 변경의 기준 위치 표현(앞뒤 사진 ID 등)과 충돌 응답.
5. 사진함에서 가져오기의 "차이만 반영" 요청 형태(4.3.7 예외).
6. 장소 검색 API 선택과 호출 주체, 호출 제한.
7. 추천 번들이 나뉘거나 합쳐지거나 30일 뒤 새로 만들어질 때 ID를 새로 받는지(카드 선택·상세 진입에 영향).

### 기술·환경

1. 길게 눌러 순서 바꾸기·자동 넘김의 WebView 제스처 체감과 진동(햅틱) 처리(`docs/architecture/web-interface-guidelines.md` "Drag와 제스처", 실기기 확인).
2. 공동 편집 화면에서 키보드가 올라올 때 고정 헤더·배너와 입력란 위치(iOS WebView).
3. 갤러리에서 가져오기의 업로드는 사진함 bridge(`docs/specs/photo-box.md`의 `pickGalleryImages`)를 그대로 쓴다.
