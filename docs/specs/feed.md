# 기능: 피드·번들 상세 (기능명세서 6장)

> Status: Draft
> Date: 2026-11-04(기능명세서 1107 수정본 반영 2026-11-07)

기능명세서의 **6장 피드**를 구현 범위로 정리한 문서다. 6장은 세 부분으로 나뉜다.

- 6.1 피드 탭: 화면 구성, 헤더, 번들 카드, 구간·끝 안내, 광고 카드, 광고 숨기기, 소속 번치 없음
- 6.2 번들 상세: 화면 구성, 번치 정보·참여 멤버, 제목·위치·날짜, 사진, 멤버별 코멘트, 좋아요·댓글 수, 댓글, 더보기, 수정·삭제·신고
- 6.3 번들 상세 시트: 장소 콕하기, 참여 멤버, 멤버 프로필

기능 ID(FEED·BUNDLE·NOTI·DRAFT)와 명세서 절 번호(6.2.8 등)로 원본과 대조한다. 번들 만들기·공동 편집은 `docs/specs/bundle-create.md`, 번치 메인·다른 번치 프로필·팔로우·알림은 `docs/specs/bunch-home.md`가 맡는다.

번들 상세는 피드 말고도 번치 메인 「번들」 탭, 다른 번치 프로필, 알림에서 들어오므로 이 spec은 `docs/specs/`에 둔다. 구현을 시작하면 화면 spec은 각 feature 폴더에 둔다. 피드 탭은 `apps/web/src/features/feed`(fixture)에 있고, 나머지 화면은 아직 구현하지 않았다.

## 목적

- 다른 번치들이 발행한 번들을 둘러본다. 팔로우한 번치를 먼저, 다 보면 공개 번치를 이어서 보여 준다.
- 발행된 번들 하나를 자세히 본다. 사진, 멤버별 코멘트, 좋아요·댓글을 한곳에서 본다.
- 번치 단위로 반응한다(좋아요, 댓글, 신고, 장소 콕하기). 모두 현재 번치 명의다.
- 메인 관리자가 발행된 번들을 고치거나 지운다.

## 문제 정의

- 지금은 번들을 만들어도 다른 번치가 볼 곳이 없다. 번치 사이의 관계(팔로우)도 볼거리가 없으면 쓸 이유가 없다.
- 좋아요·댓글·신고·콕하기가 사람이 아니라 현재 번치 명의라서, 번치를 전환하면 피드 구성과 버튼 상태가 함께 바뀌어야 한다(6.1.1 로직 1~2).
- 노출 판단(차단, 신고, 공개 범위, 팔로우 승인)이 복잡하다. 화면이 거르지 않고 서버 판단을 그대로 따라야 어긋나지 않는다(6.1.1 로직 5).

## 범위 외 항목

- 번들 만들기와 공동 편집(4장). 번들 수정(6.2.12)은 공동 편집 화면을 다시 쓰는 입구와 차이만 둔다.
- 다른 번치 프로필, 팔로우·팔로우 요청, 알림 목록(5장, `bunch-home.md`). 이 문서는 그 화면으로 가는 입구만 둔다.
- 콕한 장소 목록과 관리(콕 명세). 이 문서는 담는 동작만 둔다.
- 광고 내용 관리(서버에서 관리, 6.1.5 로직 1).
- 실시간 반영. 새 번들, 좋아요·댓글 수는 진입·앱 복귀·새로고침 때만 반영한다(6.1.1 로직 3, 6.2.1 로직 3).

## 대상 사용자와 접근 권한

가입을 마친 사람이면 소속 번치가 없어도 피드를 볼 수 있다. 가입 중인 사람은 서버가 거부한다(6.1.7 로직 1).

| 동작                                   | 소속 번치 없음    | 일반 멤버 | 공동 관리자 | 메인 관리자     |
| -------------------------------------- | ----------------- | --------- | ----------- | --------------- |
| 피드·번들 상세 보기                    | 가능(공개 구간만) | 가능      | 가능        | 가능            |
| 좋아요, 댓글·답글, 장소 콕하기·콕 취소 | 불가(안내 토스트) | 가능      | 가능        | 가능            |
| 댓글·번들 신고(다른 번치 번들)         | 불가(안내 토스트) | 가능      | 가능        | 가능            |
| 우리 번치 번들 신고                    | -                 | 가능      | 가능        | 불가(메뉴 없음) |
| 우리 번치 번들 수정·삭제               | -                 | 불가      | 불가        | 가능            |
| 내 댓글 삭제                           | -                 | 가능      | 가능        | 가능            |
| 남의 댓글 삭제                         | -                 | 불가      | 불가        | 불가            |
| 광고 숨기기(사용자 개인 단위)          | 가능              | 가능      | 가능        | 가능            |

- 소속 번치가 없을 때 번치 명의 행동을 누르면 실행하지 않고 「번치에 참여하면 할 수 있어요.」(6.1.7).
- 수정·삭제·신고 메뉴는 화면을 열 때의 역할로 정하고, 누를 때 서버가 다시 확인한다. 그사이 역할이 바뀌었으면 「권한이 변경되어 해당 기능을 이용할 수 없어요.」 후 화면을 새로 고친다(6.2.11).
- 차단 관계인 번치의 번들은 피드에 나오지 않고, 들어가면 차단된 번치 화면(5.10.6)이다. 좋아요도 누를 수 없다(6.2.6). 차단 관계인 번치의 댓글·답글과 좋아요는 목록과 수에서 뺀다(6.1.3 로직 5, 6.2.7 로직 7).
- 콕 취소는 현재 번치 멤버 누구나 할 수 있고, 다른 멤버가 콕한 장소도 취소할 수 있다(6.3.1 로직 1).

## 사용자 흐름과 route

path는 제안이다. 번들 상세는 여러 탭에서 들어오므로 탭 아래가 아니라 독립 경로로 두고, 하단 탭 막대 없이 연다(`(main)` 밖).

| 화면(명세 절)              | path(제안)                           | 진입·이탈                                                                            |
| -------------------------- | ------------------------------------ | ------------------------------------------------------------------------------------ |
| 피드 탭 (6.1)              | `/feed`(있음)                        | 하단 탭. 뒤로가기 없음. 다른 탭에 갔다 오면 스크롤 위치 유지                         |
| 번들 상세 (6.2)            | `/bundles/[bundleId]`                | 피드 카드, 번치 메인 「번들」 탭, 다른 번치 프로필, 알림. 뒤로가기는 들어온 화면으로 |
| 번들 상세 댓글로 바로 가기 | `/bundles/[bundleId]?focus=comments` | 카드·상세의 말풍선. 댓글 영역으로 스크롤하고 입력란 활성화                           |
| 번들 수정 (6.2.12)         | `/bundles/[bundleId]/edit`           | 상세 더보기 「수정하기」(메인 관리자). 저장하면 상세로                               |
| 장소 콕하기 시트 (6.3.1)   | 카드·상세 위 바텀시트                | 위치 글자                                                                            |
| 참여 멤버 시트 (6.3.2)     | 카드·상세 위 바텀시트                | 참여 멤버 프로필 영역. 멤버 → 멤버 프로필                                            |
| 멤버 프로필 (6.3.3)        | `/members/[memberId]`                | 참여 멤버 시트. 번치 줄 → 그 번치 프로필(우리 번치면 번치 메인)                      |
| 광고 외부 링크 (6.1.5)     | 앱 밖 브라우저                       | 광고 사진. 링크가 없으면 동작 없음                                                   |

- 번치를 전환하면 피드를 새 번치 기준으로 다시 불러오고 맨 위로 이동한다(6.1.1 로직 2).
- 피드 헤더 로고는 맨 위로 스크롤, 알림은 알림 목록(5.12.1), 현재 번치 이미지는 번치 메인(5.1.1)이다(6.1.2).

## 요구사항

### 필수 (Must Have)

피드 탭 (6.1, FEED-01)

- [ ] 헤더(로고·알림·현재 번치 이미지)와 하단 탭 막대는 고정, 그 사이 목록만 스크롤. 맨 위에서 당기면 새로고침.
- [ ] 알림 아이콘의 빨간 점은 현재 번치의 안 읽은 알림 기준이고 번치 메인 헤더와 같다. 화면 진입·앱 복귀 때 갱신.
- [x] 번들 카드(6.1.3): 번치 이미지·이름, 발행 경과 시간, 대표 사진 한 장(좌우로 넘기지 않음, 첫 사진을 대표로 씀) 위에 어두운 배경과 제목·위치·날짜, 하트·좋아요 수, 말풍선·댓글 수, 참여 멤버 이미지 3개와 넘는 인원 「외 N명」(Figma 기준).
- [ ] 좋아요 수·댓글 수는 차단 관계인 번치의 것을 뺀다. 댓글 수는 원댓글·답글과 삭제된 것을 모두 센다(상세 댓글 수와 같은 기준, 6.1.3 로직 5~6).
- [x] 경과 시간: 1분 미만 「방금 전」, 1시간 미만 「N분 전」, 24시간 미만 「N시간 전」, 1~7일 「N일 전」, 8일부터 「YYYY년 M월 D일」.
- [ ] 위치가 2개 이상이면 「{첫 위치} 외 N곳」에 밑줄. 위치나 날짜가 없으면 그 줄을 숨긴다.
- [x] 카드에서 누르는 곳별 이동: 번치 → 번치 프로필, 사진 → 번들 상세, 위치 → 콕하기 시트, 하트 → 좋아요, 말풍선 → 상세 댓글 영역, 참여 멤버 → 참여 멤버 시트.
- [ ] 구간(6.1.4): 팔로우한 번치 구간(최근 14일, 업로드 최신순) → 「팔로우한 번치의 소식을 모두 확인했어요」와 축하 애니메이션 → 공개 구간(발행 최신순, 앞 구간에 나온 번들 제외) → 맨 아래 「모든 피드를 확인했어요」와 체크 애니메이션. 구간 안내는 화면에 다시 들어올 때마다 다시 재생.
- [x] 팔로우한 번치 번들이 없으면 공개 구간부터. 두 구간이 모두 비면 체크 애니메이션과 「모든 피드를 확인했어요」만.
- [ ] 아래로 스크롤하면 이어서 불러온다. 커서는 지금 구간과 마지막 번들의 발행 시각·ID다(6.1.4 로직 3).
- [x] 소속 번치가 없으면 헤더에 로고만, 공개 구간만, 번치 명의 행동은 안내 토스트(6.1.7).

광고 (6.1.5~6.1.6, FEED-09)

- [ ] 번들 카드 6개마다 광고 카드 1개, 같은 광고를 연달아 넣지 않는다. 광고가 여러 개면 랜덤으로 고른다. 두 구간 모두에 넣는다.
- [x] BUNCH 로고 이미지와 「BUNCH SPOT」 배지(Figma 기준), 홍보 문구, 장소 사진(장소명·소개|위치·태그 칩), 「콕하기」, 더보기(⋯).
- [x] 「콕하기」(연한 회색)는 시트 없이 「콕 했어요」(검은 버튼)로 바꾼다. 토스트 없음. 「콕 했어요」를 누르면 장소 콕하기 시트와 같은 콕 취소 모달(6.3.1 상세 5)을 띄우고, 「삭제하기」면 「콕하기」로 돌린다. 연타는 첫 탭만.
- [x] 더보기 → 확인 시트(기획 원문의 「숨기기」/「취소」 메뉴는 Figma `5991:164178` 기준과 사용자 요청으로 뺌, 일러스트(Figma 기준), 「이 장소를 숨길까요?」, 설명, 「취소」/「숨기기」) → 카드 자리에 체크 애니메이션과 「장소를 숨김 처리 했어요」를 4초 보인 뒤 카드가 접히며 사라진다(기획 원문은 새로고침·탭 이동 뒤 제거, 요청으로 변경). 탭 이동 뒤에도 없다. 되돌리기 없음.
- [ ] 광고 콕을 현재 번치 「콕한 장소」에 저장, 이미 담긴 장소(다른 멤버가 콕한 것 포함)는 처음부터 「콕 했어요」, 숨김을 사용자 개인 단위로 저장해 새로고침 뒤에도 유지(구현 단위 10).
- [ ] 광고 사진을 눌러 앱 밖 브라우저로 이동(bridge 결정 후).

번들 상세 (6.2, BUNDLE-03)

- [x] 헤더(뒤로가기)와 맨 아래 댓글 입력란은 고정, 그 사이만 스크롤.
- [ ] 헤더 더보기(구현 단위 5·6).
- [x] 영역 순서: 번치 정보·참여 멤버 → 제목·위치·날짜 → 사진 → 멤버별 코멘트 → 좋아요·댓글 수 → 댓글 목록 → 댓글 입력란.
- [x] 번치 정보 줄의 번치를 누르면 번치 프로필, 지금 보고 있는 번치의 번들이면 번치 메인.
- [ ] 날짜는 번들 날짜(업로드 날짜 아님)이고 올해도 연도를 붙인다. 제목은 길면 줄을 나눠 전체.
- [x] 사진 pick(Figma `PickAvatar` `5367:140051`): 그 사진을 pick한 멤버의 얼굴을 겹쳐 보인다(1명 1개, 2명 2개, 3명 이상 3개). 2명 이상이면 누를 때 전체 멤버가 세로로 펼쳐지고 다시 누르면 접힌다(1명이면 버튼 아님). 얼굴은 사진이 보일 때 살짝 떠다니다가 5초 안에 멈춘다.
- [x] 멤버별 코멘트(6.2.5): 참여 멤버 칩(가로 스크롤, 처음엔 첫 멤버 선택) 아래 선택한 멤버의 코멘트. 나간·탈퇴한 멤버는 「작성자」, 내용 대신 「삭제된 코멘트입니다」.
- [x] 나간·탈퇴한 멤버의 칩은 기본 이미지(Figma `Profile Image` `DeletedUser`).
- [ ] 나간 멤버가 다시 들어오면 원래대로(fixture라 미확인, API 연결 때).
- [ ] 참여 멤버는 업로드 시점 멤버이고, 순서는 코멘트 칩 순서와 같다.

좋아요 (6.2.6, FEED-04)

- [x] 하트를 누르면 화면을 먼저 바꾼다(채움·수 +1, 취소면 반대). 피드 카드와 상세가 같은 값을 보이고, 빠른 둘째 탭(400ms 안)은 무시한다. API가 없어 화면 안에서만 바뀐다(새로고침하면 처음 값).
- [ ] 서버에 보내고, 실패하면 원래대로 되돌리고 오류 토스트. 같은 요청이 두 번 가도 한 번만 반영(구현 단위 10).
- [x] 화면 표시는 번치별로 따로 기억한다(번치를 바꾸면 그 번치의 상태). 누가 눌렀는지 보여주지 않고, 우리 번치 번들에도 누를 수 있다.
- [ ] 번치 단위(한 번치는 한 번들에 한 번). 현재 번치 멤버 누구나 누르거나 취소할 수 있고, 누가 눌렀는지 보여주지 않는다. 우리 번치 번들에도 누를 수 있다. 한 번치에 한 번만 반영하는 보장은 서버가 맡는다(구현 단위 10).
- [ ] 그사이 같은 번치의 다른 멤버가 이미 눌렀으면 좋아요된 상태로 맞춘다.

댓글 (6.2.7~6.2.10, FEED-05·FEED-07)

댓글 API가 없어 아래 [x] 항목은 화면 안에서만 동작한다. 상세를 나갔다 오면 처음 값이고 서버 반영·이어 불러오기는 구현 단위 10이다.

- [ ] 댓글 한 줄: 프로필 이미지, 닉네임, 번치 이름 배지(번치 분위기 4종에 따른 색), 작성 날짜(「YYYY.MM.DD」), 내용(줄바꿈 유지), 「답글 N」 또는 「답글 달기」, 더보기(내 댓글 「삭제」, 남의 댓글 「신고」).
- [x] 정렬: 원댓글 최신순, 답글은 원댓글 아래 오래된 순. 답글은 한 단계까지(답글에는 「답글 N」·「답글 달기」 없음). 삭제된 댓글에는 답글을 달 수 없다.
- [x] 삭제된 댓글·답글은 답글이 없어도 목록에 남기고 회색 기본 이미지, 「작성자」, 「삭제된 댓글입니다」. 배지·날짜·「답글 N」은 숨긴다. 원댓글이 지워져도 답글은 그대로. 「답글 N」의 N은 삭제된 답글 포함. 탈퇴한 사용자의 댓글·답글은 닉네임을 「작성자」로.
- [ ] 차단 관계인 번치의 댓글·답글은 숨긴다. 그 번치가 쓴 원댓글이면 아래 답글도 누가 썼든 함께 숨긴다. 숨긴 것은 상세 댓글 수와 「답글 N」에서도 빼서 화면에 보이는 수와 같게 한다(6.2.6 로직 6, 6.2.7 로직 7).
- [ ] 댓글이 없으면 「아직 작성된 댓글이 없어요」. 아래로 스크롤하면 이어서 불러온다.
- [x] 입력란: 「{현재 번치 이름}으로 댓글 달기」(받침에 따라 「으로」/「로」), 공백만이면 보내기 비활성, 최대 200자, 앞뒤 공백 제거·줄바꿈 유지, 보내면 맨 위에 추가하고 입력란 비움·키보드 내림. 연타는 한 번만 등록. 화면 안에서만 등록한다(서버 반영은 구현 단위 10).
- [x] 답글 작성 상태: 입력란 위 「{닉네임}님에게 답글 남기는 중」 + 닫기(X), 안내 문구 「{현재 번치 이름}으로 답글 달기」. 보내면 그 댓글 아래 등록하고 일반 상태로.
- [x] 등록한 댓글은 수정할 수 없고 삭제만. 삭제는 작성자만(관리자도 남의 댓글 불가): 시트 「삭제」/「취소」 → 「댓글을 삭제할까요?」 / 「데이터가 삭제되며 복구 불가능해요.」 / 「취소」·「삭제」 → 「댓글이 삭제 되었어요.」(Figma `6079:178315` 문구, 기능명세서 원문은 「댓글을 삭제했어요」).
- [ ] 댓글 신고: 「이 댓글을 신고할까요?」 신고 시트(번치 신고 5.10.7과 같은 구성), 접수하면 「신고가 접수됐어요.」 후 그 댓글을 바로 숨긴다. 내 댓글에는 메뉴 없음. 같은 번치는 같은 댓글을 24시간에 최대 2번까지 신고할 수 있다(3번째 처리는 5.10.7과 같음).

번들 더보기·수정·삭제·신고 (6.2.11~6.2.14, BUNDLE-04·05, FEED-07)

- [ ] 메뉴: 우리 번치 번들 + 메인 관리자 「수정하기」/「삭제하기」/「취소」, 우리 번치 번들 + 그 외 역할 「신고」/「취소」, 다른 번치 번들 「신고」/「취소」.
- [ ] 수정: 공동 편집 화면(4.3.1)과 같은 구성에 「업로드」 대신 「저장」. 고칠 수 있는 것은 사진(추가·삭제·순서), 캡션, 제목, 위치(최대 3개), 날짜, 공개 범위. 코멘트와 참여 멤버는 고칠 수 없다. 바뀐 내용이 있을 때만 「저장」 활성, 사진 0장이면 비활성. 사진 추가는 사진함에서 고르고 하루 업로드 한도(3.2.1)를 따른다.
- [ ] 수정 반영: 발행 시각·좋아요·댓글은 그대로라 피드에서 위로 다시 올리지 않고, 알림도 보내지 않는다. 「멤버 공개」로 바꾸면 피드에서 바로 빠진다. 위치를 지우거나 바꾸면 그 위치를 콕해 둔 번치(우리 번치 포함)의 콕한 장소에서도 알림 없이 지운다(6.2.12 로직 4~7).
- [ ] 수정 저장: 「수정한 내용을 저장할까요?」 / 「변경된 내용이 기존 번들에 반영돼요.」 / 「취소」·「저장」 → 상세로 돌아가 「번들을 수정했어요」. 저장 전까지 서버에 반영하지 않는다(공동 편집의 자동 저장과 다름).
- [ ] 수정 중 뒤로가기: 바뀐 내용이 없으면 바로 상세로, 있으면 「수정을 그만둘까요?」 / 「수정한 내용은 저장되지 않아요.」 / 「나가기」·「계속 수정」.
- [ ] 삭제: 「게시글을 삭제할까요?」 / 「데이터가 삭제되며 복구 불가능해요.」 / 「취소」·「삭제」 → 이전 화면으로 돌아가 「번들을 삭제했어요」. 남은 발행 번들 수로 뭉치 단계를 다시 계산해 내려갈 수 있다. 이 번들 위치에서 콕한 장소는 지우지 않는다(6.2.13 로직 5~6).
- [ ] 번들 신고: 「이 게시글을 신고할까요?」 신고 시트 → 「신고가 접수됐어요.」 후 이전 화면으로. 같은 번치는 같은 번들을 24시간에 최대 2번까지(5.10.7과 같음).

시트·멤버 프로필 (6.3, FEED-02·10·11)

- [x] 장소 콕하기 시트: 「어느 장소를 콕할까요?」, 장소마다 위치 아이콘·이름·주소·버튼. 담기지 않은 장소는 「콕하기」(연한 회색 + 손가락 아이콘), 이미 담긴 장소는 「콕 했어요」(검은 버튼 + 손가락 아이콘). 위치가 하나여도 같은 시트.
- [x] 「콕하기」를 누르면 담고 「콕 했어요」로 바꾼다. 시트는 닫지 않고 토스트 없음.
- [x] 「콕 했어요」를 누르면 시트를 닫고 콕 취소 모달: 「이 장소의 콕을 삭제할까요?」 / 「'{장소 이름}'이 번치의 콕한 장소에서 삭제돼요.」(받침에 따라 「이」/「가」) / 「아니요」·「삭제하기」. 「삭제하기」면 빼고 모달만 닫는다(토스트·되돌리기 없음). 「아니요」면 모달만 닫고 시트는 다시 열지 않는다. 취소한 장소는 다시 콕할 수 있다.
- [ ] 콕·취소를 서버에 반영하고 담긴 상태를 받아 온다. 다른 멤버·다른 번들·광고에서 콕한 장소도 처음부터 「콕 했어요」다(구현 단위 10, 지금은 화면에서만 바뀜).
- [ ] 같은 장소는 위치의 외부 ID 기준으로 한 번만 담긴다(8.1.3 로직 4). 콕·취소해도 번들을 만든 번치에 알림을 보내지 않는다.
- [x] 참여 멤버 시트: 「참여 멤버」, 프로필 이미지 + 닉네임(역할 배지는 Figma 기준), 누르면 멤버 프로필. 나간·탈퇴한 멤버는 「작성자」이고 누를 수 없다.
- [x] 멤버 프로필: 큰 프로필 이미지·닉네임, 「참여중인 번치」 목록(이미지, 이름, 비공개면 자물쇠, 팔로우 버튼). 팔로우 버튼은 팔로워·팔로잉 목록(5.11.1)과 같은 컴포넌트이고 현재 번치 기준, 현재 번치 자신의 줄에는 버튼 없음. 정렬은 한글 → 영문(대소문자 무시) → 숫자. 번치 줄을 누르면 그 번치 프로필, 우리 번치면 번치 메인(지금은 fixture).
- [ ] 멤버 프로필의 서버 반영: 팔로우 저장, 현재 번치 기준 상태 받기, 차단 관계인 번치 제외(구현 단위 10).

## 상태

- 로딩: 피드 첫 목록, 이어서 불러오기(목록 끝), 번들 상세, 댓글 목록과 이어서 불러오기, 멤버 프로필, 참여 멤버 시트.
- 빈 상태: 피드 두 구간 모두 없음(체크 애니메이션 + 「모든 피드를 확인했어요」), 팔로우한 번치 번들 없음(공개 구간부터), 댓글 없음(「아직 작성된 댓글이 없어요」), 위치·날짜 없음(줄 숨김).
- 오류: 오류 토스트 기본 문구는 「일시적인 오류가 발생했어요. 다시 시도해 주세요」다.
  - 목록·상세·댓글·멤버 프로필 로딩 실패, 좋아요·콕하기·콕 취소·댓글 등록·삭제·신고·광고 숨기기·수정 저장·삭제 실패. 콕하기 실패는 버튼을 「콕하기」로, 콕 취소 실패는 장소를 그대로 둔다.
  - 다른 멤버가 그사이 이미 뺀 장소의 콕 취소, 이미 지워진 댓글 삭제 → 바뀐 상태로 맞추고 따로 안내하지 않는다.
  - 이어서 불러오다 실패하면 보이던 목록은 두고, 다시 스크롤하면 재시도한다.
  - 사진 로딩 실패는 회색 자리표시, 프로필 이미지 실패는 기본 이미지.
  - 그사이 삭제된 번들(카드에서 「삭제된 번들이에요.」 후 목록 새로고침, 상세에서 「삭제되었거나 볼 수 없는 내용이에요」 후 이전 화면), 삭제된 번치(「삭제된 번치예요.」 후 이전 화면), 차단 관계(차단된 번치 화면).
  - 댓글을 쓰는 사이 번들이 삭제되거나 「멤버 공개」로 바뀜 → 등록하지 않고 「더 이상 볼 수 없는 번들이에요.」 후 이전 화면. 답글 대상 댓글이 그사이 지워졌으면 답글을 저장하지 않고 토스트 「삭제된 댓글입니다」(6.2.8).
  - 역할이 바뀌어 권한 없음 → 「권한이 변경되어 해당 기능을 이용할 수 없어요.」 후 새로 고침.
- 성공: 「번들을 수정했어요」, 「번들을 삭제했어요」, 「댓글이 삭제 되었어요.」(Figma 문구), 「신고가 접수됐어요.」, 광고 숨김 자리의 「장소를 숨김 처리 했어요」.

- 캐시: 좋아요는 카드와 상세가 같은 값을 보이므로 같은 번들의 피드 목록 캐시와 상세 캐시를 함께 고친다(optimistic update 3단계 계약, `docs/architecture/data-layer.md`). 번치를 전환하면 현재 번치가 key 입력이라 피드·상세가 새 번치 기준으로 바뀐다.
- 노출 판단(차단·신고·공개 범위·팔로우 승인)은 서버가 한다. 화면은 받은 목록을 거르지 않는다.

## 확인이 필요한 항목

기획

- 상세 캡션은 기획 변경으로 뺐다. 공동 편집의 사진 캡션 입력과 수정(6.2.12)의 캡션도 함께 없어지는지.
- 위치 밑줄: 명세는 위치가 2개 이상일 때만 밑줄이지만 디자인 시스템 `BundleInfo`는 위치가 하나여도 밑줄. Figma 기준 확인.
- 경과 시간 「N일 전」을 지난 24시간 단위로 셀지, 달력 날짜로 셀지. 지금은 24시간 단위(`features/feed/lib/elapsedTime.ts`).
- 발행 후 수정 권한 문구: 번들 업로드 확인창은 「업로드 이후에는 관리자만 수정할 수 있어요.」인데, 6.2.11 로직 1은 "수정·삭제는 메인 관리자뿐"이다. 문구를 「메인 관리자만」으로 맞출지.
- 삭제된 번들 안내 문구가 세 가지다: 카드 「삭제된 번들이에요.」(6.1.3), 상세 「삭제되었거나 볼 수 없는 내용이에요」(6.2.1), 댓글 등록 「더 이상 볼 수 없는 번들이에요.」(6.2.8)·알림 「더 이상 볼 수 없는 번들이에요」(6.2.13 로직 4, 마침표 없음). 의도한 구분인지.
- 오류 토스트 끝 마침표가 절마다 다르다(「…다시 시도해 주세요」와 「…다시 시도해 주세요.」). 하나로 통일할지.
- 번들 삭제 확인창 제목이 「게시글을 삭제할까요?」, 번들 신고가 「이 게시글을 신고할까요?」다. 다른 곳은 「번들」이라 부른다. 의도한 용어인지.
- 6.2.7 로직 번호가 3 → 「- 4.」 → 5로 이어지는 원본 표기 문제(내용은 이 spec에 반영).
- 피드 스크롤 위치 유지(6.1.1 상세 6)가 번치 전환 뒤 맨 위로 이동(로직 2)과 충돌하지 않는지: 전환할 때만 맨 위로 간다고 이해했다.
- 멤버 프로필(6.3.3)에 비공개 번치 이름·이미지도 보인다. 승인 전 번치에도 「이 사람이 비공개 번치 소속」임을 보여도 되는지, 프로필을 모으면 명단을 일부 복원할 수 있는데 확정인지. API 연결 전에 정한다.
- 6.2.12 로직 7이 콕한 장소를 「가볼 곳」으로 부른다. 번치 메인은 「콕한 장소」로 이름을 바꿨으므로(#238 브랜치에서 반영) 같은 대상인지, 문구를 맞출지.
- 6.3.1 로직 6 「추천카드 장소는 해당되지 않는다」: 추천카드가 광고 카드(BUNCH PICK)를 말하는지.
- 콕 취소 모달 버튼 순서: 6.3.1은 「아니요」/「삭제하기」다. 다른 확인 모달은 「취소」/「삭제」라 문구가 다르다. 의도한 것인지.

디자인

- Figma 노드: 피드 탭, 번들 카드, 광고 카드, 번들 상세, 댓글, 시트 3종, 멤버 프로필, 수정 화면.
- 애니메이션 자산 `FeedCaughtUp_Confetti`·`FeedCaughtUp_Check`: 로티 파일은 받아 `apps/web/src/shared/assets/lotties/feedCaughtUp*.json`에 두었다(표현식 없음). 재생 화면은 아직 없다.
- 번치 배지 색(분위기 4종)의 토큰.

백엔드

- 위 API 표 전체. 특히 피드 커서 형식(두 구간을 이어 붙이는 방법), 한 번에 받는 개수, 광고 자리 표시 방법.
- 좋아요·댓글 등록의 중복 요청 키(`Idempotency-Key`) 지원 여부.
- 소속 번치가 없을 때 피드 조회 허용(6.1.7 로직 1)과 가입 중 거부의 오류 코드.
- 나간·탈퇴한 멤버의 표시 정보(코멘트·댓글·참여 멤버)를 응답에 어떻게 담는지.

web

- 광고 외부 링크를 앱 쉘에서 앱 밖 브라우저로 여는 bridge 계약(`docs/architecture/mobile-shell.md`). 링크 검증 규칙과 함께 security-reviewer 대상이다.
- 번들 상세를 `(main)` 밖 독립 경로로 둘 때 하단 탭 막대·전환 효과(SSGOI) 처리. route-reviewer 대상이다.
- 번들 수정이 공동 편집 화면을 다시 쓰면 자동 저장을 끄고 「저장」 한 번으로 보내야 한다. 재사용과 별도 화면 중 고를 것.
