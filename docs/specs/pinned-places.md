# 기능: 콕한 장소 (기능명세서 8장)

> Status: Draft
> Date: 2026-11-07

기능명세서의 **8장 콕**(8.1.1~8.1.9)을 구현 범위로 정리한 문서다. 우리 번치 멤버들이 번들이나 BUNCH PICK에서 콕해 둔 장소를 한곳에 모아 보는 화면이다. 기능 ID는 모두 FEED-10이고, 명세서 절 번호(8.1.4 등)로 원본과 대조한다.

장소를 담는 동작(장소 콕하기 시트 6.3.1, 광고 카드 「콕하기」 6.1.5)은 `docs/specs/feed.md`, 화면 입구인 번치 메인 「콕한 장소」 버튼(5.1.4)은 `docs/specs/bunch-home.md`가 맡는다. 화면은 아직 없다. 장소 카드 컴포넌트 `LocationCard`만 디자인 시스템에 있다(#245).

## 목적

- 함께 가 보고 싶은 장소를 번치 단위로 쌓아 두고 다시 본다.
- 누가 콕했는지 멤버별로 나눠 본다.
- 장소를 담아 온 원래 번들로 돌아가거나, 주소를 복사해 지도 앱에 붙여 넣는다.
- 필요 없어진 장소를 빼고, 잘못 뺐으면 바로 되돌린다.

## 문제 정의

- 피드에서 콕한 장소가 어디에도 모이지 않으면 콕하기를 할 이유가 없다.
- 장소는 번치 것이고 멤버 누구나 담고 뺄 수 있다. 다른 멤버가 그사이 바꾼 상태와 어긋나지 않게 맞춰야 한다(8.1.8 예외).
- 원래 번들이 지워지거나 볼 수 없게 돼도 장소는 남는다. 카드가 이동할 곳이 없는 상태를 따로 다뤄야 한다(8.1.6).

## 범위 외 항목

- 장소를 담는 동작과 콕 취소 모달(6.3.1, 6.1.5). `feed.md` 범위다.
- 번들 상세 화면(6.2). 이 화면은 그 화면으로 가는 입구만 둔다.
- 실시간 반영. 다른 멤버가 콕하거나 뺀 것은 진입·새로고침·앱 복귀 때만 반영한다(8.1.1 로직 4).

## 대상 사용자와 접근 권한

- 현재 번치 멤버라면 역할과 관계없이 들어오고, 같은 메뉴를 쓴다(8.1.1 로직 2, 8.1.4 로직 1).
- 다른 멤버가 콕한 장소도 똑같이 복사하고 뺄 수 있다.
- 다른 번치의 콕한 장소는 볼 수 없다. 번치를 전환하면 그 번치의 콕한 장소가 보인다.

## 사용자 흐름과 route

path는 제안이다. 번치 메인 하위 화면이라 번치 경로 아래에 두고, 하단 탭 막대 없이 연다.

| 화면(명세 절)       | path(제안)                 | 진입·이탈                                          |
| ------------------- | -------------------------- | -------------------------------------------------- |
| 콕한 장소 (8.1.1)   | `/bunch/pinned`            | 번치 메인 「콕한 장소」 버튼. 뒤로가기는 번치 메인 |
| 더보기 시트 (8.1.4) | 화면 위 바텀시트           | 카드 더보기(⋯)                                     |
| 번들 상세 (8.1.5)   | `feed.md`의 번들 상세 경로 | 카드 누름. 뒤로가기는 콕한 장소(필터·스크롤 유지)  |
| 피드 (8.1.9)        | `/feed`                    | 빈 상태의 「피드 둘러보기」                        |

## 요구사항

### 필수 (Must Have)

화면 구성 (8.1.1)

- [ ] 헤더는 뒤로가기(<)만, 제목 없음. 헤더와 필터 칩은 고정되고 카드 목록만 스크롤한다.
- [ ] 아래로 당기면 새로고침. 목록 로딩 실패는 오류 토스트.
- [ ] 보고 있던 번치가 삭제되었거나 내보내졌으면 번치 전환 목록의 접근 불가 안내와 같게 처리한다(5.2.3).

멤버별 필터 (8.1.2)

- [ ] 맨 앞 「전체 N」(우리 번치의 콕한 장소 전체 수, 0개여도 「전체 0」), 그 뒤 멤버 칩(프로필 이미지 + 닉네임 + 그 멤버가 콕한 수). 가로 스크롤.
- [ ] 콕한 장소가 0개인 멤버 칩에는 숫자를 붙이지 않는다. 멤버 칩은 지금 번치 멤버 전원이고 순서는 멤버 관리(5.6.1 로직 1)와 같다.
- [ ] 한 번에 하나만 선택(선택 칩은 진한 배경·흰 글씨). 처음 들어오면 「전체」, 화면을 나가면 기억하지 않는다.
- [ ] '콕한 멤버'는 그 장소를 처음 콕한 사람이다. 나간 멤버(나가기·내보내짐·탈퇴)가 콕한 장소는 목록에 남고 「전체」에만 세며, 그 멤버 칩은 보여주지 않는다.
- [ ] 장소를 빼거나 되돌리면 칩 숫자를 바로 바꾼다. 고른 멤버가 그사이 나갔으면 새로고침 때 칩을 빼고 「전체」로 바꾼다.

장소 카드 (8.1.3, `LocationCard`)

- [ ] 지도 핀, 장소 이름, 주소, 출처 줄 「{번치 이름} | {번들 제목}」, 오른쪽 위 더보기(⋯). 정렬은 최근에 콕한 장소가 위.
- [ ] 광고에서 콕한 장소는 출처 자리에 「BUNCH PICK」, 눌러도 이동하지 않는다.
- [ ] 원래 번들을 볼 수 없는 장소는 출처 자리에 「볼 수 없는 번들이에요」(8.1.6).
- [ ] 이름·주소가 길면 끝을 「…」로, 출처가 길면 번들 제목 끝을 「…」로 줄인다.
- [ ] 장소 이름·주소는 번들 위치에 저장된 값, 번치 이름·번들 제목은 지금 값으로 보여준다.
- [ ] 아래로 스크롤하면 이어서 불러온다. 이어서 불러오다 실패하면 보이던 카드는 두고 다시 스크롤할 때 재시도한다.
- [ ] 원래 번들에서 그 위치가 수정으로 지워지거나 바뀌면 카드는 알림 없이 빠진다. 원래 번들이 삭제된 경우는 카드가 남는다(6.2.12, 6.2.13).

카드 눌러 번들로 이동 (8.1.5~8.1.6)

- [ ] 카드를 누르면 이동하기 전에 서버가 그 번들을 지금 볼 수 있는지 다시 확인하고, 볼 수 있으면 번들 상세로 이동한다. 연타는 첫 탭만.
- [ ] 볼 수 없으면 이동하지 않고 모달: 「이 장소가 담긴 번들을 더 이상 볼 수 없어요」 / 「번들이 삭제되었거나 비공개로 바뀌었어요.」 / 「취소」·「콕에서 빼기」.
  - 「콕에서 빼기」는 8.1.8과 같은 처리(토스트·되돌리기 포함).
  - 「취소」는 모달만 닫고, 목록을 연 뒤에 볼 수 없게 된 카드였으면 「볼 수 없는 번들이에요」 상태로 바꾼다.
- [ ] 확인 요청 실패(네트워크)는 이동하지 않고 오류 토스트.
- [ ] 다시 볼 수 있게 되면(공개로 돌아옴, 팔로우 승인, 차단 해제) 다음에 목록을 불러올 때 원래 표시로 돌아온다.

더보기 메뉴 (8.1.4, 8.1.7~8.1.8)

- [ ] 더보기(⋯) → 바텀시트(뒤 화면 어둡게): 「주소 복사하기」(복사 아이콘) / 「콕에서 빼기」(휴지통 아이콘) / 「취소」. 볼 수 없는 번들·광고 장소도 같은 메뉴.
- [ ] 주소 복사하기: 주소 전체를 클립보드에 복사(장소 이름은 넣지 않음), 시트를 닫고 토스트 「주소를 복사했어요.」(체크 아이콘). 저장된 주소가 없으면 장소 이름을 복사한다. 서버 요청 없음. 클립보드 접근 실패는 오류 토스트.
- [ ] 콕에서 빼기: 확인 모달 없이 시트를 닫고 카드를 바로 뺀다(아래 카드가 한 칸씩 올라옴). 토스트 「콕한 장소에서 뺐어요」(체크 아이콘) + 「되돌리기」.
- [ ] 되돌리기: 뺀 장소를 원래 자리로 되돌린다. 콕한 멤버·시각·담아 온 번들도 원래대로(새로 콕한 것으로 치지 않음). 토스트가 사라진 뒤에는 되돌릴 수 없다.
- [ ] 빼거나 되돌려도 알림을 보내지 않는다. 마지막 장소를 빼면 빈 상태.

빈 상태 (8.1.9)

- [ ] 고른 필터 기준으로 장소가 없으면 목록 자리 가운데: 「아직 콕한 장소가 없어요」 / 「피드에서 다른 번치의 번들을 둘러보면서 가보고 싶은 장소를 콕 해보세요.」 / 「피드 둘러보기」(피드 탭으로). 필터 칩은 그대로 둔다.
- [ ] 전체가 0개일 때와 고른 멤버만 0개일 때 같은 빈 상태를 쓴다.

### 있으면 좋은 것 (Nice to Have)

- [ ] 번들 상세에서 돌아왔을 때 필터 칩과 스크롤 위치 유지(8.1.5 상세 2). 필수 동작이지만 구현 방식(캐시·히스토리 상태)은 화면을 만들 때 정한다.

## 상태

- 로딩: 첫 목록, 이어서 불러오기, 카드 누를 때 볼 수 있는지 확인.
- 빈 상태: 전체 0개, 고른 멤버 0개(같은 빈 상태).
- 오류: 기본 문구 「일시적인 오류가 발생했어요. 다시 시도해 주세요」.
  - 목록 로딩, 이어서 불러오기, 확인 요청, 클립보드, 빼기, 되돌리기 실패.
  - 빼기 실패는 카드를 원래대로 되돌린다. 되돌리기 실패는 빠진 상태로 둔다.
  - 다른 멤버가 이미 뺀 장소 → 목록에서 빼고 따로 안내하지 않는다.
  - 「되돌리기」 전에 다른 멤버가 같은 장소를 다시 콕함 → 되돌리지 않고 다시 콕한 상태를 그대로 보여준다.
- 성공: 「주소를 복사했어요.」, 「콕한 장소에서 뺐어요」(되돌리기).

| 필터 칩 수             | 현재 번치. 응답: 전체 수, 멤버별 수(지금 멤버만)                                                                                                                           | 8.1.2        |

| 콕에서 빼기            | 콕 ID, 현재 번치. 이미 빠졌으면 성공으로 맞춤                                                                                                                              | 8.1.8        |

- 캐시: 빼기는 목록과 필터 칩 수를 함께 고친다(optimistic update, 실패하면 되돌림, `docs/architecture/data-layer.md`). 장소 콕하기 시트·광고 카드의 「콕 했어요」 상태와 같은 데이터라, 빼거나 되돌리면 그 캐시도 무효화한다(8.1.8 로직 3).
- 번치를 전환하면 현재 번치가 key 입력이라 새 번치 기준으로 바뀐다.

## 확인이 필요한 항목

기획

- 8.1.1 상세 1은 입구를 「깃발 아이콘 + 「콕한 장소」」라고 한다. 번치 메인에서 이미 이렇게 바꿨다(#238 브랜치). 피드 명세 6.2.12 로직 7은 아직 「가볼 곳」이라 문구를 맞출지(`feed.md` 확인 항목과 같음).
- 되돌리기 토스트의 표시 시간(8.1.8 로직 5 「다른 토스트와 같다」): 되돌리기 버튼이 있어 더 길어야 하는지.
- 볼 수 없는 번들 모달의 「콕에서 빼기」는 확인 없이 바로 빼는지(8.1.8처럼). 모달 자체가 확인 역할이라고 이해했다.

디자인

- Figma 노드: 콕한 장소 화면(필터 칩, 빈 상태), 더보기 시트, 볼 수 없는 번들 모달, 되돌리기 토스트.
- 「볼 수 없는 번들이에요」의 글자 굵기(`LocationCard`는 번치 이름과 같은 Caption-1-Medium으로 그림).
- 필터 칩 컴포넌트가 기존 칩(`ChipButton` 등)과 같은지.
