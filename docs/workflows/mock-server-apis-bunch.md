# 가짜 서버 연동: 번치

번치 홈·전환·온보딩·프로필 편집·멤버·더보기·다른 번치·팔로우·차단·알림의 가짜 서버 연동이다. 전체 현황과 샘플로 남긴 부분은 [mock-server-status.md](mock-server-status.md), 명세 차이는 [mock-server-backend-gaps.md](mock-server-backend-gaps.md)를 본다.

| 화면·기능                        | 사용하는 API                                                                                                                                                                                                                                                         | 비고                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 번치 홈 작성 중인 번들           | `GET …/bundles?status=DRAFT`, `DELETE …/bundles/{id}`, `POST …/bundles/{id}/leave`                                                                                                                                                                                   | 초안이 최근 수정순 카드로 보이고(제목이 없으면 「제목 없는 번들」), 누르면 작성 화면으로 이동. 삭제·작성 화면의 「나가기」가 서버에 반영되며 생성자가 나가면 초안 삭제                                                                                                                                                                                                                                                                                     |
| 번치 홈 프로필·권한·개수         | `GET /bunches/{id}/home`                                                                                                                                                                                                                                             | Swagger 생성 타입(`BunchHomeResponse`)과 스키마를 묶음(#408). 접근 범위 필드(`accessScope` 등)는 계약상 필수지만 선택으로 받음                                                                                                                                                                                                                                                                                                                             |
| 번치 홈 완성된 번들              | `GET /bunches/{id}/published-bundles`                                                                                                                                                                                                                                | 발행 최신순 50개씩, 그리드 끝에서 다음 쪽을 이어서 받음(`page`·`hasNext`). 화면에 필요한 필드만 받아 생성 타입(`BunchSocialPageBunchPublicBundleCard`)과는 아직 묶지 않음                                                                                                                                                                                                                                                                                  |
| 번치 전환 목록·접근 불가 안내    | `GET /members/me/bunches`, `PUT /bunches/{id}/last-used`, `GET·DELETE /members/me/bunch-access-notices/{noticeId}`                                                                                                                                                   | 전환하면 기본 번치(`members/me`)가 그 번치로 바뀜(실서버 동작 확인 필요). 가짜 서버는 두 번째 번치 「퇴근런클럽」과 접근 불가 안내 2건을 둠. 내가 소속되지 않은 번치에 안내가 있으면 그 번치 홈은 다른 오류보다 먼저 `409 BUNCH_008`(detail `noticeId`·`reason`, 명세 074). 확인한(지운) 안내 조회는 `RESOURCE_001`                                                                                                                                        |
| 온보딩 번치 만들기               | `GET /bunches/name-availability`, `POST /bunches/introduction-validation`, `POST /bunches`, `PUT·DELETE /bunches/{id}/profile-image`, `POST /bunches/{id}/invitations`                                                                                               | 생성은 `Idempotency-Key` 필수(BFF가 헤더를 전달함), 사진은 시연용 이미지로 바뀌고 초대 링크는 번치마다 고정 주소                                                                                                                                                                                                                                                                                                                                           |
| 온보딩 초대 참여                 | `GET /invitations/{token}`(공개 조회, 초대 링크 진입 페이지), `POST /invitations/verify`, `POST /invitations/join`                                                                                                                                                   | 참여는 `Idempotency-Key` 필수. 시연용 초대 코드 `MOCKJOIN`(여행가조, 참여하면 초대한 사람(OWNER)과 함께 번치가 생김), 초대 발급이 준 `MOCK####`(그 번치), 그 밖은 `INVITE_001`                                                                                                                                                                                                                                                                             |
| 번치 프로필 편집                 | `PUT /bunches/{id}/profile`(multipart `profile` JSON·`photo`), `GET /bunches/name-availability?excludeBunchId=`                                                                                                                                                      | `Idempotency-Key` 필수, `expectedProfileVersion`이 다르면 409, 이름 중복은 409 `BUNCH_001`. 사진은 시연용 이미지로 바뀜                                                                                                                                                                                                                                                                                                                                    |
| 번치 멤버 관리                   | `GET /bunches/{id}/memberships`, `PUT …/memberships/{id}/role`, `POST …/memberships/{id}/remove`, `POST /bunches/{id}/owner-transfer`                                                                                                                                | 소속 ID는 회원 ID로 대신함, `expectedMembershipVersion`이 다르면 409, 넘기기는 `Idempotency-Key` 필수                                                                                                                                                                                                                                                                                                                                                      |
| 번치 더보기·나가기·삭제          | `POST /bunches/{id}/leave`(메인 관리자는 `successorMembershipId`로 넘기기와 함께), `POST /bunches/{id}/deletion`(`confirmation`)                                                                                                                                     | 둘 다 `Idempotency-Key` 필수, `expectedMembershipVersion`이 다르면 409. 확인 문구는 화면 문구 「삭제하기」로 보냄(실서버 값 확인 필요). 후임 없는 메인 관리자 나가기는 가짜 코드 `MOCK_OWNER_SUCCESSOR`, `outcome`은 가짜 값 `LEFT`·`DELETED`                                                                                                                                                                                                              |
| 다른 번치 프로필·팔로우          | `GET /bunches/{id}/home`(`accessScope: EXTERNAL`, 지금 번치 명의의 `followState`·`followId`·`canViewBundles`·`canViewRelations`), `GET /bunches/{id}/published-bundles`(볼 수 있을 때만), `PUT·DELETE /bunches/{viewerId}/following/{targetId}`(취소는 `?followId=`) | 가짜 서버에 다른 번치 「캠핑러버」(3, 공개)·「책방산책」(4, 비공개)을 둠(피드 샘플과 같은 ID). 권한 오류는 `AUTH_002`, 자기 번치 팔로우는 `COMMON_001`(명세에 코드 없음)                                                                                                                                                                                                                                                                                   |
| 멤버 프로필                      | `GET /members/{memberId}/social-profile`                                                                                                                                                                                                                             | 명세 020: 멤버가 소속된 번치마다 지금 번치 기준 팔로우 상태·관계 ID, 지금 번치 자신과 소속 번치 없음이면 `showFollowButton` false. 차단 관계 번치는 뺌. 없는 멤버는 `RESOURCE_001`(탈퇴·권한 없음과 구분하지 않음). 비공개 번치 소속을 승인 전 번치에도 보이는지는 기획 결정 전이라 그대로 보임(실서버 확인 필요). 정렬은 화면이 함                                                                                                                        |
| 팔로워·팔로잉 목록과 팔로우 요청 | `GET /bunches/{targetId}/followers`·`following`(행의 `followState`는 지금 번치 명의), `GET /bunches/{viewerId}/follow-requests`, `POST …/follow-requests/{requestId}/decision`(`APPROVE`·`REJECT`)                                                                   | 팔로워·팔로잉은 50개씩 목록 끝에서 이어서 받음(`page`·`hasNext`), 팔로우 요청은 첫 쪽 50개만. 가짜 서버에 목록용 다른 번치 5~9와 팔로우 관계를 둠(여행쥬아 팔로워 3·팔로잉 2·대기 요청 3). 이미 승인된 요청은 `applied: false`·`APPROVED`, 없어진 요청은 `UNAVAILABLE`(실서버 동작 확인 필요)                                                                                                                                                              |
| 번치 차단·신고와 차단 목록       | `GET /bunches/{viewerId}/blocks`, `PUT /bunches/{viewerId}/blocks/{targetId}`, `DELETE …/blocks/{targetId}?blockId=`(목록 항목 ID), `POST /bunches/{viewerId}/reports`(`targetBunchId`·`reason`·`detail`)                                                            | 50개씩 목록 끝에서 이어서 받음(`page`·`hasNext`, 다른 번치 화면의 차단 여부는 받은 쪽 기준). 가짜 서버에 여행쥬아가 차단한 번치 2개(야간러너스·주말산책)를 둠. 해제는 메인·공동 관리자만(그 밖 403). 차단하면 두 번치 사이 팔로우·요청을 지우고, 어느 쪽이든 차단 관계면 그 번치의 홈·공개 번들·관계 목록이 403(명세에 없어 정한 값, 화면은 접근 제한). 웹은 차단 성공 뒤 남은 팔로우를 해제함(실서버가 함께 정리하는지 확인 필요, 이미 정리돼 404면 무시) |
| 번치 알림 목록·열기·모두 읽음    | `GET /bunches/{id}/notifications`, `POST …/notifications/{notificationId}/open`, `POST …/notifications/read-all`                                                                                                                                                     | 50개씩 목록 끝에서 이어서 받음(51번째부터 다음 쪽, `page`·`hasNext`). 가짜 서버에 여행쥬아 알림 4개(읽지 않음 3개, 지워진 번들을 가리켜 열 수 없는 1개)와 퇴근런클럽 1개를 둠. 번치 홈·내 번치 목록의 `unreadCount`도 이 알림으로 셈. 알 수 없는 `type`·`kind`는 문자열로 받고 번치 홈으로 보냄                                                                                                                                                            |
