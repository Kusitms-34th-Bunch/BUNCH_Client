# 가짜 서버 연동: MY·사진함·피드

로그인·가입 상태, MY(프로필·알림 설정·푸시·탈퇴·추가 정보), 사진함, 피드·광고의 가짜 서버 연동이다. 전체 현황과 샘플로 남긴 부분은 [mock-server-status.md](mock-server-status.md), 명세 차이는 [mock-server-backend-gaps.md](mock-server-backend-gaps.md)를 본다.

| 사진함 목록·날짜 미확인·상세·삭제 | `GET /bunches/{id}/photos`, `/photos/undated`, `/photos/{photoId}`, `POST …/photos/delete`, `POST …/photos`(업로드)                                           | 작성 중(DRAFT) 번들에 담긴 사진은 `usedInDraftBundle: true`(서버 PR #140, 발행된 번들에만 쓰인 사진은 false). 사진을 지우면 가짜 서버도 작성 중인 번들에서 그 사진을 빼고 0장이 된 초안은 지움. 서버가 필수로 내려 주므로 앱도 필수로 검증한다(없는 응답은 파싱 오류)                                                                                                                                                                                                                                                                                                                                                                        |

| 로그인·가입 상태                  | `GET /members/me/onboarding`, `POST /auth/terms/agreements`, `POST /members/me/registration`, `POST /api/auth/logout`·`/api/auth/reissue`, `GET /api/session` | 가짜 DB의 `session`을 따른다. 시작 세션은 `localStorage['bunch:mock-session']`으로 고르고, 저장된 가짜 DB가 없을 때만 읽는다(`anonymous` 비로그인, `signup-terms` 약관 전 가입 중이고 소속 번치 없음, 없으면 가입 완료). 약관 저장은 동의로 바꾸고 본문에 `DEMOGRAPHICS` 동의가 있으면 추가 개인정보 동의로 저장한다. 가입 완료는 `COMPLETED`로 바꾸고, `profile`에 동의 버전이 있을 때만 추가 개인정보 동의와 출생연도·성별을 저장한다(버전 값은 검사하지 않음). 로그아웃하면 세션 확인·재발급·가입 상태가 401이다. 다시 로그인하는 경로는 없다 로그아웃 뒤 재발급 401의 `code`는 실제 BFF의 쿠키 없음과 같은 `BFF_NO_SESSION`이다(#498).   |

| MY 프로필 수정·회원 탈퇴          | `PUT /members/me/profile`, `GET /members/me/withdrawal/check`, `POST /members/me/withdrawal`                                                                  | 프로필 수정은 multipart를 읽어 닉네임·사진 처리(`KEEP`·`REPLACE`·`RESET`)·출생연도와 성별(`demographics`, 빠진 값은 null)을 반영하고 새 사진은 시연 이미지로 바꿈. 동의하지 않았는데 `demographics`를 보내면 400 `MOCK_ADDITIONAL_INFO_NOT_CONSENTED`(실서버 코드 미확인). 「중복」이 들어간 닉네임은 `USER_002`(Swagger에 오류 코드 없음, 가입과 같게 둠). 탈퇴 확인은 내가 메인 관리자인 번치(혼자 있는 번치 포함, 소속 ID는 회원 ID로 대신), 탈퇴는 다른 멤버가 있는 번치의 메인 관리자면 409 `MOCK_WITHDRAWAL_OWNER`이고 성공해도 시연 데이터는 지우지 않음. 가짜 DB 기본값은 메인 관리자인 번치가 없어 「다음」이 바로 최종 확인으로 감 |
