# 가짜 서버와 서버 연동 현황

가짜 서버(MSW, `apps/web/src/mocks`)로 연결한 화면과 아직 샘플 데이터로 둔 화면, 가짜 서버와 서버 명세의 차이를 모은다. 가짜 서버를 켜고 쓰는 방법은 [testing.md](./testing.md)의 「MSW 가짜 서버」를 본다.

## 연동 상태와 샘플로 남긴 부분

번치 홈 → 번들 만들기 → 초안 작성 → 업로드 → 번치 홈 흐름만 가짜 서버(MSW)로 연결했고, 나머지는 샘플 데이터로 두었다. 샘플로 둔 것은 서버 계약이 없거나(서버 PR 미병합) 사용성 테스트(UT, 2026-11 종료) 범위 밖이어서다. 값을 임의로 정한 것도 아래에 모았다.

## 가짜 서버와 서버 명세의 차이, 백엔드 확인 항목

가짜 서버(`src/mocks`)는 Swagger와 Notion 명세를 기준으로 만들었지만, 명세끼리 다르거나 가짜 서버가 다르게 동작하는 부분이 있다. 실서버를 연결할 때 아래를 확인한다. 화면별 후속은 각 feature의 spec에 있다.

### 가짜 서버가 명세와 다른 부분

| 영역             | 차이                                                                                                                                                                                                                                   | 비고                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 사진 업로드      | 같은 파일 판별은 파일 바이트의 SHA-256이고, 합치기는 사진함 1,000장 한도를 넘어도 허용하며 합쳐진 요청도 같은 묶음 50장에 센다. 하루 100장(`PHOTO_002`)은 흉내 내지 않고, 올린 파일은 보관하지 않고 시작 데이터의 이미지로 대신 보인다 | 서버는 지금 업로드된 JPEG의 SHA-256으로 판별하지만, 실기기에서 같은 원본의 가공본 해시가 기기마다 달라 합쳐지지 않았다(원본 해시는 같음). 앱은 가공 전 원본의 SHA-256(`originalFileHash`, 소문자 hex 64자)을 평면 폼 필드로 보내고 목 서버는 이 값이 있으면 같은 사진 판별에 쓴다(서버의 필드 이름·형식·기존 사진 처리는 확정 대기, 지각 해시는 도입하지 않고 외부 매체 전송본은 다른 사진), 한도 집계는 확정 전, 요청은 Swagger와 달리 `request` JSON 파트가 아니라 `uploadBatchId`·`capturedDate`·`capturedTime` 별도 필드로 받음(실서버 확인, `capturedTime`은 `HH:mm:ss` 문자열) |
| 번들 작성        | 날짜 미래 금지 검사가 없다                                                                                                                                                                                                             | 명세에는 있음                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| 번들 작성        | 날짜 저장에서 오래된 `expectedVersion`을 BUNDLE_003으로 거절한다(실서버 v5 명세는 거절하지 않고 마지막 저장 순서로 적용)                                                                                                               | 실서버 연결 때 맞춤(v5 번들 날짜 수정 명세)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| 번들 작성        | 초안 생성의 `participantMemberIds`(서버는 생성자를 뺀 1명 이상 필수)를 읽지 않고 사진 업로더로 참여자를 만든다. 화면도 아직 참여자를 넘기지 않는다(실서버 연동 이슈에서 연결)                                                          |
| 번들 발행        | 다른 멱등 키로 같은 본문을 다시 발행하면 `BUNDLE_002`                                                                                                                                                                                  | 명세는 최초 요청과 같으면 허용                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| 번치 프로필 편집 | 버전 충돌을 409 `MOCK_PROFILE_VERSION`(가짜 코드)으로 거절한다                                                                                                                                                                         | Swagger에 오류 코드가 없음. 화면은 `BUNCH_001` 밖의 실패를 하나로 다뤄 코드와 무관하게 동작                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| 번치 멤버 관리   | 버전 충돌을 409 `MOCK_MEMBERSHIP_VERSION`(가짜 코드)으로 거절한다                                                                                                                                                                      | Swagger에 오류 코드가 없음. 화면은 실패 뒤 다시 받은 버전으로 충돌을 판단                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| 번들 삭제        | 생성자 또는 번치 관리자면 초안·발행본 모두 삭제한다(명세 본문 기준)                                                                                                                                                                    | 후속 계약(PR #55, 미병합)은 초안 폐기를 참여 중인 생성자나 OWNER/CO_OWNER로, 발행본 삭제를 OWNER로 좁힐 수 있음                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |

### 백엔드에 확인할 것

| 영역      | 확인할 것                                                                                                                                                       |
| --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |

### 실서버를 연결할 때 정리할 것

- 가짜 서버만 있는 확장은 지금 없다(편집권·캡션은 #354에서 제거). 번들 응답의 `locations`·`locationVersion`은 2026-11 타입 재생성으로 서버 계약(BundleSnapshot)에 들어와 확장이 아니다. 가짜 서버는 저장된 위치를 계약 모양(`id`·`position` 포함)으로 돌려준다. 위치를 저장하는 요청 계약(`BundleLocationInput`)도 생성 타입에 있지만, 화면 연결은 장소 검색 이슈에서 한다.
- `public/mock/photos`(약 7MB)는 `NEXT_PUBLIC_API_MOCKING`과 무관하게 운영 배포에도 정적 파일로 공개된다. 얼굴이 없는 시연 사진이라 기밀 문제는 아니고 용량 문제다. 운영 배포에서 제외할 방안을 정한다.
- 사진 목록의 `thumbnailUrl`은 URL 형식을 검증하지 않고(상세 `imageUrl`만 검증), 이미지 호스트 allowlist도 없다. 실서버를 연결할 때 함께 정한다.
- 사진 목록은 100장씩 마지막 쪽까지 순차로 받는다(상한 1,000장). 사진함 화면은 첫 쪽이 오면 먼저 보여 주고 나머지는 이어서 받으며, 번들 만들기 화면은 마지막 쪽까지 받은 뒤에만 열린다. 날짜 미확인 영역의 「N장」은 받은 쪽까지의 수라 100장을 넘으면 다 받기 전까지 적게 보일 수 있다. 목록 query는 30초가 지나면 진입·앱 복귀 때 다시 받는다.
- 번치 홈 화면의 후속(쪽 크기, 다른 번치 열람, 표지 주소 대체 등)은 `BunchHomeScreen.spec.md`의 「서버 연동의 후속과 알려진 차이」에 있다.
