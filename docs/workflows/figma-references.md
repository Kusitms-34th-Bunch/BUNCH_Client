# Figma 참조

spec과 코드가 Figma 디자인과 내부 기획 자료를 가리킬 때의 위치와 표기 기준이다. Figma 구현 흐름은 `docs/workflows/development.md`의 "Figma·스크린샷 구현"을 따른다.

## 파일 위치

- 디자인과 화면설계서는 같은 Figma 파일 `BUNCH - 작업파일`에 있다.
- 파일 링크: https://www.figma.com/design/3nvm4AeRaybVAu8kUZv5Mv/BUNCH---작업파일
- 파일은 BUNCH 조직 구성원만 접근한다. 링크나 파일 키만으로는 열 수 없고, 에이전트는 Figma MCP를 인증한 사용자 권한으로 읽는다.
- 파일 키는 이 문서에만 둔다. spec·코드 주석·이슈·PR에는 파일 키가 든 링크를 쓰지 않고 node ID만 적는다.

## node 표기

- spec에는 ``node `93:2623` ``처럼 콜론으로 쓴다. 링크로 이동할 때는 위 파일 링크 뒤에 `?node-id=93-2623`을 붙인다. URL에서는 콜론 대신 하이픈을 쓴다.
- 에이전트는 이 문서의 파일 키와 spec의 node ID를 합쳐 Figma를 읽는다. 키가 필요한 도구에 spec만 있고 키가 없으면 이 문서에서 가져온다.
- 디자인 node는 `디자인 출처`, 화면설계서 node는 `화면설계서(node ...)`로 구분해 적는다.

## 비공개 자료 표기

PRD, 기능명세서, 화면설계서는 비공개 자료다. 원문을 저장소에 올리지 않고, spec·코드 주석·이슈·PR에는 아래만 적는다. 문서의 위치는 저장소 밖에서 팀이 공유하고, 저장소에는 문서 안의 위치를 가리키는 번호만 둔다(Figma 파일 키와 node ID의 관계와 같다).

| 대상       | 쓰는 표기                                                            | 쓰지 않는 것                                           |
| ---------- | -------------------------------------------------------------------- | ------------------------------------------------------ |
| PRD        | `내부 기획 문서`                                                     | 문서 이름, 장 번호, 우선순위, 일정                     |
| 기능명세서 | 요구사항 ID로 절 번호(`1.3.1` 등). 기능 spec 제목에 해당 장을 적는다 | 문서 링크, 본문 인용                                   |
| 화면설계서 | `화면설계서(node ...)`, 설계서 프레임은 `설계서 프레임 <node>`       | 설계서 파일 이름, 화면 이름·번호, 화면 코드, 본문 인용 |

- 결정과 이유는 spec에 적는다. 근거가 비공개 자료라도 "내부 기획 문서에 따라 X로 한다"처럼 결정을 먼저 쓰고, 읽는 사람이 비공개 자료 없이 구현 의도를 이해하게 한다.
- 화면설계서의 동작 값(전환 시간, 곡선 등)을 따랐거나 따르지 않았다면 그 값과 결정 이유를 spec에 적는다.
