# 가짜 서버 연동: 번들

번들 작성(초안·픽·사진 구성·실시간 연결·제목 병합·presence)과 발행 번들(상세·수정·삭제·좋아요·댓글·신고·콕)의 가짜 서버 연동이다. 전체 현황과 샘플로 남긴 부분은 [mock-server-status.md](mock-server-status.md), 명세 차이는 [mock-server-backend-gaps.md](mock-server-backend-gaps.md)를 본다.

| 번들 댓글·답글                          | `GET·POST /bundles/{bundleId}/comments`, `GET …/comments/{commentId}/replies`, `DELETE …/comments/{commentId}`                                                                        | 명세 014~017 규칙: 원댓글 최신순·답글 오래된 순, 커서는 번들·부모·지금 번치에 묶여 다르면 `COMMON_001`. 차단 관계 번치가 쓴 댓글과 그 원댓글의 답글은 목록·수에서 빠지고 삭제 자리는 남음. 등록은 `Idempotency-Key` 필수(같은 키·내용은 처음 댓글, 다른 내용은 `REQUEST_001`), 지운 원댓글·답글에 답글은 `BUNDLE_002`(새로 등록할 때만 검사, 같은 키 재전송은 처음 결과를 돌려주고 실패 응답도 키에 저장하는데 실서버 확인 필요), 삭제는 작성자만(`AUTH_002`). 탈퇴한 작성자의 댓글은 삭제 자리로 돌려줌. 접근 판정은 좋아요와 같고 읽기는 소속 번치가 없어도 됨. 피드·상세의 댓글 수도 이 기록으로 셈                                                                                                                                                                                                                        |

| 번들 장소 콕·콕한 장소 목록             | `GET /pinned-places?memberId=&size=&cursor=`, `GET /bundles/{bundleId}/pinned-places`, `PUT /bundles/{bundleId}/locations/{locationId}/pin`, `DELETE /pinned-places/{pinId}`          | 명세 009·010·021 규칙: 지금 번치 명의, 같은 장소(제공자·외부 ID)는 한 번만 담기고 다시 콕하면 그 콕을 돌려줌. 장소 ID는 피드·상세 응답과 같은 가짜 규칙(번들 ID×10 + 순서 + 1). 접근 판정은 좋아요와 같고 조회는 소속 번치가 없어도 됨(`canPin` false). 콕 취소는 지금 번치의 콕만(아니면 `RESOURCE_001`, 웹은 이미 빠진 것으로 보고 알리지 않음). 실서버 확인 필요: 없는 콕 취소가 404인지 멱등 200인지, 소속 번치 없음 `BUNCH_010` 코드. 시작 데이터에 장소가 있는 번들이 없음. 콕한 장소 목록(명세 005)은 지금 번치의 콕을 최근 콕한 순으로, 멤버 칩은 지금 멤버 전원과 처음 콕한 수, 지금 멤버가 아닌 `memberId`는 전체로 돌림. 원래 번들을 지금 볼 수 없으면(좋아요와 같은 접근 판정) 출처 값을 비움. 커서는 넘긴 개수(실서버는 불투명 값). 시작 데이터로 여행쥬아에 콕 7개(지워진 번들 1·광고 1·나간 회원 1 포함)를 둠. |
