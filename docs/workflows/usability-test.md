# 사용성 테스트(UT) 세팅

UT는 웹에서 한 기기로 진행하고, 다른 멤버가 할 행동은 "미리 해 둔 상태"로 세팅한다(확정). 진행자가 다른 기기로 같은 번치를 함께 조작하지 않는다.

## 왜 미리 세팅하나

- 번들 업로드에는 참여 멤버 2명 이상과 참여 멤버 전원의 코멘트가 필요하다. 그래서 참여자 혼자서는 업로드까지 갈 수 없다.
- 가짜 데이터는 기기(브라우저)마다 따로 있다. 진행자 기기에서 남긴 코멘트는 참여자 화면에 보이지 않는다. MSW 가짜 DB도 브라우저의 IndexedDB에 저장된다(`docs/workflows/testing.md`의 "MSW 가짜 서버").
- 따라서 진행자의 행동은 시작 데이터에 넣어 둔다. 참여자가 업로드 직전까지 막히지 않게 하는 것이 목적이다.

## 역할

| 역할   | 계정 상태                                                    | 하는 일                                           |
| ------ | ------------------------------------------------------------ | ------------------------------------------------- |
| 참여자 | 번들 초안을 처음 만드는 사람(초안 생성자, 업로드 권한 있음)  | 과제를 수행한다                                   |
| 진행자 | 같은 번치의 일반 멤버. 이미 참여 멤버이고 코멘트를 남긴 상태 | 화면은 조작하지 않고 과제 안내와 관찰·기록만 한다 |

문서와 시작 데이터에는 실제 사람 이름 대신 역할만 쓴다. 계정 정보와 배포 주소는 저장소에 올리지 않는다.

## 시작 데이터

세팅 위치는 화면의 연동 상태에 따라 다르다.

- 서버 연동 전 화면: 화면이 읽는 샘플 데이터(`features/<feature>/fixtures/`)에 넣는다. 번들 공동 편집 화면은 `features/bundle/fixtures/draft.fixture.ts`를 읽는다.
- 서버 연동 후 화면: MSW 가짜 DB 시작 데이터(`src/mocks/db/seed.ts`)에 넣고, `NEXT_PUBLIC_API_MOCKING=enabled`로 빌드한다.

넣어 둘 상태는 아래와 같다.

- 참여자는 번치 멤버이고, 번들 초안의 생성자다.
- 진행자는 같은 번치의 일반 멤버이고, 그 초안의 참여 멤버다.
- 진행자는 그 초안에 코멘트를 이미 남겼다.
- 참여자가 자기 코멘트를 쓰면 업로드 조건이 채워진다.

## 회차 전 준비

1. UT용 빌드를 HTTPS 주소 또는 localhost로 연다. 서비스 워커는 `http://IP` 접속에서 동작하지 않을 수 있다.
2. 브라우저의 사이트 데이터를 지운다. MSW 가짜 DB는 IndexedDB에 남아 새로고침해도 이전 회차 상태가 유지된다. 샘플 데이터 화면은 새로고침만으로 시작 상태로 돌아간다.
3. 새로고침한 뒤 첫 화면이 시작 데이터 상태인지 확인한다. 진행자가 참여 멤버로 보이고 코멘트가 있어야 한다.

## 회차 사이 초기화

회차가 끝나면 "회차 전 준비"의 2·3단계를 다시 한다. 앞 참여자가 남긴 사진·코멘트가 다음 참여자에게 보이면 안 된다.

## 확인하지 않은 것

- 진행 대본(과제 문구, 진행자가 개입하는 시점)은 정해지지 않았다(미정).
- UT용 시작 데이터는 아직 만들지 않았다. 대상 화면과 과제가 정해지면 위 상태대로 만든다.
