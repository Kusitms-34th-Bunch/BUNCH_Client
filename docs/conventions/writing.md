# Writing Rules

문서, PR·이슈 본문, agent의 분석과 보고는 읽는 사람이 한 번에 이해하게 쓴다. 문장, 용어, 구조는 아래 규칙을 따른다.

## 문장

- 한 문장에는 지시 하나 또는 사실 하나만 둔다. 읽다가 주어와 서술어가 멀어지면 나눈다. 새로 쓰는 문장이 100자를 넘으면 나눌 수 있는지 먼저 본다(제안).
- 주어와 행위를 드러낸다. "cache가 갱신된다"보다 "mutation hook이 cache를 갱신한다"처럼 누가 하는지 쓴다.
- 조건을 앞에 둔다. "X이면 Y한다"로 쓰고, "Y한다. 단 X인 경우"처럼 뒤로 미루지 않는다.
- 애매한 말 대신 기준과 값을 쓴다. "적절히", "필요하면", "가능하면"은 조건이나 수치로 바꾼다.

## 용어

- 같은 개념은 같은 말로 쓴다. 문서 안에서 "참여 멤버"와 "Contributor", "Draft"와 "초안"을 섞지 않는다. 처음 나올 때 대응하는 말을 한 번만 밝힌다.
- 한 용어는 한 뜻으로만 쓴다. 서로 다른 개념에 같은 말을 쓰지 않는다.

## 구조

- 결론을 먼저 쓰고 근거를 뒤에 붙인다.
- 순서가 있는 절차는 번호 목록으로 쓰고, 한 단계에 동작 하나를 둔다.
- 한 문단에는 한 주제만 둔다. 비교나 여러 속성은 문단 대신 표나 목록으로 쓴다.
- 확정되지 않은 내용은 문장 안에서 `(확정)`, `(제안)`, `(미정)`, `(FE 판단)`으로 표시한다. 확인하지 못한 것은 확인하지 못했다고 쓴다.

## 적용 범위

`docs/`, `.agents/`의 지침, 이슈·PR 본문, agent의 최종 보고에 적용한다. 코드 주석은 `docs/conventions/coding.md`의 주석 규칙을 따른다. 기획 원본처럼 이 저장소 밖 문서는 옮겨 적을 때만 이 규칙에 맞춘다.
