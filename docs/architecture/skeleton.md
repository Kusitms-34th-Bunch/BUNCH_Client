# 스켈레톤

서버에서 받을 내용의 자리를 받는 동안 회색으로 채우는 기준이다. 스켈레톤과 덮개(`PageLoading`) 중 무엇을 쓸지는 `motion.md`의 「Lottie」 중 「로딩 상태」를 따른다. 첫 진입에서 화면 모양을 알면 스켈레톤을 쓴다(#466).

## 세 층과 배치

| 층        | 위치                                           | 맡는 것                                |
| --------- | ---------------------------------------------- | -------------------------------------- |
| 회색 상자 | `@app/design-system`의 `Skeleton`              | 모양(`shape`)·색(`tone`)·깜빡임        |
| 공용 조각 | `apps/web/src/shared/components/skeleton/`     | 두 화면 이상이 같은 모양으로 쓰는 조각 |
| 화면      | 그 화면 컴포넌트 옆(`<화면 이름>Skeleton.tsx`) | 한 화면의 배치와 여백                  |

- 깜빡이는 회색 자리는 `Skeleton`만 쓴다. 화면에서 `animate-pulse`를 직접 쓰지 않는다.
- `Skeleton` 상자로 채우기 어려운 넓은 배경은 `surface-secondary` 토큰을 직접 쓴다(예: 번치 홈의 테마 배경 자리, `BunchHomeSkeleton`).
- 화면 스켈레톤은 한 폴더로 모으지 않는다. 화면 여백이 바뀌면 함께 고쳐야 해서 화면 옆에 둔다(`app-structure.md`의 page 가까이 두는 기준).
- 조각은 두 번째 화면이 같은 모양을 필요로 할 때 `shared/components/skeleton/`으로 올린다. 지금 공용 조각은 아래 셋이다(2026-11-23 확인).
  - `ProfileRowSkeleton`: 프로필 사진과 이름이 있는 목록 한 줄. 여러 줄 목록은 같은 파일의 `ProfileListSkeleton`
  - `PhotoGridSkeleton`: 사진 격자
  - `TextFieldSkeleton`: 제목 있는 입력란

## 그리는 기준

- 실제 화면과 구조·크기·간격을 맞춘다. 내용이 도착해도 레이아웃이 움직이지 않아야 한다.
- 입력란은 제목·입력란·글자 수 자리를 모두 회색으로 그린다(2026-11-23 사용자 결정, 이전 #473 기준을 바꿈). 필수 칸은 별표 때문에 제목 줄이 더 높아 `TextFieldSkeleton`의 `required`로 맞춘다.
- 설정 목록처럼 행 문구가 고정이고 서버 값이 토글뿐인 화면은 문구를 실제로 그리고 토글만 회색으로 둔다(`NotificationSettingsSkeleton`).
- 화면 틀은 실제로 그린다. 헤더와 그 안의 버튼, 화면을 나누는 탭(예: 팔로워·팔로잉), 목록 제목(예: 「멤버」)이 해당한다. 받는 동안에도 뒤로 가기와 탭 이동을 쓸 수 있게 한다.
- 받기 전에는 입력할 수 없게 실제 `input`을 두지 않는다.
- 동의 여부처럼 받아 봐야 보일지 아는 영역은 그리지 않는다(예: 프로필 편집의 출생연도·성별).
- Figma에는 스켈레톤 상태가 없다. 깜빡임과 색(`surface-secondary`)은 프런트엔드 제안이다(`Skeleton.spec.md`).

## 화면 읽기 프로그램 안내

- 회색 상자와 스켈레톤 묶음은 `aria-hidden="true"`로 숨긴다.
- 받는 중 안내는 화면에 늘 있는 상태 영역(`role="status"`)이 맡는다. 스켈레톤이 사라져도 같은 영역이 남아야 도착 안내(예: 「프로필을 불러왔어요」)를 이어서 읽는다.
- 화면 전체를 대신 그리는 스켈레톤은 그 안에 상태 영역을 둘 수 있다(`OtherBunchSkeleton`, `PhotoBoxSkeleton`).
- 받은 값으로 만드는 제목(예: 번치 이름 `h1`)은 받은 뒤에만 둔다. 진입 초점이 실제 제목으로 한 번만 가게 한다. 고정 제목(예: 사진함의 `sr-only` `h1`)은 스켈레톤에 둘 수 있다.

## 검증

- 스켈레톤과 실제 화면을 같은 폭(390px)에서 번갈아 캡처해 자리가 맞는지 본다.
- 컴포넌트 테스트는 받는 중 상태 안내와 숨김(`aria-hidden`)을 확인한다.
