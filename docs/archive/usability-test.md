# 사용성 테스트(UT) 세팅 (보관)

> 2026-11 UT가 끝나 보관한 기록이다(#295). 상태 B 시나리오·진행자 장치·클릭 흐름 수집 코드는 지웠으므로 현재 기준으로 쓰지 않는다.

UT는 웹에서 한 기기로 진행하고, 다른 멤버가 할 행동은 "미리 해 둔 상태"로 세팅한다(확정). 진행자가 다른 기기로 같은 번치를 함께 조작하지 않는다.

## 왜 미리 세팅하나

- 번들 업로드에는 참여 멤버 2명 이상과 참여 멤버 전원의 코멘트가 필요하다. 그래서 참여자 혼자서는 업로드까지 갈 수 없다.
- 가짜 데이터는 기기(브라우저)마다 따로 있다. 진행자 기기에서 남긴 코멘트는 참여자 화면에 보이지 않는다. MSW 가짜 DB도 브라우저의 IndexedDB에 저장된다(`docs/workflows/testing.md`의 "MSW 가짜 서버").
- 따라서 진행자의 행동은 시작 데이터에 넣어 둔다. 참여자가 업로드 직전까지 막히지 않게 하는 것이 목적이다.

## 역할

| 역할   | 계정 상태                                                    | 하는 일                                           |
| ------ | ------------------------------------------------------------ | ------------------------------------------------- |
| 참여자 | 번들 초안을 처음 만드는 사람(초안 생성자, 업로드 권한 있음)  | 과제를 수행한다                                   |
| 진행자 | 같은 번치의 일반 멤버. 이미 참여 멤버이고 코멘트를 남긴 상태 | 화면은 조작하지 않고 과제 안내와 관찰·기록만 한다 |

문서와 시작 데이터에는 실제 사람 이름 대신 역할만 쓴다. 계정 정보와 배포 주소는 저장소에 올리지 않는다.

## 시작 데이터

세팅 위치는 화면의 연동 상태에 따라 다르다.

- 서버 연동 전 화면: 화면이 읽는 샘플 데이터(`features/<feature>/fixtures/`)에 넣는다. 번들 공동 편집 화면은 `features/bundle/fixtures/draft.fixture.ts`를 읽는다.
- 서버 연동 후 화면: MSW 가짜 DB 시작 데이터(`src/mocks/db/seed.ts`)에 넣고, `NEXT_PUBLIC_API_MOCKING=enabled`로 빌드한다.

넣어 둘 상태는 아래와 같다.

- 참여자는 번치 멤버이고, 번들 초안의 생성자다.
- 진행자는 같은 번치의 일반 멤버이고, 그 초안의 참여 멤버다.
- 진행자는 그 초안에 코멘트를 이미 남겼다.
- 참여자가 자기 코멘트를 쓰면 업로드 조건이 채워진다.

## 상태 B 시나리오(가짜 서버)

번치 홈에서 시작해 「+」로 사진 P1~~P4를 고르고 번들을 만들면, 가짜 서버가 초안 생성 직후 상태 B를 덧입힌다(`src/mocks/scenario/`). 고른 사진이 정확히 P1~~P4일 때만 적용되고, 다른 구성은 일반 초안이다. UT가 끝나면 `mocks/scenario/` 폴더와 `handlers/bundles.ts`의 `onDraftCreated` 호출만 지우면 된다.

| 항목                | 상태 B 값                                                                                              |
| ------------------- | ------------------------------------------------------------------------------------------------------ |
| 참여 멤버·사진 순서 | 서버 규칙 그대로(큐시즘·경진·은우, 고른 순서)                                                          |
| 제목·날짜·위치      | 제목 채움, 날짜 10월 17일, 위치 속초해수욕장 1곳                                                       |
| 캡션                | 1번 작성 완료(「아침 7시 영금정! …」), 2번 「닭강정 줄 30분 섰는데」는 경진이 편집 중, 3·4번 비어 있음 |
| 코멘트              | 경진·은우 작성 완료, 큐시즘(참여자)은 미작성                                                           |
| 공개 범위           | 미선택                                                                                                 |
| 편집 중 표시        | 2번 사진 캡션은 경진, 위치는 은우가 편집 중이며 만료·해제되지 않는다(참여자는 편집권을 얻을 수 없음)   |

- 위치 저장과 편집권(`LOCATION`)은 서버 명세에 없는 가짜 서버 확장이다. 응답에 `locations`(provider, externalId, name, address)와 `locationsVersion`을 더했고, 화면은 위치를 바꾸기 전까지 서버 값을 보인다. 위치를 바꾸는 저장은 아직 화면에서만 유지된다(장소 검색 이슈에서 계약을 정한 뒤 연결).
- 텍스트는 UT 시나리오 「번들 초안 텍스트(상태 B)」 원문이다(제목「속초 첫째 날 🌊」, 경진·은우 코멘트 포함). 시나리오에 없어 임의로 정한 값은 위치 주소(「강원 속초시 조양동」)뿐이고 `src/mocks/scenario/utStateB.ts`에서 바꾼다.
- 진행자 장치(시나리오 필수)는 아래 「진행자 장치」 절을 본다. 되돌리기·초기화 로직은 `src/mocks/scenario/utStateB.ts`(`restoreStateB`, `resetToStateA`)에 있다.

## 시작 화면과 홈 화면 앱

- UT는 **번치 홈(`/bunch`)에서 시작**한다. 번치 홈 → 「+」 → 사진 선택(상태 A) → 번들 만들기 → 작성(상태 B) → 업로드 → 번치 홈 순서다.
- 참여자 기기에서는 주소창 없이 앱처럼 열리도록 홈 화면에 추가해 쓸 수 있다. iOS는 Safari의 공유 메뉴에서 「홈 화면에 추가」, Android는 Chrome 메뉴에서 「홈 화면에 추가」를 쓴다. 홈 화면에서 열었을 때 번치 홈이 첫 화면인지, 서비스 워커가 등록되는지, Safe Area가 맞는지는 실기기에서 확인해야 한다(#216에서 확인하고 이 문서에 결과를 적는다). 현재는 확인하지 않았다.
- 서비스 워커는 HTTPS 또는 localhost에서만 동작한다. `http://IP` 접속은 가짜 서버가 켜지지 않을 수 있다.

배포 절차(Vercel)와 홈 화면 앱의 이름·아이콘 설정은 [ut-deployment.md](./ut-deployment.md)를 본다.

위 자동 테스트는 각 단계를 따로 확인한다. 처음부터 끝까지 이어서 브라우저에서 돌려 본 것은 아니므로 회차 전에 한 번 직접 확인한다.

## 회차 전 준비

1. 클릭 흐름을 수집하는 빌드면 **참가자에게 팀 휴대폰을 건네기 전에** 화면 조작 기록(누른 버튼·화면 이동, 녹화 없음)이 남는다고 알리고 동의를 받는다. 화면을 여는 순간 첫 화면 이동 기록이 전송된다. 실명·연락처 같은 개인정보는 입력하지 않도록 함께 안내한다(아래 「클릭 흐름 수집」).
2. UT용 빌드를 HTTPS 주소 또는 localhost로 연다. 서비스 워커는 `http://IP` 접속에서 동작하지 않을 수 있다.
3. 브라우저의 사이트 데이터를 지운다. MSW 가짜 DB는 IndexedDB에 남아 새로고침해도 이전 회차 상태가 유지된다. 샘플 데이터 화면은 새로고침만으로 시작 상태로 돌아간다.
4. 새로고침한 뒤 첫 화면이 시작 데이터 상태인지 확인한다. 진행자가 참여 멤버로 보이고 코멘트가 있어야 한다. 진행자 장치의 「상태 A로 초기화」로 시작하면 이번 회차가 새 사용자로 기록된다.

## 회차 사이 초기화

회차가 끝나면 진행자 장치로 **상태 A로 초기화**한다(아래 절). 장치를 쓸 수 없으면 "회차 전 준비"의 3·4단계(사이트 데이터 삭제와 시작 상태 확인)를 다시 한다. 앞 참여자가 남긴 사진·코멘트가 다음 참여자에게 보이면 안 된다.

## 클릭 흐름 수집(PostHog)

참가자가 누른 버튼 순서와 막힌 지점(연타 클릭, 반응 없는 클릭)을 PostHog로 모은다. 화면 녹화는 하지 않는다(ADR 018).

- 켜기: 가짜 서버 빌드(`NEXT_PUBLIC_API_MOCKING=enabled`)에 `NEXT_PUBLIC_POSTHOG_KEY`(PostHog 프로젝트 토큰)를 넣는다. 둘 중 하나라도 없으면 수집하지 않는다. UT 주소는 저장소 secret `UT_POSTHOG_KEY`를 UT Deploy workflow가 빌드에 넘긴다([ut-deployment.md](./ut-deployment.md)). 운영 배포에는 넣지 않는다.
- 참가자 구분: UT는 팀 휴대폰의 Expo Go로 진행한다. 진행자 장치의 「상태 A로 초기화」가 PostHog 사용자를 새 익명 사용자로 바꾼다. 회차 하나가 사용자 하나로 나뉘므로, 회차 순서·시작 시각을 진행 기록에 적어 두고 PostHog의 사용자와 맞춘다.
  - iOS 쉘은 탭마다 WebView가 따로 있다. 이미 열려 있던 다른 탭이 새 사용자로 바뀌는지는 실기기로 확인하지 않았다. 회차가 섞이지 않도록 회차 사이에 Expo Go 앱을 완전히 닫았다 연 뒤 「상태 A로 초기화」로 시작한다.
- 수집되는 글자: 누른 버튼·링크의 글자가 함께 전송된다. 참가자가 바꾼 번들 제목도 카드 버튼 글자로 보이면 전송될 수 있다. 입력칸에 쓰는 값 자체는 전송되지 않는다. 그래서 1번 동의 때 개인정보를 입력하지 않도록 안내한다. 운영에서는 사용자 글자를 수집에서 빼는 처리가 필요하다(ADR 018).
- 보기
  - 참가자별 흐름: PostHog **Activity**나 **People**에서 회차의 사용자를 고르면 클릭(`$autocapture`)·화면 이동(`$pageview`)이 시간순으로 보인다. 연타는 `$rageclick`, 반응 없는 클릭은 `$dead_click` 이벤트다.
  - 과제 퍼널: **Product analytics → New insight → Funnel**에서 단계를 화면 이동으로 정한다(예: `/bunch` → 사진 선택 → `/bunch/drafts/...` → 업로드 뒤 `/bunch`). 단계별 이탈과 걸린 시간을 본다.
  - 클릭 히트맵: PostHog **Toolbar**를 UT 주소에서 열어 화면 위에 클릭 분포를 겹쳐 본다.
- 자동화 브라우저(Playwright·헤드리스 Chrome)는 PostHog가 봇으로 보고 이벤트를 보내지 않는다. 수집 확인은 사람이 쓰는 브라우저나 Expo Go에서 한다.
- 아이콘만 있는 버튼은 접근성 이름(`aria-label`)이 함께 기록돼 구분된다. 진행자 장치(숨은 5연타 영역)의 클릭도 기록되므로 분석할 때 걸러 본다.

## 진행자 장치

가짜 서버를 켠 빌드(`NEXT_PUBLIC_API_MOCKING=enabled`)에서만 있고, 참여자 화면에는 아무것도 보이지 않는다.

- **열기(번치 홈)**: 번치 홈의 **캐릭터 자리(회색 상자)를 1초 이내 간격으로 5번 연달아** 누른다. 회차 시작 전과 사이에 상태 A로 초기화할 때 쓴다.
- **열기(작성 화면)**: 헤더 가운데(저장 상태 글자 자리)의 보이지 않는 영역을 1초 이내 간격으로 5번 연달아 누른다. 영역은 폭 160px, 높이는 상단 Safe Area + 48px이고, 뒤로 가기·업로드 버튼은 양 끝이라 가리지 않는다. 작성 화면에서만 있고 상태 B로 되돌릴 때 쓴다. 중간에 1초 넘게 쉬면 처음부터 다시 센다.
- **상태 A로 초기화**: 가짜 DB를 시작 데이터로 되돌리고(만든 초안·발행한 번들·편집권 삭제, 기존 번들 2개만 남음) 번치 홈에서 다시 시작한다. 회차 시작 전과 회차 사이에 쓴다.
- **상태 B로 되돌리기**: 작성 화면(`/bunch/drafts/{id}`)에서만 켜진다. 같은 초안에서 참여 멤버(큐시즘·경진·은우), 사진 P1~P4, 제목·캡션·위치·날짜, 경진·은우 코멘트, 고정 편집 중 표시를 상태 B로 맞추고 참여자가 쓴 코멘트와 공개 범위는 지운다. 참여자가 경진·은우를 내보내는 등 세팅이 깨졌을 때 쓴다.
- 둘 다 가짜 DB가 저장되기를 기다린 뒤(약 0.7초) 화면을 새로 불러온다. 되돌리는 순간 참여자가 입력 중이던 값이 서버에 막 저장되는 경우가 드물게 있을 수 있어, 되돌린 뒤 화면이 상태 B와 같은지 한 번 확인한다.
- UT가 끝나면 `src/mocks/scenario/`와 `ApiMockingGate`의 불러오는 부분을 지운다.

## 연동 상태와 서버 명세의 차이

현재 문서 [가짜 서버와 서버 연동 현황](../workflows/mock-server-status.md)으로 옮겼다.

## 확인하지 않은 것

- 진행 대본(과제 문구, 진행자가 개입하는 시점)은 정해지지 않았다(미정).
- UT 상태 B(번들 초안 직후 제목·캡션·위치·날짜·다른 멤버 코멘트가 채워진 상태), 편집 중 표시 고정, 회차 초기화·복구 장치는 아직 없다. 이것이 없으면 UT에서 업로드(참여 멤버 전원 코멘트)를 끝까지 할 수 없다.
- UT 시작 화면(번치 홈 또는 번들 만들기 선택 화면)이 확정되지 않았다.
