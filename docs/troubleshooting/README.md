# Troubleshooting History

재현 가능한 버그, 환경별 함정, 검증에서 발견한 반복 실패만 기록한다.

- 기록 전에는 기존 문서와 issue를 확인해 중복을 피한다.
- `records/YYYY-MM-short-title.md` 형식으로 작성하고 `.agents/templates/troubleshooting.md`를 사용한다.
- 증상, 원인, 해결, 검증, 재발 방지 또는 후속 작업을 구분한다.
- 단순 일회성 오류나 아직 원인이 확인되지 않은 추측은 기록하지 않는다.

## 외부 요인으로 아직 풀 수 없는 문제

우리 코드만으로 해결할 수 없는 OS·브라우저 정책, 라이브러리 한계, 백엔드·기획 쪽 계약 불일치는 같은 `records/`에 같은 템플릿으로 남기되, 맨 위에 상태를 적는다.

- 상태는 `open`, `monitoring`, `resolved`, `wontfix` 중 하나다. 외부 조치가 필요하면 담당 주체와 다음 확인 시점을 적는다.
- 재현 절차와 관찰 근거가 있어야 한다. 코드를 더 짜면 우리 힘으로 끝나는 일은 기록하지 않고 issue로 둔다.
- 해결되면 지우지 않고 상태와 해결일을 갱신한다. 같은 문제가 다시 나오면 새 문서를 만들기 전에 기존 기록의 조건과 임시 대응부터 확인한다.
- 증상, 영향, 임시 대응, 해소 조건을 추가로 적는다.
